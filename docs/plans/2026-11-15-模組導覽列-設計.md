# 模組導覽列：設計

2026-11-15。這份是研究與設計，不是工作單；沒有改任何程式、測試、範本。文中的行數、上限、檔名都是寫這份時對著 repo 量的（`tests/test_budget.py` 的算法）；標「估計」的是還沒寫出來的程式，實作時要重量。

**一句話**：有頁面的模組，頁面最上面多一排「模組導覽列」：主控面板、父層模組、這個模組底下的子模組，按一下就跳過去。這一排由開頁面的地方（面板的 `ui/web.py`、「互通」的 `popup.py`）在頁面載入後注入，作者不用寫任何東西；新模組、舊模組都一樣。跳過去的意思是「先關掉這一頁，再跑那個模組」——面板裡排在這次執行之後，面板外另開一個程序。底下的基礎是「問得到父層與子模組、知道是哪個模組開的這一頁」，建議做成 `app.parent`、`app.children` 與 `Core.running`（選項 B，`api_version` 3 → 4）。

**已經定的事（不再當選項）**
1. 只有有頁面的模組才顯示：用 `app.page` 開頁面的，或從面板外經「互通」開的。按下去只在訊息區印幾行就結束的模組，不另開視窗，行為不變。
2. 安全模式與 tkinter 後備面板沒有頁面，就沒有導覽列（`ui/tk.py` 的 `page` 只記一行，不動）。
3. 同一層的其他模組預設不列；有上限的收起選單寫在第 9 節，當附帶提案，不在主要設計裡。
4. 不動別人做的模組：`modules/linebot行事曆`、`modules/車車`、`modules/同事測試`。第 6 節寫它們會受到什麼影響。

### 0.2 頁面是在哪裡開的

### 0.3 執行模型：頁面開著時，面板上按什麼都只會排隊

對著程式確認過：
- `ui/web.py` 的 `_work` 是唯一的工作執行緒，一次做一件（`tests/test_web.py::test_jobs_run_one_at_a_time`）；頁面上按圖示是 `Bridge.press` → `submit`，只排進佇列。
- 模組的 `app.page` 是在那件工作裡、在工作執行緒上呼叫的，`WebPanel.page` 停在 `done.wait()`，視窗關掉才回來（`tests/test_web.py::test_page_blocks_until_closed`）。2026-11-15 跑過這兩個測試，都是綠的。
- 所以頁面開著的期間按導覽列去跑另一個模組，如果只是 `submit`，**會排在現在這件工作後面，等頁面關掉、模組跑完才動**。D89 就是因為這一點，把行事曆搬到自己的程序。
- 頁面的 JS 呼叫 `pywebview.api.<方法>` 時，pywebview 每個呼叫各開一條執行緒（行事曆 `Api` 的 `_guarded` 就是為這個抓鎖）。在那條執行緒上直接 `app.run(另一個模組)` 機械上跑得動（工作執行緒停在 `done.wait()`，等於巢狀的 `app.run`），但 `core/runner.py` 換的是整個程序的標準輸出、工作目錄與 `sys.path`，而 `_running` 是一個共用的堆疊；被叫的模組要是也開頁面，那條 JS 執行緒會卡住，原本那一頁的下一個呼叫又在別的執行緒上同時進 runner。這條路不安全，不採用。

面板外（互通）：
- `Popup._work` 只跑一件 `job`（`run.py` 給的那一個），`page` 一樣卡在 `closed.wait()`。
- `job` 跑完後 `popup.done(...)`：小視窗沒出現過、又沒出錯，就直接 `window.destroy()`，事件迴圈結束，`run.py` 最後 `os._exit`。所以「等這一個跑完、在同一個程序裡再跑下一個」做不到（回去鈕 `open_panel` 能這樣做，是因為那時小視窗一定是顯示著的、不會自己關）。

### 0.4 叫得到什麼、問得到什麼

- `app.run(name: str)`：先找面板目前這一層，找不到再找最上層（D83）；**用名字叫不到下一層**（CHANGELOG 0.5.1「這一版沒有做」：用名字叫下一層的模組）。
- `app.run(info: ModuleInfo)`：`Core.run_by_name` 收到 `ModuleInfo` 就直接 `press`，**哪一層都叫得到**（D83：「傳 `ModuleInfo` 進來的路徑不變」）。缺的是拿到那個 `ModuleInfo` 的方法。
- `app.modules` 是面板目前範圍的模組（面板外是最上層），不是「這個模組的子模組」。`app.module.has_children` 只說有沒有。
- 父層、子模組都問不到；模組要自己 `from core import scan`，用 `find_children(folder, root)`、`is_module`、`module_info`（都在 `docs/07` 第 13 節的清單上）。父層的 `level` 要自己對 `roots_from_config` 算。
- 行事曆的模組列（`modules/行事曆/iplot.py` 的 `Api._scan`、`Api.modules`、`Api.launch`，`page.html` 的 `loadModules`）：只掃最上層（`scan.find_modules(roots)`），用名字比對，經互通的 `run.py` 另開程序；最右邊的「圖示面板」只在最上層剛好一個「主控面板」時出現。
- 互通的回去鈕（`run.py` 的 `back_button`）：只看最上層（`core.all_modules()`，面板外一律是最上層）有沒有剛好一個「行事曆」或「主控面板」（D88、D93）。

## 1. 基礎：叫得到、問得到

導覽列要三樣東西，現在都沒有正式的接口：

| 要的 | 現在 | 缺什麼 |
|---|---|---|
| 這一頁是哪個模組開的 | `View.page` 不知道；`core.runner._running[-1][0]` 有資料夾，但那是 runner 的內部 | 一個正式的「正在執行的模組」 |
| 父層模組 | 沒有；要自己用 `scan` 算，`level` 還要對根目錄 | 一個算法，寫在一個地方 |
| 子模組 | `scan.find_children(folder, root)` | 不缺，但模組要知道去用它 |
| 叫它們 | `app.run(ModuleInfo)` 已經做得到 | 不缺 |

**結論：「叫」不用新東西，`app.run(ModuleInfo)` 本來就叫得到任何一層；缺的是「問」**——父層、子模組、與「誰開的這一頁」。

父層的定義（三個選項都一樣）：
- `info.folder.parent`，**不越過根目錄**：等於 `info.root` 的話沒有父層（最上層的模組沒有父層，`modules/` 本身不算）。
- 那個資料夾要是模組（`scan.is_module`，符號連結不算，跟面板一樣）。中間隔著一個不是模組的資料夾（`a/普通資料夾/b`）就沒有父層——面板也進不到 b（`find_children` 只看直接的子資料夾）。
- `level`：父層的上一層就是根目錄時，用那個根目錄的 `level`（`here`／`parent`／`extra`）；否則是 `child`。`root` 跟原本的一樣。
- 子模組：`scan.find_children(info.folder, info.root)`，跟面板進到下一層時看到的一樣（略過 `.` 開頭，名稱 NFC 排序）。

**用名字叫下一層**：三個選項都不做。有了 `ModuleInfo`，要叫子模組寫 `app.run(next(m for m in app.children if m.name == "子"))`（選項 B）；D83 的找法不動，避免原本找得到的名字變成同名錯誤（D83「沒選：兩層合在一起找」的同一個理由）。

基礎放在哪裡，是三個選項的主要差別：

- **選項 A**：不加 `app` 的方法，`api_version` 不動。面板（`ui/`）與互通各自用 `core.scan` 算；「誰開的」面板讀 runner 的內部，互通用一個 `Core` 的子類別自己記。模組要父層／子模組，照文件自己用 `core.scan` 算。
- **選項 B（建議）**：`app.parent`、`app.children` 兩個新屬性，`core.scan.parent_of`，`Core._depth` 換成公開的 `Core.running`（同樣行數）；`api_version` 3 → 4，只加不減。面板、互通（新核心上）、行事曆、任何模組都用同一套。
- **選項 C**：同 B 的基礎，但導覽列本身是一個工作坊模組，`ui/` 只開一個通用的「頁面掛勾」。

## 2. 在面板裡「跳」是什麼意思

**定義：按導覽列上的一個模組 = 關掉現在這一頁 + 跑那個模組，跟在面板上雙擊它一樣**（雙擊是執行，▸ 才是進入下一層；`ui/app.js` 的 `has_children` 那段）。那個模組有頁面，就開它的頁面、它的導覽列；只印幾行的模組，輸出進面板的訊息區。

### 2.1 面板裡：先關掉這一頁，排在這次執行之後

1. 頁面上按一顆鈕 → JS 呼叫 `pywebview.api._iplot_nav(i)`（`i` 是編號，不是路徑；見第 3.3 節）。
2. Python 這邊（pywebview 的那條執行緒）：檢查 `i` 是整數、在範圍內，記下目標，`window.destroy()`。
3. `closed` → `WebPanel.page` 從 `done.wait()` 回來；回來之前 `submit` 一件工作：重新確認目標還是模組（`is_module`），是就 `self.press(core, 目標)`，不是就重掃、在訊息區說一句找不到。
4. 現在這件工作繼續：模組 `app.page` 之後的程式照跑（例如行事曆的 `finally` 刪 `.pid`），跑完；接著工作執行緒做第 3 步排的那一件。

「主控面板」：只關掉這一頁，不排工作；頁面關掉後，同一個程序裡剩下的視窗就是面板（實作時在 Mac 上量它會不會到最前面；不會的話再排一件「叫到最前面」的工作，做法照「主控面板」模組在面板程序裡的那段）。

不採用的做法：
- **頁面開著直接跑**：做不到（第 0.3 節），只會排隊，使用者按了沒反應。
- **在 JS 那條執行緒上跑**：不安全（第 0.3 節）。
- **面板裡也另開程序**（像行事曆的模組列那樣經 `run.py`）：被叫的模組的訊息不進面板、`app.memory` 不共用、跟在面板裡雙擊的結果不一樣；而且沒有裝互通就不能跳。

已知的限制，要寫進文件：
- 頁面是巢狀開的——模組 X 用 `app.run` 叫了 Y、Y 開頁面——跳的那一件要等 X 也跑完；X 之後又開自己的頁面的話，要等那一頁也關掉。
- 頁面是在另一頁的 JS 呼叫裡開的（工作執行緒還卡在外面那一頁）：跳的那一件要等外面那一頁關掉。**建議：這種時候不畫導覽列**（`WebPanel` 記著目前開著幾頁，已經有一頁開著就不注入），免得按了像沒反應。
- 跳 = 關掉這一頁，跟按視窗的 ✕ 一樣：模組自己沒存的東西，風險跟使用者自己關一樣（行事曆已知「關視窗前最後一秒打的字可能沒存」）。
- 每跳一次就是關一個視窗、開一個新的，新視窗開在預設位置。要不要記住上一頁的位置，列在第 11 節。
- 目標是工作坊裝來、還沒確認過的模組（`.unconfirmed`），照 `Core.press` 原本的做法先問一次。

### 2.2 面板外（互通）：另開一個程序

1. 按一顆鈕 → `pywebview.api._iplot_nav(i)`。
2. Python 這邊：`subprocess.Popen([sys.executable, <run.py>, <目標資料夾>], start_new_session=True, stdin/stdout/stderr=DEVNULL)`，環境變數去掉 `IPLOT_CALENDAR`（照行事曆 `Api.launch` 的寫法）。開成功才 `window.destroy()`；開不成功（`OSError`）就在小視窗說一句、頁面留著。
3. 這一頁關掉 → 模組跑完 → `popup.done` → 程序結束，跟使用者自己關掉頁面一樣。
4. 「主控面板」：`run.py` 跑最上層那個「主控面板」模組的資料夾（它會找開著的面板叫到最前面，沒有就開一個），也是另開程序。只在最上層剛好一個「主控面板」時才列（跟 `back_button` 同一個條件）。

在同一個程序裡接著跑做不到（第 0.3 節：小視窗沒出現過時，`done` 會直接關掉、`os._exit`）。另開程序也是互通原本的模型（每次一個獨立的程序，D81），行事曆的模組列、`launch` 也是這樣做。多出來的代價是每跳一次多啟動一次 Python（D89 量過約 1–2 秒）。

## 3. 導覽列放在哪裡

### 3.1 四個做法

| 做法 | 怎麼做 | 為什麼不（或為什麼要） |
|---|---|---|
| 字串層級包一層 | 開視窗前在 `html` 字串的 `<body>` 後面插一段 | 模組給的是任意字串：可能沒有 `<body>`、可能是整份產生的；要自己剖析 HTML。插進去的段落在模組的 `<script>` 之前跑，跟模組的初始化搶順序。頁面換頁（模組用連結換一頁）之後就沒了。不採用 |
| iframe 包一層 | 外面一頁放導覽列，模組的頁面放進 iframe | pywebview 只把 `pywebview.api` 注入最上層那一頁，模組頁面裡的 JS 叫不到自己的 `api`。不採用 |
| 視窗上另外一排 | 原生工具列（macOS 的 NSToolbar）或另一個小視窗貼著 | 要寫平台各自的程式（`ui/` 裡沒有，`AppKit` 只在互通的 `mac_dock` 用過）；Windows 未經實機驗證的地方更多；小視窗貼不住。不採用 |
| **載入後注入（採用）** | 視窗的 `events.loaded` 之後 `evaluate_js` 一段固定的 JS，在 `<body>` 最前面放一個元素，內容放在 Shadow DOM 裡 | 不碰模組的字串；換頁後 `loaded` 再來一次，再注入一次；樣式隔開 |

### 3.2 注入的那一段長什麼樣

- 一個自訂元素 `<iplot-nav>`（不用 `div`，模組的 `div { … }` 選擇器碰不到它），`document.body.prepend(...)`。
- 元素本身的 inline style：`all: initial; display: block; flex: none; position: sticky; top: 0; z-index: 2147483647`。`all: initial` 擋住繼承來的字型與顏色；inline style 蓋過模組樣式表裡不是 `!important` 的規則。
- 內容放在 `attachShadow({mode: "closed"})` 裡：模組的 CSS 進不去，導覽列的 CSS 出不來；深淺色用 shadow 裡的 `prefers-color-scheme`。
- 字一律 `textContent`（名稱可能有 `<`、引號），跟面板與互通的頁面同一條規則。
- 整段包在一個立即執行的函式裡，不留全域變數；已經有 `<iplot-nav>` 就不再加（同一頁 `loaded` 兩次時）。
- 高度約 32px；子模組多時這一排橫向捲動，不換行、不設上限（列的都是這個模組自己的子模組）。
- 長相（估計）：

```
┌────────────────────────────────────────────────────────────┐
│ 🎛 主控面板 │ ↑ 課程作業 │ 📄 HK1  📄 HK2  📄 HK3  …        │  ← <iplot-nav>
├────────────────────────────────────────────────────────────┤
│                    模組自己的頁面                           │
```

  主控面板固定在最左；父層用「↑ <父層的顯示名稱>」，不寫「上一層」（面板上紅色的「上一層」是 iPLoT 資料夾的上一層，`T["parent"]`，會混淆）；子模組用 `ICON`（沒有就用顯示名稱的第一個字，跟行事曆的模組列一樣，不載入 `icon.png`——`html=` 開的頁面裡 `file://` 的圖顯示不出來，2026-10-14 量過），旁邊是顯示名稱；滑鼠停著顯示說明（`description`）。沒有父層就不畫那一格；沒有子模組就只有前兩格。

### 3.3 會不會影響模組自己的頁面

| 模組的東西 | 影響 |
|---|---|
| 樣式 | 模組的 CSS 進不了 Shadow DOM。`<iplot-nav>` 本身會被 `*`、`body > *`、`:first-child` 這類選擇器選到；`all: initial` 的 inline style 擋住大部分，`!important` 的擋不住 |
| 版面 | `body` 是 `flex-direction: column`（行事曆、互通的小視窗都是）或一般的流排：導覽列在最上面，內容往下推 32px，正常。`body` 是橫向的 flex 或 grid：導覽列會變成左邊一欄——這種頁面要關掉導覽列。`html, body { height: 100% }` 又不是 flex 的頁面：會多出 32px 的捲動 |
| JS | `document.body.firstElementChild`、`document.body.children` 會多一個元素；`document.body.innerHTML = …` 整個換掉的頁面會把導覽列一起換掉（換掉就沒有了，不會壞）。不留全域變數 |
| `pywebview.api` | 多一個函式 `_iplot_nav`，用 `window.expose` 加。**撞不到模組的方法**：pywebview 把 `js_api` 攤開時略過底線開頭的名字（`lib/webview/util.py` 的 `get_functions`），所以模組的 `api` 永遠不會有 `_iplot_nav`；`expose` 本身不擋底線（`lib/webview/window.py` 的 `expose`、`js/api.js` 的 `_createApi`）。模組的 JS 自己呼叫它也只是跳過去，跟按鈕一樣 |
| 安全 | `_iplot_nav` 只收一個編號；目標的 `ModuleInfo` 是 Python 在開頁面時算好、留在 Python 這邊的，頁面給不了路徑（跟 `Bridge` 只認面板上有的 id 同一個原則）。跳之前再確認一次還是模組 |

`window.expose` 與 `events.loaded` 在 `lib/` 的 pywebview 6.2.1 都有；0.5.0、0.5.1、0.6.0 的 `requirements/web-mac.txt` 都釘 6.2.1，所以互通在舊核心上也能用。

### 3.4 模組怎麼關掉這一排

在自己的 HTML 裡放一行：

```html
<meta name="iplot-nav" content="off">
```

注入的 JS 先找這個標記，有就什麼都不做。選這個而不是 `app.page(..., nav=False)`：加參數要改 `View.page` 的簽名，那是 `docs/07` 第 13 節釘住的承諾，互通 0.2.x 的 `Popup.page` 收到第四個參數會直接 `TypeError`；也不用 `iplot.py` 裡的常數（`NAV = False`），那要改 `core/meta.py`（核心邏輯）。HTML 的標記不碰任何接口，換頁之後也跟著頁面走。

1. **選項**：B（建議；核心邏輯上限 516 → 530，`api_version` 4，核心 0.7.0）、還是 A（核心邏輯不動，0.6.4）。這也決定互通要不要先出一版認 0.7。
2. **`ui/web.py` 的上限** 230 → 235，與新的 `ui/nav.py`、`ui/nav.js` 各 60，可不可以。
3. **面板裡跳到「主控面板」**只是關掉這一頁（建議），還是也要把面板的麵包屑帶到這個模組那一層（要用 `Core.enter`，它不在第 13 節的清單上，也會改變使用者原本停的位置）。
4. **跳到別的模組時，面板要不要跟著換到那一層**：建議不要，面板停在原本的地方；跳過去的模組照樣跑得動（`Core.press` 不看面板停在哪裡）。
5. **巢狀的頁面**（一頁開著的期間又開了一頁）不畫導覽列（建議），還是照畫、讓跳的那一件等外面那一頁關掉。
6. **互通裡跳的時候要不要關掉原本那一頁**：建議關（跟面板一樣，「跳」的意思才一致）；不關的話，面板外會同時開著好幾頁、好幾個程序。
7. **頁面視窗的位置**：每跳一次就開一個新視窗。要不要記住上一頁的位置與大小、新的開在同一個地方（`ui/web.py` 與互通各再幾行），還是先不做。
8. **視窗高度**：導覽列約 32px 佔掉模組原本 640×520 的一部分。維持 520（建議，最簡單），還是有導覽列時開 552。
9. **行事曆**：照第 6.1 節加標記、關掉新的那一排（建議），還是讓兩排並存。
10. **別人的模組**（`車車`、`linebot行事曆`）會自動多一排、`linebot行事曆` 會出現兩排：照「不動別人的模組」不改，在發佈紀錄裡寫清楚，讓作者自己加標記（建議）；還是在導覽列這邊另外想辦法（例如頁面裡已經有某種標記就自動不畫——這份沒有找到不靠猜的判斷法）。
11. **父層的字**：「↑ <父層的顯示名稱>」（建議），還是要一個固定的字。不用「上一層」，會跟面板上紅色那組混淆。
12. **同一層的模組**（第 9 節）：先不做（建議），還是跟這次一起做。
13. **互通的回去鈕**（D88、D93）這次不動（建議）；有了 `app.parent` 之後要不要讓它在有父層時回父層，留到下一次。
14. 這次的需求清單在「`app`」那一項之後就斷了；第 7 節每個選項另外寫了互通、行事曆、測試、代價，是照前面幾項的意思補的。有漏掉的項目要再補。
