# M7 開放上傳：設計反查

2026-10-19。對象是 `docs/plans/2026-10-19-M7-開放上傳-設計.md`（下稱「設計」）在 commit c046a23 的版本。查三件事：設計提到的名稱、路徑、D 編號，對著程式與 `docs/03`、`docs/07` 核一次；照設計做出來的 zip 與 `index.json`，現在的 `modules/工作坊/workshop.py` 收不收得下；機器人的安全。

**結果：Critical 3 條、Important 25 條、Minor 25 條，全部改進設計，一條一個 commit（c046a23 之後的 53 個，加一個整理的 2f8a87d）。另有 3 條被推翻，沒改。** 每條的「改了」寫的是那一條的 commit。

## 怎麼查的

- 五個面向各一位反查者：引用與發佈、工作坊收不收得下、Actions 與 GitHub、zip 的處理、名字歸屬與碰不碰得到別人的東西。每個面向再一位對抗驗證者，逐條試著推翻（自己讀程式、做實驗、查 docs.github.com）。最後一位補漏。
- 實驗都在 session 的暫存資料夾做，只讀 repo：用 `ditto -c -k --sequesterRsrc --keepParent`（Finder「壓縮」的同一種壓法）壓中文、NFD、帶符號連結、帶自訂圖示的資料夾；Python 3.12、3.14 的 `zipfile`、`ast` 對加密、Deflate64、壞的 deflate、宣告大小騙人、很深的巢狀；git 2.50.1 在 `core.ignorecase=false` 下對 `.gitignore`、`.gitattributes`、`.git` 檔、`GIT~1`、rebase 的競爭；`urllib` 轉址時帶不帶 `Authorization`；`workshop.py` 的副本對 NFC／NFD、`#`、`%` 名稱的安裝。
- 沒碰 `iplot-workshop` 的本機 clone 與網站。GitHub 那邊的行為（表單送出後的內文、附件網址、核可、push protection 擋不擋 `GITHUB_TOKEN`）查不到的，都放進 Task 0。

## Critical

**C1 Finder 壓的 zip 沒標 UTF-8，中文名的模組全部被退。**
- 位置：§5.2 第 4 步（檔名編碼那一條）、§10「檔名編碼」、§14、§17「收」。
- 問題：設計寫「檔名有中文、zip 卻沒標 UTF-8：不收」。Finder 的「壓縮」寫的檔名是 UTF-8，卻每一條都不標旗標（`flag_bits` 沒有 0x800，也沒有 Unicode Path 擴充欄位）；Python 預設照 cp437 解成亂碼（「整理桌面/」讀成 `µò┤τÉåµíîΘ¥ó/`）。照字面做，R4 的主流程第一步就斷了；改成「看名字裡有沒有中文」也不行：亂碼裡一個中文字都沒有，模組會用亂碼名稱發佈。§9.3 的種子是 `publish.py` 打的（Python 會自動標旗標），驗收看不出來；§17 的樣本用 `zipfile` 造也看不出來。
- 建議：用 `zipfile.ZipFile(f, metadata_encoding="utf-8")` 打開，解不開（Big5）才退；解完做 NFC。§17 的 Finder 樣本用 ditto 真的壓一份放進 `tests/`。Task 0 加一項：在 Finder 壓一個中文名的模組，真的從表單傳。
- 改了：eb2062f。

**C2 一份上傳就能讓 receive 每次都失敗，之後誰的都收不進來；receive 一失敗，build、deploy 全跳過。**
- 位置：§5.1、§5.2 開頭與最後一段、§5.5 build／deploy 的 `if`、§10、D104。
- 問題：receive 每次從最舊的、還開著的 issue 收起。設計只寫「哪一步不過就回那一句」，沒寫丟例外怎麼辦。實驗：用 `zip -P` 加密的 zip 讀出時丟 `RuntimeError`、Deflate64 丟 `NotImplementedError`、壞的 deflate 丟 `zlib.error`、標了 UTF-8 卻不是的檔名在 `ZipFile()` 就丟 `UnicodeDecodeError`、100 KB 的一串 `-` 讓 `ast.parse` 丟 `MemoryError`、`.GIT/`、`GIT~1/`、`working-tree-encoding` 讓 `git add` 回 128——都不是 `BadZipFile` 或 `SyntaxError`。這一份永遠排第一，每次都卡住。另外 build `needs: receive` 又沒有狀態函式，GitHub 預設前一個 job 失敗後面全部跳過，連研究助理的 push（下架）都不會部署。
- 建議：每一份包在自己的 `try` 裡（從 `ZipFile()` 到 `git add`）；已知的例外回「zip 打不開或壞了」、貼「沒收」；其他 `Exception` 回「機器人處理不了」、貼「卡住」、拿掉「上傳」，不再排進下一次；寫到一半就 `git reset --hard` 加 `git clean`。build、deploy 的 `if` 帶 `!cancelled()`。
- 改了：42ba95d。

**C3 說明、notes、`ICON` 沒有長度上限。**
- 位置：§5.2 第 7、8 步、§6、§13 第 4 條。
- 問題：CHANGELOG 第一段 60 MB 壓起來只有 12 萬位元組，過得了 25 MB、100 MB 兩道。照 `publish.latest` 的取法，`index.json` 就是 60 MB，每個人按「工作坊」都要下載；`registry.json` 存每一筆的 notes，兩份就超過 GitHub 的 100 MiB，之後每一次 push 都被拒，所有上傳卡住。
- 建議：說明 500 字、notes 1000 字、`ICON` 16 字，超過截短；build 時 `index.json` 超過 2 MB 不部署；數字寫進 §13。
- 改了：868eb8e。
