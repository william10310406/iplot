# iPLoT 0.5.1 版本報告（2026-10-15）

對象：已經發佈的 `v0.5.1`（工作坊 `https://william10310406.github.io/iplot-workshop/`）。這一份只檢查、只記錄，沒有改任何程式；檢查中發現的問題寫在第 6 節，沒有修。給使用者看的操作說明是 [`docs/08_操作說明-0.5.1.md`](../08_操作說明-0.5.1.md)。

文中「推測，未親眼看」指的是根據程式、系統工具的輸出與 macOS 的已知行為推出來、沒有人在那個畫面上親眼看過的部分。

## 1. 結論

- **能不能把下載連結直接給一個從沒裝過 iPLoT 的人：不建議直接給，要附上安裝說明。** 下載、解壓、程式本身都沒問題（線上的包與 `update.json` 的 sha256 一致，測試 804 個全綠），卡在三件事：
  1. **雙擊 `iPLoT.command` 會被 macOS 擋下來。** 從瀏覽器下載的包帶著隔離標記，`iPLoT.command` 沒有簽章，`spctl` 判定「rejected，no usable signature」（第 3.2 節）。README 安裝第 3 步說的「選『打開』」在這台的 macOS 26.5 上不對（下載頁則完全沒提）：要到「系統設定 → 隱私權與安全性」按「強制打開」（或在終端機用一行指令拿掉隔離標記）。這一步沒有人在乾淨的帳號上親眼走過。
  2. **要先自己裝 Python 3.10 以上。** macOS 內建的 `/usr/bin/python3` 是 3.9.6，iPLoT 會說一句「iPLoT 需要 Python 3.10 以上（目前是 3.9.6）。請安裝 python.org 的版本。」就結束；下載頁沒有寫這個前提（第 3.3 節）。
  3. **第一次啟動可能連續跳出幾個「終端機想要取用……」的權限對話框**（掃描上一層會列出家目錄底下的「桌面」「文件」「下載項目」，推測，未親眼看；第 3.3 節）。
- **另外，行事曆的「發佈」有一個會把取消公開的日子留在 `發佈/` 的問題**（第 6 節第 1 項）：要用「發佈」的人，交出去之前先決定修或先在說明裡交代。
- **已經有舊版的人按「更新」能不能直接用：0.5.0 可以，0.4.0 以前不行。** 0.5.0 按「更新」換成 0.5.1 已經用腳本對真的網址走過（複本標成 0.4.9，18/18 通過；0.5.0 到 0.5.1 之間「更新」「工作坊」「作業系統」三個模組一行都沒變，所以這條路就是 0.5.0 的人會走的那一條）。但「更新」只換核心：要「互通」「主控面板」「行事曆」，換完之後還要在「工作坊」各裝一次（行事曆要先有互通）。0.3.0、0.4.0 沒有「更新」這個模組，只能重新下載。

## 2. 這一版給使用者的東西

- **互通**：任何模組都可以不開面板就打開——Spotlight 打名字、把捷徑資料夾拖到 Dock 當一排按鈕、或在終端機打一行指令；模組的對話框與輸出在一個小視窗裡。模組按過「加上」之後，在終端機直接 `python3 iplot.py` 也是用小視窗跑。小視窗跑完時有一顆回去鈕（有行事曆就回行事曆，否則回主控面板）。
- **主控面板**：任何地方都叫得出 iPLoT 的面板；面板已經開著就把它叫到最前面，不會開第二個。
- **行事曆**：打開就是這個月的月曆。每天寫行程、心情（五個表情加一句話）、看到了什麼、做了什麼，放照片（iPhone 的 HEIC 會另外轉一張 JPG）；打字停一秒就自動存。全部存成一天一個資料夾的純文字與照片，同時產生成網頁（綜合、年、月、日），雙擊就能看。打開「公開」的日子，按「發佈」另外產生一份可以放上網路的資料夾（照片縮小、拿掉拍攝地點；這一版不會幫忙上傳）。上方的模組列可以叫任何模組。
- **核心（D83）**：面板停在下一層的時候，模組用名字叫別的模組，這一層找不到就會去最上層找。其他跟 0.5.0 一樣，舊模組不用改。

這台：`sw_vers` → macOS 26.5（25F71），arm64。對下載的包手動加上 Safari 的隔離標記，再用 `ditto -x -k` 解開：

```

### 3.3 第一次啟動的前提（讀程式得到的）

**要哪個 Python、怎麼找。** `iPLoT.command` 只有兩行：

```
#!/bin/bash
cd "$(dirname "$0")" && exec python3 main.py "$@"
```

它用終端機的 `PATH` 找 `python3`。python.org 的安裝檔會把 `python3` 放進 `/usr/local/bin`（也會在 `~/.zprofile` 加路徑），所以裝了就會被找到；Homebrew 的在 `/opt/homebrew/bin`。`main.py` 第一件事是比版本：低於 3.10 就印「iPLoT 需要 Python 3.10 以上（目前是 {版本}）。請安裝 python.org 的版本。」並結束（`core/text.py` 的 `need_python`）。版本夠就用同一個 Python 跑 `pip install --target lib/`（`ui/install.py`），裝 `requirements/web-mac.txt` 的十個套件。

**沒有 Python 或太舊時看到什麼。**
- 只有 macOS 內建的 `/usr/bin/python3`（3.9.6，裝過命令列開發者工具的 Mac 才有）：終端機視窗裡一句「iPLoT 需要 Python 3.10 以上（目前是 3.9.6）。請安裝 python.org 的版本。」，iPLoT 不開。
- 連命令列開發者工具都沒有：`/usr/bin/python3` 會跳出 macOS 的對話框問要不要安裝命令列開發者工具（推測，未親眼看）；裝了也只是 3.9.6，還是上面那一句。
- 有 3.10 以上但沒有網路：終端機說「介面安裝失敗：…安裝需要網路。再試一次：重新啟動 iPLoT。現在先改用備用面板」，接著開 tkinter 的備用面板（Homebrew 的 Python 預設沒有 tkinter，這時會說「這個 Python 沒有 tkinter，安全模式與備用面板都開不了；請用 python.org 的版本」並結束）。

**放在「下載項目」裡、與掃描上一層。** `config.py` 的 `ROOTS = ["modules", ".."]`：除了 `modules/`，還掃 iPLoT 資料夾的上一層。掃描時對上一層的每一個子資料夾做 `os.listdir`（`core/scan.py` 的 `is_module`）。
- 解在「下載項目」裡（Safari 預設會自動解開 zip，推測，未親眼看）：上一層就是 `~/Downloads`，裡面每個子資料夾都會被列一次，有 `iplot.py` 的會出現在面板的「上一層」那一組；終端機要讀「下載項目」，第一次可能問一次權限（推測，未親眼看）。
- 照 README 搬到 `~/iPLoT`：上一層是家目錄，會列 `~/Desktop`、`~/Documents`、`~/Downloads` 等資料夾的內容。這三個是 macOS 保護的資料夾，第一次啟動時終端機可能各問一次「想要取用…」（推測，未親眼看；這台的終端機早就允許過，看不到）。按「不允許」只是那幾個資料夾不掃，面板照常開。
- 不管放哪裡，面板上「上一層」那一組的 ＋ 會把新模組建在那個上一層（例如家目錄底下）。

```

## 6. 檢查中發現的新問題（沒有修）

1. **取消最後一個公開的日子之後按「發佈」，`發佈/` 不會清掉，那一天的內容還在裡面。** 公開的日子變成 0 天時，`Api.publish` 先回「還沒有打開「公開」的日子」就結束（`modules/行事曆/iplot.py` 的 `publish`，頁面那頭 `page.html` 的 `publish()` 也是直接叫它），清掉多餘檔案的那一步（`pages.publish` 的 `_prune`）沒有跑。照著再把 `發佈/` 上傳一次，已經取消公開的日子照樣在網路上。單元測試 `test_unpublishing_removes_the_day_and_relinks_the_public_neighbours` 用的是三天公開、取消其中一天，沒有碰到「剩 0 天」。在 scratchpad 用假的 app 重現（沒有開視窗）：

   ```
   save: {'saved': ['行程'], 'unreadable': []}
   public on: {'public': True}
   publish 1: 1 None
   exists after publish 1: True
   public off: {'public': False}
   publish 2: {'error': '還沒有打開「公開」的日子'}
   exists after unpublish + publish 2: True | content has 很私人: True
   ```

   M5 人工驗收第 8 項（取消今天的「公開」再按「發佈」）只有今天一天公開時會因為這個不過。碰到時的做法：把 `發佈/` 整個丟進垃圾桶（下一次有公開的日子再「發佈」時會重新產生）。
2. **README 安裝第 3 步與下載頁的 Gatekeeper 說明不對。** README 寫「第一次 macOS 可能問你要不要打開，選『打開』」，下載頁只寫「解壓縮後雙擊 iPLoT.command」，`docs/06` 也說選「打開」。這台是 macOS 26.5，從瀏覽器下載的 `iPLoT.command` 被 `spctl` 拒絕（證據在第 3.2 節）。雙擊時大概會看到（推測，未親眼看）：macOS 15 起，沒簽章又帶隔離標記的檔，雙擊跳出「無法打開『iPLoT.command』」一類的對話框，只有「完成」與「丟到垃圾桶」，沒有「打開」；按右鍵選「打開」在 macOS 15 起也不再能繞過。要打開得先按「完成」，再到「系統設定 → 隱私權與安全性」，往下捲到「安全性」那一段，按「強制打開」（按鈕的字依系統版本不同，未核），再確認一次並輸入密碼或用 Touch ID。另一條路是在終端機執行 `xattr -dr com.apple.quarantine ~/iPLoT`（拿掉整個資料夾的隔離標記）之後再雙擊。macOS 14 以前可以按右鍵選「打開」，但「直接雙擊、選『打開』」也不對（直接雙擊的對話框沒有「打開」）。
3. **下載頁沒寫要先裝 Python 3.10 以上。** 下載頁（`tools/publish.py` 產生的 `index.html`）只寫「解壓縮後雙擊 iPLoT.command；第一次啟動會自動安裝介面，要有網路。」README 第一行有寫，但從下載頁來的人不會先看到 README。
4. **包裡有開發用 Mac 的個人路徑與帳號名**（第 4 節的表），以及用的人用不到的開發資料（`tests/`、`docs/plans/` 等，超過 1 MB）。原因是核心的包是 `git archive` 整個 repo。
5. **第一次啟動可能跳出好幾個權限對話框。** 掃描上一層時對每個子資料夾 `os.listdir`（第 3.3 節），放在 `~/iPLoT` 時會碰到「桌面」「文件」「下載項目」。README 只在「互通」那一節說捷徑「可能會問」，安裝那一節沒提。（M4 回報第 7 節說「只是 `stat`、應該不會跳框」的，是互通那一小段往上找 `run.py`，不是面板的掃描；面板的掃描會列資料夾內容。）會不會真的跳框：推測會，未親眼看。
6. **行事曆的資料預設在 `~/Documents/行事曆`。** 那台 Mac 若開著 iCloud 的「桌面與文件」同步，日記、心情、照片會跟著上 iCloud；第一次存的時候也可能問一次「文件」的權限（推測，未親眼看）。程式沒有提醒；README 也沒寫。

## 7. 交出去之前要先問收件人的事

- 有沒有裝過 iPLoT？哪一版（看面板的標題，例如「iPLoT v0.5.0」）？0.5.0 可以按「更新」；0.4.0 以前要重新下載（設定與自己的模組要自己搬，見操作說明）。
- Mac 的 macOS 版本（蘋果選單 → 關於這台 Mac）。15 以上照第 6 節第 2 項的「強制打開」；14 以前可以右鍵「打開」。
- 有沒有 Python 3.10 以上？在終端機打 `python3 --version` 看；是不是 python.org 裝的（備用面板與安全模式要 tkinter）。
- 用 Safari 還是 Chrome 下載（Safari 預設自動解壓，會直接得到資料夾）。
- iPLoT 要放在哪裡；有沒有開 iCloud「桌面與文件」（關係到行事曆的資料會不會上雲端）。
- 要不要用「發佈」放上網頁空間；要的話，那個空間怎麼上傳（這一版沒做上傳），並先說明第 6 節第 1 項（取消最後一個公開的日子時要自己刪 `發佈/`）。

## 8. 建議（選項，不替人決定）

**Gatekeeper：**
- A. 只改文件：README 安裝第 3 步、下載頁、`docs/06` 改成「系統設定 → 隱私權與安全性 → 強制打開」，並附 `xattr -dr` 的一行指令。成本最低，但每個新使用者都要走一次。

**包的內容：**
- A. 照舊（完整的 repo）。
