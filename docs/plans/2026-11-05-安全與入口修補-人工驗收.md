# 安全與入口修補：人工驗收清單

分支 `fix/safety-and-vision`，依據 2026-11-05 的現況盤點（報告本身含本機路徑，不進 repo，結論記在 D118–D120）。這一份是要用滑鼠在真的面板上按的項目；單元測試與真的 pywebview 視窗的自動檢查已經做過（見下面「已經自動驗過的」），但下面這些只有真的按過、看過才算數。決定記在 D118–D120（`docs/03_設計決定.md`），變更記在 `CHANGELOG.md` 的 `[Unreleased]`。

驗收前：

```bash
git checkout fix/safety-and-vision
python3 main.py
```

按完之後，在這份檔案的最後一欄勾起來或寫下看到了什麼。第 1–8 項涉及真的送一則公開的討論，送完要刪（第 8 項）。

## 一、出錯回報（網頁面板）

先做一個會出錯的模組：在面板「這一層」按最後一格「＋」，名稱打「出錯測試」，確定；編輯器打開後，把 `def run(app):` 底下改成 `1 / 0`，存檔，點回 iPLoT 視窗。

| # | 怎麼按 | 應該看到 | 結果 |
|---|---|---|---|
| 1 | 雙擊「出錯測試」 | 訊息區出現紅色的錯誤，旁邊有「打開檔案」「詳細」「回報這個問題」三個按鈕 | |

| 3 | 在預覽視窗裡從上往下讀標題與內文 | 找不到 `/Users/…`、`/Volumes/…`、你的帳號名；路徑都變成 `~/…` 或 `<家目錄>` 一類的替身；上方說「已自動遮蔽 N 處」 | |

## 二、出錯回報（tkinter 面板）

在終端機（iPLoT 資料夾裡）執行 `python3 main.py --safe`，開的是 tkinter 面板。

| # | 怎麼按 | 應該看到 | 結果 |
|---|---|---|---|
| 9 | 單擊「出錯測試」，再按錯誤列的「回報這個問題」 | 編輯器打開一份草稿；跳出一個確認框，**最前面**是「這會公開在網路上，任何人都看得到。送出前請自己再看一次，刪掉姓名、學號等個人資料。」，接著是「草稿在 回報/…」 | |
| 10 | 按確認框的「取消」 | 什麼都沒送、瀏覽器沒有打開；訊息區說「沒有送出；草稿留在 回報/…」 | |

## 四、從零啟動、按 ＋

在一份複本上做，不動你的 iPLoT：

```bash
rsync -a --exclude .git --exclude .venv --exclude spikes <你的 iPLoT 資料夾>/ ~/iplot-zero/
rm -rf ~/iplot-zero/modules
cd ~/iplot-zero && python3 main.py
```

| # | 怎麼按 | 應該看到 | 結果 |
|---|---|---|---|
| 16 | 面板出現後看「這一層 modules/」那一組 | 那一組寫著「找不到 …/modules」，**但最後一格有「＋ 新模組」**；「上一層」那一組也有 ＋ | |
| 17 | 按「這一層」的 ＋，打名稱「第一個」，確定 | 面板出現「第一個」；`~/iplot-zero/modules/第一個/iplot.py` 建好了（用 Finder 看）；「找不到 …/modules」那一行不見了。訊息區會說「沒有『作業系統』模組，無法執行 edit」，編輯器不會打開——這是預期的，這份複本沒有「作業系統」模組（D118） | |
| 18 | 雙擊「第一個」 | 訊息區出現「第一個 執行了」 | |
| 19 | 關掉面板，在終端機執行 `rm -rf ~/iplot-zero/modules && python3 main.py --safe`，按「這一層」標題右邊的「＋」 | tkinter 面板一樣有 ＋，按了建得出模組 | |

驗完把 `~/iplot-zero` 丟進垃圾桶。
