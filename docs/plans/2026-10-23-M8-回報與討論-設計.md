## 0. 一句話

iPLoT 出錯時，訊息區那一列除了「打開檔案」「詳細」，多一個「回報這個問題」。按下去，新的模組「回報與討論」整理出 iPLoT 版本、作業系統、Python、出錯的模組與它的版本、traceback，**先把家目錄、使用者名稱、路徑、學號遮掉**，在一頁裡給人看、讓人改，按「在瀏覽器打開」就用預填網址開 `…/discussions/new?category=…&title=…&body=…`，剩下的（登入、按送出）在瀏覽器裡做。平常雙擊「回報與討論」這一格，是「回報問題／提建議／問問題／看論壇」四個入口。

## 1. 需求

來源：研究助理（2026-10-23）：老闆已經開始測試 iPLoT，出問題只能等 meeting 才講；要一個大家都能留言、回報、提建議的地方，之後當成 iPLoT 社群的基礎。

- **R1 出錯就地回報**：錯誤訊息旁邊一個「回報這個問題」，按了整理好環境與 traceback。
- **R2 先看再送**：送出前使用者看得到全文、改得動。
- **R3 隱私（最重要）**：論壇公開；老闆會用 iPLoT 跑學生作業，路徑、檔名、程式碼裡可能有學生姓名、學號。送出前自動遮蔽；規則集中在一處、有測試。
- **R4 不存憑證**：iPLoT 不存密碼、不存 token；送出在瀏覽器。
- **R5 不用伺服器**：論壇是 GitHub Discussions；iPLoT 只組網址、開瀏覽器。
- **R6 建議／討論入口**：面板上一格，開到論壇的分類頁或新增貼文頁。
- **R7 網址有上限**：traceback 太長要截斷並註明，完整內容另外給得出去。
- **R8 盡量不動核心**（D80）：能放模組的都放模組；非動不可的部分寫明、要研究助理點頭。

**做好的樣子：**
- 老闆跑學生作業，某個模組出錯 → 訊息區那一列有「回報這個問題」→ 按下去開一頁：標題「[回報] 科學計算：FileNotFoundError（iPLoT 0.6.0）」、內文是環境、traceback（`/Users/laoban/課程/HK2/王小明_B11201234/作業.py` 已經變成 `<HOME>/.../<檔名已遮蔽>.py`），上面一行「遮蔽了 3 個路徑、1 個使用者名稱、1 個疑似學號；論壇是公開的，送出前再看一次」→ 改兩個字、按「在瀏覽器打開」→ 瀏覽器開在 Discussions 的「問題回報」新增頁、標題內文都填好 → 按 Start discussion。
- 想提建議的人：雙擊「回報與討論」→ 按「提建議」→ 瀏覽器開在「功能建議」的新增頁，內文帶好 iPLoT 版本與作業系統。
- 研究助理：在 GitHub 的 Discussions 收到，跟對方在同一串裡來回。

## 2. 現況（讀程式的結論）

### 2.1 模組怎麼註冊、怎麼掛進面板

- **沒有註冊這回事**：資料夾裡有 `iplot.py` 就是模組（`core/scan.py`），掃描只讀不執行，讀出 docstring、`TITLE`、`ICON`、`run`、`on_files`（`core/meta.py`）。面板上一格就是一個模組；**iPLoT 沒有選單列**，「選單」只有每一格的右鍵選單，而那是 `ui/app.js` 的 `menuFor` 寫死的（`docs/07` 第 3 節）。所以需求裡「選單裡一個按鈕」在這裡就是**面板上的一格模組**（第 13 節「要決定的」第 3 項）。
- **執行**：雙擊 → `Bridge.press` → `Core.press` → `runner.run_module(info, App, handler, args)`：乾淨命名空間跑 `iplot.py`，有 `handler`（預設 `run`）就呼叫 `handler(app, *args)`。這條路也是「事件」的路（`docs/07` 第 5 節）：`on_files`、作業系統模組的七個函式都是指定 `handler` 的 `press`。
- **核心把事情交給某個名字的模組**的前例：`Core.action` 交給 `modules/作業系統`（`SYSTEM_MODULE`，D50）；「主控面板」是固定名字的模組（D82）。
- **可以照抄的範例**：
  - 開自己一頁 HTML：「工作坊」（`modules/工作坊/iplot.py` → `app.page(title, html, api)`，頁面在 `page.html`，JS 用 `pywebview.api.<方法>` 叫 Python 那一頭的 api 物件）。
  - 連網、錯誤變一句話：「工作坊」「更新」（`docs/07` 第 6 節）。
  - 模組自己的設定、網址放在模組資料夾（`docs/07` 第 6 節：`app.config` 只有五個值，放不進別的）。
  - 既是隨附又從工作坊發：「行事曆」0.1.1（D108）。
  - 測試：`tests/test_workshop.py` 用 `importlib` 從 `modules/工作坊/` 載入模組的檔、用 `conftest.FakeApp`／`FakeView`、來源用 `file://`，不連網。

### 2.3 錯誤現在在哪裡被接住、怎麼顯示

| 錯誤 | 在哪被接住 | 變成什麼 | 怎麼顯示 |
|---|---|---|---|
| 模組裡的例外（含 `SyntaxError`、沒接住的 `EOFError`、非零 `exit`） | `core/runner.py` 的 `run_module`：`except SystemExit`、`except Exception` | `errors.from_exception(exc, info, "module")` → `ErrorInfo`（`kind`、`message`、`file`、`line`、`traceback_text`、`source`、`module`） | `Core.press` → `view.report(error)` |
| 模組沒有指定的 handler | `run_module` | `ErrorInfo("MissingHandler", …)` | 同上 |
| `app.run` 叫的別的模組出錯 | 內層的 `press` 自己報 | 同上，`module` 是內層的名字 | 同上（外層照常繼續） |
| 「作業系統」的動作出錯（右鍵「打開程式碼」等） | `Core.action` → `press(作業系統, …, quiet=True)` | `module` 是「作業系統」 | 同上 |
| `config.py` 壞了 | `core/core.py` 的 `load_config` | `ErrorInfo(…, "config", None)` | 啟動時 `panel.report(err)` |
| 核心自己的錯（網頁面板工作執行緒上的一件工作丟出來） | `ui/web.py` 的 `WebPanel._work`：`except Exception` | `Core.report_internal` → `from_exception(exc, None, "core")`，另寫 `logs/iplot.log` | `view.report` |
| 核心自己的錯（tkinter 回呼） | `ui/tk.py`：`root.report_callback_exception = core.report_internal` | 同上 | 同上 |
| 模組自己那一頁（`app.page`）的 api 方法丟例外 | pywebview 把它交給那一頁的 JS（promise 被拒）；「工作坊」自己接、在那一列說一句 | 不經過 `ErrorInfo` | 那一頁上 |
| 面板外執行（「互通」） | `modules/互通/popup.py` 自己的 `View.report` | `ErrorInfo` | 小視窗 |

**面板怎麼畫：**網頁面板（`ui/app.js` 的 `entry`）是白話一句（`errors.describe`）＋「打開檔案」（`Bridge.open_error(id)`，id 是 `WebPanel.errors` 這份清單的編號）＋「詳細」（展開 traceback）。tkinter 面板（`ui/tk.py` 的 `report`）是整段 traceback、最後一句白話、一個「打開檔案」按鈕。

**沒有接到面板的**（第一階段不處理，寫進「不做」）：
- 啟動時、面板開起來之前的例外（`main.py` 沒有 `sys.excepthook`）：只在終端機看得到 traceback。網頁面板開不起來的原因會變成一句 note 寫進後備面板的訊息區。
- `BaseException` 但不是 `Exception` 的（`KeyboardInterrupt` 等）：`run_module` 與 `_work` 都不接；沒有 `threading.excepthook`。
- `Bridge` 方法本身（在 pywebview 的執行緒上，例如 `state()`）丟的例外：回到頁面 JS，面板不顯示。

## 5. 模組「回報與討論」

```
modules/回報與討論/
  iplot.py      run(app)：四個入口；on_error(app, error)：出錯回報
  forum.py      論壇的網址與分類 slug（只有這裡寫死，第 12 節填）
  redact.py     遮蔽規則：全部在這一個檔（第 6 節）
  report.py     收集環境、組內文、組網址、截斷（第 7、8 節）
  page.html     預覽與編輯的那一頁（零外部資源、內容一律當文字）
  CHANGELOG.md  0.1.0
  回報/         （執行時才建）完整的、遮蔽過的回報文字，一份一個檔；不進包
```

- **`on_error(app, error)`**：`error` 是面板交過來的 `ErrorInfo`（`docs/07` 第 13 節列的型別，可以依賴）。`report.collect(error, app)` → `redact.redact(…)` → 網頁面板開 `page.html`（`app.page`），tkinter 面板走 5.2 的檔案流程。
- **`run(app)`**（雙擊那一格）：一頁四顆鈕：
  - 「回報問題」：沒有錯誤訊息的問題（畫面不對、太慢）——同樣的預覽頁，內文是環境資訊＋空白的「發生了什麼／預期是什麼」，可以從清單選一個相關的模組（`app.modules`）。
  - 「提建議」：開 `功能建議` 分類的新增頁，內文帶 iPLoT 版本與作業系統。
  - 「問問題」：開 `問答` 分類的新增頁。
  - 「看論壇」：開 `…/discussions`。
- **開瀏覽器**：標準庫 `webbrowser.open(url)`（跟 M7b 的「上傳」一樣）。開不起來（回 `False` 或丟例外）就在頁面上顯示網址讓人自己複製。
- **不連網**：第一階段整個模組不發任何網路請求，只組網址交給瀏覽器。

### 5.1 預覽頁（網頁面板）

- 上面一行：「論壇是公開的，任何人都看得到。已自動遮蔽：3 個路徑、1 個使用者名稱、1 個疑似學號。送出前請再看一次，特別是學生的名字。」（數字來自 `redact` 的統計。）
- 標題一格、內文一格（`<textarea>`），改得動。旁邊一行「網址長度 6 812 / 8 000」；超過時說「traceback 會從中間截斷，完整內容存在 回報/…txt」。
- 「在瀏覽器打開」：JS 把標題、內文交給 api 的 `send(title, body)`；**Python 這一頭再遮一次**（使用者貼進來的路徑也遮），組網址、截斷、存檔、開瀏覽器，回傳一句結果給頁面顯示。
- 「取消」：關視窗，什麼都不存。
- 頁面上的內容一律 `textContent`／`value`，不用 `innerHTML`（traceback 裡可能有 `<script>`）。

### 5.2 tkinter 面板（安全模式、後備面板、Linux）

`app.page` 在那裡只記一行，所以改成檔案：把遮蔽過的回報寫進 `回報/<日期時間>-<kind>.md`，`app.edit` 打開，`app.confirm("改好、存檔之後按確定，就用瀏覽器打開")`；確定就讀回來、再遮一次、組網址、開瀏覽器；取消就留著檔案、說一句在哪。

## 6. 隱私遮蔽（D111）

規則全部在 `redact.py`：一張有順序的表 `RULES`，每一條是「名字、怎麼找、換成什麼」；`redact(text, ctx) -> (text, counts)` 是純函式，`ctx` 帶這台的事實（家目錄、使用者名稱、iPLoT 資料夾、Python 的 prefix、出錯模組的資料夾、路徑分隔符號），所以測試可以在任何平台上餵 macOS、Windows、Linux 的路徑。

**遮什麼（照順序）：**

1. **iPLoT 自己與 Python 的檔留著，換成短名**：`<IPLOT>/core/runner.py`、`<IPLOT>/ui/web.py`、`<IPLOT>/main.py`、`<IPLOT>/lib/webview/…`、`<PYTHON>/lib/python3.14/json/decoder.py`（`sys.prefix`、`sys.base_prefix`）。這些路徑底下沒有個人的東西，而且是除錯最需要的。
2. **出錯模組的資料夾**：`<模組:科學計算>/hk_tk.py`——只留模組資料夾**第一層**的檔名；更深的一律 `<模組:科學計算>/.../<檔名已遮蔽>.py`（學生作業在 `HK2/<學生>/` 這種深處，D95）。模組名稱留著（回報要知道是哪個模組）。
3. **其他在家目錄底下的路徑**：`<HOME>/.../<檔名已遮蔽>.py`。中間的資料夾全部變成 `...`，檔名遮掉、副檔名留著。
4. **其他絕對路徑**（`/Volumes/…`、`D:\…`、網路磁碟 `\\server\…`）：`<PATH>/.../<檔名已遮蔽>.txt`。
5. **使用者名稱**：`getpass.getuser()`、環境變數 `USER`／`USERNAME`、家目錄最後一段，在路徑以外的地方出現也換成 `<USER>`（整個詞才換；少於 3 個字的不換，免得 `a` 把整段吃掉——這種情況在統計裡標「使用者名稱太短，沒有遮，請自己看」）。
6. **疑似學號**：英文字母開頭接 7–9 位數字、或 8–10 位的純數字，前後不是字母數字（例如 `B11201234`、`411234567`）→ `<疑似學號>`。行號、記憶體位址（`0x…`）不會中：行號太短、位址有 `0x`。
7. **電子郵件** → `<EMAIL>`。
8. **模組的原始碼那幾行**：traceback 裡 `File "…", line N, in f` 底下那一行是原始碼，學生的程式可能把名字寫在字串裡。**落在第 1 條（iPLoT、Python）以外的 frame，原始碼那一行拿掉**，換成 `    （原始碼已略過）`；iPLoT 與 Python 的 frame 照留。
9. **錯誤訊息裡的相對路徑**：`FileNotFoundError: … 'HK2/王小明/作業.py'` 這種，引號裡含 `/` 或 `\` 的字串照第 3 條遮成 `.../<檔名已遮蔽>.py`。

**比對的細節**：路徑比對同時試 `Path` 原樣、`resolve()` 過的、正斜線與反斜線兩種寫法；Windows 與 macOS 不分大小寫；家目錄是 `/Users/x` 時不能吃到 `/Users/xyz`（以分隔符號為界）。macOS 的 `/private/var/…`、`/var/…` 都算其他絕對路徑。

**能保證與不能保證**（寫進 `docs/07` 第 7 節）：能保證的是上面那張表裡的東西不會原樣出現在網址裡（有測試）；**不能保證**的是長得不像路徑、學號、使用者名稱的個人資料——例如錯誤訊息裡直接出現的學生姓名（`KeyError: '王小明'`）。所以遮完一定先給人看（R2），頁面上那一行提醒是規格的一部分，不是客套話。

**測試**（`tests/test_report.py` 的遮蔽那一段，表格式，一列一個例子）：macOS／Windows／Linux 的家目錄路徑、模組深處的學生資料夾、iPLoT 與 Python 的路徑留著、`/Users/x` 不吃 `/Users/xyz`、大小寫、反斜線、使用者名稱出現在一般文字、太短的使用者名稱、學號的正反例（行號、`0x7f…`、時間戳不能中）、email、原始碼行拿掉與留著、相對路徑在錯誤訊息裡；另一條：遮過的再遮一次結果不變（冪等）；最後一條：整份樣本 traceback（裡面埋了學生姓名路徑、學號、使用者名稱）遮完之後，用 `in` 檢查那幾個字串一個都不在。

## 8. 網址與截斷（D113）

- 網址：`https://github.com/william10310406/iplot/discussions/new?category=<slug>&title=<…>&body=<…>`。`forum.py` 寫 `REPO = "william10310406/iplot"` 與四個 slug。每個值用 `urllib.parse.quote(value, safe="")`（UTF-8）。

  1. 整條放得下：照用。
  2. 放不下：traceback 留第一行（`Traceback (most recent call last):`）和**最後面**的幾行（最內層的 frame 與例外那一行，最有用），中間換成一行 `…（中間 N 行太長，已截斷；完整內容在附檔，見下面）…`；用二分找最多能留幾行。

- **完整內容**：只要截過，整份（遮過的、沒截的）存進 `回報/<日期時間>-<kind>.txt`，`app.reveal` 指給人看；內文最後加一句「完整的 traceback 太長，請把 iPLoT 打開的那個 .txt 檔拖進這個留言框當附件」。（GitHub 收 `.txt` 附件，探針第 3 項確認。）

## 17. 寫工作單時查到的修訂（2026-10-23）

寫工作單（`docs/plans/2026-10-23-M8-回報與討論.md`）時，六個唯讀的查核分頭對著程式、真的 traceback 與 github.com 核過這份設計。下面每一條都是前面的內文寫錯了、或沒想到的；工作單照這裡做。研究助理定的方向（D110 是 D80 的例外、0.6.0、其他照建議）沒有改。

1. **0.6.0 一定要連「互通」一起出新版**（第 3 節「不改」漏了它）。`modules/互通/boot.py:17` 是 `SUPPORTED = "0.5."`：核心一變 0.6.0，互通 0.1.0 的 `run.py` 就拒跑（捷徑、檔頭那一小段、面板外的執行都停，結束碼 2），`tests/test_interop.py` 有 18 個測試會紅；「行事曆」一律經過互通的 `run.py` 開頁面，在面板裡雙擊也一樣停。另外，0.5.2 之後合進 main 的 f406275 讓 `run.py` 用到 `core.scan.home_path`，這在 0.5.2 的核心裡沒有。**修訂（2026-10-24，研究助理定）**：「更新」只換 `core/`、`ui/`、`main.py`、`requirements/`（失敗時四樣全部放回），`modules/` 一律不碰；工作坊可以單獨換互通、不看核心版本。所以「核心 0.6.0＋互通 0.1.x」（每個舊用戶按完「更新」、還沒換互通之前）與「核心 0.5.x＋互通 0.2.0」（先換互通再更新、更新失敗放回、手動回到舊版、0.5.0 的人自己裝）兩種組合都會出現。做法：互通出 0.2.0，`SUPPORTED = ("0.5.", "0.6.")`，那一句改成「互通 {mine} 支援 iPLoT 0.5、0.6…iPLoT 比較舊就按「更新」，比較新就到工作坊看看互通有沒有新版」；`run.py` 的 `_expand` 在核心沒有 `home_path`（`ImportError`）時照 0.1.0 的做法——判斷看屬性不看版本號；加「從 0.5.2 更新到 0.6.0 前後都跑得動」的測試。互通 0.2.0 先 commit（在核心 0.5.2 上就全綠）、0.6.0 後 commit；發佈時**互通 0.2.0 先上工作坊、再發核心**。「核心 0.6.0＋互通 0.1.x」這一種，0.1.0 的拒跑在使用者的電腦上、改不了：工作坊先有 0.2.0，notes 叫已經在用的人**先到工作坊更新互通、再按「更新」**（研究助理 2026-10-24 定；notes 是「要更新嗎」那個對話框裡的字，所以講已經在用的人的那一句一開頭就叫人先按「取消」，第②步回來時按「確定」）。互通 0.1.0 在 iplot-modules 上那 4 個 ruff I001 是兩個 repo 的 isort 對 `core` 的看法不同（iPLoT 是第一方、iplot-modules 是第三方），0.2.0 在那 4 個 import 區塊加 `# noqa: I001`，兩邊都全過才上傳。寫工作單時對 `git archive` 出來的 v0.5.0、v0.5.1、v0.5.2 核心各跑過一次 0.2.0，也真的用 v0.5.2 自己的「更新」換到 0.6.0 再跑：結束碼都是 0。
2. **`MAX_URL` 不是 8000**（第 8 節、第 13 節第 5 項）。對 github.com 實測（沒登入、只帶一個 User-Agent、沒有 cookie）：整條網址到大約 7004 字還是 302 轉去登入；7006 到 8191 回 HTTP 500（不是 414，也不是截掉內文）；8192 起才是 414。cookie 和其他標頭的位元組從同一個額度裡扣，一個位元組扣一個字：像 Chrome 那樣的標頭（約 624 位元組）剩大約 6585；登入之後的瀏覽器還帶著 GitHub 的 session cookie，只會更短，實際多少要在登入的瀏覽器裡量（探針第 2 項）。Windows 的 `webbrowser.open` 走 `os.startfile`（ShellExecute），微軟的資料說 ShellExecute 的網址上限大約 2083 字，超過可能被悄悄截掉（未經實機驗證）。照第 13 節第 5 項「量到更短的上限再往下調」：先用 macOS、Linux 4000，Windows 2000，常數只在 `report.py`，探針第 2 項之後再定。
3. **「取消」做不到**（第 5.1 節）。模組的那一頁關不了自己的視窗：`WebPanel.page` 把視窗留在自己手上（`ui/web.py:286-291`），pywebview 6.2.1 的 cocoa 後端不理 JS 的 `window.close()`，模組也不能 import `webview`（D72）。改成：頁面上沒有「取消」，寫一句「不送的話，直接關掉這個視窗」；送出之後說「可以關掉這個視窗了」。
4. **頁面那一頭不能叫 `app` 的任何方法**（第 5.1 節）。頁面的 JS 叫 api 的方法時，pywebview 在另一條執行緒上跑它，這時候模組還停在 `app.page` 裡。`app.reveal` 經過 `core.action` → `Core.press`，`Core.press` 沒有鎖、會改整個程序的工作目錄、`sys.stdout`、`sys.path`、`builtins.input`：實驗裡，頁面在那個 `reveal` 還沒做完時被關掉，之後整個程序的工作目錄停在 `modules/回報與討論`、`print` 不見了、`input` 還是模組的對話框。所以 api 的 `send` 只做三件事——再遮一次、組網址（截過就存檔，用絕對路徑）、`webbrowser.open`（標準庫，不經過核心）——而且拿著一把鎖；存了檔的話，`app.reveal` 等頁面關掉、回到 `on_error` 之後才做。這跟「工作坊」的做法一樣（`docs/07` 第 4 節：api 的方法只碰檔案與字串，碰面板的事等視窗關掉）。
5. **`reportable` 不放 `error_json`**（第 4 節）。`error_json(error)` 是模組層的函式、只拿得到那一筆錯誤，`tests/test_web.py` 也逐鍵比它的回傳值；`reportable` 改在 `WebPanel.report` 跟 `id` 一起加。另外 `Bridge` 原本找模組的 `WebPanel.find` 只看目前這一層，面板停在下一層時找不到 `modules/回報與討論`，所以 `report_error` 照 `Core.action` 找「作業系統」的寫法用路徑找。
6. **按「回報這個問題」用 `quiet=True`**（第 4 節）。不然 `on_error` 跑完訊息區多一行「回報與討論 完成（0.0 秒）」；`Core.action` 也是 quiet。網頁面板照樣有「執行中」的狀態（經過 `WebPanel.press`）。同一列的鈕按一次就變灰，不會排好幾個預覽頁。
7. **判斷面板要先看 `ui.tk`**（第 7 節）。網頁面板開不起來、退到後備的 tkinter 面板時，`ui.web` 已經 import 過了，兩個都在 `sys.modules`。順序是：有 `ui.tk` → tkinter（走檔案的流程，第 5.2 節）；否則有 `ui.web` → 網頁；兩個都沒有 → 面板外（「互通」的小視窗，`app.page` 在那裡能用）。
8. **模組名稱也可能是學生的名字**（第 6 節第 2 條、第 7 節）。「科學計算」的每個學生資料夾本身就是一個模組（D95），在那裡出錯時 `error.module` 是 `王小明_B11201234`，會進標題與那一句白話。改成：從 `error.file` 往上找到叫 `error.module` 的那個模組資料夾，再往上找到最上層的模組（上一層沒有 `iplot.py` 為止）；標題、`<模組:…>` 用最上層的名字，中間的模組名稱一律換成 `<下一層模組>`，內文寫「出錯的是它的下一層模組，名稱已遮蔽」。
9. **遮蔽要認得真的 traceback 的樣子**（第 6 節）。查核跑了 3.10、3.12、3.14 的真 traceback：3.11 起原始碼底下多一行 `~~~^^^` 的標記（3.12 只有 `^`、3.10 沒有），拿掉原始碼時要一起拿掉；`SyntaxError` 的位置那一行沒有 `, in f`，底下是原始碼與 `^`；`ExceptionGroup` 每一行前面有 `  | `；有些 frame 沒有原始碼（`<frozen runpy>`、`<string>`）；frame 的檔名可以是相對路徑（`File "HK2/王小明/x.py"`）；`SyntaxError` 的訊息尾巴帶著檔名（`invalid syntax (壞掉.py, line 1)`）；串起來的例外有兩個 `Traceback (most recent call last):`；`traceback_text` 可以是空的（`MissingHandler`、`config.py` 型別錯）。學號那一條的「前後不是字母數字」只算 ASCII：`'明'.isalnum()` 是 True，照字面寫會漏掉 `王小明B11201234`。Homebrew 的 Python 在 traceback 裡用的是 `/opt/homebrew/Cellar/…` 的真實路徑，`sys.base_prefix` 卻是 `/opt/homebrew/opt/…`：`<PYTHON>` 要連 `realpath` 一起比。`getpass.getuser()` 找不到名字時 3.10 丟 `ModuleNotFoundError`／`KeyError`、3.13 起丟 `OSError`，都要接。
10. **Python 的來源看 `realpath(sys.base_prefix)`，不看 `sys.executable`**（第 7 節）。在 venv 裡（包括開發用的 `.venv`）`sys.executable` 在 venv 裡；python.org 的版本從 `/usr/local/bin/python3` 開的時候 `sys.executable` 就是那個捷徑；Homebrew 的是 `/opt/homebrew/opt/…`；macOS 的 `/usr/bin/python3` 其實在 Xcode 裡、而且是 3.9，iPLoT 不收。`realpath(sys.base_prefix)` 在 `/Library/Frameworks/Python.framework/` 底下是 python.org、含 `/Cellar/python@` 或在 `/opt/homebrew/` 底下是 Homebrew、在 `/usr` 底下（不含 `/usr/local`）或 Xcode／CommandLineTools 底下是系統的，其他是「其他」。作業系統那一行：macOS 用 `platform.mac_ver()[0]`（`platform.release()` 是 Darwin 的版本）；Windows 寫 build 號（3.10 的 `platform.release()` 把 Windows 11 說成 10）。
11. **slug**（第 12 節第 3 步）。公開 repo 上看到的：中文名的 slug 就是那幾個中文字（網址裡是 `%XX`），英文字母變小寫，空白、`/`、`&` 變成 `-`；改名之後 slug 看起來會跟著新的名字變（推測）。所以「先用英文建再改名」那條退路多半沒用，拿掉；改成：分類的名字定了就不要再改，要改就連 `forum.py` 一起改。`forum.py` 先放中文名當 slug（`問題回報`、`功能建議`、`問答`、`公告`），探針第 1 項核對。`/discussions/new` 的 `category`、`title`、`body` 這幾個參數 docs.github.com 沒有寫，只有社群的說法；探針第 1、2、5 項就是在驗它。
12. **測試**（第 11 節）。`conftest.FakeApp` 沒有 `reveal`、`edit`、`ask`、`modules`，它的 `page` 也不會叫 api：模組的流程用 `App(FakeCore(…), info)`、加一個會在 `page` 裡叫 api 的 `FakeView`（`tests/test_calendar.py` 的做法），不改 conftest。模組會在自己的資料夾寫 `回報/`，所以測試先把模組複製到 tmp 再跑。pytest 的 `tmp_path` 在 macOS 上帶著真的帳號名：這正好拿來做一個端對端的測試（真的跑一個會出錯的模組、遮完之後帳號名與 tmp 路徑都不能在裡面）。`forum.py` 的 slug 先有值，測試不會因為還沒開 Discussions 而紅。
13. **其他順手的**：模組帶「互通」的那一小段（跟「主控面板」「行事曆」一樣，不然互通的狀態頁會把它列成「可以加上」），所以 `core` 一律在函式裡 import；`.gitignore` 加 `modules/回報與討論/回報/`；工作坊的名字「回報與討論」寫設計時還沒登記，2026-10-24 已在 iplot-modules f733ddc 登記給研究助理（`docs/plans/2026-10-24-M8-名字保留-評估.md` 第八節）；發佈時照樣先傳它（它在 0.5.2 上也能用，只是沒有那顆鈕），那是一般的第一次上傳，不是佔名字；`docs/02` 的 Bridge「十個方法」、`docs/06` 的行數與測試數、`docs/09` 的版本號也要跟著改（第 3 節漏列）；核心邏輯現在量到 501/505（0.5.2 之後的 f406275 改過 `core/core.py`、`core/scan.py`），不是 502。
