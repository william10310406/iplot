> **給執行者：** 用 superpowers:executing-plans（或 subagent-driven-development）逐個 Task 做。每個 Task 都是先寫失敗的測試、看到紅、再寫程式、看到綠、commit。步驟用 `- [ ]` 追蹤。

**目標**：核心一行作業系統的程式碼都沒有；碰作業系統的事（打開、編輯、顯示、終端機、垃圾桶）全部由隨附模組 `modules/作業系統/` 做，macOS、Windows、Linux 各一個檔；`app` 開滿五個動作；模組名稱可攜；啟動器與 CI 三平台；文件寫給一般讀者。

```
    ui.py               右鍵選單、「打開檔案」改走 core.action；不再 import actions
    create.py           名稱檢查改可攜規則
    text.py             + SYSTEM_MODULE、no_system；menu_reveal／menu_terminal 改中性詞；bad_name 改寫
    （actions.py 刪除）
  modules/作業系統/
    iplot.py            選擇器：看 sys.platform 匯入 mac／win／linux，轉出五個函式；run(app) 印出目前用哪一個
    mac.py  win.py  linux.py
  iPLoT.command  iPLoT.bat  iPLoT.sh
  tests/smoke.py        取代 smoke.sh
```

依賴方向不變：`ui`、`main` 在上，`core`、`app` 在中，底下 `scan`、`meta`、`runner`、`errors`、`create`、`history` 六個檔互不相識。

### 2. 「作業系統」模組的契約

- 核心只在 `modules/` 找名字剛好是「作業系統」（NFC）的模組；`..` 或 `ROOTS` 其他位置的同名資料夾不算。`--safe` 只掃 `modules/`，安全模式照樣有。
- 五個 handler，跟 `run(app)`、`on_files(app, paths)` 同一種長相：

| handler | `mac.py` | `win.py`（未經實機驗證） | `linux.py` |
|---|---|---|---|
| `open(app, path)` | `open <path>` | `os.startfile(str(path))` | `xdg-open <path>` |
| `edit(app, path, editor, line)` | `editor` 是 `None` → `open -t <path>`；否則 `[p.format(file=str(path), line=line or 1) for p in editor]`；`path` 是資料夾一律改走 `open`（D38） | `None` → `notepad <path>`；否則同左，但 `argv[0]` 先過 `shutil.which`（`code` 在 Windows 是 `code.cmd`） | `None` → `xdg-open <path>`；否則同左 |
| `reveal(app, path)` | `open -R <path>` | `explorer /select,<path>`（一個參數，逗號後面直接接路徑） | `xdg-open <path 的上一層>`（沒有選取） |
| `terminal(app, path)` | `open -a Terminal <path>` | `shutil.which("wt")` 有 → `wt -d <path>`；沒有 → `Popen(["cmd"], cwd=path, creationflags=0x10)`（`CREATE_NEW_CONSOLE`，用數值常數，非 Windows 上沒有那個名字） | 依序 `shutil.which` 找 `x-terminal-emulator`、`gnome-terminal`、`konsole`、`xfce4-terminal`、`xterm`；找到的用 `Popen([名字, *旗標], cwd=path)`，旗標：gnome-terminal／xfce4-terminal `--working-directory=<path>`、konsole `--workdir <path>`、其他沒有；都沒有 → `raise OSError("找不到終端機程式，試過：x-terminal-emulator、gnome-terminal、konsole、xfce4-terminal、xterm")` |
| `trash(app, path) -> Path \| None` | 搬到 `~/.Trash/<名>`（`mkdir(exist_ok=True)`），同名加「 2」「 3」…；回搬到哪 | `ctypes` 呼叫 `shell32.SHFileOperationW`：`wFunc=3`（FO_DELETE）、`fFlags=0x454`（FOF_SILENT 0x4 ＋ FOF_NOCONFIRMATION 0x10 ＋ FOF_ALLOWUNDO 0x40 ＋ FOF_NOERRORUI 0x400）、`pFrom=str(path)+"\0"`（雙 NUL）；回傳值非 0 → `raise OSError(f"資源回收筒拒絕：{code}")`；成功回 `None`（資源回收筒沒有路徑） | XDG：`~/.local/share/Trash/files/<名>` ＋ `info/<名>.trashinfo`（內容三行：`[Trash Info]`、`Path=<urllib.parse.quote(str(原絕對路徑))>`、`DeletionDate=<YYYY-MM-DDTHH:MM:SS>`）；同名加序號（`<名> 2` 與 `<名> 2.trashinfo`）；回搬到哪 |

- 每個檔頂層一個常數 `NAME`：`"macOS"`、`"Windows"`、`"Linux"`。
- 啟動外部程式一律 `subprocess.Popen(list)`，啟動後不等（`notepad`、`cmd` 會一直開著，用 `run` 會凍住面板）。不拼字串。
- 執行檔不存在時 `Popen` 自己丟 `FileNotFoundError`；按 D37 錯誤定位在模組資料夾內最內層那一格，所以面板顯示「模組『作業系統』第 N 行出錯：FileNotFoundError, …'xdg-open'」，N 是 `linux.py` 的行號。
- `iplot.py` 的 `run(app)`：`app.log(f"作業系統：{backend.NAME}，用的是 {檔名}。要改打開檔案、資料夾、終端機、垃圾桶的做法：右鍵這顆按鈕 → 打開程式碼，再改 {檔名}")`。
- `win.py` 的 `import ctypes` 放在 `trash` 函式內，讓 macOS／Linux 的測試能 import 這個檔。

### 3. 核心的改動

- `Core.action(name, *args) -> Any`：`modules/作業系統` 不是模組 → `view.log(T["no_system"].format(module=SYSTEM_MODULE, name=name))`、回 `None`；是 → `press(info, name, args, quiet=True).value`。
- `Core.press(info, handler="run", args=(), quiet=False)`：`quiet` 只省掉「完成（x 秒）」那一行；快照、輸出、錯誤照舊。
- `Core.create` 建好之後 `self.action("edit", folder / "iplot.py", self.config.editor, None)`。
- `App.open/edit/reveal/terminal/trash` 各一行轉 `core.action`；`edit` 自己把 `config.editor` 補進去。
- `ui.py` 右鍵三項與「打開檔案」改叫 `self.core.action(...)`。標籤改中性：`menu_reveal` 「在資料夾中顯示」、`menu_terminal` 「在終端機打開」（`text.py` 不能看 `sys.platform`）。
- `create.new_module` 名稱規則改可攜，三平台都擋：空白；以 `.` 開頭；結尾是 `.` 或空白；含 `/ \ : * ? " < > |` 或控制字元（`ord(c) < 32`）；去掉第一個 `.` 之後的部分、轉大寫後是 `CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`。理由：模組以後會被複製到別的電腦。
- `EDITOR` 留在 `config.py`，核心當參數傳進 `edit`；預設編輯器由各 OS 檔案決定。

### 4. 資料流

```
模組 A 呼叫 app.open(p)
  → core.action("open", p)
      → modules/作業系統 不是模組 → view.log(no_system) → 回 None
      → 是模組 → press(作業系統, "open", (p,), quiet=True)
            → history.snapshot（內容沒變就不存）
            → runner：exec iplot.py → import mac → open(app, p) → Popen(["open", p])
            → print 進訊息區；錯誤進面板；不印「完成」
      → 回 Result.value
```

按 ＋：`Panel._create` → `core.create` → `new_module` → `rescan` → `action("edit", …)`。沒有作業系統模組時前三步照常，第四步變一行提示。

### 5. 錯誤處理

- 作業系統模組不存在：每個動作一行提示，其他全部正常；從零啟動六個情境（`modules/` 空）不受影響。
- 作業系統模組改壞：按鈕標 ⚠；每次動作面板顯示檔案與行號。已知限制：這時「打開程式碼」自己也壞，要手動打開 `modules/作業系統/` 底下的檔案改回來（`.history/` 有上一版）。
- Linux 找不到終端機：模組丟 `OSError`，列出試過的名字。
- Windows 全部未經實機驗證；CI 不會真的跑（沒有遠端）。兩者都寫進文件。

### 6. 不做

`runner`、`View`、`history` 不動；右鍵選項變模組（這條路的下一步）、來源確認、`app.secret()`、Windows 實機測試——寫進 `07` 與 `03` 當延後項。
