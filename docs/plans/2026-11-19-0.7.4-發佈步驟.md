# 0.7.4 發佈步驟與人工驗收（等研究助理確認）

寫於 2026-11-19 晚上。分支 `fix/workshop-always-opens`（PR #10，草稿），從 `main` 的 `f173d59`（0.7.3）開出來。**還沒合併、沒打 tag、沒上傳任何東西。**

## 這一版做了什麼

起因：老闆從 0.5.x 換到 0.7.3 之後，「互通」「工作坊」都沒換到新版；互通要他去工作坊，工作坊卻幫不上忙。研究助理要的：工作坊在哪一版都要打得開、只有它自己會自動更新、它不是核心。做法見 `docs/03_設計決定.md` 的 D158。

| 項目 | 值 |
|---|---|
| 核心 | 0.7.4，只改版本號；核心邏輯仍是 695 行 |
| 工作坊 | 1.0.0（第一次有版本號）：新增 `selfupdate.py`；舊設定指著凍結清單時改讀新清單；互通的另開出錯照舊在面板開 |
| 測試 | 新的 `tests/test_workshop_every_core.py`：v0.5.0 到 v0.7.3 共 11 版核心，每一版都真的按一次工作坊（開清單、裝模組、自己更新）。CI 改成 `fetch-depth: 0` |
| 其他 | 全部測試 2510 passed；另外 8 個失敗在 `main` 上也一樣（那台機器沒有 tkinter、用 root 跑），跟這次無關 |

## 1. 人工驗收（約 10 分鐘，在 Mac 上）

在 iPLoT 資料夾開終端機：`git fetch && git checkout fix/workshop-always-opens`，再「重新啟動」。視窗標題應該是「iPLoT v0.7.4」。

1. **照常開**：雙擊「工作坊」。預期：跟以前一樣在另一個視窗打開清單，訊息區沒有「自動更新」那一句（網站上還沒有工作坊）。
2. **舊設定**：打開 `config.py`，把 `WORKSHOP_URL` 暫時改成 `"https://william10310406.github.io/iplot-workshop/index.json"`，存檔，「重新啟動」，雙擊「工作坊」。預期：訊息區先說「工作坊的清單搬家了…」，清單照樣打開，而且是新清單（看得到「車車」）。改回來。
3. **互通壞了也能開**：把 `modules/互通/separate.py` 改名成 `separate.py.bak`，在旁邊新建一個 `separate.py`，內容只寫 `1/0`。雙擊「工作坊」。預期：清單照樣打開（在面板裡開，開著的時候面板會等它）。刪掉這個 `separate.py`，把 `.bak` 改回來。

自己更新自己要等網站上有工作坊才看得到，放在第 2 節最後一步。

有任何一項不對：先不要發，回到這個對話說哪一項、看到什麼。要退回原狀：`git checkout main`，再「重新啟動」。

## 2. 發佈（確認之後）

1. CI 六個 job 全綠（這一版的跨版本測試要 tag，CI 已經設好）。
2. 合併：`git checkout main && git pull && git merge --no-ff fix/workshop-always-opens && git push`，等 `main` 的 CI 全綠。
3. 打 tag：`git tag v0.7.4 && git push origin v0.7.4`。0.7.3 的 tag 還沒推的話一起推：`git tag v0.7.3 f173d59 && git push origin v0.7.3`。
4. 發核心：`python3 tools/publish.py --version 0.7.4 --base-url https://william10310406.github.io/iplot-workshop --out ../iplot-workshop --modules-site https://william10310406.github.io/iplot-modules/`，到 `../iplot-workshop` commit「0.7.4（v0.7.4，<hash>）」、推上去。
5. 上傳模組（iplot-modules 的上傳表單，從乾淨的 checkout 壓）：「工作坊」1.0.0；還沒傳的「互通」0.4.0、「回報與討論」0.2.2 一起傳。上傳「工作坊」時如果機器人因為名字是隨附模組而退件，回來說，我改。
6. **自己更新自己（真的走一次）**：網站上看得到工作坊 1.0.0 之後，在你的 Mac 上把 `modules/工作坊/CHANGELOG.md` 裡的 `## [1.0.0]` 暫時改成 `## [0.9.0]`，雙擊「工作坊」。預期：訊息區「工作坊已自動更新：0.9.0 → 1.0.0（舊的存在 modules/工作坊/.history/）」，清單打開；`CHANGELOG.md` 又變回 1.0.0。
7. 寫 `docs/plans/2026-11-19-0.7.4-發佈紀錄.md`，D158 改成「採用」。

## 3. 給老闆

他跑過「修好互通與工作坊」那個檔的話，工作坊已經是 0.7.3 的，沒有自動更新：等 0.7.4 發佈後按「更新」→「重新啟動」，工作坊就是 1.0.0，之後自己會更新。

## 4. 這一版沒做的

- 隨附同步為什麼沒換到老闆那台的互通與工作坊，沒查到（要他電腦上的 `ls -a modules/互通 .backup` 與 `.bundled-version`）。我在這邊模擬從 0.5.1、0.5.2、0.6.x、0.7.x 按「更新」升上來，每一次都換成功。
- 其他模組不自動更新（研究助理的決定）。
