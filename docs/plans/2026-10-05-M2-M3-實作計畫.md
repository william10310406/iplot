# M2／M3 實作計畫：圖示面板（pywebview）、第一次啟動自動安裝、更新、工作坊

> **給執行者：** 用 superpowers:executing-plans（或 subagent-driven-development）逐個 Task 做。每個 Task 先寫失敗的測試、看到紅、再寫程式、看到綠、commit。步驟用 `- [ ]` 追蹤。**Task 1 的 spike 失敗就停下來回報；Task 9 與 Task 16 停在人工驗收等人按，不要自己合併、不要自己打 tag。** 每個 Task 完成時回報：測試數、預算數字（`pytest tests/test_budget.py -v` 的輸出）、commit。

**目標**：第一部分（Task 0–9，0.4.0）把面板換成 pywebview 視窗裡的圖示格，第一次啟動自動把 pywebview 裝進 `lib/`，交付。第二部分（Task 10–16，0.5.0）加「更新」與「工作坊」兩個隨附模組與發佈工具，交付。

**架構**：`Core` 與 `View` 不變（`View` 少 `window`、多 `confirm`、M3 再多 `page`）。`ui/web.py` 實作 `View`，單一工作執行緒把網頁的動作交給 `Core`；`ui/tk.py` 是原面板，只在安全模式與後備出現；`ui/install.py` 跑 pip。更新與工作坊是模組，核心只多一個「第一次執行前確認」的標記檢查。

**技術**：Python ≥ 3.10 加 pip；pywebview（`lib/`）；HTML/CSS/JS 無框架、零外部資源；pytest、ruff。

**規格**：`docs/plans/2026-10-05-M2-網頁面板與更新.md`（以下稱「規格」；§ 號都指它）。計畫只寫規格沒決定的事：哪個檔、什麼名字、什麼簽名、哪個測試。

## 全域限制

規格「全域限制」整節照抄適用，重點：Python 端只用標準庫加 `lib/`；`core/` 不 import `webview`；`ui/*.html|js|css` 無 `http://`、`https://`；預算 核心邏輯 ≤ 500、`ui/web.py` ≤ 200、`ui/tk.py` ≤ 180、`ui/install.py` ≤ 80、`index.html` ≤ 120、`app.js` ≤ 400、`style.css` ≤ 300，超過就停；`core/`（`text.py` 除外）、`ui/*.py`、`main.py` 不寫中文常數；`except Exception` 只在 `runner`、`load_config`、`ui/web.py` 工作迴圈；文件不出現「您」、不稱呼特定的人；分支 `m2-panel`（第二部分 `m3-workshop`）；沒有遠端，不 push；Windows、Linux 一律標未經實機驗證。

## 審查焦點

規格的六條（§審查焦點）各釘在負責的 Task；另外五條規格沒明說、但一般人一用就會踩到的：

1. **`lib/.installed` 對得上、import 還是壞、重裝後仍壞**：只重裝一次就退到後備，不會無限 `execv` → Task 7 `test_reinstall_happens_once`。
2. **模組名稱含單引號或反斜線**（`it's`、`a\b`）經過 JSON 進 `evaluate_js`：頁面照常顯示、按得到 → Task 4 `test_show_escapes_names_for_js`。
3. **使用者在面板關掉前連按「更新」兩次**：第二次排隊、看到「已是最新」而不是再換一次 → Task 12 `test_update_twice_second_is_noop`。
4. **工作坊的 zip 裡最上層不是 `<name>/`**（打包錯）：不解壓、一句話 → Task 14 `test_install_rejects_wrong_top_folder`。
5. **`.origin` 被手動改壞**（缺行、亂碼）：狀態算 `modified`，不是 traceback → Task 14 `test_broken_origin_counts_as_modified`。
