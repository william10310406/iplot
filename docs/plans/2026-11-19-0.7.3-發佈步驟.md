## 1. 人工驗收（約 10 分鐘，在 Mac 上）

先切到分支：在 iPLoT 資料夾開終端機，`git checkout fix/page-blocks-panel`，再雙擊 `iPLoT.command`（或「重新啟動」）。視窗標題應該是「iPLoT v0.7.3」。

1. **另開**：雙擊「工作坊」。預期：訊息區出現「在另一個視窗打開「工作坊」」，接著另一個視窗出現清單（第一次可能要一兩秒，請記下大約幾秒）。
2. **面板沒被卡住（這次要修的事）**：工作坊的清單開著，回到面板雙擊「開工」。預期：馬上跑，不用等清單關掉。
3. **不開第二個**：清單還開著，再雙擊一次「工作坊」。預期：訊息區「「工作坊」已經開著」，清單那個視窗跑到最前面；沒有第二個清單。
4. **新裝的模組出現**：在清單裡裝一個模組（例如「打開核心原始碼」已裝的話按「覆蓋」也可以），關掉清單，點一下面板。預期：面板重掃，模組在上面。
5. **關掉之後**：清單關掉後，`modules/工作坊/` 裡沒有 `.pid`（在 Finder 按 ⌘⇧. 看隱藏檔）。再雙擊「工作坊」，會重新另開。
6. **回報與討論**：雙擊「回報與討論」，同 1–3。再故意讓一個模組出錯（例如新增一個模組、內容寫 `1/0`），按錯誤旁邊的「回報這個問題」。預期：這一個照舊在面板裡開，內容是剛才那個錯誤。
7. **互通**：雙擊「互通」，同 1–3；狀態頁的「再同步一次」照常。
8. **導覽列**：在另開的工作坊視窗上方的導覽列點「主控面板」。預期：工作坊的視窗關掉，回到面板。
9. **Dock**：開著的時候 Dock 上多一個 Python 的圖示（已知，CHANGELOG 有寫）。

有任何一項不對：先不要發，回到這個對話說哪一項、看到什麼。要退回原狀：`git checkout main`，再「重新啟動」。

## 2. 發佈（確認之後）

順序跟 0.7.0 一樣：先模組、後核心；每一個等網站更新、對著線上的 `index.json` 確認版本與 sha256 才做下一個。這一版順序反了也不會壞（沒有 `separate.py` 時照舊在面板裡開），只是先發的那一個暫時沒效果。

1. 推分支，等 CI 六個 job 全綠：`git push -u origin fix/page-blocks-panel`。Windows 的 job 如果紅在 Tcl/Tk 裝壞（0.7.2 碰過），只重跑紅的那個。
2. 上傳「互通」0.4.0：在 Finder 對 `modules/互通` 按右鍵「壓縮」之前，先確認資料夾裡沒有 `.pid`、`.python` 以外的個人檔（`捷徑/`、`.lock`、`.sync-error` 也搬開，或照 0.7.0 的做法從乾淨的 checkout 壓）；到 iplot-modules 的上傳表單送出；等機器人回「收到了」、網站更新，核對 `index.json` 的版本 0.4.0 與 sha256 跟下載的 zip 一致。
3. 上傳「回報與討論」0.2.2：同上。
4. 合併：`git checkout main && git merge --no-ff fix/page-blocks-panel`，推上去，等 `main` 的 CI 全綠。
5. 打 tag：`git tag v0.7.3 && git push origin v0.7.3`。
6. 發核心：`python3 tools/publish.py --version 0.7.3 --base-url https://william10310406.github.io/iplot-workshop --out ../iplot-workshop --modules-site https://william10310406.github.io/iplot-modules/`，到 `../iplot-workshop` commit「0.7.3（v0.7.3，<hash>）」、推上去。
7. 發佈之後：`python3 tests/acceptance_workshop.py --published ../iplot-workshop` 要全過；`update.json` 的版本 0.7.3、sha256 跟線上 zip 一致。
8. 寫 `docs/plans/2026-11-19-0.7.3-發佈紀錄.md`（照 0.7.2 那一份的格式），D157 的狀態改成「採用」，日誌記一筆。
