# M4 互通：模組在哪裡都打得開、彼此叫得到、叫得出主控面板（設計）

2026-10-07。這份是設計（規格），不是工作單：設計在 2026-10-07 的對話裡分三段逐段確認過，寫成這份給人審；審過之後才寫給 Claude Code 的工作單（`docs/plans/2026-10-07-M4-互通.md`）。

## 0. 一句話

任何模組都能從面板以外的地方打開——Spotlight 或 Dock 上的捷徑、一行指令、直接 `python3 iplot.py`——打開之後跟在面板裡一樣拿得到 `app`；任何模組都能用 `app.run` 叫別的模組，用 `app.run("主控面板")` 叫出面板。做法是兩個工作坊模組（「互通」「主控面板」），加上核心一次小改（0.5.1）。

**四種開法，最後都進同一個入口 `Core.press`：**

| 開法 | 路徑 |
|---|---|
| Spotlight／Dock 點捷徑 | `捷徑/<名稱>.app` → `<記下的 Python> run.py <模組資料夾>` |
| 在模組資料夾 `python3 iplot.py [參數…]` | 檔頭那一小段 → `<同一個 Python> run.py <模組資料夾> [參數…]` |
| 一行指令（終端機、捷徑 App、快捷鍵） | `<Python> <iPLoT>/modules/互通/run.py <名稱或路徑> [參數…]` |
| 面板裡雙擊 | 跟現在一樣 |

每一次面板外的執行都是一個獨立的程序：跟開著的面板之間不連線，`app.memory` 不共用，訊息不進面板。iPLoT 照樣不聽任何 port。

## 4. 核心 0.5.1

### 4.1 `Core.run_by_name`：找不到時退到最上層（D83）

- 名稱先 NFC 正規化（不變）。
- 先在目前這一層找（`self.all_modules()`，不變）：剛好一個就執行它；兩個以上丟 `LookupError`（`T["ambiguous"]`，不變）。
- 目前這一層一個都沒有，才去最上層找：`scan.find_modules(self.roots())` 的所有模組。剛好一個就執行；兩個以上丟 `ambiguous`；沒有丟 `not_found`。
- 面板在最上層時，目前這一層就是最上層，行為跟 0.5.0 一模一樣；原本找得到的照樣找得到，不會多出新的同名錯誤。
- 傳 `ModuleInfo` 進來的路徑不變。
- `run_by_name` 與 `App.run` 的 docstring、`docs/api.md` 的 `app.run` 那一列改成：「執行另一個模組：先找面板目前這一層，找不到再找最上層；同一處有兩個同名就丟 LookupError，不猜。」

### 4.2 範本裡的那一小段（D84）

`core/text.py` 的 `TEMPLATE` 在第一行的 docstring 之後加上下面這一段，其餘不變；docstring 仍然是第一個敘述（面板的說明文字照樣讀得到）。同一段文字也是 `modules/互通/snippet.py` 的 `TEXT`，兩邊必須一字不差（測試擋）。

```python
# ── 互通 ── 直接執行這個檔（python3 iplot.py）時交給 iPLoT 用彈出式視窗跑；從 iPLoT 裡執行時這段不做事。不要可以整段刪掉
import sys
if __name__ == "__main__" and "core.runner" not in sys.modules:
    import os
    import subprocess
    here = folder = os.path.dirname(os.path.abspath(__file__))
    run = None
    while run is None and folder != os.path.dirname(folder):  # 往上一層層找 iPLoT：模組在它裡面或旁邊都找得到
        folder = os.path.dirname(folder)
        try:
            names = [""] + sorted(os.listdir(folder))
        except OSError:
            names = [""]
        runs = (os.path.join(folder, n, "modules", "互通", "run.py") for n in names)
        run = next((r for r in runs if os.path.isfile(r)), None)
    sys.exit(subprocess.call([sys.executable, run, here, *sys.argv[1:]]) if run
             else "找不到 iPLoT 的「互通」：先在工作坊裝「互通」；模組要放在 iPLoT 資料夾裡或它旁邊")
# ── 互通 ──
```

- 認得出來的記號：檔案裡有 `# ── 互通 ──` 這一行開頭的字。
- 在 iPLoT 裡執行（面板、或 `run.py`）時 `core.runner` 已經載入，這段不做事；直接執行時，往上一層層找，每一層看它自己和它底下每個資料夾有沒有 `modules/互通/run.py`。所以模組放在 iPLoT 資料夾裡（任何一層）、或放在 iPLoT 旁邊（`ROOTS` 預設的 `".."`，連同它的下一層）都找得到；`ROOTS` 另外加的資料夾（例如 `~/Desktop`）找不到，只印那一句、以結束碼 1 結束。
- 參數原樣往後傳；`run.py` 的結束碼原樣傳回。
- 寫法只用 Python 3.8 就有的語法：直接執行的人手上的 `python3` 可能是系統內建的舊版（第 5.1 節會換成對的那個）；也要過 `ruff check`（分開的 import、不用 `import os, subprocess`）。
- 限制：那一小段要跑得到才有用。檔案裡用了舊 Python 看不懂的語法（例如 `match`），用舊 Python 直接執行時會在讀檔階段就出錯，輪不到它換 Python；這種情況照實寫進 README。
- **約定（D84）**：那一小段叫 `run.py` 的方式是 `<python> <run.py> <模組資料夾> [參數…]`。範本在核心裡、到下一個大版本都不會變，所以「互通」的每一版都要接受這個呼叫方式。
- 2026-10-07 在沙盒驗過：放在 iPLoT 裡第一層與第二層、iPLoT 旁邊與它的下一層，都找到 `run.py`、收到「模組資料夾＋參數」；結束碼原樣傳回；在 iPLoT 裡（`core.runner` 已載入）不做事；找不到時那一句與結束碼 1；說明文字與 `run` 照樣讀得到。

## 5. 「互通」

### 5.1 `run.py`：面板外唯一的入口

**用法：** `<python> <iPLoT>/modules/互通/run.py <目標> [參數…]`

- **目標**：模組資料夾的路徑、`iplot.py` 的路徑，或最上層模組的名稱。
- **參數**：有的話當作檔案路徑（以呼叫時的工作目錄為準變成絕對路徑），交給模組的 `on_files(app, paths)`；沒有就執行 `run(app)`（沒有 `run` 時執行最外層，跟面板一樣）。
- **結束碼**：0＝模組跑完沒出錯；1＝模組出錯、取消執行、找不到模組、使用者按了停止；2＝開不起來（Python、iPLoT 的位置、核心版本、pywebview）。

**依序做的事：**

1. **先確認 Python 對不對（D86）。** 這一步的程式只用 Python 3.8 的語法（跟 `main.py` 的 D46 同一個理由）。
   - iPLoT 的位置：`run.py` 往上兩層（`modules/互通/run.py` → iPLoT）；那裡沒有 `core/app.py` 與 `main.py` → 提示框「「互通」要放在 iPLoT 的 modules/ 裡才能用：<路徑>」，結束碼 2。
   - 把 iPLoT 放進 `sys.path` 第一個、`iPLoT/lib` 第二個（跟 `main.py` 一樣，iPLoT 自己的東西排在系統的套件前面），試著 `import core`、`import webview`。
   - Python 低於 3.10、或上面兩個 import 失敗（`lib/` 的編譯檔是給別的 Python 的）：如果 `modules/互通/.python` 記著一個存在、而且不是現在這個的 Python，又還沒換過（環境變數 `IPLOT_INTEROP_REEXEC` 沒設），就設好那個環境變數、`os.execv` 換成它重跑一次。否則提示框說一句（第 8 節），結束碼 2。
2. **核對核心版本。** `core.__version__` 是 `0.5.x`、而且 `core.app.App.api_version >= 3`；不合 → 提示框「互通 <版本> 支援 iPLoT 0.5，這台是 <版本>。到工作坊看看互通有沒有新版。」，結束碼 2。
3. **記下這個 Python。** 走到這裡表示這個 Python 跑得動：`sys.executable` 跟 `.python` 記的不一樣就寫進去。
4. **擋住 tkinter。** 跟 `main.py` 的 `NoTk` 同一種做法（`sys.meta_path` 最前面），訊息改成面板外的版本（第 8 節）。理由也一樣：主執行緒被 pywebview 佔著，模組在別的執行緒開 tkinter 視窗，整個程序會被作業系統中止。
5. **讀設定。** `load_config(iPLoT/config.py)`；壞了就用預設值，並在小視窗回報（跟面板一樣）。
6. **開小視窗、建 Core。** `popup = Popup(home, webview)`、`core = Core(home, config, popup)`、`popup.attach(core)`，然後 `popup.run(工作)`：主執行緒進 pywebview 的事件迴圈，工作在工作執行緒上做（第 5.2 節）。
7. **工作執行緒上：**
   1. `core.rescan()`（`app.modules` 才有東西；在面板外一律是最上層）。
   2. 找目標（第 5.1.1 節）。找不到就在小視窗說一句，跳到 iv。
   3. `core.press(info, quiet=True)`，有參數就 `core.press(info, "on_files", (paths,), quiet=True)`。用 `quiet` 是為了不讓核心的「完成（x 秒）」那一行把小視窗叫出來；跑完由小視窗自己決定要不要顯示「完成」。快照、`input()` 變對話框、從工作坊裝來的模組先問一次、錯誤回報，全部是 `Core.press` 原本就做的事。
   4. 告訴小視窗結果（成功、出錯、取消、找不到）。
   5. 同步一次（第 5.4 節）。
8. 小視窗關掉（自己關、或使用者關）之後，以上面的結束碼結束。用 `os._exit`：模組自己開的非 daemon 執行緒不能讓程序賴著不走。

#### 5.1.1 找目標

- 目標是存在的路徑：是資料夾就用它，是 `iplot.py` 就用它的上一層；那個資料夾裡沒有 `iplot.py` → 「不是模組：<路徑>（資料夾裡沒有 iplot.py）」。`ModuleInfo` 的 `root`、`level` 取第一個包含它的根目錄（`core.roots()` 的順序），都不包含就用它的上一層、`"extra"`。
- 目標是不存在的路徑（看起來像路徑：含 `/`，或以 `~` 開頭）→ 「找不到這個模組：<路徑>。它可能被改名或刪掉了；捷徑已經重新整理。」（同步會拿掉指向它的捷徑）。
- 其餘當名稱：NFC 正規化，在最上層找；沒有 → `T["not_found"]`；兩個以上 → `T["ambiguous"]`（列出路徑）。名稱不找下一層（D83）。

### 5.2 彈出式視窗（`popup.py`、`popup.html`）

`Popup` 照核心的 `View` 做八個方法，另外有 `attach(core)`、`run(job) -> int`。建構子收 `webview`（測試傳 `tests/conftest.py` 的 `FakeWebview`，跟 `ui/web.py` 的 `WebPanel` 一樣）。執行緒的做法照 `ui/web.py`：主執行緒是 pywebview，工作執行緒一次做一件，頁面呼叫 Python 的方法只排工作、立刻回傳；對話框用 `threading.Event` 等頁面回答。

**小視窗：**
- 標題是模組的顯示名稱；460×320，最小 360×220；一開始藏著（`hidden=True`）。
- 這些時候跳出來：`log`（包括 `print` 的輸出，它們在模組跑完時由 `Core.press` 一行行送進來）、`report`、`ask`、`confirm`、`choose_files`、`choose_folder`（先跳出來再開檔案選擇視窗），以及模組跑了 1 秒還沒結束（顯示「執行中：<名稱>…」和「停止」）。
- `page(title, html, api)`：另開一個 640×520 的視窗，關掉才回來，跟 `WebPanel.page` 一樣；不會因此把小視窗叫出來。
- `show(scope)`：不做事。
- 對話框開在小視窗裡，跟面板裡的長相與操作一樣：Enter 確定、Esc 取消；`ask` 有輸入框。視窗關掉時，等著回答的對話框一律當作取消。
- 錯誤：白話的那一句（`core.errors.describe`），「打開檔案」（有檔案時，交給 `core.action("edit", 檔案, config.editor, 行號)`，排進工作執行緒），「詳細」展開 traceback。
- 頁面上所有來自模組的字一律用 `textContent`，不用 `innerHTML`；頁面不載入任何外部資源；深色模式跟著系統；樣式寫在 `popup.html` 裡，不引用 `ui/style.css`（`ui/` 是核心的一部分，D80）。

**跑完之後：**

| 結果 | 小視窗沒出現過 | 小視窗已經出現 |
|---|---|---|
| 成功 | 直接結束，什麼都不顯示 | 底下顯示「完成（x 秒），3 秒後關閉」並倒數；在視窗裡按任何一下就取消倒數、改成「關閉」按鈕 |
| 取消執行（工作坊裝來的模組，第一次問的時候按取消） | （問的時候已經出現） | 同「成功」 |
| 出錯、找不到模組 | 跳出來顯示 | 留著，底下是「出錯了」和「關閉」 |

- 按「停止」或在執行中關掉視窗：結束這一個程序（結束碼 1）。面板不受影響——這是面板外執行比面板裡好的地方。
- 同步在跑完之後做；小視窗要等同步做完才真的關。

### 5.3 那一小段（`snippet.py`）

- `TEXT`：第 4.2 節那一段（一字不差）。`MARK = "# ── 互通 ──"`。
- `has(source) -> bool`：有沒有 `MARK`。
- `where(source) -> int`：插在第幾行：模組的 docstring、`from __future__`、以及開頭連續的 import 之後，其他程式之前。放在最外層程式之前，是為了沒有 `run` 的模組（D47，最外層就是動作）直接執行時不會先跑一次；放在開頭的 import 之後，是為了不讓那些 import 變成「程式碼之後的 import」（ruff E402）。用 `ast` 找；檔案有語法錯誤就丟 `SyntaxError`，呼叫的人跳過。模組自己已經 `import sys` 的話，那一小段的 `import sys` 是重複的，無害；只有 repo 裡要過 `ruff check` 的模組要處理（ruff F811）：讓那一小段的 `import sys` 取代模組自己的那一行（例如「重新啟動」）。
- `add(path, keep) -> bool`：已經有就回 `False`；否則先用 `core.history.snapshot(path, keep)` 存快照，插進去、寫回，回 `True`。保留原本的 BOM 與換行方式（runner 用 `utf-8-sig` 讀）。

### 5.4 同步（`sync.py`）

`sync(home, config) -> list[str]`（回這一次的問題，一個一句）。觸發的時機只有兩個：`run.py` 每次跑完、在面板按「互通」。沒有背景程式（D84）。

1. **鎖：** `os.open(".lock", O_CREAT | O_EXCL)`；已經有鎖、而且不到 120 秒 → 這次跳過（回空清單）；超過 120 秒當作上次沒清掉，拿掉再鎖。做完一定拿掉。
2. **列出模組：** `scan.roots_from_config(home, config.roots)` 的每個根目錄，`scan.find_modules` 拿最上層，再用 `scan.find_children` 一路往下拿每一層。
3. **補那一小段**（每個模組只補一次）：
   - 跳過：資料夾已經記在 `.patched`；有 `.origin`（工作坊裝來的，補了會變「已修改」，D77）；最上層 `modules/` 裡的作業系統、更新、工作坊；在 `ROOTS` 另外加的根目錄底下（那一小段在那裡找不到 iPLoT）。
   - 已經有記號的：只記進 `.patched`。
   - 其餘：`snippet.add`，成功就記進 `.patched`；語法錯誤 → 問題「<名稱>：有語法錯誤，沒補」；寫不進去 → 「<名稱>：沒補：<錯誤>」。
   - `.patched` 是 JSON，資料夾絕對路徑的清單。記的是路徑，所以模組改名之後算新的，會再檢查一次（那時候它通常已經有記號，只會記進去）。
4. **捷徑**（只在 macOS，第 5.5 節）。
5. **寫紀錄：** 有問題就寫進 `.sync-error`（一行一個，覆蓋上一次的），沒有就刪掉它。

## 6. 「主控面板」

```python
"""主控面板：打開 iPLoT 的面板；已經開著就叫到最前面。任何模組寫 app.run("主控面板") 就會用到這裡。"""
ICON = "🎛️"
```

`run(app)`，三種情況：

1. **在面板的程序裡**（`"ui.web"` 或 `"ui.tk"` 已經在 `sys.modules` 裡）：把自己叫到最前面（macOS：`NSRunningApplication.currentApplication().activateWithOptions_(NSApplicationActivateIgnoringOtherApps)`），記一行「主控面板已經開著」。
2. **在面板外、面板開著：** 找面板的程序——`ps -axo pid=,command=` 裡指令有 `python`（不分大小寫）也有 `main.py` 的程序，不算自己；指令裡有 `<iPLoT>/main.py` 就算；只寫 `main.py` 的（`iPLoT.command` 就是這樣開的），再用 `lsof -a -p <pid> -d cwd -Fn` 看它的工作目錄是不是 iPLoT。找到 → 用 `NSRunningApplication.runningApplicationWithProcessIdentifier_(pid)` 叫到最前面，記一行「主控面板已經開著，叫到最前面了」。
3. **在面板外、面板沒開：** `subprocess.Popen([sys.executable, <iPLoT>/main.py], cwd=<iPLoT>, start_new_session=True)`，輸入輸出都接到 `DEVNULL`，記一行「打開主控面板」。用的 Python 是正在跑的這一個：在面板外，`run.py` 已經確認過它跑得動面板（D86）。

- `AppKit` 來自 `lib/` 裡的 pyobjc（pywebview 在 macOS 上需要它，本來就在）；import 不到時不叫到最前面，只記一行說明。
- macOS 以外：情況 1 只記一行；情況 2、3 都直接開一個（找不到開著的面板），記一行「這個系統還不會把開著的面板叫到最前面」。
- 開不起來 → 回報「打不開主控面板：<錯誤>」。

## 9. 安全（`docs/07` 第 7 節要改的地方）

- 仍然不聽任何 port；面板外的每次執行都是獨立程序，彼此不連線。
- 「模組程式碼只在有人動手時執行」：動手多了三種——點捷徑、打那一行指令、直接 `python3 iplot.py`。仍然沒有自動啟動、沒有背景程式。
- 同步會改模組的檔案，但只做一件事：在沒有那一小段的模組裡加上它，每個模組一次，改之前存快照；工作坊裝來的模組與三個隨附模組不碰。除此之外，「互通」只寫自己的資料夾。
- 捷徑的指令稿裡三個路徑都經過 `shlex.quote`；`Info.plist` 用 `plistlib` 寫；提示框的字當參數傳。
- `.python` 是 `run.py` 會拿來執行的路徑。改得了 `modules/` 的人本來就能用這個使用者的權限執行任何東西（第 7 節「不能保證的」第一條），這不是新的一類風險；照實寫進去。

2. ⌘＋空白鍵打「開工」，Enter：Finder、文件、終端機都開了；小視窗顯示「開工：…都開了」，3 秒後自己關。
3. 終端機進某個模組的資料夾，`python3 iplot.py`：用彈出式視窗跑。
4. 一個有 `input()` 的模組從捷徑開：對話框在小視窗；按取消 → 那一句 `EOFError`。
5. 一個會出錯的模組從捷徑開：小視窗留著，「打開檔案」跳到那一行。
6. 面板沒開，從捷徑開一個寫了 `app.run("主控面板")` 的模組 → 面板開了；把面板藏到別的視窗後面，再開一次 → 面板跑到最前面，沒有第二個。
7. 面板停在下一層，那一層的模組用名字叫最上層的模組 → 跑了（0.5.1）。
8. 按 ＋ 建一個新模組，直接 `python3 iplot.py` → 能跑；再從捷徑開任何一個模組之後，新模組的捷徑出現了。
9. 在 Finder 改一個模組的名字、刪掉另一個，再從捷徑開任何一個模組 → 捷徑跟著改名、拿掉。
10. 一個 `time.sleep(30)` 的模組從捷徑開：約 1 秒後出現「執行中」，按停止就結束；面板照常能用。
11. 用 `/usr/bin/python3 iplot.py` 執行 → 自動換成記下的 Python，照常跑。
12. 把 `捷徑/` 拖到 Dock：點開是一排按鈕，點一個就跑。

## 12. 設計決定（寫進 `docs/03`）

**D80 核心只在大版本修改；新功能以工作坊模組上線。** 理由：使用者 2026-10-07 定的規則：核心穩定，功能各自迭代、各自發佈。例外要明講並記在這裡——第一個例外是 0.5.1（D83、D84，使用者同意）。代價：功能模組要用到核心內部才做得到某些事（D85），那些介面因此跟 `app` 一樣凍結；核心的已知問題（D56 等）留到 1.0.0。沒選：每個功能都改核心。狀態：採用，2026-10-07。

**D81 面板外執行由工作坊模組「互通」提供：`run.py`＋彈出式視窗（pywebview）；每次是獨立的程序，不連開著的面板。** 理由：R1–R3；不聽 port，`docs/07` 第 7 節不變；`app` 照樣是普通物件；用 `app.page` 的模組（例如工作坊）在面板外也能跑；外觀與面板一致。沒選：把工作送進開著的面板（要跨程序連線，推翻第 7 節）；macOS 原生對話框（`osascript`，`app.page` 不能用、只有 macOS）；tkinter（Homebrew 的 Python 常常沒有，而且不能跟 pywebview 在同一個程序）。代價：面板外的模組不共用 `app.memory`、訊息不進面板；靠 `lib/` 的 pywebview；Dock 可能閃一下 Python 的圖示。狀態：採用，2026-10-07。

**D82 打開主控面板是一個模組「主控面板」，用 `app.run("主控面板")`；不加 `app.panel()`。** 理由：`app` 在核心裡（D80）；連打開面板都只是一個模組（D01）。沒選：`app.panel()`。代價：名字固定叫「主控面板」；面板開著時靠程序的指令與工作目錄找它，只在 macOS 會叫到最前面。狀態：採用，2026-10-07。

**D83 `app.run`（`Core.run_by_name`）先找目前這一層，找不到再找最上層；核心 0.5.1。** 理由：R3；面板停在下一層時，原本叫不到最上層的模組（2026-10-07 在沙盒驗過會丟 `LookupError`）。沒選：兩層合在一起找（原本找得到的會變成同名錯誤）；「父/子」寫法（延後）；不改核心、讓模組自己找 `ModuleInfo` 再交給 `app.run`（做得到，但每個模組都要多寫三行）。代價：目前這一層找不到時多掃一次最上層；核心邏輯上限 500 → 505（D68 修訂）。狀態：採用，2026-10-07。

**D84 直接 `python3 iplot.py` 靠模組檔頭的一小段：新模組由 ＋ 的範本帶（0.5.1），舊模組由「互通」同步時補一次；不用背景程式。** 那一小段與 `run.py` 的約定是 `<python> <run.py> <模組資料夾> [參數…]`，「互通」的每一版都要接受。理由：背景程式改檔會跟剛打開的編輯器撞（＋ 一建好就開編輯器）、會讓工作坊裝來的模組全部變「已修改」（D77）、開機啟動與關閉沒有地方放（要寫進 `~/Library/LaunchAgents`，不再看得見、可移除）。沒選：背景程式；只用按鈕補（新模組要有人記得按）；`usercustomize`（影響這個使用者的每一個 Python、裝在 iPLoT 外面）。代價：核心的範本寫死了「互通」的名字與位置（同 D52 的做法）；那一小段 18 行（含頭尾兩行記號），每個新模組都有；`ROOTS` 另外加的資料夾裡的模組找不到 iPLoT；還沒裝「互通」時，那一小段只會說一句。狀態：採用，2026-10-07。

**D85 工作坊模組可以依賴的核心介面（清單在 `docs/07` 第 13 節），到 1.0.0 前只加不改；`tests/test_interfaces.py` 釘住。** 理由：D80 之後，功能模組非用到核心內部不可（R1 要自己建 `Core`、實作 `View`）；不列清楚，下一次改核心就會悄悄弄壞工作坊上的模組。代價：這些介面跟 `app` 一樣成了承諾。狀態：採用，2026-10-07。

**D86 面板外一定用跟面板同一個 Python：「互通」記下跑得動的 `sys.executable`（`modules/互通/.python`），捷徑寫死這一個；`run.py` 用錯 Python 時自動換一次。** 理由：`lib/` 裡的 163 個編譯檔全部只給 Python 3.14 用（2026-10-07 查過）；從 Spotlight、Dock 開的程式拿不到終端機的 PATH，`python3` 會是系統內建的舊版。沒選：捷徑用登入 shell 找 `python3`（`zsh -l`，看使用者的 shell 設定，靠不住）；捷徑用 `.command`（會開終端機視窗）。代價：換了 Python 之後要在面板按一次「互通」重新記下（`run.py` 會這樣說）。狀態：採用，2026-10-07。

**D68 修訂：** 核心邏輯上限 500 → 505（2026-10-07，D83 的兩三行）。
