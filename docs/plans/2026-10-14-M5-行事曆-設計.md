# M5 行事曆：以行事曆為主控，寫下每一天、變成網頁（設計）

2026-10-14。這份是設計（規格），不是工作單：需求在 2026-10-14 的對話裡分兩輪問答確認過，研究助理定案；Claude Code 依這份寫工作單（`docs/plans/2026-10-14-M5-行事曆.md`）再實作。
前提：M4（互通）還沒合併（`m4-interop`，七項人工驗收還沒做）。M5 從 `m4-interop` 的 HEAD 開 `m5-calendar`；合併順序是 M4 先、M5 後。
參考：老闆的 `David.txt`（舊 SQP 的行事曆模組）只當作「行事曆長這樣」的示範；它的資料格式（`DavidSPACE/DYYYYMM.txt`）、LCMDs、Lonergan、執行專案資料夾，這一版都不沿用。

## 0. 一句話

工作坊模組「行事曆」：打開就是行事曆，每天寫行程、心情、看到了什麼、做了什麼，放圖片；全部存成一天一個資料夾，並且產生成網頁（綜合、年、月、日各一頁）；打開「公開」的日子另外產生一份可以放上網路的網站。行事曆上方是模組列，從這裡叫任何模組；任何模組寫 `app.run("行事曆")` 就叫得到它；模組跑完，小視窗的回去鈕回到行事曆。

## 1. 需求

來源：老闆（2026-10-14，研究助理轉述）：「以行事曆為主控，一樣可以互相呼叫；可以寫行事曆、寫心情、寫看到了什麼做了什麼，也可以上傳圖片；上傳的所有資料都以網頁形式存在，有一個綜合的網頁，每個日期有不同的分頁，以年、月、日區分。」

- **R1 行事曆是主控**：打開就是它；從它叫得到任何模組；任何模組叫得到它；模組跑完能回到它。
- **R2 每一天四欄加圖片**：行程、心情、看到了什麼、做了什麼；圖片。
- **R3 全部以網頁存在**：綜合網頁；年、月、日各一頁。
- **R4 可以放上網路**：每一天自己決定公開，預設不公開；老闆自己按「發佈」。網頁空間是學校或其他地方，上傳方式還不知道。
- **R5** 除了打字之外只用滑鼠；看得見、可移除（資料是 Finder 看得到的檔案）。

**做好的樣子：**
- Dock 點「行事曆」→ 這個月的月曆，今天標出來；格子裡有心情的表情和那天的第一行。
- 點今天 → 四個欄位，打字，點別的地方就存好；把一張 iPhone 照片拖進來 → 出現縮圖。
- 按「看網頁」→ 瀏覽器打開這一天的網頁；綜合網頁看得到最近 30 天。
- 在上方模組列點「開工」→ 開工跑了，行事曆照樣能用；開工的小視窗按「行事曆」→ 回到行事曆，沒有第二個行事曆。
- 打開某一天的「公開」，按「發佈」→ `發佈/` 裡多了那一天；沒打開的日子不在裡面；照片裡沒有拍攝地點。
- 面板上雙擊「行事曆」→ 行事曆在自己的視窗打開，面板照常能按別的模組。

## 3. 架構

```
modules/行事曆/
  iplot.py      面板上的「行事曆」：不在自己的程序裡 → 另開程序（或叫到最前面）；在自己的程序裡 → 開頁面
  diary.py      資料：讀寫一天、列出一個月與一年、心情、公開標記、.history
  site.py       產生網頁：日、月、年、綜合；本機版與公開版
  photos.py     圖片：收進來（HEIC 轉 JPG）、縮圖、公開版縮小與去掉中繼資料
  page.html     行事曆的畫面
  CHANGELOG.md
  設定.json     自動產生：資料夾位置（不進 git、不進發佈的包）
  .pid          自動產生：開著的那個行事曆程序（不進 git、不進發佈的包）
```

依賴：只用 `docs/07` 第 13 節的核心介面與 `app`；靠「互通」的 `run.py`（D84 的約定：`<python> <run.py> <模組資料夾>`）另開程序；不 import 「互通」「主控面板」的任何檔。

### 3.1 程序（D89）

`run(app)` 依序：
1. **已經有一個行事曆開著**（`.pid` 記的程序還活著，而且它的指令裡有「互通」的 `run.py` 與行事曆的資料夾）→ 叫它到最前面（macOS：`NSRunningApplication` 直接叫，被拒絕就交給一個子程序叫，照抄「主控面板」的做法），記一行「行事曆已經開著」，結束。
2. **這個程序是行事曆自己另開的**（環境變數 `IPLOT_CALENDAR=1`）→ 先把 `IPLOT_CALENDAR` 從 `os.environ` 拿掉（之後從行事曆開的子程序不會繼承它），寫 `.pid`，`app.page("行事曆", page.html, Api)`，頁面關掉後刪 `.pid`。
3. **其他情況**（面板的程序裡、別的模組 `app.run("行事曆")`、小視窗的回去鈕、Dock 捷徑）→ `subprocess.Popen([sys.executable, <home>/modules/互通/run.py, <行事曆資料夾>], env={…, "IPLOT_CALENDAR": "1"}, start_new_session=True)`，輸入輸出接 `DEVNULL`，記一行「打開行事曆」，結束。沒有「互通」的 `run.py` → 記一行「行事曆要用『互通』另開視窗：到工作坊裝『互通』」，不開。

結果：行事曆的頁面只在它自己另開的程序裡開，所以面板不會因為它而排隊（`app.page` 開著的期間，同一個程序裡別的模組只會排隊，`docs/api.md`）、叫它的模組不會被卡住、小視窗的回去鈕馬上就回來。

### 3.2 從行事曆叫模組

- 上方一排模組列：`app.modules`（在自己的程序裡就是最上層）去掉「作業系統」與「行事曆」自己；每個顯示 `ICON` 或名稱的第一個字，滑鼠停上去顯示名稱。
- 點一個 → `Api.launch(name)`：在 `app.modules` 裡找這個名字（找不到或同名兩個 → 頁面上一句），`Popen([sys.executable, run.py, <模組資料夾>], start_new_session=True, DEVNULL)`。每個模組在自己的程序裡跑、有自己的小視窗，行事曆不被卡住。
- 最右邊「圖示面板」：最上層有「主控面板」才出現，同樣用 `run.py` 開它。

## 4. 資料（`diary.py`，D90）

- **位置**：`設定.json` 的 `資料夾`，預設 `~/Documents/行事曆`；第一次存東西時才建立。設定裡可以「換資料夾」（`app.choose_folder`：選擇視窗由「互通」的小視窗開，所以小視窗會先跳出來）。換資料夾不搬資料，只是指到新的地方。
- **一天一個資料夾** `<資料夾>/<YYYY>/<MM>/<DD>/`：
  - `行程.txt`、`看到.txt`、`做了.txt`：UTF-8 文字；存成空的就刪掉那個檔。
  - `心情.txt`：第一行是五個表情之一（😄 🙂 😐 😟 😢）或空行，第二行起是一句話。第一行不是那五個之一（例如用文字編輯器改過）→ 沒有表情，整個檔都當作那句話。
  - `公開`：空檔案，有就是公開（Finder 看得到，跟核心的 `.unconfirmed` 同一種做法）。
  - 圖片：資料夾裡的 `.jpg .jpeg .png .gif .heic .heif`；同名的 `.heic` 與 `.jpg` 並存時顯示 `.jpg`。
  - `.history/`：覆寫文字檔之前，舊的那一份存成 `<欄位>-<YYYYmmdd-HHMMSS>.txt`，每個欄位留 `app.config.history_keep` 份。
  - `.縮圖/`：行事曆畫面用的小圖（Task 0 決定要不要，見第 12 節）。
  - `index.html`：這一天的網頁（產生的）。
- 寫檔一律先寫暫存檔再 `os.replace`。讀不成 UTF-8 的檔：畫面顯示「讀不到」，不覆寫它。
- 一個月的摘要（月曆用）：每一天的表情、第一行（依序取行程、做了、看到的第一個非空行）、有沒有圖片、公不公開。

## 5. 網頁（`site.py`，D91）

**本機版**，在資料夾本身：
```
<資料夾>/index.html             綜合
<資料夾>/2026/index.html        這一年
<資料夾>/2026/10/index.html     這個月
<資料夾>/2026/10/14/index.html  這一天
```
- **日**：「2026 年 10 月 14 日（三）」；表情和那句話；行程、看到了什麼、做了什麼（空的不顯示，換行照原樣）；圖片（點了看原圖，`loading="lazy"`）；上面是「綜合 › 2026 › 10 月」，下面是前一個／後一個有內容的日子。
- **月**：月曆格子，星期日在最左邊；有內容的日子是連結，顯示表情、第一行（最多 20 個字）、有圖片時一個 🖼；上一個月、下一個月（有內容才連）。
- **年**：12 個小月曆；有內容的日子是連結，顯示表情或一個點。
- **綜合**：最近 30 個有內容的日子，新的在上面，每一天顯示表情、三個欄位全文、最多 4 張小圖；底下是每一年、每個月的入口與天數。
- 每一頁：`<meta charset="utf-8">`、viewport、樣式寫在頁面裡、跟著系統的深色模式；**不用 JS、不載入任何外部資源、連結全是相對路徑**；所有文字 `html.escape`。雙擊 `index.html` 就能看，整個資料夾搬到哪裡都能看。
- **什麼時候產生**：存一天 → 重新產生那一天、那個月、那一年、綜合。設定裡「重建全部網頁」：給直接改過 `.txt` 的時候。

**公開版**，在 `<資料夾>/發佈/`，只在按「發佈」時產生：
- 同樣四種頁，但**只包含有 `公開` 標記的日子**；沒公開的日子在公開版裡就像沒寫過（月曆上不是連結、綜合裡不出現、前一天後一天跳過它）。
- 每一頁多 `<meta name="robots" content="noindex">`：知道網址的人看得到，搜尋引擎不收。
- 只放網頁與處理過的圖片；不放 `.txt`、`.history/`、`公開` 標記、`.縮圖/`、原圖、HEIC。
- `發佈/` 跟應有的清單比：多的刪掉（取消公開的那一天會消失）、少的補上、原圖比較新的圖片才重做。

## 6. 圖片（`photos.py`，D91 的一部分）

- **收進來**：頁面用 `<input type="file" multiple accept="image/*">` 或拖放拿到檔案，讀成 base64 交給 `Api.add_image(date, name, data)`。檔名只取 basename，拿掉 `/`、`:`、開頭的 `.`；重名加「 2」「 3」。單張超過 30 MB → 一句話，不收。
- **HEIC／HEIF**（macOS）：`sips -s format jpeg <原檔> --out <同名>.jpg`（清單參數、不經過 shell），原檔留著。轉不出來 → 原檔留著，一句「這張轉不成 JPG，Chrome 看不到」。
- **拿掉**：`app.trash`（同名的 `.jpg`、`.heic` 一起），不直接刪。
- **公開版的圖片**：`sips -Z 1600`（長邊 1600 像素）縮成新檔，再用純 Python 拿掉中繼資料：JPEG 拿掉 APP1（EXIF、XMP）與 APP13 區段；PNG 拿掉 `eXIf`、`tEXt`、`iTXt`、`zTXt` 區塊；GIF 照原樣。其他格式不放上網路，問題清單一句。macOS 以外不縮，只拿掉中繼資料。

## 7. 畫面（`page.html`）

```
┌ [🔆][⌨️][🧰]…（模組列）                     [圖示面板] ┐
│ [年][月][日]   ‹  2026 年 10 月  ›  [今天]  [看網頁][發佈][⚙] │
│ 日 一 二 三 四 五 六                                      │
│  …  14 🙂 開會…  🖼 🌐 …                                  │
└──────────────────────────────────────────────┘
```
- **月**（預設）：格子裡是日期、表情、第一行（兩行內）、🖼（有圖）、🌐（公開）；今天標出來；點一天 → 日。
- **年**：12 個小月曆，有內容的日子上色；點一天 → 日。
- **日**：‹ 日期 ›；五個表情（再點一次取消）＋一句話；行程、看到了什麼、做了什麼三個輸入框；圖片列（縮圖、×、「加圖片」，也可以拖進來）；「公開」開關；「看網頁」開這一天的網頁。
- **存**：離開輸入框、點表情、換一天、換檢視時自動存；狀態列顯示「已存」或存不進去的那一句；存不進去時字留在輸入框裡，下一次再試。
- **看網頁**：月、年、日檢視分別開那一頁的本機網頁（`app.open`）；綜合從 ⚙ 開。
- **發佈**：先在頁面上問（不是 `app.confirm`，`docs/api.md` 寫 `app.page` 的第四件事）：「要放上網路的有 N 天（只有打開『公開』的日子）。產生發佈用的資料夾？」→ 產生 `發佈/` → 上傳方式還沒設定（D92）：在 Finder 打開 `發佈/`，一句「上傳方式還沒設定：把『發佈』裡的東西放到網頁空間」。
- **⚙**：資料夾位置＋「換資料夾」、「打開資料夾」、「打開綜合網頁」、「重建全部網頁」。
- 視窗是 `app.page` 的 640×520（核心固定，可以拉大）。
- 來自資料的字一律 `textContent`；`Api` 自己的屬性一律底線開頭（`docs/api.md` 寫 `app.page` 的四件事）。

**`Api` 的方法**（頁面傳進來的日期一律 `YYYY-MM-DD`，用正規表示式＋`datetime` 檢查；頁面不傳路徑）：`month(ym)`、`year(y)`、`day(date)`、`save(date, fields)`、`set_public(date, on)`、`add_image(date, name, data)`、`remove_image(date, name)`、`open_page(kind, key)`、`publish()`、`modules()`、`launch(name)`、`settings()`、`change_folder()`、`reveal_folder()`、`rebuild()`。

## 8. 互相呼叫：「互通」的回去鈕（D93）

- `run.py` 決定要不要給回去鈕：最上層**剛好一個**「行事曆」、而且跑的不是它 → 鈕是「行事曆」；否則照 D88（剛好一個「主控面板」、而且跑的不是它 → 「主控面板」）；都沒有 → 不給。
- 小視窗：鈕上的字就是那個名字；按下去跑那個模組（D88 的做法不變：等模組與同步跑完、跑完沒出錯就關掉小視窗）。行事曆照 D89 會另開程序或叫到最前面，馬上回來，所以小視窗馬上關。
- 測試：`test_interop.py` 加「有行事曆 → 鈕是行事曆」「行事曆有兩個 → 退回主控面板」「跑的就是行事曆 → 主控面板」；原本 D88 的測試照樣綠。

## 9. 出錯時

一律一句話，不丟 traceback。

| 情況 | 在哪裡說 | 那一句 |
|---|---|---|
| 沒有「互通」 | 訊息區或小視窗 | 行事曆要用「互通」另開視窗：到工作坊裝「互通」 |
| 已經開著、叫不到最前面 | 訊息區或小視窗 | 行事曆已經開著（在 Dock 上找它） |
| 資料夾建不起來、寫不進去 | 頁面狀態列 | 存不進去：<原因>。字還在，等一下會再試 |
| 檔案不是 UTF-8 | 頁面那個欄位 | 讀不到這個檔（不是 UTF-8），沒有覆寫它：<路徑> |
| 圖片太大、格式不收 | 頁面 | <檔名>：太大（超過 30 MB）／不是圖片 |
| HEIC 轉不成 | 頁面 | <檔名>：轉不成 JPG，Chrome 看不到 |
| 發佈時沒有公開的日子 | 頁面 | 還沒有打開「公開」的日子 |
| 發佈時某張圖處理不了 | 頁面（清單） | <日期> <檔名>：沒放上網路：<原因> |
| 模組列點的模組不在了 | 頁面 | 找不到「<名稱>」（可能被改名或刪掉了） |

## 10. 安全（`docs/07` 第 7 節要補的）

- 仍然不聽任何 port、這一版不連網：「發佈」只產生資料夾，不上傳。
- 公開與本機分開：`發佈/` 只拿得到打開「公開」的日子；文字原檔、`.history/`、原圖、HEIC 從來不會被複製進去；照片去掉拍攝地點等中繼資料；網頁有 noindex。
- 產生的網頁不含 JS、不載入外部資源、文字全部跳脫。
- 頁面傳進來的只有日期字串、模組名稱、圖片的檔名與內容：日期嚴格檢查、模組名稱只在 `app.modules` 裡找、檔名只取 basename；沒有任何一個 `Api` 方法收路徑。
- 心情、日記、照片是私人的：README 寫清楚 `發佈/` 一旦放上網路，知道網址的人都看得到，沒有密碼。

## 11. 測試

先寫會失敗的測試、確認它因為對的理由紅，再寫程式。`tests/test_calendar.py`；模組的檔照 `tests/test_bundled.py` 的寫法載入。`subprocess.Popen`、`sips`、`app.trash`、`app.open`、AppKit 在測試裡一律換成假的；資料夾一律是 `tmp_path`，絕不碰 `~/Documents/行事曆`。

## 14. 設計決定（寫進 `docs/03`）

**D89 行事曆的頁面只在它自己另開的程序裡開；一次只開一個。** 在別的地方被叫到（面板、`app.run`、小視窗的回去鈕、Dock 捷徑），一律經過「互通」的 `run.py` 另開一個程序（環境變數 `IPLOT_CALENDAR=1` 記號，那個程序一開始就把它拿掉），已經開著就叫到最前面（`.pid`）。理由：`app.page` 開著的期間同一個程序裡的模組只會排隊——行事曆整天開著，放在面板的程序裡等於鎖住面板；叫它的模組不會被卡住；小視窗的回去鈕馬上回來。沒選：在面板的程序裡開（面板被鎖）；改核心讓 `app.page` 不擋（D80）。代價：Dock 捷徑開的時候多一跳（多啟動一次 Python，約 1–2 秒）；依賴「互通」；「叫到最前面」那段跟「主控面板」重複一份。狀態：採用，2026-10-14。

**D90 資料一天一個資料夾，純文字加圖片；網頁從它產生。** `<資料夾>/<年>/<月>/<日>/` 裡 `行程.txt`、`心情.txt`、`看到.txt`、`做了.txt`、圖片、`公開` 標記；預設 `~/Documents/行事曆`，在模組外面。理由：Finder 看得到、文字編輯器改得了、整個資料夾就是備份（看得見、可移除）；刪掉或更新模組不會刪到日記。沒選：一個 JSON 或 SQLite（看不見）；沿用 DavidSPACE（每個月一段 Python 程式，要 `exec` 才讀得到）。代價：檔案很多；直接改 `.txt` 之後要按「重建全部網頁」。狀態：採用，2026-10-14。

**D91 本機版與公開版分兩份：`發佈/` 只放打開「公開」的日子，照片縮小、去掉中繼資料，網頁加 noindex。** 理由：心情、日記、照片是私人的，預設不外流；不公開的東西從來不會進任何要上傳的資料夾，不會一個不小心放上網路；照片的 GPS 會洩漏住處。沒選：全部公開；同一份網頁靠隱藏（原檔會跟著上傳）。代價：圖片存兩份；公開版要按「發佈」才更新。狀態：採用，2026-10-14。

**D92 上傳方式這一版不做，只留接口：「發佈」做到產生 `發佈/`、在 Finder 打開為止。** 理由：學校網頁空間怎麼上傳（SFTP、FTP、網路磁碟）還不知道；猜錯一種就白做。接口：`site.publish(root) -> 發佈資料夾`；之後加 `upload.py` 的一個函式，「發佈」做完產生就呼叫它。代價：第一版要人自己把 `發佈/` 放上去。狀態：採用，2026-10-14。

**D93（D88 修訂）小視窗的回去鈕：最上層剛好一個「行事曆」就回行事曆，否則照 D88 回主控面板。** 理由：老闆要行事曆當主控。代價：同時想要兩個的人只有一個鈕（主控面板在行事曆的「圖示面板」）。狀態：採用，2026-10-14。
