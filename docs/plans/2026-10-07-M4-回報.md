為了確定是什麼擋的，在不受保護的地方（session 的暫存資料夾）做同樣的 `探針TCC.app`，Python 腳本放在暫存資料夾，腳本去讀 `~/Documents` 裡的檔：

```
--- 從 .app 開（open 探針TCC.app）
pid=18450 ppid=1 exe=/Library/Frameworks/Python.framework/Versions/3.14/bin/python3
（讀 ~/Documents/6000_work/iplot/main.py 卡住 25 秒，被 alarm 結束，一行結果都沒有）

read OK   /Users/waiheng/Documents/6000_work/iplot/lib/webview/__init__.py (0.00s)
```

判讀：擋的是 macOS 的隱私權保護（TCC），不是 Gatekeeper。「文件」「桌面」「下載項目」這幾個資料夾，只有被允許的 App 讀得到；從終端機跑時算在終端機頭上（已經允許過），從捷徑 `.app` 開時算在那個 `.app` 頭上——它沒被允許過，所以讀的那一刻跳出系統的同意對話框（`UserNotificationCenter` 跑到最前面），沒人按就一直卡著；`.app` 本身放在「文件」裡那一次則是直接 `Operation not permitted`。iPLoT 放在這幾個資料夾裡時（這台就是），捷徑連 `run.py`、`lib/` 都讀不到。推測（沒驗）：每個捷徑是一個獨立的 App，第一次開各問一次；捷徑重做之後（換 Python、搬家）可能再問。

另一條路的機制驗過（沒驗 TCC 本身）：指令稿改用 `open -n -a <Python.app> --args <腳本> <參數…>`，腳本照樣收到參數，跑起來的身分是 Python 自己（`org.python.python`，PSF 簽名，TeamIdentifier `BMM5U3QVKW`），不是捷徑：

```
argv=['…/scratchpad/tcc/pyapp.py', '/some/模組 資料夾', 'x']
exe=/Library/Frameworks/Python.framework/Versions/3.14/Resources/Python.app/Contents/MacOS/Python
pid=18824 ppid=1
```

這條路如果成立，同意對話框是問「Python」一次、所有捷徑共用。選了這條路之後的驗證在 0.7 節。
