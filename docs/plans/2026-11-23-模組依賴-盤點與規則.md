# 模組依賴：盤點與規則建議（2026-11-23）

範圍：iPLoT `origin/main`（0.7.4）的 `core/`、`ui/`、`main.py`、`modules/` 全部 14 個隨附模組；iplot-modules `main` 上的 11 個模組（含別人上傳的「車車」、Angelina1114 的「linebot行事曆」）。只讀，沒改任何程式。逐檔的 import 清單是用 AST 腳本掃出來的（比交給 Gemini／ChatGPT 逐檔讀更快、也不會漏），判斷與核對是我自己做的，每一條都附了位置。

## 1. 結論

1. **William 的原則現在就有破口。** 工作坊在網頁面板裡會交給「互通」另開視窗。互通一壞，工作坊只說「在另一個視窗打開『工作坊』」，實際上什麼都沒開，也沒有錯誤訊息。跨版本測試沒有測到這條路。
2. **「互通」實際上是第二個核心。** 它有 20 處直接 import `core` 的內部，自己建 `Core`、自己做 `View`。行事曆、主控面板、開Terminal、重新啟動、linebot行事曆，還有工作坊、回報與討論，都經過它。docs/07 第 13 節把這些內部凍結「到 1.0.0 之前」，可是新設計的 1.0 正好就是把 `core/` 搬走的那一版。設計稿完全沒提第 13 節（D85）。
3. **有兩件「環境事實」被寫死在使用者的程式碼裡。** 一件是 `"core.runner" in sys.modules`（iPLoT 裡 13 個檔，iplot-modules 上別人上傳的車車、linebot行事曆也有），一件是 `"ui.web"`／`"ui.tk"` 在不在 `sys.modules`（3 處）。核心或面板只要換了載入方式，這些模組就會判斷錯，而且沒辦法從核心那一端修。
4. **規則模糊在三個地方。** 「模組只能用 `app`」和「工作坊模組可以用第 13 節的核心零件」兩種說法同時存在。模組依賴其他模組、依賴第三方套件、依賴哪一版核心，這三件事完全沒有規則。
5. **沒有任何檢查擋在模組這一側。** `test_boundaries` 只看 `core/`，`test_interfaces` 只釘核心那一端的簽名，不管模組實際用了什麼。iplot-modules 收件時只查 zip 結構與授權，不看 import。

沒有發現硬的 import 循環。模組之間沒有直接 `import` 別的模組，靠的是檔案路徑、名字字串和抄程式碼（見第 2 節）。

### 2.3 核心／面板 → 模組名字（寫死的）

- `core/text.py` L109–114：`BUNDLED`（11 個名字）、`SYSTEM_MODULE`、`REPORT_MODULE`
- `core/core.py` L153：`modules/作業系統`
- `ui/web.py` L152 L289 L301、`ui/tk.py` L147 L181、`ui/errlog.py` L65 L88：回報與討論
- `ui/errlog.py` L39–44：知道「科學計算」學生作業的資料夾長什麼樣子
- `core/core.py` L110 L201、`core/modify.py`、`core/bundled.py` L66：工作坊的 `.origin`、`.unconfirmed`

這些設計稿第 2 節大多已經列了，這裡不重複。

**「隨附」有三種定義，彼此對不上：** `core/text.py` 的 `BUNDLED` 有 11 個；`工作坊/workshop.py` L35 和 `互通/sync.py` L23 各有一份 3 個的 `BUNDLED`（作業系統、更新、工作坊）；iplot-modules 的 `registry.json` 只保留了 2 個（作業系統、更新）。

### 2.4 第三方套件

| 誰 | 套件 | 從哪來 | 有沒有退路 |
|---|---|---|---|
| 互通 popup.py L29–31 | `AppKit`、`PyObjCTools`、**`webview.platforms.cocoa`**（pywebview 的內部） | `lib/`（pywebview 6.2.1 拉進來的 pyobjc） | 沒有 |
| 互通 run.py L131 | `webview` | `lib/` | `boot.ensure_python` 先試過 |
| 主控面板、行事曆、互通 separate、linebot行事曆 | `AppKit`、`PyObjCTools` | `lib/` | 有，`except ImportError` |
| 科學計算、課程作業 | numpy、matplotlib… | 課程自己的 `.venv`，用 `REQUIRES` 宣告 | 有，設計好的 |

模組能用 pyobjc，只是因為面板剛好把 `lib/` 放上了 `sys.path`。這件事沒有寫在任何文件裡。0.9 把 pywebview 的安裝搬進 `modules/面板/` 時，這條路徑很可能會變。

### 2.5 版本依賴

只有互通會檢查核心版本（boot.py `MIN_CORE = (0, 5)`、`MIN_API = 3`），而且只擋下限（D151）。其他模組都不宣告自己需要哪一版，工作坊的清單也不分核心版本，全部照列。另外 boot.py 的 `iplot_home` 認 iPLoT 的方式是 `core/app.py` 和 `main.py` 都在，1.0 一定會認不得。

## 3. 問題，照優先順序

**P1 工作坊在網頁面板裡可能靜悄悄打不開（違反「任何版本都要能開」）。**
`互通/separate.py` L120–133 用 `Popen` 開 `run.py`，stdout 和 stderr 都丟到 DEVNULL，只要 Popen 本身沒丟錯就回 False。工作坊（iplot.py L80–92）只在「載入 separate.py 失敗」時退回自己開。所以 `run.py` 啟動之後才掛掉的情況，例如核心內部改了、`sync.py` 的頂層 import 失敗、1.0 時 `iplot_home` 認不得，工作坊都不會打開。只有 boot 階段的錯誤會在 macOS 跳 osascript 提示框，之後的錯誤完全沒有聲音。`tests/test_workshop_every_core.py` 是在 `ui.web` 不在 `sys.modules` 的情況下按的，所以 separate 這條路從來沒被跑過。另外遠端的 tag 只到 v0.7.2，這個測試也沒涵蓋 0.7.3／0.7.4。
修法（只動模組）：工作坊交出去之後，等最多約 5 秒，看另開的程序有沒有寫出工作坊資料夾的 `.pid`；沒有就在這裡開。再加一個測試：互通的 run.py 一啟動就丟例外，工作坊仍然要開。

**P2 互通凍結了核心內部，可是凍結的期限正好落在設計要打破它的那一版。**
D85 和第 13 節說「到 1.0.0 之前只加不改」；設計稿 1.0 要把核心搬進 `modules/核心/`，用檔案路徑載入，`import core` 就沒了。設計稿第 3.4 節的「問題 4」說工作坊只要寫在指令集 1 上就安全，可是它沒看到工作坊、行事曆、回報與討論都經過互通，而互通寫在核心內部上。互通要在 0.9 以前改成只用角色（自己提供 `app.page` 的另開版本，或提供 `page.separate`），不能留到 1.0 才處理。

**P3 「是不是在 iPLoT 裡」和「是哪一種面板」靠 `sys.modules` 裡的名字猜。**
`"core.runner" not in sys.modules` 出現在 iPLoT 的 13 個檔（8 個隨附模組、互通的 snippet.py、科學計算 4 個），iplot-modules 上的車車和 linebot行事曆也有，而且是互通用 sha256 凍結、寫進使用者自己模組的文字，沒辦法從核心那一端統一更新。核心改用別的模組名載入的話，每按一次模組都會被當成「直接執行」，改經互通另開。`"ui.web"`／`"ui.tk"`（主控面板 L48、互通 separate L121–122、回報與討論 report.py L57–60）在 0.9 面板搬出 `ui/` 之後會判斷錯。第 13 節把這兩件事列成「執行時的兩件事實」承諾，跟 0.9、1.0 的計畫直接衝突。
修法：把 `sys.modules["core.runner"]` 存在這件事當成永久義務，1.0 的核心模組載入時要放一個同名別名，CI 測它。面板種類改由面板提供角色（例如 `panel.kind`），舊的檢查保留一版過渡。

**P4 `SYSTEM_MODULE`（0.8 已處理，0.9 還卡著）。**
設計稿原本寫 0.8 要拿掉它。我已經通知做 0.8 的 thread，他們決定在 0.8 保留 `SYSTEM_MODULE`、`REPORT_MODULE`、`BUNDLED`，並把下面這四處列成 0.9 的前置條件：互通 sync.py L18、互通 iplot.py L82、行事曆 iplot.py L46、linebot行事曆 iplot.py L57。我也確認了 0.8 從 `T` 拿掉的鍵沒有任何模組在讀。

**P5 第三方套件是偷渡進來的。** 見 2.4。最危險的是互通 import pywebview 的內部模組 `webview.platforms.cocoa`：pywebview 一升版，互通就可能壞，P1 會跟著發作。

**P6 模組之間的依賴沒有宣告。** 行事曆和 linebot行事曆沒有互通就不能用，但工作坊的清單上看不出來，要按下去才會說「到工作坊裝互通」。

**P7 「隨附」三種定義。** 見 2.3。工作坊不覆蓋的、更新會換的、核心不准改名的，各是不同的一份名單。

**P8 沒有版本宣告。** 見 2.5。用到 `api_version` 4 才有的 `app.parent` 的模組，在 0.6 上會直接 AttributeError，清單上看不出來。

**P9 用抄程式碼代替依賴，但沒有明文。** `activate()` 有 4 份（主控面板、行事曆、互通 separate、linebot），`nav.js` 有 2 份（有測試釘住相等），`plain()`／`REASONS` 有好幾份。抄其實是對的（對方壞了自己不受影響），但要寫成規則，抄的地方要註明出處。

**P10 `scan.MARKER` 越過了第 13 節清單。** 很小，但這證明沒有人在檢查模組實際用了什麼。

## 5. 規則建議（每一條都能用 CI 檢查）

名詞先定好：**核心**是 `core/`，1.0 之後是 `modules/核心/`。**面板**是 `ui/`，0.9 之後是 `modules/面板/`。**模組**是其他所有東西，隨附的和工作坊來的一視同仁，差別只在白名單。

| # | 規則 | CI 怎麼查 | 現在的違規 |
|---|---|---|---|
| R1 | 模組只能 import 標準庫和自己資料夾（含子資料夾）裡的檔。不能 import、不能用檔案路徑或 `runpy` 載入別的模組的檔，也不能 `Popen` 別的模組的檔。要用別的模組的功能，0.8 起用角色（`app.call`／`providers`）。 | AST 掃 `Import`、`ImportFrom`；`spec_from_file_location`、`run_path`、`Popen` 的參數裡出現 `"modules"` 加另一個模組的名字就紅。現有的列進白名單，每一筆註明預定哪一版拿掉。 | 工作坊、回報與討論→separate.py；行事曆、linebot、各模組的「那一小段」→run.py |
| R2 | 模組 import `core.*` 只限一份**資料檔**上的名字（把第 13 節做成 `tools/contract.json`），而且只限名單上的模組。目標是 0.9 清到 0。 | 同一支掃描器比對 `from core.x import y` 和 `scan.<屬性>` 的用法；`test_interfaces.py` 也改讀同一份資料檔，兩邊就不會走樣。 | `scan.MARKER`；名單外沒有 |
| R3 | 不准用 `sys.modules` 的名字或固定路徑猜環境（`"core.runner"`、`"ui.web"`、`"ui.tk"`、`modules/互通/run.py`）。改問核心或面板提供的角色。核心永久保留 `sys.modules["core.runner"]` 這個別名，給已經寫進使用者程式碼的那一小段用。 | 字串常數掃描，新出現的就紅；另一個測試確認核心執行模組時 `"core.runner"` 在 `sys.modules` 裡（1.0 也要過）。 | 15 個檔加 3 處 |
| R4 | 第三方套件只能三種情況：一、在 `try/except ImportError` 裡，而且有退路；二、模組自己宣告 `REQUIRES`、自己裝（課程作業的做法）；三、面板自己。禁止 import 任何套件的內部模組（例如 `webview.platforms.*`）。 | AST 找非標準庫、非自己檔的 import，檢查它在不在 `Try` 節點裡，或模組有沒有 `REQUIRES`。 | 互通 popup.py L29–31 |
| R5 | 用名字找別的模組，或依賴某個角色才能用的模組，頂層要宣告 `NEEDS = ("互通",)`（0.8 之後改成角色名，例如 `NEEDS = ("page.separate",)`）。工作坊清單上顯示，安裝時一併提示。 | 程式碼裡（不含註解）出現別的模組名字的字串，或 `app.call("x")`，卻不在 `NEEDS` 裡，就紅。 | 行事曆、linebot、互通、工作坊、回報與討論 |
| R6 | 核心和面板不准出現任何模組的名字。過渡用的名字（`SYSTEM_MODULE`、`REPORT_MODULE`、`BUNDLED`）列在白名單上，註明哪一版拿掉。這是設計稿「核心裡不准有角色字串」的延伸。 | 掃 `core/`、`ui/` 的字串常數，比對 `modules/` 底下的資料夾名。 | 2.3 列的那些 |
| R7 | 工作坊特別條款：只能用 `app` 在 0.5 就有的五樣、標準庫和自己的檔。任何別的依賴都要可有可無，**交出去之後要確認對方真的開起來了，否則自己開**。 | 跨版本測試加三案：互通的 run.py 壞掉、互通不在、模擬網頁面板（`ui.web` 在 `sys.modules`）。TAGS 之外再加上目前的 HEAD 和正在做的核心分支。 | P1 |
| R8 | 用到 `api_version` 4 以後才有的 `app` 成員，要嘛用 `hasattr` 判斷，要嘛頂層宣告 `MIN_API = n`；工作坊在核心太舊時顯示「需要新版核心」，不給安裝。 | 掃 `app.<屬性>`，對照每個屬性是哪一個 `api_version` 加的（資料檔），沒宣告也沒 `hasattr` 就紅。 | 目前沒有，是預防 |
| R9 | 寧可抄也不要依賴：要別的模組的小工具，抄一份，註明出處和抄的那一版。 | 選做：像 `nav.js` 那樣測兩份相等。 | 建議成文就好 |
| R10 | iplot-modules 收件時跑同一支掃描器。維護者的模組違規就擋；別人上傳的只警告，警告寫在 issue 回覆和清單上。 | `tools/receive.py` 呼叫掃描器；`tools/iplot_rules.py` 已經是兩個 repo 共用一份的做法，照抄。 | — |

做法：一支 `tools/check_deps.py` 加上 `tests/test_module_deps.py`，第一次上線時把現在的違規全部列進白名單（每一筆寫好預定移除的版本），CI 只擋**新增**的違規。這樣不會一上線就全紅，0.8 期間也不會再多出新的耦合。
