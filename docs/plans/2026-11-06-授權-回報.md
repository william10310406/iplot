# 第四部分：複審後重做——機器人不解讀授權文字（兩個 repo 的 `license-mit`，已 push、未合併）

複審找到的：開頭的「版權行」可以夾帶任意條款（`COPYRIGHT_RE` 的 copyright、`(c)` 都能省略，行數沒有上限，可以放 bidi 字元）；黑名單沒列到的授權檔名照收（`LICENSE_GPL`、`LICENSES/`、`GPL-3.0.txt`、`NOTICE`、`EULA.txt`、全形、零寬空白）；改版時舊的版權行可以被拿掉（`place()` 先 rmtree，下一版不附 LICENSE 或附一份刪掉原作者的）。新原則：**機器人不解讀任何上傳者寫的授權文字。**

## 做了什麼

2. **LICENSE 由機器人產生。** `licensing.render()`：`"MIT License\n\n"` ＋每筆一行 `Copyright (c) <年份> <版權人>` ＋ `"\n\n"` ＋ MIT 全文；同樣的清單位元組一模一樣。新檔 `licenses.json`：`{sha256: [[年份, 版權人], ...]}`，每產生一份就加一筆（`write_in` 同一個 commit 寫、`git add`）。

## 偏離清單

1. **`.origin` 不是 JSON。** 指示說「它是 JSON」，但工作坊（`modules/工作坊/workshop.py` 的 `write_origin`／`read_origin`）寫的是一行一個「`key: value`」，網址在 `url:` 那一行，而且網址是 `%XX` 寫法（`iplot_rules.url`）。只讀 JSON 的話這一項永遠不會生效。我兩種都認：先試 JSON 物件的 `"url"`，不是的話找 `url: ` 那一行。有測試對著隔壁 iPLoT 的 `write_origin` 寫出來的檔讀（隔壁沒有 iPLoT clone 時 skip）。
2. **標準名字清單多了 `license`。** 指示列的是 `copying`、`licence`、`copyright`、`unlicense`；`license` 不在裡面（因為 `license`、`license.md`、`license.txt` 由機器人換掉）。我把 `license` 也放進基底，所以 `LICENSE-MIT`、`LICENSE.GPL`、`license.md.bak`、`LICENSE.docx` 也不收：這些是 GitHub 認得的授權檔名，放它們進來等於是舊黑名單想擋的那一件事。副作用：全形的 `ＬＩＣＥＮＳＥ`（NFKC 之後等於 `license`，但不是 ASCII）也不收。代價若不要：把 `STANDARD_BASES` 的 `"license"` 拿掉，再讓 `LICENSE` 資料夾單獨處理。
3. **資料夾也算最上層的名字。** 最上層叫 `licence/`、`copyright-notes/` 的資料夾也不收（`LICENSE/` 資料夾本來就不能收，不然機器人寫 LICENSE 時會衝突）。指示說「模組最上層」，沒分檔與資料夾，我取字面。
4. **年份也檢查。** 指示只列 id 與顯示名；年份若不查，手動改壞的年份欄一樣能把換行寫進 LICENSE。年份要是 1000–9999 的整數（不是 `True`）。
5. **`fork_of` 找得到的定義。** registry 有這一筆、不是保留名字（`reserved`）就算找到；下架（`removed`）的也找得到（版權人仍要保留）。找到但沒有 `copyright`（舊的、沒授權的模組，例如「車車」）：收，但不加任何人。
6. **聯集的順序**跟上一輪偏離 1 一致：registry 原本的清單在最前，上傳者在最後；中間是 LICENSE → `.origin` → `fork_of`。
7. **回覆的格式。** 版權人清單放在「略過的檔」之後、備註之前，單獨一段（標題一句＋程式碼區塊），不放在備註的條列裡（條列裡放多行程式碼區塊會被縮排弄壞）。每一份上傳都列，包括沒有 fork 的；原本的「模組裡沒有 LICENSE：已補上 MIT 的 LICENSE。」也一起拿掉了，標題那句取代它。
8. **兩句拒收的話改了。** `license_like`：照指示把建議改成「拿掉 `<檔名>` 再傳」，原本「用到別人的套件請寫在 REQUIRES…」那句從回覆拿掉（README〈授權〉還留著這個建議）。`license_unknown`：多一個出路（「或拿掉它、在表單填「改自工作坊的哪個模組」」），因為現在有 `fork_of` 了。README 拒收表同步。

## 探針 2：issue #20（沒勾授權）

用 `gh issue create --label 上傳` 開，內文照 #19 的格式，把「授權」整節拿掉。機器人回「要勾『以 MIT 授權公開』才能收；用表單重新開一個。」，標籤「上傳」＋「沒收」，issue 已關（not_planned）。

**偏離：** 指示是「不附 zip」。`gh.form_refusal` 的順序是先看有沒有 zip（`no_zip`），再看確認、再看授權，所以內文完全沒有 zip 連結的話，回的會是「沒有附 zip」，探不到授權那一格。我把 #19 內文裡的同一行 zip 連結留著（沒有新上傳任何檔），授權的檢查在下載之前，所以不會真的下載。
