## 2. 壞了但沒說哪裡壞

### 2.1 擋發佈：文字型作業在 iPLoT 裡什麼都看不到

- **情境**：一門新課，老師寫一份只回文字的作業（`draw = None`，`REQUIRES = []` 或沒有 matplotlib；`docs/09` 第 2 節明說「純文字作業就只回 text」）。雙擊那一格 → 問「這門課的 .venv 還沒建：要建在 …嗎？HK1 沒有要裝的套件」→ 確定 → 訊息區「HK1：case-1 的視窗開了（在 Dock 上找 Python）」→ **沒有任何視窗**。範例課程的 HK8 一樣：先按 HK8（還沒按過 HK2／HK6）就是這樣；人工驗收 M10 寫的順序是 HK2 → HK6 → HK8，所以 M10 剛好不會踩到。
- **為什麼**：`CW_FROM_IPLOT` 時殼把文字放進 matplotlib 的視窗（`coursework.py:309-320`、`360-364`）；課的 `.venv` 只裝了這份作業的 `REQUIRES`（`course.py:520`、`561-598`），沒有 matplotlib → `ModuleNotFoundError` → 被 `except Exception` 接住再開一次文字視窗又失敗（`386-387`）→ 沒印 `SHOWN_MARK` → 結束碼 1 → 框架 `_watch` 用同一個 `.venv` 跑 `coursework.py --show-text`（`type.py:139-145`）→ 又是 `ModuleNotFoundError`，這次的 stderr 沒人讀。D142 的「代價」有寫到「課的 `.venv` 沒有 matplotlib 時開不了文字視窗」，但沒有把它當成要修的。
- **重現**：`python3 -m venv <暫存>/v`（不裝東西）；`CW_FROM_IPLOT=1 PYTHONPATH=<作業類型/算完畫圖> <暫存>/v/bin/python HK8.py --case case-1` → 印完結果後 `ModuleNotFoundError: No module named 'matplotlib'`，結束碼 1。
- **建議**：殼是 iPLoT 裡顯示的工具，它自己要的套件要由框架裝。最小改法：`type.py` 加 `SHELL_REQUIRES = ("matplotlib",)`，`_press` 把它併進 `need`（`course.py:520`），`course_button` 的聯集也併；或殼在 `CW_FROM_IPLOT` 且 import matplotlib 失敗時改用 tkinter 的文字視窗當後路（R13 擋的是作業檔，殼可以用 tk）。兩種都不碰 core/、ui/。

### 2.2 應修：課的 `.venv` 壞掉——課那一格整段 traceback，作業那一格指錯檔

- **情境**：老師把建 `.venv` 時用的 Python 移掉或換版（例如 python.org 3.13 升 3.14 後把 3.13 解除安裝；一個學期內很常見），`<課>/.venv/bin/python` 變成斷掉的連結或跑不起來。
- **看到的**：
  - 課那一格（`course.py:384-406`）：`missing()`／`install()` 的 `Popen` 丟 `FileNotFoundError`，`course_button` 沒接 `OSError` → 面板上是整段 Python traceback。
  - 作業那一格：`homework_button` 接住 `OSError`（`course.py:500-501`），但句子是「HK1：讀不了 HK1.py（No such file or directory），沒跑」——指到作業檔，其實壞的是 `.venv/bin/python`。
  - 連結斷掉時更糟：`venv_python` 回 `None`（`is_file()` 對斷掉的連結是 False），框架以為沒建 → 問一次 → `python -m venv` 蓋在舊資料夾上，結束碼 0 **但不會修好斷掉的連結**（實測）→ 接著 `install` 又 `FileNotFoundError`。每次按都重來，老師沒有出路。
- **建議**：`venv_python`／`ensure_venv`（`course.py:230-254`）看到 `exe.is_symlink() and not exe.exists()`，或 `missing`／`install`／`popen` 丟 `OSError` 時，一句「<課>/.venv 用的 Python 已經不在（或跑不起來）：把 <課>/.venv 丟進垃圾桶再按一次」；`course_button` 也包同一層 `except OSError`。

## 4. 打包與路徑安全

讀了 `type.pack`、`_space`（`type.py:162-192`）、`_write_zip`（`course.py:622-637`）、`check_and_pack`，並真的打了幾個包看 `namelist()`。

- **zip 裡的路徑**：第一層固定 `<代號>/`，成員是 `<代號>.py`、`coursework.py`、`<代號>Space/…`、`README.txt`；Space 底下的路徑用 `relative_to(作業資料夾).as_posix()`，全是相對的，沒有 `..`、沒有絕對路徑。實測一個包：`['HK1/HK1.py', 'HK1/HK1Space/', 'HK1/HK1Space/資料.csv', 'HK1/README.txt', 'HK1/coursework.py']`。
- **連結**：Space 本身是連結 → 放一個空的 `<代號>Space/`，說一句；Space 裡的連結（檔或資料夾）→ 不跟、不放、列名字（實測 `link -> /etc/hosts` 被列出、不在包裡）。`.` 開頭、`__pycache__` 不放。只有 2.5.3 的 FIFO 那種默默不放。
- **會不會把老師機器上的東西打進去**：README 只有佔位代換（代號、六個指令常數），殼 `coursework.py` 是正本原 bytes、裡面沒有路徑；`.版本/`、`.venv/`、`iplot.py`、`發出去的/` 都不在清單裡。剩下唯一會帶私人路徑的是**作業檔本身的內容**：R20 只擋字串常數，老師在註解或 `NOTE` 裡寫了 `/Users/<帳號>/…` 會原樣進包；N3 只在驗收腳本裡掃範例課程，「檢查與打包」時不掃。**可留**：打包時掃一次 `Path.home()`、`getpass.getuser()`，有就 ⚠ 一句（不擋）。
- **檔名編碼**：`ZipInfo.flag_bits |= 0x800`，中文檔名帶 UTF-8 旗標（測試有核對）；Windows 10 以後的檔案總管認這個旗標。NFD／NFC：macOS 上以 NFD 存的名字（韓文、越南文、帶重音的拉丁字母）會照 NFD 進包，Windows 解開後看起來一樣但 bytes 不同；中文沒有這個問題。**可留**，記著。
- **寫 zip 的方式**：先寫 `.tmp` 再 `os.replace`，第二次打包蓋掉前一份；`.版本/` 那份 `copyfile` 同 bytes。例外時 `.tmp` 留著（2.5.2）。

結論：沒有找到會把老師的私人路徑或檔案打進學生包的路徑，前提是老師自己的作業檔裡沒寫。

## 6. M5：視窗在最前面——不改 core/、ui/ 的做法

**先弄清楚事實**（這次查到的）：
- matplotlib 3.11.2 的 macosx 後端 `FigureManagerMac.show()` 在 `rcParams["figure.raise_window"]`（預設 True）時呼叫 `_raise()`，裡面是 `activateIgnoringOtherApps:` 加 `makeKeyAndOrderFront:`。所以殼現在**已經**在要求跳到最前面，回報 Task 16 之後從終端機量到約 1 秒就到前面，跟這個一致。
- 還沒量過的：從真的 pywebview 面板按下去（父程序是 iPLoT）。「殼跑出來的 matplotlib 視窗不會跳到最前面」這件事在這份審查裡沒有重現，也沒有反證。
- 框架的程式跑在面板的工作執行緒（`ui/web.py:209` 的 `_work`），不是主執行緒；iPLoT 的 `lib/` 有 pyobjc（pywebview 的 cocoa 後端要的）；課的 `.venv` 是 python.org 的 framework build 時，`bin/python` 最後執行的是 `…/Versions/3.14/Resources/Python.app` 裡的二進位（Dock 上那個「Python」），`.venv/pyvenv.cfg` 的 `home` 可以推到它。

**做法，照建議的順序**：

| | 做法 | 改哪裡 | 風險 |
|---|---|---|---|
| A | **先量**：從真的面板按 HK1，用回報 Task 16 的 `lsappinfo` 探針每 0.5 秒讀最前面的程式 | 不改程式 | 沒風險。量出來本來就會到前面，M5 就不用改；量出來不會，才看是哪一種：視窗沒出現、出現在後面、還是出現了又被 iPLoT 蓋回去 |
| B | **殼裡再 raise 一次**：`plt.show()` 之前掛一個單次 timer（`fig.canvas.new_timer(interval=300)`，`single_shot=True`），callback 用 `getattr(fig.canvas.manager, "_raise", None)` 再叫一次。針對的是「事件迴圈還沒跑起來之前的 activate 被系統丟掉」這種常見狀況 | 只改 `coursework.py` 的 `_show_text` 與 `main` 畫圖那段 | `_raise` 是私用名（用 `getattr` 守，沒有就不做）；只在 `sys.platform == "darwin"` 且後端是 macosx 時掛；Agg（測試）下 timer 不會跑，測試只能驗「有掛」。如果問題是 macOS 的合作式啟動拒絕背景程式，這招沒效 |
| C | **框架用 `open -a` 叫到前面**：`_watch` 執行緒在子程序開始後，從 `.venv/pyvenv.cfg` 的 `home` 推出 `…/Resources/Python.app`，`subprocess.run(["open", "-a", 那個 .app])`。LaunchServices 的啟動不需要 TCC「自動化」權限、不用 pyobjc | 只改 `course.py` 的 `_watch`（或 `_press` 之後） | 只對 framework build（python.org、Homebrew）有效；時機要猜：matplotlib 還沒建 NSApp 時 `open -a` 會另開一個空的 Python.app 實例，要等（例如子程序 stderr 出現第一行、或固定 1–2 秒、或輪詢 `lsappinfo`）；同時跑兩份作業時叫的是同一個 bundle，哪一個到前面不確定 |
| D | **框架用 pyobjc**：`NSRunningApplication.runningApplicationWithProcessIdentifier_(pid).activateWithOptions_(…)`，macOS 14 起另有 `NSApp.yieldActivationToApplication_`（由最前面的 iPLoT 讓出啟動權，是蘋果現在要的做法） | 只改 `course.py` | AppKit 要在主執行緒，框架在工作執行緒；tk 後備面板沒有 pyobjc；違反「框架只 import 標準庫」；Windows／Linux 要分支。不建議第一版做 |
| E | `osascript -e 'tell application "System Events" …'` | 殼或框架 | 第一次跳 TCC「自動化」的框，可能被拒；殼在學生機器上也會跑到。不建議 |

**建議**：A → B → C。B、C 都不碰 core/、ui/，也不改學生看到的行為（B 在學生自己跑時也會多 raise 一次，無害）。訊息區那句「在 Dock 上找 Python」照舊當後路。
