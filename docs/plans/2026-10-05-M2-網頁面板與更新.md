# M2 網頁面板與更新：圖示面板（pywebview）、第一次啟動自動安裝、更新與工作坊（0.4.0、0.5.0）

> **給執行者：** 這份檔案前半（「全域限制」「設計」）是規格，後半是 Task 清單。Task 清單在規格核可後才補上；補上之前不要動手。做法沿用 M1.4：用 superpowers:executing-plans 逐個 Task 做，每個 Task 先寫失敗的測試、看到紅、再寫程式、看到綠、commit。步驟用 `- [ ]` 追蹤。

**目標（0.4.0，M2）**：面板從 tkinter 的按鈕清單換成圖示格，照 macOS／Windows 的操作習慣：單擊選取、雙擊執行、右鍵選單、圖示有顏色有個性。面板用 HTML/CSS/JS 寫，在 pywebview 開的原生視窗裡跑；pywebview 在第一次啟動時自動安裝到 `lib/`。核心邏輯不動，模組的寫法不動（`app` 只少一個 `window`）。樣稿：`https://claude.ai/artifact/HCVNzSkLxt4J1DwcUaq1a6`（互動版，動作都是模擬的；它就是 `ui/index.html` 的第一版）。

**目標（0.5.0，M3）**：更新核心不碰使用者的東西；模組可以像外掛一樣從一個索引下載、更新，裝進來的東西不會蓋掉自己做的。本檔第 13 節只定方向與不變量，Task 另開一份計畫。

**架構**：`Core` 與 `View` Protocol 不變（`View` 少一個 `window`）。新的 `ui/web.py` 實作 `View`：把 `show／log／report／ask` 翻成對網頁的呼叫，把網頁送來的動作排進單一工作執行緒交給 `Core`。原 `core/ui.py` 搬到 `ui/tk.py`，只在安全模式、或網頁面板開不起來時出現。這是 Jupyter 的架構：Python 在後面、網頁是臉；差別是沒有 server，JS 直接呼叫 Python（pywebview 的 `js_api`），沒有 port、沒有 CSRF、不需要網路。

**技術**：Python ≥ 3.10 加 pip（任何來源，Homebrew 的也可以；tkinter 不再是必要的，只有安全模式需要它）；pywebview（第一次啟動裝進 `lib/`）；HTML/CSS/JS 不用框架、不用 build、零外部資源；開發端 pytest、ruff。

**規格**：本檔「設計」一節。Task 把它寫回 `docs/02_重構設計.md`（v2.0）、`docs/03_設計決定.md`（D61–D70）、`docs/06`、`docs/07`、`docs/api.md`、`README.md`、`CHANGELOG.md`。前文：`02` v1.2、`03` D01–D60。

**來源**：2026-10-05 的設計討論。先把 `m1.4-boundaries` 以 `--no-ff` 合回 `main`、tag `v0.3.0`（人工驗收 (a)–(f) 已過），再從 `main` 開分支 `m2-panel`。`modules/test*` 四個未追蹤的草稿留在原地。

## 全域限制

- Python ≥ 3.10。**Python 端只用標準庫，加上 `lib/` 裡釘死版本的 pywebview**（D61、D62）。`core/` 一行都不能 import `lib/` 的東西；只有 `ui/web.py` 可以。
- UI 層（`ui/index.html`、`ui/app.js`、`ui/style.css`）**不准出現任何外部網址**：沒有 CDN、沒有網路字型、沒有函式庫；`tests/test_boundaries.py` 用 grep 擋 `http://`、`https://`。
- 預算（`tests/test_budget.py`，D68）：核心邏輯（`core/` 扣掉 `text.py`）≤ 500 有效行；`ui/web.py` ≤ 220（2026-10-05 由 200 調到 220：M3 的 `page` 5 行，日後關閉前確認 8 行）；`ui/tk.py` ≤ 180；`ui/install.py` ≤ 80；`ui/index.html` ≤ 120；`ui/app.js` ≤ 400；`ui/style.css` ≤ 300。做之前核心邏輯 479。**超過就停下來回報，不要調預算。**
- `core/`（`text.py` 除外）、`ui/*.py`、`main.py` 不寫中文字串常數（D32）；所有畫面文字在 `core/text.py`，網頁啟動時由 Python 整份送進去（§7）。
- `core/*.py` 原始碼不得出現 `subprocess`、`sys.platform`、`os.name`、`startfile`、`ctypes`（M1.4 的規則，照舊）。`ui/install.py` 可以用 `subprocess`（跑 pip），一律列表形式、不經 shell。
- `exec` 只在 `core/runner.py`；`except Exception` 只在 `runner`、`load_config`，以及 `ui/web.py` 的工作執行緒迴圈（第三處，`# noqa: BLE001`，`07` 的說法同步改）。
- `app.api_version` 1 → 2（拿掉 `window`，D66）；核心版本 0.3.0 → 0.4.0。
- 文件寫給一般讀者，不出現「您」，不稱呼特定的人。每個數字對著 repo 核。
- 分支 `m2-panel`；做完 `git merge --no-ff` 回 `main`、tag `v0.4.0`；沒有遠端，不 push。
- Windows 沒有機器可驗：`requirements/web-win.txt` 與 `win.py` 的新函式只用假的呼叫驗；文件一律標「未經實機驗證」。Linux 的網頁面板延後（§8），用 `--safe`。

## 審查焦點

規格沒明說、但一般人一用就會踩到的六件事，各釘一個測試：

1. **第一次啟動沒網路**：主控台一句白話說要連網、怎麼再試，程序以代碼 1 結束，沒有 traceback → `tests/test_install.py::test_install_fails_offline_with_plain_message`。
2. **`lib/` 在、但 import 壞掉**（裝到一半被中斷）：重裝一次；再壞就退到 tk 面板並把原因寫進訊息區 → `tests/test_main.py::test_broken_lib_reinstalls_then_falls_back`。
3. **模組執行中連按兩次、或按別的模組**：工作執行緒一次只做一件，第二件排隊，面板不凍、不重入 → `tests/test_web.py::test_jobs_run_one_at_a_time`。
4. **模組 `input()` 時使用者關掉視窗**：等待中的 `ask` 收到 None，模組拿到 EOFError，程序正常結束 → `tests/test_web.py::test_close_window_cancels_pending_ask`。
5. **icon.png 壞掉或超過 1 MB**：忽略、用預設圖示、訊息區記一行，不影響其他模組 → `tests/test_web.py::test_bad_icon_falls_back`。
6. **面板上的模組在檔案總管被刪掉後雙擊**：不是 traceback，重掃、圖示消失 → `tests/test_web.py::test_press_missing_module_rescans`。

## 設計

### 1. 決定（寫進 `docs/03`）

**D61 UI 層可以用 HTML/CSS/JS；Python 端仍只用標準庫加 `lib/` 裡釘死版本的套件。**
理由：要「圖示有個性、介面有現代感」，tkinter 的上限是 2010 年的 Finder，自己用 Canvas 畫 400–600 行也到不了；CSS 一行就有圓角、hover、深色模式。核心（`core/`）一行不變，原則 1、2、3 都不受影響：面板只是顯示器。
沒選：留在 tkinter（上限太低）；PySide6（一兩百 MB，API 巨大）；http.server 加瀏覽器（打開是分頁不是視窗、要管 port 與 CSRF）。
代價：UI 層兩種語言；前端沒有自動測試，靠人工驗收（§11）。
狀態：採用，2026-10-05。推翻 `02` §1「全部 Python」。

**D62 取消零安裝：第一次啟動自動把需要的套件裝進 `lib/`。**
理由：零安裝只剩兩條路（tkinter、瀏覽器），都達不到要的介面。裝進 iPLoT 自己的 `lib/`，不碰系統的 Python；拖進垃圾桶整個消失，「可移除」不變。
沒選：要求使用者先 `pip install`（裝不起來的人正是最需要照顧的）；裝進系統 site-packages（權限、污染）。
代價：第一次啟動要網路、要等（macOS 約幾十 MB）；pip 壞了要有白話的出口（§8）。版本釘死；**hash 釘死延後**——wheel 的 hash 依 Python 版本不同，要列所有支援版本的 hash 才能用 `--require-hashes`，等有需要再做。
狀態：採用，2026-10-05。`02` §1 的「零安裝」改成「第一次啟動自動安裝」。

**D63 面板用 pywebview 開原生視窗；tkinter 面板降級為安全模式與後備。**
理由：pywebview 用 macOS 內建的 WebKit，打開就是一個叫 iPLoT 的視窗，不是瀏覽器分頁；JS 直接呼叫 Python，不用 server。tk 面板只有 118 行，留著當 `--safe` 和「網頁面板開不起來」的出口，成本低。
沒選：Chrome 的 `--app` 模式（沒裝 Chrome 的人沒有）；Safari「加入 Dock」（要手動一次、網址要固定）。
代價：模組不能再靠 tkinter 開自己的視窗（主執行緒被 Cocoa 佔走）；模組要有畫面的做法是 M3 的 `app.page`（§13）。Windows 要 WebView2 runtime（Windows 11 內建）；Linux 延後。
狀態：採用，2026-10-05。

**D64 單擊選取、雙擊執行；推翻 D13。**
理由：照 macOS／Windows 的習慣；單擊就執行等於一按錯就跑程式。單擊選到的模組，說明顯示在下方狀態列，`description` 第一次有地方顯示。
沒選：維持單擊執行（D13）。
代價：多一個動作；右鍵選單要多「執行」。
狀態：採用，2026-10-05。D13 狀態改「推翻，見 D64」。

**D65 圖示來源的順序：模組資料夾裡的 `icon.png` 或 `icon.svg` → `iplot.py` 頂層的 `ICON = "🧩"` 常數 → 名字第一個字、顏色由名字決定。**
理由：資料夾放圖檔跟 autostart 標記同一種思路，Finder 看得到、滑鼠拖得進去；`ICON` 常數跟 `TITLE` 一樣用 ast 讀，零成本就有一個 emoji；預設圖示是最重要的那一個——每個新模組一開始都沒有圖示，預設如果是灰方塊，活力就死在最需要的地方。HyperCard 1987 年的按鈕就有「Icon…」對話框從圖庫挑圖示。
沒選：只支援圖檔（新模組全是灰的）；由面板隨機配色（同一個模組每次顏色不同）。
代價：掃描多讀一個檔名；`ModuleInfo` 多兩個欄位。
狀態：採用，2026-10-05。

**D66 拿掉 `app.window`；`api_version` 1 → 2。**
理由：沒有 tk 主視窗了；grep 過，沒有任何隨附或草稿模組用到它。「介面只加不減」在這裡破一次，趁沒人用的時候。
沒選：保留並回傳 None（騙人的介面）；回傳 pywebview 的 window（把模組綁死在另一個套件上）。
代價：api_version 升到 2，CHANGELOG 要寫清楚。
狀態：採用，2026-10-05。

**D67 面板的「選檔案」「選資料夾」用 pywebview 的原生對話框。**
理由：瀏覽器的檔案選擇拿不到真實路徑，pywebview 的 `create_file_dialog` 是原生的 NSOpenPanel，回路徑。不走作業系統模組：這是面板的事，不是模組的事。
沒選：osascript 的 `choose file`（多一層）；在網頁裡自己做檔案瀏覽器（重做一個 Finder）。
狀態：採用，2026-10-05。

**D68 預算改寫：核心邏輯 ≤ 500 不變；UI 另訂（見全域限制）。**
理由：原則 2 靠「讀得完」成立。核心仍然一個下午讀得完。UI 變成兩種語言、六個檔，各自訂上限，總量比原來的 150 行多很多，這是 D61 的代價，寫明白。
沒選：UI 不設預算（會長成一個普通網頁 app）。
狀態：採用，2026-10-05。D48 狀態改「修訂，見 D68」。

**D69 更新只換 `core/`、`ui/`、`main.py`、`requirements/`；永遠不碰 `config.py`、`custom.css`、`modules/`、`logs/`、`lib/`，也不碰 iPLoT 資料夾以外的任何東西；換之前先備份，換的時候先解到暫名再改名交換。**（M3）
理由：「更新核心不動到使用者做的東西」是已確認的需求。使用者的東西全在那四個以外。改名交換是為了中途當機也不會留下半套的 `core/`。
代價：隨附模組在 `modules/` 裡，更新也不碰它們；它們的新版走工作坊（D70）。
狀態：採用為原則，2026-10-05；實作在 M3（§13）。

**D70 模組的下載與更新由隨附模組「工作坊」做；索引是一個 JSON；來源記在模組資料夾的 `.origin`；覆蓋前整個資料夾存進 `.history/`。**（M3）
理由：原則 1——模組的商店也是模組。Steam 工作坊的做法：訂閱、更新、不碰存檔。
狀態：採用為方向，2026-10-05；實作在 M3（§13）。D59 從「延後」改「M3 採用」：工作坊裝的模組第一次執行前確認。

另外修訂：**D15** 單一視窗不變，「單一欄」改「格狀」；**D14** ＋ 每一組一顆不變，從標題列搬到該組最後一格；**D60** 照舊（▸ 只有有子模組的才有；第一個子模組靠右鍵）；**D56** 仍延後（執行緒變了，但模組仍在程序內執行）；**D11** 不變（視窗取得焦點就重掃，改由 JS 的 `focus` 事件觸發）。

### 3. 啟動流程（`main.py`）

```
python3 main.py [--safe]
 1  版本檢查（不變：< 3.10 印 need_python，結束）
 2  sys.path 前面加 home/lib
 3  --safe  → ui.tk.Panel（只掃 modules/）；沒有 tkinter 就印 T["no_tk"] 結束。到此為止
 4  嘗試 from ui.web import WebPanel（裡面 import webview）
      成功 → WebPanel + Core → panel.run()（webview.start 佔主執行緒）→ 視窗關掉就結束
 5  失敗、而且 lib/.installed 不存在或內容不等於目前 requirements 檔的 sha256
      → ui.install.install(...)：主控台印 T["installing"]（第一次啟動、正在安裝介面、大約多大、要網路）
        pip 一行行印進度；成功 → 寫 lib/.installed → os.execv 重啟自己（乾淨的程序，tk 與 Cocoa 不同時存在）
        失敗 → 印 T["install_failed"]（原因、再試一次的方法、安全模式怎麼開）；
                有 tkinter → 開 ui.tk.Panel 並把原因寫進訊息區；沒有 → 代碼 1 結束
                （2026-10-05 定：這個後備面板不是安全模式，掃完整範圍——上一層與 ROOTS；只有 --safe 才只掃 modules/）
 6  失敗、而且 lib/.installed 對得上（裝過但壞了）→ 刪 lib/.installed，回到 5 再裝一次；再失敗照 5 的失敗處理
```

雙擊 `iPLoT.command` 時 Terminal 視窗本來就會開著，第一次啟動的進度就印在那裡；之後每次啟動 Terminal 視窗只閃一下（跟現在一樣）。`main.py` 不 import tkinter，除非走到 3 或 5 的後備。

### 4. `ui/web.py`：WebPanel 與橋

- **視窗**：`webview.create_window(T["title"].format(version=…) + 安全模式字樣, url=<home/ui/index.html>, js_api=Bridge(...), width=820, height=620, min_size=(480, 420))`；`webview.start()`。視窗關掉 `start()` 回傳、`main()` 結束。`重新啟動` 模組的 `os.execv` 照常可用。
- **工作執行緒**：一條 `threading.Thread`（daemon），`queue.Queue` 排工作。Bridge 的方法（§附錄 B）只把工作排進去、立刻回傳；`state()` 例外，直接回目前的 scope；`answer()` 例外，直接喚醒等待中的 `ask`。一次只做一件（審查焦點 3）。迴圈裡沒接住的例外 → `core.report_internal(type(e), e, e.__traceback__)`，迴圈繼續。
- **View**：
  - `show(scope)` → `window.evaluate_js("iplot.show(" + json + ")")`（形狀見附錄 A）。圖示在這裡解析成字串（§6）。
  - `log(text)`、`report(error)` → `iplot.log(...)`、`iplot.report(...)`。`report` 送整個 `ErrorInfo` 加 `describe(error)` 那一句，白話與 traceback 分開，由頁面決定怎麼排。
  - `ask(prompt, default)` → 配一個遞增 id，推 `iplot.ask(id, prompt, default)`，在 `threading.Event` 上等；JS 呼叫 `answer(id, value)` 給字串或 null。視窗關掉時（`window.events.closing`）所有等待中的 ask 都收到 None（審查焦點 4）。
  - `choose_files()`、`choose_folder()` → `window.create_file_dialog(...)`（D67）；取消回 `[]`／`None`，跟現在一樣。
  - `confirm(prompt) -> bool`（`View` 新增的第七個方法，`app.confirm` 對應；M3 的 D59 用它）→ 面板內兩顆鈕的對話框，走跟 `ask` 一樣的 id／`answer` 機制，值是 true／false。tk 面板用 `messagebox.askokcancel`。
- **頁面載入完成**（`window.events.loaded`）→ 推 `iplot.init(T, version, safe)`，再 `core.rescan()`。
- **模組的身分**：JS 拿到的每個模組有 `id` = 資料夾絕對路徑字串。Bridge 用 `core.all_modules()` 找回 `ModuleInfo`；找不到（被刪了）就 `core.rescan()`、不報錯（審查焦點 6）。
- **重掃**：JS 在 `window` 的 `focus` 事件呼叫 `api.rescan()`（D11）。
- **執行緒與核心**：`Core` 不知道執行緒的存在，所有對 `Core` 的呼叫都在工作執行緒上；`Core.press` 的 `_depth／_pending` 機制照舊有效。

### 5. 面板行為（`index.html`、`app.js`、`style.css`）

以樣稿為準，差異處以本節為準：

### 8. 安裝（D62）

- `requirements/web-mac.txt`：`pywebview==<版本>` 與它在 macOS 的依賴（pyobjc 的幾個 framework 套件），全部釘死版本；在開發機上用 `pip install --target` 裝一次、`pip freeze --path` 取版本。`requirements/web-win.txt` 同樣寫法（pythonnet 等），標未經實機驗證。Linux：pywebview 需要系統層的 GTK／WebKit2GTK，pip 裝不了，這一版 Linux 只用 `--safe`，`README` 寫明。

### 13. M3：更新與工作坊（0.5.0）

這一節是 M3 的完整設計，Task 在實作計畫的第二部分。**平常使用不需要網路**：更新與工作坊只在使用者按下時連網；來源網址沒設定時，兩個模組各說一句怎麼設定，其他功能不受影響。要不要接上網路，是使用者（或替他設定的人）填不填 `config.py` 那兩行的事。

**13.1 設定與 `app`（`api_version` 2 → 3，只加）**
- `config.py` 多兩行：`UPDATE_URL = None`（`update.json` 的網址）、`WORKSHOP_URL = None`（`index.json` 的網址）。`Config` 多兩個欄位（預設 `None`）；`load_config` 驗型別：`None` 或 `str`，不對就整份用預設值並回報（跟 `ROOTS` 一樣）。
- `app.config -> Config`（唯讀）、`app.version -> str`（核心版本）、`app.page(title, html, api=None) -> None`：開第二個 pywebview 視窗顯示 `html`，`api` 的公開方法給那一頁的 JS 用 `pywebview.api.<方法>` 呼叫；視窗關掉才回傳（像對話框）。安全模式的 tk 面板沒有這個能力：`page` 在訊息區記一行 `page_unsupported` 就回傳。`View` 多第八個方法 `page`。
- D59 採用：`Core.press` 在存快照之前，若 `info.folder / ".unconfirmed"` 存在，先 `view.confirm(T["confirm_foreign"])`；按取消就記一行 `cancelled`、回 `Result(False, None, 0.0, "")`，不執行；確定就刪掉標記再照常執行。標記是空檔案，跟 autostart 同一招（D16），核心不用解析任何格式。核心邏輯預計 +6 行。

**13.2 更新（隨附模組 `modules/更新`，`ICON = "⬆️"`）**
- `UPDATE_URL` 指到一個 `update.json`：`{"version": "0.5.1", "zip_url": "…/iPLoT-v0.5.1.zip", "sha256": "…", "notes": "這一版改了什麼"}`。zip 就是交付用的那一個（`git archive`，最上層 `iPLoT-vX.Y.Z/`）。
- 按「更新」：沒設網址 → 一句話說在 `config.py` 填 `UPDATE_URL`。抓 json；版本不比現在新 → 「已是最新（x.y.z）」。比較新 → `app.confirm` 顯示版本與 `notes`；確定 → 下載到 `.backup/download-<版本>.zip`、驗 sha256（不符就刪掉、一句話、什麼都不動）；把目前的 `core/`、`ui/`、`main.py`、`requirements/` 複製到 `.backup/<舊版本>-<日期時間>/`；zip 解到 `.update-tmp/`，四樣各先放到 `<名稱>.new` 再改名交換；清掉暫存；訊息區「已更新到 x.y.z，按『重新啟動』」。
- 不變量（`tests/test_update.py`，tmp 裡假的 iPLoT 與假的 zip，`file://` 網址）：更新前後 `config.py`、`custom.css`、`modules/`（含 `.history/`）、`logs/`、`lib/` 逐位元組相同，iPLoT 資料夾以外沒有任何寫入；`.backup/` 裡有舊版四樣；換上的四樣與 zip 一致；sha256 不符一個檔都不動；`.update-tmp/` 做完不存在。
- 不是熱更新：換完要按「重新啟動」；`app.memory` 清空，檔案都在。下一次啟動若 `requirements/` 變了，§8 的機制自動重裝 `lib/`（要網路）。
- 使用者觸發，不自動；網路錯誤、json 缺欄位都是一句白話，不是 traceback。不做：差異比較、回溯到任一版（`.backup/` 用手搬回去就是回溯，README 寫一段）。

**13.3 工作坊（隨附模組 `modules/工作坊`，`ICON = "🧰"`）**
- `WORKSHOP_URL` 指到一個 `index.json`：`{"modules": [{"name": "整理桌面", "version": "1.0.0", "zip_url": "…/整理桌面.zip", "sha256": "…", "description": "一句話", "icon": "🧹"}]}`。每個 zip 最上層是 `<name>/`，裡面是模組資料夾的內容（不含 `.history/`、`.origin`、`.unconfirmed`、`__pycache__`）。
- 來源記錄 `modules/<name>/.origin`，一行一個 `key: value`：`url`、`version`、`sha256`（zip 的）、`digest`（安裝完當下資料夾內容的摘要）、`installed`（日期時間）。`digest` = 依相對路徑排序後，把「路徑＋內容」逐一餵進 sha256，略過 `.history/`、`.origin`、`.unconfirmed`、`__pycache__`。
- 每個索引項目的狀態：`absent`（`modules/<name>/` 不存在）、`installed`（有 `.origin`、版本相同、digest 相同）、`update`（索引版本較新、digest 相同）、`modified`（digest 跟 `.origin` 不同，不管版本）、`unknown`（資料夾在但沒有 `.origin`：使用者自己建的同名模組，或 0.5.0 之前的隨附模組）。
- 按「工作坊」：沒設網址 → 一句話。抓索引，`app.page` 開一頁：每個項目一列，名稱、說明、索引版本、本機狀態（中文）、一顆按鈕（`absent` → 安裝；`update` → 更新；`modified`／`unknown` → 覆蓋，按了先 `confirm`「這會覆蓋現有的『X』，舊版會整個存進 .history/」；`installed` → 沒有按鈕）。按鈕呼叫 `pywebview.api.install(name)`，回傳新的狀態字串，那一列更新。關掉頁面 → `app.rescan()`（執行中的重掃本來就會延到結束）。
- 安裝：下載到 `modules/.workshop-tmp/<name>.zip`、驗 sha256（不符就刪、回一句話、不解壓）；資料夾已存在就先把整個資料夾（略過 `.history/`）壓成 `modules/<name>/.history/<日期時間>-folder.zip`；解壓覆蓋；寫 `.origin`；建空檔案 `.unconfirmed`；清掉暫存。
- 不變量（`tests/test_workshop.py`）：只寫進 `modules/<name>/` 與暫存，`modules/` 裡其他資料夾逐位元組不變；覆蓋前 `.history/` 裡有整個舊資料夾的 zip；sha256 不符不解壓、不寫 `.origin`；安裝完 `.unconfirmed` 存在、狀態是 `installed`；改一個檔之後狀態是 `modified`。
- 隨附模組（開工、作業系統等）不帶 `.origin`，在索引裡列出時狀態是 `unknown`：覆蓋前先快照再問，跟使用者自己的同名模組一樣處理。核心更新（13.2）不碰 `modules/`，隨附模組的新版只從這裡來。
- 跟 Steam 工作坊對照：訂閱 = 安裝；更新 = 索引版本比本機新；存檔不碰 = 只寫進自己裝的資料夾、覆蓋前存快照；第一次執行前確認 = D59。不做：評分、留言、自動更新、多個索引、移除（搬到垃圾桶用右鍵，M2 後段）。

**13.4 發佈工具（`tools/publish.py`，開發端）**
- `python3 tools/publish.py --version 0.5.0 --base-url https://example.com/iplot --modules 整理桌面 開工` → 在 `交付/發佈/` 產生：`iPLoT-v0.5.0.zip`（`git archive` 該 tag）、`update.json`（sha256、`zip_url` = base-url + 檔名、`notes` 從 `CHANGELOG.md` 該版本那一節取）、`模組/<name>.zip` 每個模組一個、`index.json`。把 `交付/發佈/` 整個上傳到放檔案的地方，`config.py` 填 `UPDATE_URL`、`WORKSHOP_URL` 指到那兩個 json。
- 放檔案的地方（2026-10-05 定）：GitHub 公開 repo，用 raw 網址直接取檔——`https://raw.githubusercontent.com/<帳號>/<repo>/<分支>/<路徑>/update.json`，`--base-url` 填到放 `update.json` 的那一層；README「更新與工作坊」照這個寫。其他能用 `https://` 直接取檔的地方技術上也行；Google Drive 的分享連結不是直接取檔，不行。
- 驗收用 `file://` 網址（13.6），不需要先決定放哪裡。
