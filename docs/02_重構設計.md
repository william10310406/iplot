## 0. 一句話

一個可以放在任何位置的資料夾。啟動後把周圍（上一層、這一層、下一層）含有 `iplot.py` 的資料夾變成按鈕；按下去就執行那個檔案，錯了在面板上用白話說清楚；按「＋」用滑鼠長出新按鈕。核心本身不內建任何用途，連 iPLoT 自己的工具都是模組。

## 1. 目標與不變的原則

三個原則是老闆的想法，每一個設計決定都用它們檢查：

1. **機器本身不為任何功能。** 核心不內建任何「用途」；所有用途都是模組，包括 iPLoT 自己的工具。
2. **所有人都能改原始碼。** 所以原始碼要看得到、小到讀得完、改壞了救得回來。
3. **大多數事情只用滑鼠。** 連「長出新能力」這件事也要能用滑鼠完成，不只是按已經有的按鈕。

三個已確認的需求：

- 滑鼠能做的事越多越好。
- 任何人都要能使用：零安裝、雙擊啟動、錯誤用白話顯示、更新核心不動到使用者做的東西。
- 掃上一層、這一層、下一層是想法的一部分，保留，並用一條規則統一三層。

硬限制：全部 Python；macOS 先行；Windows、Linux 的做法寫在 `modules/作業系統` 裡，但 Windows 未經實機驗證、Linux 沒有在真的桌面上跑過，文件一律照實標示；使用者端只用標準庫。

## 2. 範圍與非範圍

**做（M1–M3，見 §13）**：三層掃描、面板、執行模組、錯誤面板、滑鼠新增模組、右鍵選單、拖放（可選依賴）、模組快照與復原、自動啟動、安全模式、原版 `X/X.txt` 模組的匯入（用工具模組做，不進核心，見 §8.5 與附錄 D）、作業系統整合做成模組（M1.4，`modules/作業系統`，D50）、測試、CI、文件。

**這一版不做**：工作情境切換、檔案整理規則、排程自動化、核心的滑鼠版復原、模組間共用狀態（`app.shared`）。這些都是加法，之後需要時再加；現在加進來只會讓核心超過任何人一個下午讀得完的大小。

## 3. 名詞

| 名詞 | 定義 |
|---|---|
| 模組 | 一個資料夾，裡面有一個 `iplot.py`。資料夾名稱就是模組名稱。 |
| 根目錄 | 核心去找模組的資料夾。`config.py` 的 `ROOTS` 清單，相對於 iPLoT 程式資料夾。 |
| 層 | 模組來自哪裡：`here`（`modules/`）、`parent`（`..`）、`extra`（`ROOTS` 另外加的）、`child`（進入某個模組後看到的子模組）。 |
| 處理函式 | 模組裡核心會呼叫的函式：`run(app)` 與 `on_files(app, paths)`，都可省略。沒有 `run` 時，最外層程式碼就是按下的動作（D47）。 |
| 面板 | 主視窗。單一視窗、單一欄。 |
| 範圍（scope） | 面板目前顯示的那一組模組：頂層是「這一層 + 上一層 + extra」，進入某個模組後是它的子模組。 |
| 快照 | 模組 `iplot.py` 執行前的複本，存在模組自己的 `.history/`。 |
| 作業系統模組 | `modules/` 裡名字剛好是「作業系統」的模組。核心把打開、編輯、顯示、終端機、垃圾桶五個動作交給它（§6.2、D50、D52）。 |

## 4. 總體架構

### 4.1 資料夾

整個東西就是一個資料夾，放在哪都行，拖進垃圾桶就移除：

```
iPLoT/
  main.py            入口：python3 main.py [--safe]
  iPLoT.command      雙擊啟動（macOS），給不開終端機的人
  iPLoT.bat          雙擊啟動（Windows，未經實機驗證）
  iPLoT.sh           啟動（Linux，沒有在真的桌面上跑過）
  config.py          使用者設定：ROOTS、EDITOR、HISTORY_KEEP
  core/              核心套件
    __init__.py      __version__
    types.py         附錄 B 的資料結構，所有檔案共用
    core.py          組裝與編排：持有設定、畫面、記憶；load_config / press / rescan / enter / back / run_by_name / create（autostart 在 M2）
    scan.py          找模組
    meta.py          不執行地讀模組資訊（ast）
    runner.py        執行模組
    errors.py        例外 → ErrorInfo → 白話
    create.py        新增模組與範本
    history.py       快照與復原
    app.py           模組看得到的 App 介面
    ui.py            tkinter 面板，薄的一層
    text.py          所有畫面文字（一個 dict）與新模組範本 TEMPLATE
  modules/           「這一層」：隨附的工具模組 + 使用者自己做的模組
    開工/iplot.py
    打開核心原始碼/iplot.py
    開Terminal/iplot.py
    重新啟動/iplot.py
    作業系統/          碰作業系統的事都在這（D50）
      iplot.py       選擇器：看 sys.platform 匯入下面其中一個，轉出五個函式
      mac.py  win.py  linux.py    open / edit / reveal / terminal / trash 各系統的做法
  logs/iplot.log     核心錯誤的紀錄（.gitignore）
  tests/             pytest 的測試，與 smoke.py（真的啟動六個情境）
  docs/
  CHANGELOG.md
  README.md
  requirements-dev.txt   pytest、pytest-cov、ruff；使用者端零依賴
```

### 4.2 核心的六個職責

找（`scan`）、讀但不執行（`meta`）、執行（`runner`）、報錯（`errors`）、新增（`create`）、記住上一版（`history`）。其餘四個檔案是支援：`app` 給模組用、`core` 編排、`ui` 畫面、`text` 文字（另有 `types` 放共用的資料結構）。碰作業系統的事不在核心，在 `modules/作業系統`（D50）。

**行數預算**：核心邏輯（`core/` 扣掉 `ui.py`、`text.py`）**500 行以內**（D48）；`ui.py` **150 行以內**。不含測試、註解、docstring。這是上限，目標比它低。預算是功能不是細節：「所有人都能改原始碼」只在原始碼讀得完時成立。

### 4.3 三層掃描，一條規則

**資料夾裡有 `iplot.py` 就是模組。** 三層都用這一條。檔名要一字不差：APFS 不分大小寫，所以比對資料夾裡實際的檔名，原版的 `iPLoT.py` 不算（D34）。

- 上一層：iPLoT 程式資料夾的上一層底下的資料夾。把 iPLoT 放在 `~/`，`Documents`、`Projects` 只要放進一個 `iplot.py` 就變成按鈕。這就是「長在宿主系統上」的具體樣子。
- 這一層：`iPLoT/modules/` 底下的資料夾。
- 下一層：任何模組資料夾裡面再有模組，按鈕旁出現 ▸，點進去看，可以一直往下。
- 根目錄是 `config.py` 的 `ROOTS`，預設 `["modules", ".."]`；要加 `~/Desktop` 自己加一行。
- 掃描只看檔名和用 `ast` 讀原始碼，**不執行任何模組程式碼**。這是核心在模組全壞時照樣能開的保證。
- 以 `.` 開頭的資料夾略過；不跟隨符號連結。讀不到的根目錄在那一組的位置記一行；根目錄底下讀不到的資料夾靜默略過（D35）。

### 4.4 除了核心，全部都是模組

「打開核心原始碼」「開 Terminal」「重新啟動」跟使用者寫的「開工」一樣，都是 `modules/某某/iplot.py`。這是原則 1 的實證：機器自己的工具也是用它自己的機制做的。M1.4 起連「怎麼打開一個檔案」「怎麼開終端機」也是模組（`modules/作業系統`，D50）：核心不知道自己在哪個作業系統上。

### 4.5 核心可整個換掉

更新 iPLoT 就是換 `core/` 與 `main.py`，並把隨附的 `modules/作業系統/` 一起換掉（D50）。使用者做的東西（`modules/`、`config.py`、其他層的模組、各模組的 `.history/`）全在 `core/` 外面。

## 5. 模組契約與 `app` 介面

### 5.1 `iplot.py` 裡核心認得的四樣東西

```python
"""一句話說明這個模組做什麼。"""
# TITLE = "顯示名稱"     # 要讓按鈕文字跟資料夾名稱不同時才打開這一行

def run(app):             # 可省略：沒有 run 時最外層程式碼就是按下的動作
    app.open(app.home)

def on_files(app, paths): # 可選。有定義，按鈕才接受拖放和右鍵「選擇檔案後執行…」
    for p in paths:
        app.log(f"收到 {p.name}")
```

其他東西隨便寫。對應 HyperCard：`run` 是 `on mouseUp`，`on_files` 是收到拖放的 handler。

四樣都可省略。課本寫的腳本不改一行就是模組（腳本語意，§7、D47）——`input()` 跳對話框、`print()` 進訊息區：

```python
x = input("年齡")
print("你的年齡是" + x + "歲")
```

`def run(app)` 留給想用 `app` 額外能力的人；有 `run` 時，最外層程式碼先跑完，再呼叫 `run(app)`。

### 5.2 核心讀這個檔案的兩個階段

**啟動與掃描時：只讀不跑。** `meta.read_meta` 用 `ast` 解析原始碼，取 docstring 第一段、頂層 `TITLE = "..."` 常數、有沒有頂層 `def run`、有沒有頂層 `def on_files`。語法錯誤或解碼錯誤的模組**照樣列在面板上**，標 ⚠，`ModuleInfo.error` 帶錯誤訊息，按下去顯示錯誤和「打開檔案」。

**按下時：每次重新執行。** `runner.run_module`：
1. 讀檔，`compile(原始碼, 檔案路徑, "exec")`，所以 traceback 會寫出模組檔案的路徑與行號。
2. 在一個乾淨的 dict 裡執行：`{"__name__": "__main__", "__file__": 檔案路徑}`；執行期間程序環境換成腳本的樣子，結束時還原（§7「腳本語意」）。
3. 從 dict 取 `run`（或指定的處理函式），有就呼叫 `run(app)`（或 `on_files(app, paths)`）。沒有 `run` 不是錯：最外層程式碼已經跑完，那就是動作。指定 `on_files` 而模組沒定義才是錯（`MissingHandler`）。
4. 命名空間用完即丟。改完檔案再按一次就是新版本，沒有 reload；模組資料夾裡被 import 的檔案（`helper.py`）也一樣，跑完就從 `sys.modules` 清掉。
5. 執行期間 `print()` 的輸出（stdout 與 stderr）收進 `Result.output`，核心逐行寫到訊息區。任何人都會用 `print()`，用了就要看得到。

語意：
- 跨次執行要保留的東西放 `app.memory`；跨次啟動要保留的寫成檔案放模組自己的資料夾（`app.module.folder`）。
- 同步執行，在主視窗的執行緒上。長時間工作（`time.sleep`、長迴圈）會凍住視窗；`app.background` 是之後的事。
- 執行期間工作目錄是模組自己的資料夾，`sys.path` 最前面也是它：`open("x.txt")` 讀寫的是模組資料夾裡的檔案，`import helper` 找的是旁邊的 `helper.py`；跑完還原（§7「腳本語意」）。`app.module.folder / "x.txt"` 照樣可用。
- 模組呼叫 `exit()` / `sys.exit(0)` / `quit()` 是正常結束，就像 `python3 iplot.py`；代碼非零（`exit(1)`、`sys.exit("壞了")`）才算錯誤。兩種都不會關掉 iPLoT（D49）。

### 5.3 `app`：模組看得到的全部

每次執行新建一個 `App`，`module` 與 `memory` 在建立時綁好；其他成員轉呼叫 `core`；`open`、`edit`、`reveal`、`terminal`、`trash` 五個動作由 `core.action` 交給 `modules/作業系統` 執行，沒有那個模組時在訊息區記一行、動作不執行（§6.2）。

| 組 | 成員 | 說明 |
|---|---|---|
| 身分 | `app.module` | 正在執行的模組的 `ModuleInfo`（見附錄 B） |
| | `app.home` | iPLoT 程式資料夾（`Path`） |
| | `app.modules` | 目前範圍內所有模組的唯讀清單（`tuple[ModuleInfo, ...]`） |
| 狀態 | `app.memory` | 這個模組自己的 `dict`，iPLoT 開著期間保留，以模組資料夾路徑為鍵存在 `core` 裡 |
| 動作 | `app.log(text)` | 寫到面板下方的訊息區 |
| | `app.open(path)` | 打開：資料夾用檔案總管、檔案用預設程式 |
| | `app.edit(path, line=None)` | 用 `config.EDITOR` 開檔案；`EDITOR = None` 時用系統預設文字編輯器（各系統的做法見 `07_接口與邊界.md` §2）；`path` 是資料夾時改用 `open`（D38） |
| | `app.reveal(path)` | 在檔案總管裡顯示並選取這個檔案或資料夾（M1.4） |
| | `app.terminal(path)` | 在終端機打開這個資料夾（M1.4） |
| | `app.trash(path) -> Path \| None` | 搬到系統垃圾桶，永遠不直接刪除；回傳搬到哪裡，Windows 的資源回收筒沒有路徑，回 `None`（M1.4，D53） |
| | `app.run(name)` | 執行目前範圍內另一個模組。`name` 可以是字串或 `ModuleInfo`。同名就報錯（`LookupError`）並列出兩個路徑，不猜 |
| | `app.rescan()` | 重新掃描並重畫面板；在模組執行中呼叫時，等這次執行結束後才做（§6.2） |
| 問人 | `app.ask(prompt, default="") -> str \| None` | 對話框問一個字串；取消回 `None` |
| | `app.choose_files() -> list[Path]` | 檔案選擇視窗；取消回空清單 |
| | `app.choose_folder() -> Path \| None` | 資料夾選擇視窗 |
| 畫面 | `app.window` | tkinter 主視窗，模組要自己畫東西時用 |
| 版本 | `app.api_version` | 整數，第一版是 `1` |

介面只加不減；要拿掉東西就升 `api_version` 並寫進 `CHANGELOG.md`。`core/app.py` 每個成員都有繁體中文 docstring，`docs/api.md` 從那裡整理。

### 5.4 名稱

資料夾叫什麼模組就叫什麼：中文、空白都可以，沒有識別字限制。按鈕文字預設是資料夾名稱；只有打開 `TITLE` 那一行時才不同。兩層有同名模組時都顯示。

## 6. 核心內部介面與資料流

### 6.1 檔案與簽名

| 檔案 | 介面 | 依賴 |
|---|---|---|
| `config.py` | `ROOTS: list[str]`、`EDITOR: list[str] \| None`、`HISTORY_KEEP: int`（預設見附錄 C） | — |
| `core/types.py` | 附錄 B 的 `frozen dataclass`，沒有邏輯 | — |
| `core/scan.py` | `is_module(folder: Path) -> bool`、`module_info(folder: Path, root: Path, level: Level) -> ModuleInfo`（`name` 先 NFC 正規化）、`roots_from_config(home: Path, roots: Iterable[str]) -> list[Root]`（同一個資料夾只留一個：路徑存在時用 `os.path.samefile`，不存在時比 resolve 後的字串）、`find_modules(roots: list[Root]) -> list[Group]`（讀不到的根目錄回傳空的 `Group` 並填 `note`）、`find_children(folder: Path, root: Path) -> list[ModuleInfo]`（讀不到回空清單） | meta |
| `core/meta.py` | `read_meta(file: Path) -> Meta` | text |
| `core/runner.py` | `run_module(info: ModuleInfo, app: Any, handler: str = "run", args: tuple = ()) -> Result`（傳進來的是 `App`；標成 `Any` 是為了 runner 不必 import 中層的 app）；處理函式的回傳值放在 `Result.value` | errors |
| `core/errors.py` | `from_exception(exc: BaseException, info: ModuleInfo \| None, source: Source) -> ErrorInfo`、`describe(error: ErrorInfo) -> str` | text |
| `core/create.py` | `new_module(parent: Path, name: str) -> Path`（回傳新模組的資料夾；`Core` 之後重掃取得 `ModuleInfo`）：資料夾不存在就建立；存在但沒有 `iplot.py` 就只寫入 `iplot.py`（把既有資料夾變成模組）；已有 `iplot.py` 丟 `AlreadyExists`；名稱不可攜丟 `BadName`——空白、以 `.` 開頭、結尾是 `.` 或空白、含 `/ \ : * ? " < > |` 或控制字元、或是 Windows 保留字（`CON`、`NUL`、`COM1` 這類），三個平台都擋（D54）；「已有 `iplot.py`」的判斷不分大小寫，資料夾裡有原版的 `iPLoT.py` 也算，絕不覆寫。`template() -> str`（回傳 `text.TEMPLATE`） | text |
| `core/history.py` | `snapshot(file: Path, keep: int) -> Path \| None`、`versions(file: Path) -> list[Path]`、`restore(file: Path, version: Path, keep: int) -> None` | — |
| `core/app.py` | `class App`（§5.3） | —（`core` 只用在型別標註） |

### 6.2 `Core` 與 `View`

```python
class View(Protocol):              # ui.Panel 實作；測試用 FakeView
    window: Any                    # tkinter 主視窗；FakeView 是 None
    def show(self, scope: Scope) -> None: ...
    def log(self, text: str) -> None: ...
    def report(self, error: ErrorInfo) -> None: ...
    def ask(self, prompt: str, default: str = "") -> str | None: ...
    def choose_files(self) -> list[Path]: ...
    def choose_folder(self) -> Path | None: ...

class Core:
    def __init__(self, home: Path, config: Config, view: View, safe: bool = False): ...
    scope: Scope                   # 目前顯示的範圍；第一次 rescan 之前是 Scope(("iPLoT",), ())
    memories: dict[Path, dict]     # 各模組的 app.memory
    def roots(self) -> list[Root]  # 要掃的根目錄；safe 時只有 "modules"
    def rescan(self) -> None       # 重掃目前範圍並 view.show；進入過的資料夾不再是模組時，退回仍然存在的那一層
    def enter(self, info: ModuleInfo) -> None   # 進入下一層：一組，label = info.title、root = info.folder、
                                                # level 沿用進入前那一組；子模組的 ModuleInfo.root 仍是頂層根目錄
    def back(self, depth: int) -> None          # 麵包屑回上；0 是頂層
    def all_modules(self) -> tuple[ModuleInfo, ...]   # 目前範圍內的所有模組（app.modules）
    def press(self, info: ModuleInfo, handler="run", args=(), quiet=False) -> Result
                                   # 執行中 busy；期間收到的 rescan 延到執行結束才做（try/finally）
                                   # 快照失敗只在訊息區記一行，模組照樣執行（D40）
                                   # quiet 只省掉「完成（x 秒）」那一行；快照、輸出、錯誤照舊
    def run_by_name(self, name: str | ModuleInfo) -> Result
                                   # 只比對資料夾名稱；比對前先 unicodedata.normalize("NFC")，macOS 的檔名可能是 NFD
                                   # 找不到或不只一個：丟 LookupError，訊息列出所有同名模組的路徑
    def action(self, name: str, *args) -> Any
                                   # 交給 modules/ 裡的「作業系統」模組：press(那個模組, name, args, quiet=True).value
                                   # 沒有那個模組：view.log 一行、回 None；壞了就像任何模組一樣在面板報錯（D50–D52）
    def create(self, parent: Path, name: str) -> Path | None
                                   # 新增後重掃並打開編輯器（self.action("edit", …)）；名稱不對、已存在、建不了（OSError）時寫 view.log、回 None
    def report_internal(self, exc_type, exc, tb) -> None      # 核心自己的錯誤：進面板 + logs/iplot.log
    # M2 再加：autostart()（safe 時不做；逐一走 press，D39）、rename(info, new_name)、set_autostart(info, on)、
    #          restore(info, version)、trash(info)
```

**依賴方向只有一個**：`ui` 和 `main` 在最上面，`core`、`app` 在中間，`scan`、`meta`、`runner`、`errors`、`create`、`history` 在底下，除了上表依賴欄列出的（`scan` → `meta`、`runner` → `errors`）以外互不相識（共用附錄 B 的資料結構與 `text`）。底下六個檔案一行 tkinter 都不 import；`tests/test_boundaries.py` 用把 `tkinter` 塞成 `None` 的方式強制。

**核心零作業系統程式碼（M1.4，D50）。** `Core.action` 把五個動作（打開、編輯、顯示、終端機、垃圾桶）交給 `modules/作業系統`，走的是 `press`——跟 `run`、`on_files` 同一扇門（§7 第 2 條，D51），所以快照、輸出、錯誤回報全部沿用。核心只在 `modules/` 找名字剛好是「作業系統」的模組（D52）。`core/` 的原始碼連 `subprocess`、`sys.platform`、`os.name`、`startfile`、`ctypes` 這幾個字都不能出現，`tests/test_boundaries.py` 用字串掃描強制。要上別的系統，在那個模組裡加一個檔，核心不動。

### 6.3 按一下按鈕，資料怎麼流

```
Panel 按鈕 → core.press(info)
  → history.snapshot(info.file, keep)        內容跟最新一份不同才存
  → runner.run_module(info, App(core, info))
       compile → 換成腳本環境 → exec 進乾淨 dict → 有 run 就呼叫 → 還原環境
       任何例外 → errors.from_exception → Result(ok=False, error=...)
  → ok：view.log(「開工 完成（0.3 秒）」)
  → 錯：view.report(error)  traceback 在上，最後是白話描述 + 「打開檔案」按鈕（捲到底看到的是人話）
```

模組呼叫 `app.open(p)`（其他四個動作、右鍵選單的前三項、「打開檔案」都一樣）：

```
模組 A 呼叫 app.open(p)
  → core.action("open", p)
      → modules/作業系統 不是模組 → view.log(一行說明) → 回 None
      → 是模組 → press(作業系統, "open", (p,), quiet=True)
            → history.snapshot（內容沒變就不存）
            → runner：exec iplot.py → import mac（或 win、linux）→ open(app, p) → Popen(["open", p])
            → print 進訊息區；錯誤進面板；不印「完成」
      → 回 Result.value
```

按 ＋：`Panel._create` → `core.create` → `new_module` → `rescan` → `action("edit", …)`。沒有作業系統模組時前三步照常，第四步變成訊息區的一行說明。右鍵「在這裡新增下一層模組…」走同一條路，只是 `parent` 是那個模組的資料夾（`info.folder`），不是那一組的 `root`。

### 6.4 `config.py` 怎麼載入

`main.py` 呼叫 `core.load_config`，它用 `runpy.run_path` 執行 `config.py`，取出 `ROOTS`、`EDITOR`、`HISTORY_KEEP`，缺的用預設值補。`config.py` 丟任何例外（包括呼叫 `exit()`）或值的型別不對（`ROOTS` 要是字串清單、`EDITOR` 是 `None` 或字串清單、`HISTORY_KEEP` 是 ≥ 1 的整數；`ROOTS` 的每一項都要能 `expanduser`，`"~Desktop"` 這種少了斜線的寫法算壞）：整份用預設值啟動，面板顯示它哪裡壞。`--safe` 時 `ROOTS` 強制為 `["modules"]`。

## 7. 錯誤處理

1. **啟動時不執行任何模組程式碼。** 掃描只靠檔名與 `ast`。
2. **進入模組程式碼只有一個門：`runner.run_module`。** 核心其他地方沒有 `exec`。
3. **錯誤是資料。** `ErrorInfo`（種類、訊息、檔案、行號、完整 traceback、來源），由 `errors.describe` 組成一句話，例如「模組『開工』第 7 行出錯：NameError，name 'x' is not defined」。訊息保留 Python 原文，不翻譯（D36）。檔案與行號取 traceback 裡位於模組資料夾內的最內層那一格；模組的錯誤找不到這樣的一格時（例如讀檔就解碼失敗），檔案是模組的 `iplot.py`、不帶行號；traceback 是空的就都不帶；核心與設定的錯誤取最後一格（D37）。
4. **模組呼叫 `exit()` / `sys.exit(0)` / `quit()` 是正常結束；代碼非零才算錯誤**（「模組以 exit(1) 結束」，附檔案與行號）。兩種都不會關掉 iPLoT（`runner` 接 `SystemExit`，代碼是 `None` 或 `0` 就當正常結束，D49；`KeyboardInterrupt` 不接）。
5. **核心自己的錯誤**（tkinter 回呼裡丟出來的）接到同一個面板，標成「核心錯誤」，並寫進 `logs/iplot.log`。`main.py` 把主視窗的 `report_callback_exception` 指到 `core.report_internal`。
6. **`--safe`**：不自動啟動、只掃 `modules`、不載入拖放套件。核心改壞了這是最後一道門；再壞就是 git 的事（§9）。

**腳本語意（M1.2，D47；M1.3，D49）。** 按下按鈕 ＝ 在模組自己的資料夾裡執行 `python3 iplot.py`，只是鍵盤和螢幕換成了視窗。課本寫的腳本不改一行就能當模組；`def run(app)` 留給想用 `app` 額外能力的人。`runner.run_module` 在執行模組程式碼之前把程序環境換成腳本的樣子；執行之後——正常結束、出錯、`exit()` 都一樣——一定還原：

| 項目 | 執行期間 | 跑完 |
|---|---|---|
| `__name__` | `"__main__"`，所以 `if __name__ == "__main__":` 底下的會跑。錯誤訊息裡的模組名稱仍是資料夾名稱 | — |
| 工作目錄 | 模組自己的資料夾：`open("x.txt")` 讀寫的是模組資料夾裡的檔案 | 切回原本的 |
| `sys.path` | 最前面插入模組資料夾：`import helper` 找的是旁邊的 `helper.py` | 移除那一筆 |
| `sys.argv` | `[iplot.py 的路徑]` | 還原 |
| `input()` | 跳對話框（就是 `app.ask`），提示字是對話框的文字；上次問完之後 `print` 的東西放在提示前面，像螢幕上問題前面的那幾行（猜數字的「太大」要在下一次問之前看得到）。按取消丟 `EOFError`（訊息「在提問時按了取消」），像真的 `input()` 在 Ctrl-D；模組可以 `except EOFError` 接，不接就以這一句錯誤結束，行號指到呼叫 `input()` 的那一行（D49）。換的是 `builtins.input`，所以模組 import 的 helper 裡呼叫 `input()` 也一樣 | 還原 |
| 旁邊的檔案 | 執行期間不寫 `.pyc`（它的有效性只看秒級的修改時間和檔案大小，同一秒內改成同樣大小的內容會讀到舊的） | 這次執行才從模組資料夾載入的模組（含子資料夾裡的，有沒有 `__init__.py` 都算）清出 `sys.modules`：`helper.py` 改了下次會重讀，維持「每次都是乾淨的」。模組用 `app.run` 跑別的模組時，外層模組的 helper 先收起來、跑完放回去，兩邊同名的 `helper.py` 不會拿錯 |
| 沒有 `run` | 不是錯：最外層程式碼就是動作。只有指定 `on_files` 而模組沒定義時才回 `MissingHandler` | — |

`print`（全部輸出照樣在跑完後逐行進訊息區）、例外、快照、`app.*` 都不變；`exit()` 照上面第 4 條（代碼 0 是正常結束，exit 之前 `print` 的照樣進訊息區）。還原的是 iPLoT 自己換掉的東西；模組自己改的（例如自己 `sys.path.append`）不會被復原。

已知限制：
- `time.sleep` 或長迴圈會凍住視窗——單一執行緒；M2 用背景執行緒。
- 按取消丟的是 `EOFError`，所以 `except ValueError` 的驗證迴圈出得去；但迴圈裡寫 `except:` 或 `except Exception:`（什麼都接）的會把取消也接走、再問一次，只能輸入一個合法的值或強制結束 iPLoT。真的終端機上這種迴圈遇到 Ctrl-D 也一樣，只是那裡還有 Ctrl-C；要不要讓取消在這種迴圈裡也出得去，待裁定（D49）。
- `if __name__ == "__main__":` 底下的程式碼和 `run(app)` 都會跑（先最外層、再 `run`）；模組自己定義不收參數的 `def run():` 會被當成處理函式呼叫而出錯。

### 8.6 拖放依賴

`ui.py` 建主視窗時：`--safe` 完全不載入 `tkinterdnd2`；否則 `try: from tkinterdnd2 import TkinterDnD`，成功就以 `TkinterDnD.Tk()` 當主視窗（註冊拖放是 M2 的事），`ImportError` 就用 `tkinter.Tk`。`TkinterDnD.Tk()` 本身丟 `RuntimeError`／`TclError`（原生 tkdnd 載入失敗）時，視窗其實已經建好，就直接用那個視窗、只是沒有拖放；不 destroy 重建（D42）。功能不消失，只是降級。

## 9. 版本管理

### 9.1 開發端：git

- iPLoT 自己是一個 git repo，建在 `6000_work/iplot`。老闆的 `iPLoT.py`、`iPLoT.txt` 移到 `docs/original/`，連同 `00_現況分析.md`、`01_從零啟動.md` 與 `docs/original/step1_patched/`（步驟 1 修補實驗的對照組）當第一個 commit，打 tag `v0.0-original`。外層 `6000_work` 若本身是 repo，把 `iplot/` 加進它的 `.gitignore`。
- `main` 永遠可以啟動：合進 `main` 的每個 commit 都要通過 §12 的從零啟動情境，CI 擋。
- 語意化版本：`core/__init__.py` 的 `__version__`，顯示在視窗標題；`CHANGELOG.md` 照 keep-a-changelog；`app.api_version` 獨立計。
- 功能分支短命，合回 `main` 就刪；一個人開發也走 PR，PR 頁面就是設計決定的紀錄。還沒有遠端時（M1）在本地分支 `m1-seed` 開發，v0.1.0 時 `git merge --no-ff` 回 `main` 再打 tag（D30）。
- `.gitignore`：`logs/`、`.history/`、`__pycache__/`、`.DS_Store`。

### 9.2 使用者端：`history.py`

- 時機：每次執行前 `snapshot`；每次 `restore` 前也先 `snapshot`，所以復原本身可以再復原。
- 位置：`<模組>/.history/2026-10-02_140905.py`。藏在模組自己的資料夾裡，刪模組就一起消失。
- 去重：跟最新一份比 sha256，相同就不存。保留份數 `HISTORY_KEEP`，超過刪最舊的。只認自己命名的檔案（`YYYY-MM-DD_HHMMSS[_n].py`）；`.history/` 裡別的檔案不比對、不刪（D44）。
- 復原：右鍵「回到上一版…」（§8.3）。
- 範圍：只管模組。核心改壞了靠 git（`git checkout -- core/`）；第一版不做滑鼠版的核心復原。

1. `modules/` 空、上一層沒有模組 → 開窗，每組顯示「尚無模組，按 ＋ 新增」，stderr 乾淨。
2. `ROOTS` 含不存在的路徑 → 略過，面板記一行，照常開。

5. 模組 `run` 丟例外 / 呼叫 `exit(1)` → 面板顯示檔案與行號，iPLoT 活著。
6. 沒裝 `tkinterdnd2` → 照常開，拖放關閉，沒有任何錯誤訊息。
7. 滑鼠三下：按 ＋、打名字、按確定 → 編輯器開了範本、按鈕在面板上、按下去訊息區出現範本的那一行 log。
8. `modules/` 沒有「作業系統」模組（M1.4）→ 按 ＋ 模組照樣建好、按鈕出現，訊息區一行說明為什麼沒開編輯器；其他功能不受影響。情境 1–6 的乾淨副本裡 `modules/` 是空的，本來就沒有這個模組。

## 附錄 B：資料結構（全部 `frozen dataclass`）

```python
Level = Literal["here", "parent", "extra", "child"]
Source = Literal["module", "core", "config"]

@dataclass(frozen=True)
class Meta:
    title: str | None          # 頂層 TITLE 常數；沒有就 None
    description: str           # docstring 第一段；沒有就 ""
    has_run: bool
    accepts_files: bool        # 有頂層 def on_files
    error: str | None          # 語法或解碼錯誤的訊息

@dataclass(frozen=True)
class ModuleInfo:
    name: str                  # 資料夾名稱
    title: str                 # Meta.title 或 name
    description: str
    folder: Path
    file: Path                 # folder / "iplot.py"
    root: Path                 # 來自哪個根目錄
    level: Level
    has_run: bool
    accepts_files: bool
    has_children: bool         # folder 底下還有模組
    error: str | None

@dataclass(frozen=True)
class Root:
    label: str                 # 「這一層」「上一層」或 extra 在 config 裡寫的字串
    level: Level
    path: Path                 # 已 expanduser、resolve

@dataclass(frozen=True)
class Config:
    roots: tuple[str, ...]     # 附錄 C 的 ROOTS
    editor: tuple[str, ...] | None
    history_keep: int

@dataclass(frozen=True)
class Group:
    label: str                 # 頂層同 Root.label；進入某個模組後是那個模組的 title

    root: Path                 # 頂層是根目錄；進入某個模組後是那個模組的資料夾（＋ 建在這裡）

@dataclass(frozen=True)
class Scope:

class ErrorInfo:

    file: Path | None
    line: int | None
```

## 附錄 D：原版模組的包裝檔（「匯入原版模組」寫入的 `iplot.py`）

```python
"""原版 iPLoT 模組的相容包裝。每次按下都重新執行旁邊的 <資料夾名>.txt。"""

def run(app):
    import os, tkinter
    src = app.module.folder / (app.module.name + ".txt")
    names = {
        "__name__": app.module.name,
        "__file__": str(src),
        "os": os,
        "tkinter": tkinter,
        "iPLoTWIN": app.window,                       # 原版：主視窗
        "iPLoTHOMEDIR": str(app.home),                # 原版：iPLoT 資料夾
        app.module.name + "HOMEDIR": str(app.module.folder),  # 原版：<名稱>HOMEDIR
    }
    exec(compile(src.read_text(encoding="utf-8"), str(src), "exec"), names)
```

- 提供的名字就是上面這幾個。原版模組用到其他核心內部名字（例如 `DPanel`、`cmdEXCUTE_iPLoT`、`TkinterDnD`）時，面板會顯示「模組『X』第 N 行出錯：NameError，name '…' is not defined」，行號是 `X.txt` 裡的行號（錯誤定位取模組資料夾內最內層的一格），「打開檔案」打開的就是 `X.txt`，缺哪個一目了然；真的有人需要再加進包裝檔，不進核心。
- 包裝檔本身是普通模組，所以快照、復原、自動啟動、右鍵選單對它全部有效。
- `.txt` 還在，`iplot.py` 也在：Finder 裡兩個檔案並排，老闆改 `.txt`，不用碰 `iplot.py`。
