# iPLoT 重構設計

- 版本：v1.1，2026-10-02。v1 已審核通過；v1.1 依 §14 的三個答案修訂（預設不掃桌面；原版模組用「匯入原版模組」相容；編輯器預設維持系統預設）。
- 性質：取代原版 `iPLoT.py` + `iPLoT.txt` 的全新實作。想法沿用老闆的；程式碼與架構是新的。
- 前文：`00_現況分析.md`（原版的行為與問題）。原版程式碼存檔於 `docs/original/`。
- 配套：`03_設計決定.md`（每一個可推翻的決定、理由與替代方案）。
- 用語：「核心」= `core/` 套件；「模組」= 含 `iplot.py` 的資料夾；「面板」= 主視窗；「層」= 模組來自哪個掃描位置。

---

## 0. 一句話

一個可以放在任何位置的資料夾。啟動後把周圍（上一層、這一層、下一層）含有 `iplot.py` 的資料夾變成按鈕；按下去就執行那個檔案，錯了在面板上用白話說清楚；按「＋」用滑鼠長出新按鈕。核心本身不內建任何用途，連 iPLoT 自己的工具都是模組。

## 1. 目標與不變的原則

三個原則是老闆的想法，每一個設計決定都用它們檢查：

1. **機器本身不為任何功能。** 核心不內建任何「用途」；所有用途都是模組，包括 iPLoT 自己的工具。
2. **所有人都能改原始碼。** 所以原始碼要看得到、小到讀得完、改壞了救得回來。
3. **大多數事情只用滑鼠。** 連「長出新能力」這件事也要能用滑鼠完成，不只是按已經有的按鈕。

三個已確認的需求：

- 滑鼠能做的事越多越好。
- 任何人都要能使用：零安裝、雙擊啟動、錯誤用白話顯示、更新核心不動到使用者做的東西。
- 掃上一層、這一層、下一層是想法的一部分，保留，並用一條規則統一三層。

硬限制：全部 Python；macOS 先行；使用者端只用標準庫。

## 2. 範圍與非範圍

**做（M1–M3，見 §13）**：三層掃描、面板、執行模組、錯誤面板、滑鼠新增模組、右鍵選單、拖放（可選依賴）、模組快照與復原、自動啟動、安全模式、原版 `X/X.txt` 模組的匯入（用工具模組做，不進核心，見 §8.5 與附錄 D）、測試、CI、文件。

**這一版不做**：工作情境切換、檔案整理規則、排程自動化、背景執行（`app.background`）、跨平台、核心的滑鼠版復原、模組間共用狀態（`app.shared`）。這些都是加法，之後需要時再加；現在加進來只會讓核心超過任何人一個下午讀得完的大小。

## 3. 名詞

| 名詞 | 定義 |
|---|---|
| 模組 | 一個資料夾，裡面有一個 `iplot.py`。資料夾名稱就是模組名稱。 |
| 根目錄 | 核心去找模組的資料夾。`config.py` 的 `ROOTS` 清單，相對於 iPLoT 程式資料夾。 |
| 層 | 模組來自哪裡：`here`（`modules/`）、`parent`（`..`）、`extra`（`ROOTS` 另外加的）、`child`（進入某個模組後看到的子模組）。 |
| 處理函式 | 模組裡核心會呼叫的函式：`run(app)` 必要、`on_files(app, paths)` 可選。 |
| 面板 | 主視窗。單一視窗、單一欄。 |
| 範圍（scope） | 面板目前顯示的那一組模組：頂層是「這一層 + 上一層 + extra」，進入某個模組後是它的子模組。 |
| 快照 | 模組 `iplot.py` 執行前的複本，存在模組自己的 `.history/`。 |

## 4. 總體架構

### 4.1 資料夾

整個東西就是一個資料夾，放在哪都行，拖進垃圾桶就移除：

```
iPLoT/
  main.py            入口：python3 main.py [--safe]
  iPLoT.command      雙擊啟動，給不開 Terminal 的人
  config.py          使用者設定：ROOTS、EDITOR、HISTORY_KEEP
  core/              核心套件
    __init__.py      __version__
    types.py         附錄 B 的資料結構，所有檔案共用
    core.py          組裝與編排：持有設定、畫面、記憶；load_config / press / rescan / enter / back / run_by_name / create / autostart
    scan.py          找模組
    meta.py          不執行地讀模組資訊（ast）
    runner.py        執行模組
    errors.py        例外 → ErrorInfo → 白話
    create.py        新增模組與範本
    history.py       快照與復原
    actions.py       唯一碰 macOS 的地方：open / edit / reveal / terminal / trash
    app.py           模組看得到的 App 介面
    ui.py            tkinter 面板，薄的一層
    text.py          所有畫面文字（一個 dict）與新模組範本 TEMPLATE
  modules/           「這一層」：隨附的工具模組 + 使用者自己做的模組
    開工/iplot.py
    打開核心原始碼/iplot.py
    開Terminal/iplot.py
    重新啟動/iplot.py
  logs/iplot.log     核心錯誤的紀錄（.gitignore）
  tests/
  docs/
  CHANGELOG.md
  README.md
  requirements-dev.txt   pytest、ruff；使用者端零依賴
```

### 4.2 核心的六個職責

找（`scan`）、讀但不執行（`meta`）、執行（`runner`）、報錯（`errors`）、新增（`create`）、記住上一版（`history`）。其餘四個檔案是支援：`actions` 碰作業系統、`app` 給模組用、`core` 編排、`ui` 畫面、`text` 文字。

**行數預算**：核心邏輯（`core/` 扣掉 `ui.py`、`text.py`）**400 行以內**；`ui.py` **150 行以內**。不含測試、註解、docstring。這是上限，目標比它低。預算是功能不是細節：「所有人都能改原始碼」只在原始碼讀得完時成立。

### 4.3 三層掃描，一條規則

**資料夾裡有 `iplot.py` 就是模組。** 三層都用這一條。檔名要一字不差：APFS 不分大小寫，所以比對資料夾裡實際的檔名，原版的 `iPLoT.py` 不算（D34）。

- 上一層：iPLoT 程式資料夾的上一層底下的資料夾。把 iPLoT 放在 `~/`，`Documents`、`Projects` 只要放進一個 `iplot.py` 就變成按鈕。這就是「長在宿主系統上」的具體樣子。
- 這一層：`iPLoT/modules/` 底下的資料夾。
- 下一層：任何模組資料夾裡面再有模組，按鈕旁出現 ▸，點進去看，可以一直往下。
- 根目錄是 `config.py` 的 `ROOTS`，預設 `["modules", ".."]`；要加 `~/Desktop` 自己加一行。
- 掃描只看檔名和用 `ast` 讀原始碼，**不執行任何模組程式碼**。這是核心在模組全壞時照樣能開的保證。
- 以 `.` 開頭的資料夾略過；不跟隨符號連結。讀不到的根目錄在那一組的位置記一行；根目錄底下讀不到的資料夾靜默略過（D35）。

### 4.4 除了核心，全部都是模組

「打開核心原始碼」「開 Terminal」「重新啟動」跟使用者寫的「開工」一樣，都是 `modules/某某/iplot.py`。這是原則 1 的實證：機器自己的工具也是用它自己的機制做的。

### 4.5 核心可整個換掉

更新 iPLoT 就是換 `core/`。使用者做的東西（`modules/`、`config.py`、其他層的模組、各模組的 `.history/`）全在 `core/` 外面。

## 5. 模組契約與 `app` 介面

### 5.1 `iplot.py` 裡核心認得的四樣東西

```python
"""一句話說明這個模組做什麼。"""
# TITLE = "顯示名稱"     # 要讓按鈕文字跟資料夾名稱不同時才打開這一行

def run(app):             # 必要。按下按鈕時執行
    app.open(app.home)

def on_files(app, paths): # 可選。有定義，按鈕才接受拖放和右鍵「選擇檔案後執行…」
    for p in paths:
        app.log(f"收到 {p.name}")
```

其他東西隨便寫。對應 HyperCard：`run` 是 `on mouseUp`，`on_files` 是收到拖放的 handler。

### 5.2 核心讀這個檔案的兩個階段

**啟動與掃描時：只讀不跑。** `meta.read_meta` 用 `ast` 解析原始碼，取 docstring 第一段、頂層 `TITLE = "..."` 常數、有沒有頂層 `def run`、有沒有頂層 `def on_files`。語法錯誤或解碼錯誤的模組**照樣列在面板上**，標 ⚠，`ModuleInfo.error` 帶錯誤訊息，按下去顯示錯誤和「打開檔案」。

**按下時：每次重新執行。** `runner.run_module`：
1. 讀檔，`compile(原始碼, 檔案路徑, "exec")`，所以 traceback 會寫出模組檔案的路徑與行號。
2. 在一個乾淨的 dict 裡執行：`{"__name__": 模組名, "__file__": 檔案路徑}`。
3. 從 dict 取 `run`（或指定的處理函式），呼叫 `run(app)`（或 `on_files(app, paths)`）。
4. 命名空間用完即丟。改完檔案再按一次就是新版本，沒有 reload。
5. 執行期間 `print()` 的輸出（stdout 與 stderr）收進 `Result.output`，核心逐行寫到訊息區。任何人都會用 `print()`，用了就要看得到。

語意：
- 跨次執行要保留的東西放 `app.memory`；跨次啟動要保留的寫成檔案放模組自己的資料夾（`app.module.folder`）。
- 同步執行，在主視窗的執行緒上。長時間工作會凍住視窗；`app.background` 是之後的事。
- 不改變工作目錄，不改 `sys.path`。模組要讀自己的檔案用 `app.module.folder / "x.txt"`。
- 模組呼叫 `exit()` / `sys.exit()` 算錯誤，iPLoT 不會關掉。

### 5.3 `app`：模組看得到的全部

每次執行新建一個 `App`，`module` 與 `memory` 在建立時綁好；其他成員轉呼叫 `core`。

| 組 | 成員 | 說明 |
|---|---|---|
| 身分 | `app.module` | 正在執行的模組的 `ModuleInfo`（見附錄 B） |
| | `app.home` | iPLoT 程式資料夾（`Path`） |
| | `app.modules` | 目前範圍內所有模組的唯讀清單（`tuple[ModuleInfo, ...]`） |
| 狀態 | `app.memory` | 這個模組自己的 `dict`，iPLoT 開著期間保留，以模組資料夾路徑為鍵存在 `core` 裡 |
| 動作 | `app.log(text)` | 寫到面板下方的訊息區 |
| | `app.open(path)` | macOS `open`：資料夾進 Finder、檔案用預設程式 |
| | `app.edit(path, line=None)` | 用 `config.EDITOR` 開檔案；`EDITOR = None` 時用 `open -t`（系統預設文字編輯器） |
| | `app.run(name)` | 執行目前範圍內另一個模組。`name` 可以是字串或 `ModuleInfo`。同名就報錯並列出兩個路徑，不猜 |
| | `app.rescan()` | 重新掃描並重畫面板 |
| 問人 | `app.ask(prompt, default="") -> str \| None` | 對話框問一個字串；取消回 `None` |
| | `app.choose_files() -> list[Path]` | 檔案選擇視窗；取消回空清單 |
| | `app.choose_folder() -> Path \| None` | 資料夾選擇視窗 |
| 畫面 | `app.window` | tkinter 主視窗，模組要自己畫東西時用 |
| 版本 | `app.api_version` | 整數，第一版是 `1` |

介面只加不減；要拿掉東西就升 `api_version` 並寫進 `CHANGELOG.md`。`core/app.py` 每個成員都有繁體中文 docstring，`docs/api.md` 從那裡整理。

### 5.4 名稱

資料夾叫什麼模組就叫什麼：中文、空白都可以，沒有識別字限制。按鈕文字預設是資料夾名稱；只有打開 `TITLE` 那一行時才不同。兩層有同名模組時都顯示。

## 6. 核心內部介面與資料流

### 6.1 檔案與簽名

| 檔案 | 介面 | 依賴 |
|---|---|---|
| `config.py` | `ROOTS: list[str]`、`EDITOR: list[str] \| None`、`HISTORY_KEEP: int`（預設見附錄 C） | — |
| `core/types.py` | 附錄 B 的 `frozen dataclass`，沒有邏輯 | — |

| `core/meta.py` | `read_meta(file: Path) -> Meta` | text |

| `core/errors.py` | `from_exception(exc: BaseException, info: ModuleInfo \| None, source: Source) -> ErrorInfo`、`describe(error: ErrorInfo) -> str` | text |

| `core/history.py` | `snapshot(file: Path, keep: int) -> Path \| None`、`versions(file: Path) -> list[Path]`、`restore(file: Path, version: Path, keep: int) -> None` | — |

| `core/app.py` | `class App`（§5.3） | core |
| `core/core.py` | `load_config(path: Path) -> tuple[Config, ErrorInfo \| None]`（型別不對也算壞，用預設值）、`class Core`、`class View(Protocol)`（§6.2） | 以上全部 |
| `core/ui.py` | `class Panel(View)` | core、text |
| `core/text.py` | `T: dict[str, str]`、`TEMPLATE: str`（新模組範本，附錄 A） | — |
| `main.py` | 解析 `--safe`、載入 `config.py`、組裝 `Core` + `Panel`、自動啟動、`mainloop` | 全部 |

### 6.2 `Core` 與 `View`

```python
class View(Protocol):              # ui.Panel 實作；測試用 FakeView
    window: Any                    # tkinter 主視窗；FakeView 是 None
    def show(self, scope: Scope) -> None: ...
    def log(self, text: str) -> None: ...
    def report(self, error: ErrorInfo) -> None: ...
    def ask(self, prompt: str, default: str = "") -> str | None: ...
    def choose_files(self) -> list[Path]: ...
    def choose_folder(self) -> Path | None: ...

class Core:
    def __init__(self, home: Path, config: Config, view: View, safe: bool): ...
    scope: Scope                   # 目前顯示的範圍
    memories: dict[Path, dict]     # 各模組的 app.memory
    def rescan(self) -> None       # 重掃目前範圍並 view.show
    def enter(self, info: ModuleInfo) -> None   # 進入下一層
    def back(self, depth: int) -> None          # 麵包屑回上
    def press(self, info: ModuleInfo, handler="run", args=()) -> Result
                                   # 執行中 busy=True；期間收到的 rescan 延到執行結束才做
    def run_by_name(self, name: str | ModuleInfo) -> Result
                                   # 名稱比對前先 unicodedata.normalize("NFC")，macOS 的檔名可能是 NFD
    def create(self, parent: Path, name: str) -> ModuleInfo   # 新增後重掃並打開編輯器
    def autostart(self) -> None    # safe 時不做；逐一走 press
    def report_internal(self, exc_type, exc, tb) -> None      # 核心自己的錯誤：進面板 + logs/
    # M2 再加：rename(info, new_name)、set_autostart(info, on)、restore(info, version)、trash(info)
```

**依賴方向只有一個**：`ui` 和 `main` 在最上面，`core`、`app` 在中間，`scan`、`meta`、`runner`、`errors`、`create`、`history`、`actions` 在底下，除了上表依賴欄列出的（`scan` → `meta`、`runner` → `errors`）以外互不相識（共用附錄 B 的資料結構與 `text`）。底下七個檔案一行 tkinter 都不 import；`tests/test_boundaries.py` 用把 `tkinter` 塞成 `None` 的方式強制。`actions.py` 是唯一碰 macOS 的地方，全部走 `subprocess.run([...])` 列表形式；以後要上別的系統只換這一個檔案。

### 6.3 按一下按鈕，資料怎麼流

```
Panel 按鈕 → core.press(info)
  → history.snapshot(info.file, keep)        內容跟最新一份不同才存
  → runner.run_module(info, App(core, info))
       compile → exec 進乾淨 dict → 取 run → 呼叫
       任何例外 → errors.from_exception → Result(ok=False, error=...)
  → ok：view.log(「開工 完成（0.3 秒）」)
  → 錯：view.report(error)  白話描述 + 檔案與行號 + 「打開檔案」按鈕
```

### 6.4 `config.py` 怎麼載入

`main.py` 用 `runpy.run_path` 執行 `config.py`，取出 `ROOTS`、`EDITOR`、`HISTORY_KEEP`，缺的用預設值補。`config.py` 丟任何例外：用預設值啟動，面板顯示它哪裡壞。`--safe` 時 `ROOTS` 強制為 `["modules"]`。

## 7. 錯誤處理

1. **啟動時不執行任何模組程式碼。** 掃描只靠檔名與 `ast`。
2. **進入模組程式碼只有一個門：`runner.run_module`。** 核心其他地方沒有 `exec`。
3. **錯誤是資料。** `ErrorInfo`（種類、訊息、檔案、行號、完整 traceback、來源），由 `errors.describe` 組成一句話，例如「模組『開工』第 7 行出錯：NameError，name 'x' is not defined」。訊息保留 Python 原文，不翻譯（D36）。檔案與行號取 traceback 裡位於模組資料夾內的最內層那一格；模組的錯誤找不到這樣的一格時（例如讀檔就解碼失敗），檔案是模組的 `iplot.py`、不帶行號；traceback 是空的就都不帶；核心與設定的錯誤取最後一格（D37）。
4. **模組呼叫 `exit()` 算錯誤**，不會關掉 iPLoT（`runner` 接 `SystemExit`；`KeyboardInterrupt` 不接）。
5. **核心自己的錯誤**（tkinter 回呼裡丟出來的）接到同一個面板，標成「核心錯誤」，並寫進 `logs/iplot.log`。`main.py` 把主視窗的 `report_callback_exception` 指到 `core.report_internal`。
6. **`--safe`**：不自動啟動、只掃 `modules`、不載入拖放套件。核心改壞了這是最後一道門；再壞就是 git 的事（§9）。

## 9. 版本管理

### 9.1 開發端：git

- iPLoT 自己是一個 git repo，建在 `6000_work/iplot`。老闆的 `iPLoT.py`、`iPLoT.txt` 移到 `docs/original/`，連同 `00_現況分析.md`、`01_從零啟動.md` 與 `docs/original/step1_patched/`（步驟 1 修補實驗的對照組）當第一個 commit，打 tag `v0.0-original`。外層 `6000_work` 若本身是 repo，把 `iplot/` 加進它的 `.gitignore`。
- `main` 永遠可以啟動：合進 `main` 的每個 commit 都要通過 §12 的從零啟動情境，CI 擋。
- 語意化版本：`core/__init__.py` 的 `__version__`，顯示在視窗標題；`CHANGELOG.md` 照 keep-a-changelog；`app.api_version` 獨立計。
- 功能分支短命，合回 `main` 就刪；一個人開發也走 PR，PR 頁面就是設計決定的紀錄。還沒有遠端時（M1）在本地分支 `m1-seed` 開發，v0.1.0 時 `git merge --no-ff` 回 `main` 再打 tag（D30）。
- `.gitignore`：`logs/`、`.history/`、`__pycache__/`、`.DS_Store`。

### 9.2 使用者端：`history.py`

- 時機：每次執行前 `snapshot`；每次 `restore` 前也先 `snapshot`，所以復原本身可以再復原。
- 位置：`<模組>/.history/2026-10-02_140905.py`。藏在模組自己的資料夾裡，刪模組就一起消失。
- 去重：跟最新一份比 sha256，相同就不存。保留份數 `HISTORY_KEEP`，超過刪最舊的。
- 復原：右鍵「回到上一版…」（§8.3）。
- 範圍：只管模組。核心改壞了靠 git（`git checkout -- core/`）；第一版不做滑鼠版的核心復原。

## 附錄 B：資料結構（全部 `frozen dataclass`）

```python
Level = Literal["here", "parent", "extra", "child"]
Source = Literal["module", "core", "config"]

@dataclass(frozen=True)
class Meta:
    title: str | None          # 頂層 TITLE 常數；沒有就 None
    description: str           # docstring 第一段；沒有就 ""
    has_run: bool
    accepts_files: bool        # 有頂層 def on_files
    error: str | None          # 語法或解碼錯誤的訊息

@dataclass(frozen=True)
class ModuleInfo:
    name: str                  # 資料夾名稱
    title: str                 # Meta.title 或 name
    description: str
    folder: Path
    file: Path                 # folder / "iplot.py"
    root: Path                 # 來自哪個根目錄
    level: Level
    has_run: bool
    accepts_files: bool
    has_children: bool         # folder 底下還有模組
    error: str | None

@dataclass(frozen=True)
class Root:
    label: str                 # 「這一層」「上一層」或 extra 在 config 裡寫的字串
    level: Level
    path: Path                 # 已 expanduser、resolve

@dataclass(frozen=True)
class Config:
    roots: tuple[str, ...]     # 附錄 C 的 ROOTS
    editor: tuple[str, ...] | None
    history_keep: int

@dataclass(frozen=True)
class Group:
    label: str                 # 同 Root.label
    level: Level
    root: Path
    modules: tuple[ModuleInfo, ...]
    note: str | None = None    # 根目錄讀不到時的說明，顯示在這一組的位置

@dataclass(frozen=True)
class Scope:
    crumbs: tuple[str, ...]    # 麵包屑，頂層是 ("iPLoT",)
    groups: tuple[Group, ...]

@dataclass(frozen=True)
class ErrorInfo:
    kind: str                  # 例外類別名稱
    message: str
    file: Path | None
    line: int | None
    traceback_text: str
    source: Source
    module: str | None         # 模組名稱；核心錯誤時 None

@dataclass(frozen=True)
class Result:
    ok: bool
    error: ErrorInfo | None
    duration: float            # 秒
    output: str                # 執行期間 print 到 stdout / stderr 的內容
```

## 附錄 D：原版模組的包裝檔（「匯入原版模組」寫入的 `iplot.py`）

```python
"""原版 iPLoT 模組的相容包裝。每次按下都重新執行旁邊的 <資料夾名>.txt。"""

def run(app):
    import os, tkinter
    src = app.module.folder / (app.module.name + ".txt")
    names = {
        "__name__": app.module.name,
        "__file__": str(src),
        "os": os,
        "tkinter": tkinter,
        "iPLoTWIN": app.window,                       # 原版：主視窗
        "iPLoTHOMEDIR": str(app.home),                # 原版：iPLoT 資料夾
        app.module.name + "HOMEDIR": str(app.module.folder),  # 原版：<名稱>HOMEDIR
    }
    exec(compile(src.read_text(encoding="utf-8"), str(src), "exec"), names)
```

- 提供的名字就是上面這幾個。原版模組用到其他核心內部名字（例如 `DPanel`、`cmdEXCUTE_iPLoT`、`TkinterDnD`）時，面板會顯示「模組『X』第 N 行出錯：NameError，name '…' is not defined」，行號是 `X.txt` 裡的行號（錯誤定位取模組資料夾內最內層的一格），「打開檔案」打開的就是 `X.txt`，缺哪個一目了然；真的有人需要再加進包裝檔，不進核心。
- 包裝檔本身是普通模組，所以快照、復原、自動啟動、右鍵選單對它全部有效。
- `.txt` 還在，`iplot.py` 也在：Finder 裡兩個檔案並排，老闆改 `.txt`，不用碰 `iplot.py`。
