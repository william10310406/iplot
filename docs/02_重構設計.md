## 0. 一句話

一個可以放在任何位置的資料夾。啟動後把周圍（上一層、這一層、下一層）含有 `iplot.py` 的資料夾變成按鈕（面板上一格一格的圖示）；雙擊就執行那個檔案，錯了在面板上用白話說清楚；按「＋」用滑鼠長出新按鈕。核心本身不內建任何用途，連 iPLoT 自己的工具都是模組。

## 1. 目標與不變的原則

三個原則是老闆的想法，每一個設計決定都用它們檢查：

1. **機器本身不為任何功能。** 核心不內建任何「用途」；所有用途都是模組，包括 iPLoT 自己的工具。
2. **所有人都能改原始碼。** 所以原始碼要看得到、小到讀得完、改壞了救得回來。
3. **大多數事情只用滑鼠。** 連「長出新能力」這件事也要能用滑鼠完成，不只是按已經有的按鈕。

三個已確認的需求：

- 滑鼠能做的事越多越好。
- 任何人都要能使用：第一次啟動自動安裝（原本是「零安裝」，D62 取消：需要的套件裝進 iPLoT 自己的 `lib/`，不碰系統的 Python）、雙擊啟動、錯誤用白話顯示、更新核心不動到使用者做的東西。
- 掃上一層、這一層、下一層是想法的一部分，保留，並用一條規則統一三層。

硬限制：Python 端只用標準庫，加上 `lib/` 裡釘死版本的 pywebview（D61、D62）；`core/` 不 import `lib/` 的東西，只有 `ui/web.py` 可以。UI 層可以用 HTML/CSS/JS（D61），不用框架、不用 build、零外部資源。macOS 先行；Windows、Linux 的做法寫在 `modules/作業系統` 裡，但 Windows 未經實機驗證、Linux 沒有在真的桌面上跑過，而且 Linux 沒有網頁面板：啟動時先說一句，然後改用後備的 tkinter 面板（§7、§8.7）；文件一律照實標示。

## 2. 範圍與非範圍

**做（M1–M3，見 §13）**：三層掃描、面板、執行模組、錯誤面板、滑鼠新增模組、右鍵選單、拖放（M2 後段，§8.6）、模組快照與復原、自動啟動、安全模式、原版 `X/X.txt` 模組的匯入（用工具模組做，不進核心，見 §8.5 與附錄 D）、作業系統整合做成模組（M1.4，`modules/作業系統`，D50）、網頁面板與第一次啟動的自動安裝（M2，D61–D68）、更新與工作坊（M3，D69–D77：兩個隨附模組、`config.py` 的兩個來源網址、外來模組第一次執行前確認、開發端的發佈工具，§9.3）、測試、CI、文件。哪些已經做了、哪些還沒，以 §13 為準。

**這一版不做**：工作情境切換、檔案整理規則、排程自動化、核心的滑鼠版復原、模組間共用狀態（`app.shared`）。這些都是加法，之後需要時再加；現在加進來只會讓核心超過任何人一個下午讀得完的大小。更新與工作坊自己不做的事（自動檢查、一鍵回溯、移除模組、評分等）列在 §9.3 最後。

## 3. 名詞

| 名詞 | 定義 |
|---|---|
| 模組 | 一個資料夾，裡面有一個 `iplot.py`。資料夾名稱就是模組名稱。 |
| 根目錄 | 核心去找模組的資料夾。`config.py` 的 `ROOTS` 清單，相對於 iPLoT 程式資料夾。 |
| 層 | 模組來自哪裡：`here`（`modules/`）、`parent`（`..`）、`extra`（`ROOTS` 另外加的）、`child`（進入某個模組後看到的子模組）。 |
| 處理函式 | 模組裡核心會呼叫的函式：`run(app)` 與 `on_files(app, paths)`，都可省略。沒有 `run` 時，最外層程式碼就是按下的動作（D47）。 |
| 面板 | 主視窗。單一視窗、分組的圖示格（D15 修訂：單一欄改成格狀）。預設是網頁面板：pywebview 開的原生視窗，裡面跑 `ui/index.html`（§8.2）。tkinter 面板是安全模式與後備，仍是單一欄的按鈕（§8.7）。 |
| 圖示 | 模組那一格上的圖。來源依序：模組資料夾裡的 `icon.png`／`icon.svg` → `iplot.py` 頂層的 `ICON` 常數 → 名字第一個字（D65，§8.2）。 |
| 範圍（scope） | 面板目前顯示的那一組模組：頂層是「這一層 + 上一層 + extra」，進入某個模組後是它的子模組。 |
| 快照 | 模組 `iplot.py` 執行前的複本，存在模組自己的 `.history/`。工作坊覆蓋一個模組之前，另外把整個資料夾壓成一個 zip，也存在那裡（§9.3）。 |
| 作業系統模組 | `modules/` 裡名字剛好是「作業系統」的模組。核心把打開、編輯、顯示、終端機、垃圾桶五個動作交給它（§6.2、D50、D52）；第一次啟動的安裝另外問它兩件事：裝哪一份需求檔、缺不缺前置條件（§7）。 |
| 工作執行緒 | 網頁面板裡替 `Core` 做事的那一條執行緒：頁面送來的動作排隊，一次做一件（§6.2）。`Core` 不知道它的存在。 |
| 安全模式 | `python3 main.py --safe`：開 tkinter 面板、只掃 `modules/`、不需要也不碰 `lib/`，視窗標題有「（安全模式）」。只有加 `--safe` 才是安全模式（§7 第 6 條）。 |
| 後備面板 | 網頁面板開不起來（這個平台沒有網頁面板、缺前置條件、pip 失敗、裝完還是不行）時自動改用的 tkinter 面板。跟安全模式是同一個 `ui/tk.py`，但它不是安全模式：照常掃上一層與 `ROOTS`，標題沒有「（安全模式）」；為什麼改用它，主控台與訊息區各說一次（0.5.0 改的，D75；0.4.0 這裡退到的是安全模式，§7、§8.7）。 |
| `lib/` | 第一次啟動時用 pip 裝進 iPLoT 資料夾的套件（pywebview 與它的依賴）。不碰系統的 Python；刪掉它，下次啟動會再裝（D62）。需求檔變了（「更新」換過 `requirements/`），下次啟動也會重裝（D76，§7）。 |
| 更新 | 隨附模組 `modules/更新`：把核心的四樣（`core/`、`ui/`、`main.py`、`requirements/`）換成新版，換之前先備份到 `.backup/`；其他東西一律不碰（D69，§4.5、§9.3）。 |
| 工作坊 | 隨附模組 `modules/工作坊`：從一份索引（`index.json`）安裝、更新模組；只寫進自己裝的那個模組資料夾，覆蓋之前先把舊資料夾整個存起來；不覆蓋「作業系統」「更新」「工作坊」這三個 iPLoT 自己要用的隨附模組（D70、D74，§9.3）。 |
| 來源網址 | `config.py` 的 `UPDATE_URL`（`update.json` 的網址）與 `WORKSHOP_URL`（`index.json` 的網址），預設都是 `None`。沒設定時「更新」「工作坊」各說一句怎麼設定，不連網；設定了也只有按下去才連網（D71）。 |
| `.origin` | 工作坊在它裝的模組資料夾裡寫的來源記錄：從哪個網址、哪一版、zip 的 sha256、裝進來的是哪些檔、那些檔安裝完當下的摘要、什麼時候裝的。工作坊靠它判斷「已安裝／可更新／已修改」；核心不讀它（§9.3）。 |
| `.unconfirmed` | 模組資料夾裡的空檔案，意思是「這個模組是從外面裝進來的，還沒有人確認過」。有它，第一次執行前核心先問一次；按了確定就拿掉。工作坊裝模組時放它；核心只看它在不在（D59、D73，§7 第 7 條）。 |

### 4.2 核心的六個職責

找（`scan`）、讀但不執行（`meta`）、執行（`runner`）、報錯（`errors`）、新增（`create`）、記住上一版（`history`）。其餘三個檔案是支援：`app` 給模組用、`core` 編排、`text` 文字（另有 `types` 放共用的資料結構）。畫面不在核心：面板在 `ui/`（M2，D61、D63），核心只透過 `View` 跟它說話（§6.2）。碰作業系統的事也不在核心，在 `modules/作業系統`（D50）。

**行數預算**（D68，修訂 D48）：七項各有上限，`tests/test_budget.py` 擋。不含測試。Python 的有效行＝非空白、非純註解、非 docstring 的行；HTML／CSS／JS 的有效行＝非空白、非整行註解的行。

| 項目 | 上限（有效行） | 現在（0.5.0） | 0.4.0 |
|---|---|---|---|
| 核心邏輯（`core/` 扣掉 `text.py`） | 500 | 500 | 490 |
| `ui/web.py` | 220（0.4.0 是 200） | 199 | 194 |
| `ui/tk.py` | 180 | 120 | 118 |
| `ui/install.py` | 80 | 58 | 49 |
| `ui/index.html` | 120 | 30 | 30 |
| `ui/app.js` | 400 | 256 | 256 |
| `ui/style.css` | 300 | 126 | 126 |

這是上限，目標比它低。預算是功能不是細節：「所有人都能改原始碼」只在原始碼讀得完時成立。核心邏輯的上限沒變，仍然是一個下午讀得完的大小。UI 從一個檔變成兩種語言、六個檔，各自訂上限：六個上限合計 1300 行，現在合計 789 行，比原來 `ui.py` 的 150 行上限多很多——這是 D61 的代價，寫明白。

0.5.0 動了兩個地方（D68 修訂）：

- **`ui/web.py` 的上限從 200 調到 220。** 理由：`page`（模組開自己的一頁，§5.3）用掉 5 行；另外替日後的「模組執行中關視窗先確認」留 8 行——那件事決定延後，還沒做。其他六項的上限沒動，超過照舊是測試失敗。
- **核心邏輯 500 行，剛好在上限。** 這一版核心多了十幾行（`Config` 兩欄、`load_config` 兩個 key、`View.page`、`press` 的確認與標記拿不掉時照常執行、`App` 的三個成員）。為了不動 500 這個上限，`core/scan.py` 把找圖示檔併進 `module_info` 原有的那一段、三處 `try/except OSError` 改成 `contextlib.suppress`，行為不變。之後核心再要加東西，就得先從別處省出行數。

兩個新的隨附模組與發佈工具不在這七項裡：它們是模組與開發端工具，不是核心也不是面板。它們的大小列在 §9.3。

### 4.3 三層掃描，一條規則

**資料夾裡有 `iplot.py` 就是模組。** 三層都用這一條。檔名要一字不差：APFS 不分大小寫，所以比對資料夾裡實際的檔名，原版的 `iPLoT.py` 不算（D34）。

- 上一層：iPLoT 程式資料夾的上一層底下的資料夾。把 iPLoT 放在 `~/`，`Documents`、`Projects` 只要放進一個 `iplot.py` 就變成按鈕。這就是「長在宿主系統上」的具體樣子。
- 這一層：`iPLoT/modules/` 底下的資料夾。
- 下一層：任何模組資料夾裡面再有模組，圖示右下角出現 ▸（tkinter 面板是按鈕旁），點進去看，可以一直往下。
- 根目錄是 `config.py` 的 `ROOTS`，預設 `["modules", ".."]`；要加 `~/Desktop` 自己加一行。
- 掃描只看檔名和用 `ast` 讀原始碼，**不執行任何模組程式碼**。這是核心在模組全壞時照樣能開的保證。
- 以 `.` 開頭的資料夾略過；不跟隨符號連結。讀不到的根目錄在那一組的位置記一行；根目錄底下讀不到的資料夾靜默略過（D35）。

### 4.4 除了核心，全部都是模組

「打開核心原始碼」「開 Terminal」「重新啟動」跟使用者寫的「開工」一樣，都是 `modules/某某/iplot.py`。這是原則 1 的實證：機器自己的工具也是用它自己的機制做的。M1.4 起連「怎麼打開一個檔案」「怎麼開終端機」也是模組（`modules/作業系統`，D50）：核心不知道自己在哪個作業系統上。M2 起「第一次啟動要裝哪一份套件、這台電腦缺不缺前置條件」也是問那個模組（§7）。M3 起「把核心換成新版」「安裝別人做的模組」也是模組（`modules/更新`、`modules/工作坊`，§9.3）：核心自己不連網，也不知道有更新這回事；它為這兩件事加的只有：從 `config.py` 多讀兩個網址（§6.4）、`app` 的三個成員（`config`、`version`、`page`，§5.3），與一個檢查——模組資料夾裡有沒有空檔案 `.unconfirmed`（§7 第 7 條）。

### 4.5 核心可整個換掉

更新 iPLoT 就是換四樣：`core/`、`ui/`、`main.py`、`requirements/`（D69）。使用者的東西——`config.py`、`custom.css`、`modules/`、`logs/`、`lib/`、其他層的模組、各模組的 `.history/`——全在這四樣外面。

0.5.0 起這件事由隨附模組「更新」做（`modules/更新`，流程與每一條保證見 §9.3）。按下去，它從 `config.py` 的 `UPDATE_URL` 讀 `update.json`；有新版就先問一次，確定之後下載、驗 sha256，把現在的四樣複製到 `.backup/<舊版本>-<日期時間>/`，再把包裡的四樣換上去。

- **換哪四樣**：`core/`、`ui/`、`main.py`、`requirements/`，都是整個換掉，不是疊上去。
- **不碰什麼**：`config.py`、`custom.css`、`modules/`（含各模組的 `.history/`）、`logs/`、`lib/` 逐位元組不變；包裡夾帶的其他東西（README、`modules/`、`config.py`）不套用；iPLoT 資料夾以外沒有任何寫入（`tests/test_update.py::test_apply_replaces_only_parts_and_keeps_rest`）。
- **不是熱更新**：換完要執行「重新啟動」才用新版。新版的需求檔跟舊的不一樣時，下一次啟動會重裝 `lib/`（§7）。
- **隨附模組不跟著換**：它們在 `modules/` 裡，「更新」不碰——包括「更新」自己與「作業系統」。開工、打開核心原始碼、開Terminal、重新啟動的新版可以從「工作坊」來（D70、D74）；「作業系統」「更新」「工作坊」三個，工作坊不覆蓋（D74 修訂，§9.3），要換新版只能自己把新的資料夾複製進 `modules/`。
- **回到舊版**：沒有一鍵回溯；把 `.backup/<舊版本>-<日期時間>/` 裡的四樣用手搬回去，再重新啟動。

手動換檔案照樣可以，而且從 0.4.0 升到 0.5.0 只能手動（0.4.0 沒有「更新」這個模組）：換掉那四樣，把 `modules/更新`、`modules/工作坊` 複製進 `modules/`，`config.py` 加 `UPDATE_URL`、`WORKSHOP_URL` 兩行（不加也能用，等於沒設定）。從 0.3.0（或更早）手動升上來的，還要把隨附的 `modules/作業系統/` 一起換成新的（D50）：0.4.0 它多了兩個函式，沒換的話第一次啟動裝不了介面，會改用後備的 tkinter 面板並說明原因。從 0.5.0 起，下一版可以直接按「更新」——前提是有人把新版的檔案放上去、`UPDATE_URL` 填好；到現在為止這條路只用 `file://` 網址驗過。

## 5. 模組契約與 `app` 介面

### 5.1 `iplot.py` 裡核心認得的五樣東西

```python
"""一句話說明這個模組做什麼。"""
# TITLE = "顯示名稱"     # 要讓按鈕文字跟資料夾名稱不同時才打開這一行
# ICON = "🧩"            # 按鈕的圖示：一個 emoji；或在資料夾放 icon.png（M2，D65）

def run(app):             # 可省略：沒有 run 時最外層程式碼就是按下的動作
    app.open(app.home)

def on_files(app, paths): # 可選。有定義，按鈕才接受拖放和右鍵「選擇檔案後執行…」
    for p in paths:
        app.log(f"收到 {p.name}")
```

其他東西隨便寫。對應 HyperCard：`run` 是 `on mouseUp`，`on_files` 是收到拖放的 handler。`on_files` 的兩個入口（拖放、右鍵「選擇檔案後執行…」）都還沒做，現在定義了面板也不會呼叫它（§8.3）。

圖示（M2，D65）：`ICON` 跟 `TITLE` 一樣是頂層的字串常數，核心用 `ast` 讀、不執行。模組資料夾裡放 `icon.png` 或 `icon.svg`（檔名要一字不差）的話，圖檔優先於 `ICON`；兩者都沒有，面板用名字第一個字（§8.2）。圖示只在網頁面板顯示，tkinter 面板（安全模式與後備）不畫圖示。

模組資料夾裡核心還認得一樣東西，不在 `iplot.py` 裡：空檔案 `.unconfirmed`（M3，D73）。有它，按下時核心先問一次要不要執行；按了確定就拿掉它，之後不再問（§7 第 7 條）。它是「工作坊」裝模組時放的，自己做的模組沒有。核心只看它在不在，不讀內容；工作坊寫的另一個檔 `.origin`，核心完全不看（§9.3）。

五樣都可省略。課本寫的腳本不改一行就是模組（腳本語意，§7、D47）——`input()` 跳對話框、`print()` 進訊息區：

```python
x = input("年齡")
print("你的年齡是" + x + "歲")
```

`def run(app)` 留給想用 `app` 額外能力的人；有 `run` 時，最外層程式碼先跑完，再呼叫 `run(app)`。

### 5.2 核心讀這個檔案的兩個階段

**啟動與掃描時：只讀不跑。** `meta.read_meta` 用 `ast` 解析原始碼，取 docstring 第一段、頂層 `TITLE = "..."` 與 `ICON = "..."` 常數、有沒有頂層 `def run`、有沒有頂層 `def on_files`。語法錯誤或解碼錯誤的模組**照樣列在面板上**，有標記（網頁面板是圖示右上角的紅點，tkinter 面板是名稱前的 ⚠），`ModuleInfo.error` 帶錯誤訊息，執行它就顯示錯誤和「打開檔案」。

**按下時：每次重新執行。** `Core.press` 先看模組資料夾裡有沒有 `.unconfirmed`（有就先問，取消就到此為止，§7 第 7 條），再存快照，然後交給 `runner.run_module`：
1. 讀檔，`compile(原始碼, 檔案路徑, "exec")`，所以 traceback 會寫出模組檔案的路徑與行號。
2. 在一個乾淨的 dict 裡執行：`{"__name__": "__main__", "__file__": 檔案路徑}`；執行期間程序環境換成腳本的樣子，結束時還原（§7「腳本語意」）。
3. 從 dict 取 `run`（或指定的處理函式），有就呼叫 `run(app)`（或 `on_files(app, paths)`）。沒有 `run` 不是錯：最外層程式碼已經跑完，那就是動作。指定 `on_files` 而模組沒定義才是錯（`MissingHandler`）。
4. 命名空間用完即丟。改完檔案再按一次就是新版本，沒有 reload；模組資料夾裡被 import 的檔案（`helper.py`）也一樣，跑完就從 `sys.modules` 清掉。
5. 執行期間 `print()` 的輸出（stdout 與 stderr）收進 `Result.output`，核心逐行寫到訊息區。任何人都會用 `print()`，用了就要看得到。

語意：
- 跨次執行要保留的東西放 `app.memory`；跨次啟動要保留的寫成檔案放模組自己的資料夾（`app.module.folder`）。
- 同步執行，一次只跑一個模組。網頁面板把執行排在工作執行緒上（§6.2）：模組跑很久時視窗不會凍住，但不能中途停掉，這段時間再按別的要排隊。tkinter 面板（安全模式與後備）在主視窗的執行緒上執行，長時間工作（`time.sleep`、長迴圈）會凍住視窗。`app.background` 還沒做（§7 已知限制）。
- 執行期間工作目錄是模組自己的資料夾，`sys.path` 最前面也是它：`open("x.txt")` 讀寫的是模組資料夾裡的檔案，`import helper` 找的是旁邊的 `helper.py`；跑完還原（§7「腳本語意」）。`app.module.folder / "x.txt"` 照樣可用。
- 模組呼叫 `exit()` / `sys.exit(0)` / `quit()` 是正常結束，就像 `python3 iplot.py`；代碼非零（`exit(1)`、`sys.exit("壞了")`）才算錯誤。兩種都不會關掉 iPLoT（D49）。

### 5.3 `app`：模組看得到的全部

每次執行新建一個 `App`，`module` 與 `memory` 在建立時綁好；其他成員轉呼叫 `core`；`open`、`edit`、`reveal`、`terminal`、`trash` 五個動作由 `core.action` 交給 `modules/作業系統` 執行，沒有那個模組時在訊息區記一行、動作不執行（§6.2）。

| 組 | 成員 | 說明 |
|---|---|---|
| 身分 | `app.module` | 正在執行的模組的 `ModuleInfo`（見附錄 B） |
| | `app.home` | iPLoT 程式資料夾（`Path`） |
| | `app.modules` | 目前範圍內所有模組的唯讀清單（`tuple[ModuleInfo, ...]`） |
| | `app.config` | `config.py` 讀出來的設定，唯讀的 `Config`（附錄 B）：`roots`、`editor`、`history_keep`、`update_url`、`workshop_url`（M3，D72） |
| 狀態 | `app.memory` | 這個模組自己的 `dict`，iPLoT 開著期間保留，以模組資料夾路徑為鍵存在 `core` 裡 |
| 動作 | `app.log(text)` | 寫到面板下方的訊息區 |
| | `app.open(path)` | 打開：資料夾用檔案總管、檔案用預設程式 |
| | `app.edit(path, line=None)` | 用 `config.EDITOR` 開檔案；`EDITOR = None` 時用系統預設文字編輯器（各系統的做法見 `07_接口與邊界.md` §2）；`path` 是資料夾時改用 `open`（D38） |
| | `app.reveal(path)` | 在檔案總管裡顯示並選取這個檔案或資料夾（M1.4） |
| | `app.terminal(path)` | 在終端機打開這個資料夾（M1.4） |
| | `app.trash(path) -> Path \| None` | 搬到系統垃圾桶，永遠不直接刪除；回傳搬到哪裡，Windows 的資源回收筒沒有路徑，回 `None`（M1.4，D53） |
| | `app.run(name)` | 執行目前範圍內另一個模組。`name` 可以是字串或 `ModuleInfo`。同名就報錯（`LookupError`）並列出兩個路徑，不猜 |
| | `app.rescan()` | 重新掃描並重畫面板；在模組執行中呼叫時，等這次執行結束後才做（§6.2） |
| 問人 | `app.ask(prompt, default="") -> str \| None` | 對話框問一個字串；取消回 `None`。網頁面板是面板內的對話框，tkinter 面板是 tkinter 的對話框；模組的 `input()` 走的也是這個（§7） |
| | `app.confirm(prompt) -> bool` | 「確定／取消」的對話框；按確定回 `True`（M2） |
| | `app.choose_files() -> list[Path]` | 檔案選擇視窗（網頁面板用 pywebview 的原生對話框，D67）；取消回空清單 |
| | `app.choose_folder() -> Path \| None` | 資料夾選擇視窗；取消回 `None` |
| 頁面 | `app.page(title, html, api=None) -> None` | 開第二個視窗顯示一頁 HTML，那個視窗關掉才回來（像對話框）；`api` 的公開方法給那一頁的 JS 用 `pywebview.api.<方法>` 呼叫。tkinter 面板（安全模式與後備）沒有頁面，只在訊息區記一行 `page_unsupported`（M3，D72） |
| 版本 | `app.api_version` | 整數，現在是 `3`。`1` 是第一版；`2` 拿掉了 `app.window`（D66）；`3` 加了 `config`、`version`、`page`（D72） |
| | `app.version` | 核心的版本字串，例如 `"0.5.0"`（`core/__init__.py` 的 `__version__`）；類別屬性，跟 `api_version` 放在一起（M3，D72） |

介面只加不減；要拿掉東西就升 `api_version` 並寫進 `CHANGELOG.md`。這條規則用過一次：0.4.0 拿掉 `app.window`（原本是 tkinter 主視窗，給模組自己畫東西用），`api_version` 從 1 升到 2（D66）——主視窗不再是 tkinter 的，而隨附的模組都沒有用到它。同一版加了 `app.confirm`。網頁面板下，模組不能再靠 tkinter 開自己的視窗（D63 的代價）；模組要有自己的畫面，0.5.0 起用 `app.page`：模組給一頁 HTML，面板替它開第二個 pywebview 視窗（§6.2）。

0.5.0 的 2 → 3 只加不減（D72）：多了 `app.config`、`app.version`、`app.page` 三個成員，沒有拿掉任何東西，既有的模組不用改。三個都是為「更新」「工作坊」加的——讀來源網址、知道現在是哪一版、顯示清單頁——但任何模組都可以用。`core/app.py` 每個成員都有繁體中文 docstring，`docs/api.md` 從那裡整理（`version` 是類別屬性，沒有自己的 docstring，寫在類別的 docstring 裡）。

### 5.4 名稱

資料夾叫什麼模組就叫什麼：中文、空白都可以，沒有識別字限制。按鈕文字預設是資料夾名稱；只有打開 `TITLE` 那一行時才不同。兩層有同名模組時都顯示。

### 6.2 `Core` 與 `View`

```python
class View(Protocol):              # ui/ 裡的面板實作（web.WebPanel、tk.Panel）；測試用 FakeView
    def show(self, scope: Scope) -> None: ...        # 八個方法；M2 拿掉了 window 屬性（D66）
    def log(self, text: str) -> None: ...
    def report(self, error: ErrorInfo) -> None: ...
    def ask(self, prompt: str, default: str = "") -> str | None: ...
    def confirm(self, prompt: str) -> bool: ...      # M2 新增；app.confirm 轉給它；M3 起 press 也用它問外來模組
    def page(self, title: str, html: str, api: object | None) -> None: ...   # M3 新增；app.page 轉給它（D72）
    def choose_files(self) -> list[Path]: ...
    def choose_folder(self) -> Path | None: ...

class Core:
    def __init__(self, home: Path, config: Config, view: View, safe: bool = False): ...
    scope: Scope                   # 目前顯示的範圍；第一次 rescan 之前是 Scope(("iPLoT",), ())
    memories: dict[Path, dict]     # 各模組的 app.memory
    def roots(self) -> list[Root]  # 要掃的根目錄；safe 時只有 "modules"（只有 --safe；後備面板的 safe 是 False）
    def rescan(self) -> None       # 重掃目前範圍並 view.show；進入過的資料夾不再是模組時，退回仍然存在的那一層
    def enter(self, info: ModuleInfo) -> None   # 進入下一層：一組，label = info.title、root = info.folder、
                                                # level 沿用進入前那一組；子模組的 ModuleInfo.root 仍是頂層根目錄
    def back(self, depth: int) -> None          # 麵包屑回上；0 是頂層
    def all_modules(self) -> tuple[ModuleInfo, ...]   # 目前範圍內的所有模組（app.modules）
    def press(self, info: ModuleInfo, handler="run", args=(), quiet=False) -> Result
                                   # M3：info.folder 裡有 .unconfirmed 就先 view.confirm（D73，§7 第 7 條）
                                   #     取消 → view.log 一行、回 Result(False, None, 0.0, "")：不存快照、不執行、標記留著
                                   #     確定 → 拿掉標記，照常往下（拿不掉，例如唯讀，也照常往下，只是下次還會問）
                                   # 執行中 busy；期間收到的 rescan 延到執行結束才做（try/finally）
                                   # 快照失敗只在訊息區記一行，模組照樣執行（D40）
                                   # quiet 只省掉「完成（x 秒）」那一行；快照、輸出、錯誤照舊
    def run_by_name(self, name: str | ModuleInfo) -> Result
                                   # 只比對資料夾名稱；比對前先 unicodedata.normalize("NFC")，macOS 的檔名可能是 NFD
                                   # 找不到或不只一個：丟 LookupError，訊息列出所有同名模組的路徑
    def action(self, name: str, *args) -> Any
                                   # 交給 modules/ 裡的「作業系統」模組：press(那個模組, name, args, quiet=True).value
                                   # 沒有那個模組：view.log 一行、回 None；壞了就像任何模組一樣在面板報錯（D50–D52）
    def create(self, parent: Path, name: str) -> Path | None
                                   # 新增後重掃並打開編輯器（self.action("edit", …)）；名稱不對、已存在、建不了（OSError）時寫 view.log、回 None
    def report_internal(self, exc_type, exc, tb) -> None      # 核心自己的錯誤：進面板 + logs/iplot.log
    # 還沒做（M2 後段）：autostart()（safe 時不做；逐一走 press，D39）、rename(info, new_name)、
    #          set_autostart(info, on)、restore(info, version)、trash(info)
```

M2 沒有動 `Core`：`press`、`rescan`、`action`、`create` 都跟 0.3.0 一樣，換的只是誰來實作 `View`。M3 對 `Core` 只動了 `press` 開頭的那六行（外來模組的確認）；`rescan`、`action`、`create` 照舊。`View` 現在有三個實作加一個測試替身，八個方法都要有：`ui/web.py` 的 `WebPanel`、`ui/tk.py` 的 `Panel`、`ui/install.py` 的 `ConsoleView`，與 `tests/conftest.py` 的 `FakeView`。

**依賴方向只有一個**：`ui/`（`web`、`tk`、`install`）和 `main` 在最上面，`core`、`app` 在中間，`scan`、`meta`、`runner`、`errors`、`create`、`history` 在底下，除了上表依賴欄列出的（`scan` → `meta`、`runner` → `errors`）以外互不相識（共用附錄 B 的資料結構與 `text`）。`core/` 的檔案一行 tkinter 都不 import，也不 import `ui/` 和 `lib/` 裡的 pywebview；`tests/test_boundaries.py` 用把 `tkinter` 塞成 `None` 的方式（`test_bottom_layer_never_imports_tkinter`）與檢查每一個 import（`test_core_never_imports_webview`）強制。

**網頁面板與工作執行緒（M2，D61、D63）。** 網頁面板有兩頭：Python 這一頭是 `ui/web.py`，頁面那一頭是 `ui/index.html`、`app.js`、`style.css`，在 pywebview 開的原生視窗裡跑。頁面用 `file://` 網址載入，沒有 HTTP server、沒有 port。兩個方向各一條路：

- 頁面 → Python：JS 呼叫 `pywebview.api.<方法>`，就是 `Bridge` 的公開方法（十個，§6.1；每個動作叫哪一個見 §8.3）。除了 `state`（直接回目前的範圍）與 `answer`（回答等待中的對話框），全部只把一件工作排進佇列、立刻回傳。
- Python → 頁面：`WebPanel` 用 `window.evaluate_js("iplot.<名字>(…)")` 呼叫頁面的七個入口（`init`、`show`、`log`、`report`、`ask`、`confirm`、`busy`）。參數是純 ASCII 的 JSON，模組名稱裡有引號、反斜線、換行都不會壞（`tests/test_web.py::test_show_escapes_names_for_js`）。

排進去的工作由**單一工作執行緒**依序做，一次一件：連按兩個模組，第二個排在第一個後面（`test_jobs_run_one_at_a_time`）。pywebview 的事件迴圈佔住主執行緒、模組在工作執行緒上跑，所以模組跑很久時視窗照樣可以捲、可以看。`Core` 不知道執行緒的存在：所有對 `Core` 的呼叫都在工作執行緒上，`press` 的 `_depth`／`_pending`（執行中收到的重掃延到結束才做）照舊有效。一件工作裡沒接住的例外交給 `core.report_internal`，迴圈繼續做下一件（§7 第 5 條）。

頁面載入完成時，`WebPanel` 先送 `iplot.init`（畫面文字 `T` 整份、版本、是不是安全模式），工作執行緒在那之後才開始，所以頁面拿到文字之前不會收到別的呼叫。`ask` 與 `confirm`：`WebPanel` 給對話框一個編號、推給頁面，然後在 `threading.Event` 上等；頁面用 `answer(編號, 值)` 回來。視窗關掉或頁面重新載入時，等待中的對話框都當作按了取消（`test_close_window_cancels_pending_ask`、`test_page_reload_cancels_pending_ask`）。`choose_files`、`choose_folder` 是 pywebview 的原生對話框（D67）。

**模組自己的一頁（M3，D72）。** `app.page(title, html, api)` 轉給 `view.page`。`WebPanel.page` 用 pywebview 再開一個視窗（640×520），內容是模組給的那一頁 `html`，`api` 當那個視窗的 `js_api`；然後在工作執行緒上等那個視窗的 `closed` 事件，視窗關掉才回傳——模組像等對話框一樣等它，主面板這段時間顯示「執行中」（`tests/test_web.py::test_page_blocks_until_closed`）。那一頁的 JS 呼叫的是模組給的 `api` 物件的公開方法，不是 `Bridge`；pywebview 會把公開屬性一路攤開，所以 `api` 上不想露出去的東西要用底線開頭（「工作坊」的 `Api` 只露出 `install`，§9.3）。面板不檢查那一頁的內容，「零外部資源」那條規則（§8.2）管的是面板本體的三個檔，管不到模組的頁；隨附的「工作坊」那一頁自己守這一條（`tests/test_bundled.py::test_update_and_workshop_keep_their_logic_beside_iplot_py`）。tkinter 面板的 `page` 沒有頁面可開，只在訊息區記一行 `page_unsupported`（`tests/test_tk_smoke.py::test_page_logs_unsupported`）；`ConsoleView` 的 `page` 什麼都不做。真的視窗開發時走過一遍：第二個視窗開得起來、那一頁的 JS 呼叫得到 `api`、關掉之後模組繼續；那支腳本沒有進 repo。

`Bridge` 只認目前面板上有的東西。模組的 `id` 是資料夾的絕對路徑，要在目前範圍內、而且那個資料夾還是模組；`create` 的資料夾要是目前某一組的 `root`。找不到（例如模組剛在檔案總管被刪掉）就重掃，不報錯（`test_press_missing_module_rescans`）。`action` 只收 `edit`、`reveal`、`terminal`，其他名稱不做任何事。

給頁面的 JSON（`scope_json`、`error_json`；`WebPanel.report` 另外給每筆錯誤一個編號 `id`，「打開檔案」用它指回來）：

```
init   = {"text": T 整份, "version": "0.5.0", "safe": bool}
scope  = {"crumbs": ["iPLoT", …],
          "groups": [{"label", "level", "path", "root", "note", "modules": [module, …]}]}
module = {"id": "<資料夾絕對路徑>", "name", "title", "description",
          "icon": {"file": "data:image/png;base64,…"} | {"text": "🧩"} | null,
          "has_children": bool, "error": "<字串或 null>"}
error  = {"kind", "message", "file", "line", "traceback", "source", "module", "sentence": describe(error), "id"}
```

**核心零作業系統程式碼（M1.4，D50）。** `Core.action` 把五個動作（打開、編輯、顯示、終端機、垃圾桶）交給 `modules/作業系統`，走的是 `press`——跟 `run`、`on_files` 同一扇門（§7 第 2 條，D51），所以快照、輸出、錯誤回報全部沿用。核心只在 `modules/` 找名字剛好是「作業系統」的模組（D52）。`core/` 的原始碼連 `subprocess`、`sys.platform`、`os.name`、`startfile`、`ctypes` 這幾個字都不能出現，`tests/test_boundaries.py` 用字串掃描強制。要上別的系統，在那個模組裡加一個檔，核心不動。

### 6.3 執行一個模組，資料怎麼流

```
網頁面板：雙擊圖示 → app.js 呼叫 pywebview.api.press(id) → Bridge.press 排一件工作、立刻回傳
          → 工作執行緒：用 id 找回 ModuleInfo → core.press(info)
tkinter 面板（安全模式與後備）：按按鈕 → core.press(info)

core.press(info)
  → 模組資料夾裡有 .unconfirmed（工作坊裝進來的）→ view.confirm；取消就到此為止，確定就拿掉標記（M3，D73）
  → history.snapshot(info.file, keep)        內容跟最新一份不同才存
  → runner.run_module(info, App(core, info))
       compile → 換成腳本環境 → exec 進乾淨 dict → 有 run 就呼叫 → 還原環境
       任何例外 → errors.from_exception → Result(ok=False, error=...)
  → ok：view.log(「開工 完成（0.3 秒）」)
  → 錯：view.report(error)
       網頁面板：訊息區一筆錯誤——白話那一句，右邊「打開檔案」（帶著出錯的行號交給編輯器）與「詳細」（展開 traceback）
       tkinter 面板：traceback 在上，最後是白話描述 + 「打開檔案」按鈕（捲到底看到的是人話）
```

模組呼叫 `app.open(p)`（其他四個動作、右鍵選單的「打開程式碼」「在資料夾中顯示」「在終端機打開」、「打開檔案」都一樣；第一次啟動的安裝問 `requirements`、`webview_ready` 走的也是這條路）：

```
模組 A 呼叫 app.open(p)
  → core.action("open", p)
      → modules/作業系統 不是模組 → view.log(一行說明) → 回 None
      → 是模組 → press(作業系統, "open", (p,), quiet=True)
            → history.snapshot（內容沒變就不存）
            → runner：exec iplot.py → import mac（或 win、linux）→ open(app, p) → Popen(["open", p])
            → print 進訊息區；錯誤進面板；不印「完成」
      → 回 Result.value
```

按 ＋：網頁面板是面板內的對話框問名字 → `pywebview.api.create(那一組的 root, 名字)` → 工作執行緒 → `core.create`；tkinter 面板是 `Panel._create` → `core.create`。之後兩邊一樣：`new_module` → `rescan` → `action("edit", …)`。沒有作業系統模組時前面照常，最後一步變成訊息區的一行說明。右鍵「在這裡新增下一層模組…」走同一條路（網頁面板呼叫的是 `add_child(id, 名字)`），只是 `parent` 是那個模組的資料夾（`info.folder`），不是那一組的 `root`。

### 6.4 `config.py` 怎麼載入

`main.py` 呼叫 `core.load_config`，它用 `runpy.run_path` 執行 `config.py`，取出 `ROOTS`、`EDITOR`、`HISTORY_KEEP`、`UPDATE_URL`、`WORKSHOP_URL`，缺的用預設值補。`config.py` 丟任何例外（包括呼叫 `exit()`）或值的型別不對（`ROOTS` 要是字串清單、`EDITOR` 是 `None` 或字串清單、`HISTORY_KEEP` 是 ≥ 1 的整數、`UPDATE_URL` 與 `WORKSHOP_URL` 各是 `None` 或字串；`ROOTS` 的每一項都要能 `expanduser`，`"~Desktop"` 這種少了斜線的寫法算壞）：整份用預設值啟動，面板顯示它哪裡壞。安全模式（只有 `--safe`）`ROOTS` 強制為 `["modules"]`；網頁面板開不起來時改用的後備面板不是安全模式，照 `ROOTS` 掃（0.5.0 改的，D75，§7）。

兩個網址（M3，D71）沒寫就是 `None`，等於沒設定；舊的 `config.py` 不加這兩行也照常能用。`load_config` 只驗型別，不驗它是不是一個打得開的網址——那是按下「更新」「工作坊」時的事，連不上會在訊息區說一句。核心自己不用這兩個值，只透過 `app.config` 交給模組（§5.3、§9.3）。測試：`tests/test_startup.py::test_config_urls_default_none_and_type_checked`、`::test_default_config_has_no_urls`。

## 7. 錯誤處理

1. **啟動時不執行任何模組程式碼。** 掃描只靠檔名與 `ast`。
2. **進入模組程式碼只有一個門：`runner.run_module`。** 核心其他地方沒有 `exec`。
3. **錯誤是資料。** `ErrorInfo`（種類、訊息、檔案、行號、完整 traceback、來源），由 `errors.describe` 組成一句話，例如「模組『開工』第 7 行出錯：NameError，name 'x' is not defined」。訊息保留 Python 原文，不翻譯（D36）。檔案與行號取 traceback 裡位於模組資料夾內的最內層那一格；模組的錯誤找不到這樣的一格時（例如讀檔就解碼失敗），檔案是模組的 `iplot.py`、不帶行號；traceback 是空的就都不帶；核心與設定的錯誤取最後一格（D37）。
4. **模組呼叫 `exit()` / `sys.exit(0)` / `quit()` 是正常結束；代碼非零才算錯誤**（「模組以 exit(1) 結束」，附檔案與行號）。兩種都不會關掉 iPLoT（`runner` 接 `SystemExit`，代碼是 `None` 或 `0` 就當正常結束，D49；`KeyboardInterrupt` 不接）。
5. **核心自己的錯誤**接到同一個面板，標成「核心錯誤」，並寫進 `logs/iplot.log`。兩種面板各有一個入口，都交給 `core.report_internal`：tkinter 面板是 tkinter 回呼裡丟出來的例外（`Panel.attach` 把主視窗的 `report_callback_exception` 指過去）；網頁面板是工作執行緒迴圈接住的例外——一件工作出錯，回報之後迴圈繼續做下一件（`tests/test_web.py::test_job_exception_goes_to_report_internal`）。
6. **`--safe`（安全模式）**：開 tkinter 面板（§8.7），只掃 `modules`、不自動啟動、不載入拖放套件、不需要 `lib/`，也不檢查 `lib/` 要不要重裝。只有加 `--safe` 才是安全模式。網頁面板開不起來時自動改用的後備面板是同一個 tkinter 面板，但它不是安全模式：照常掃上一層與 `ROOTS`（0.5.0 改的，D75，見下面「啟動流程」）。核心或面板改壞了，`--safe` 是最後一道門；再壞就是 git 的事（§9）。
7. **外來模組第一次執行前先問（M3，D59 採用、D73）。** 模組資料夾裡有空檔案 `.unconfirmed` 時，`Core.press` 在存快照之前先用 `view.confirm` 問一次（`confirm_foreign`：「『{title}』是從外面裝進來的，第一次執行前確認：要執行嗎？」）。按取消 → 訊息區記 `cancelled` 那一行，不執行、不存快照、標記留著，下次還問。按確定 → 拿掉標記、照常執行，之後不再問（標記拿不掉，例如資料夾是唯讀的，也照常執行，只是下次還會再問）。標記是空檔案：核心只看它在不在，不解析任何格式，跟設想中的 `autostart` 是同一招（§8.4）。放標記的是「工作坊」——從那裡安裝或覆蓋的模組都帶著它，包裡與磁碟上那個模組資料夾底下每一個有 `iplot.py` 的資料夾都有一個，所以進到下一層執行子模組也會先問，包裡只帶了子模組旁邊的檔、沒帶它的 `iplot.py` 也一樣（§9.3）；自己做的模組沒有標記，從來不問。檢查在 `press` 裡，所以雙擊、右鍵「執行」、`app.run` 都一樣會先問。這只是多問一次，不是隔離：按了確定，它就跟任何模組一樣在 iPLoT 自己的程序裡執行（已知限制的第一條）。測試：`tests/test_core.py::test_unconfirmed_module_asks_first`、`::test_unconfirmed_cancel_does_not_run`、`::test_modules_without_the_marker_are_never_asked`、`::test_marker_that_cannot_be_removed_does_not_block_the_module`。

**啟動流程與安裝失敗（M2，D62、D63；M3 加了第 4 步、改了後備面板，D75、D76）。** `main.py` 依序做：

```
python3 main.py [--safe]
 1  版本檢查：Python < 3.10 → 印 need_python 那一句，結束
 2  把 iPLoT 資料夾裡的 lib/ 加進 sys.path（排在 iPLoT 自己的資料夾後面、系統的套件前面）；load_config
 3  --safe → tkinter 面板的安全模式（只掃 modules/，完全不碰 lib/）；這個 Python 沒有 tkinter → 印 no_tk，代碼 1。到此為止
 4  需求檔變了嗎（refresh，M3）：lib/.installed 記的 sha256 對不上 requirements/ 裡任何一份（記號檔壞了也算）
      → 印 refreshing → pip 重裝進 lib/（連不上馬上放棄）；lib/.installed 先不動
          裝好 → 寫 lib/.installed，直接往下（還沒 import 任何 lib/ 的東西，不用重啟）
          沒裝成 → 印 refresh_failed，照樣往下，用現有的 lib/ 開；同一句也進面板的訊息區
      沒有 lib/.installed（沒裝過）、requirements/ 整個不見、這個平台沒有網頁面板、缺前置條件 → 什麼都不做
 5  開網頁面板（run_web）；開得起來 → 視窗關掉，程序結束
 6  開不起來（lib/ 裡沒有 pywebview，或它裝壞了）→ bootstrap：
      問「作業系統」模組：裝哪一份需求檔（requirements）、缺不缺前置條件（webview_ready）
      可以裝 → 刪掉 lib/.installed → 印 installing → pip 裝進 lib/，輸出一行行印在主控台
          成功 → 寫 lib/.installed → 印 install_done → 重啟自己（os.execv，乾淨的程序），從 1 再來
          失敗 → 印 install_failed（pip 說的原因、安裝需要網路、怎麼再試、現在先改用備用面板）→ 後備的 tkinter 面板
      不能裝（這個平台沒有網頁面板、缺前置條件、作業系統模組不在或壞了）→ 印 web_failed → 後備的 tkinter 面板
 7  剛裝完重啟的那一次還是開不起來 → 不再裝，印 web_failed → 後備的 tkinter 面板
```

- 需求：Python ≥ 3.10 加 pip（任何來源都可以）；第一次啟動要網路。tkinter 不再是必要的，只有安全模式與後備需要它。裝好之後平常使用不需要網路；之後會連網的只有兩種時候：`lib/` 要重裝（壞了，或需求檔變了），以及按「更新」「工作坊」（要先在 `config.py` 設好來源網址，§9.3）。
- pip 的指令是 `python -m pip install --target lib --upgrade --no-input --disable-pip-version-check -r <需求檔>`，列表形式、不經 shell（`ui/install.py`）。裝進 iPLoT 自己的 `lib/`，不碰系統的 Python；把 iPLoT 資料夾丟進垃圾桶就整個消失，「可移除」不變（D62）。需求檔的版本釘死；hash 釘死（`--require-hashes`）還沒做。
- `bootstrap` 的安裝一次啟動最多一次：重啟自己時帶環境變數 `IPLOT_BOOT=1`，每次啟動一開始就把它拿掉；剛重啟的那一次再開不起來就不裝了，不會無限重啟（`tests/test_main.py::test_reinstall_happens_once`、`test_broken_lib_reinstalls_then_falls_back`）。
- **後備面板不是安全模式（0.5.0 改的，D75）。** 改用後備的 tkinter 面板時，原因印在主控台，同一句也寫在那個面板的訊息區。它照常掃上一層與 `ROOTS`，視窗標題沒有「（安全模式）」；只有 `--safe` 才只掃 `modules/`。0.4.0 這裡退到的是安全模式，所以在網頁面板裝不起來的電腦上（Linux 一律如此）只看得到 `modules/` 裡的模組；0.5.0 改掉了，`web_failed` 那一句的結尾也跟著改成「已改用備用面板」，`install_failed` 的結尾是「現在先改用備用面板」（不再叫人用 `--safe`）。連 tkinter 都沒有，就印 `no_tk`、以代碼 1 結束（`test_install_failure_without_tk_exits_1`）。這幾條路都沒有 traceback。測試：`tests/test_main.py::test_install_failure_falls_back_to_tk_with_note`、`::test_platform_without_web_panel_falls_back_without_pip`、`::test_missing_system_module_falls_back_without_pip`、`::test_broken_lib_reinstalls_then_falls_back`（四個都驗後備面板的 `safe` 是 `False`）、`::test_safe_uses_tk`（`--safe` 才是 `True`）。
- **需求檔變了 → 下次啟動重裝 `lib/`（M3，D76）。** `lib/.installed` 記著 `lib/` 是照哪一份需求檔裝的（那個檔內容的 sha256）。「更新」把 `requirements/` 換成內容不一樣的新版之後，記號就對不上 `requirements/` 裡任何一份了（需求檔的內容沒變就照樣對得上，不重裝）——`ui/install.py` 的 `stale(home)` 看的就是這個，不用執行任何模組。`main.py` 的 `refresh` 在開網頁面板之前檢查：過期就印 `refreshing`、用 pip 重裝（多帶 `--retries 0 --timeout 8`，連不上馬上放棄，不讓人等 pip 重試），裝好直接往下開面板。沒有記號（沒裝過）不算過期，那是第一次安裝的事；記號檔壞了（不是文字）當作過期、重裝一次，不會讓啟動變成 traceback；`requirements/` 整個不見就沒得比，不重裝；別的平台的需求檔變了不影響；`--safe` 完全不碰 `lib/`。0.4.0 只有比對用的 `installed()`，啟動流程沒有呼叫它；這一段是 0.5.0 補上的。測試：`tests/test_install.py::test_stale_means_lib_was_installed_from_other_requirements`、`::test_stale_survives_a_garbled_marker_and_a_missing_requirements_folder`、`::test_quick_install_gives_up_fast`，`tests/test_main.py::test_changed_requirements_reinstall_before_the_panel_opens`、`::test_up_to_date_lib_is_not_reinstalled`、`::test_safe_mode_never_touches_lib`、`::test_changed_requirements_on_a_platform_without_web_panel_does_nothing`。
- **更新之後沒有網路。** 重裝失敗時，主控台與網頁面板的訊息區都說 `refresh_failed` 那一句（「介面的套件這次沒有換成新的：…先用現有的開；有網路之後重新啟動 iPLoT 會再試一次。」），然後照常用現有的 `lib/` 開網頁面板。重裝之前不拿掉記號，所以每次啟動都會再試，直到裝成（`tests/test_main.py::test_changed_requirements_offline_opens_the_old_panel_and_keeps_trying`）。萬一新版的 `ui/` 非要新套件不可、舊的 `lib/` 開不起來，就接到第 6 步：照第一次安裝的路再裝一次，還是不行就改用後備面板。這最後一種情況照程式是這樣走，沒有實際遇過。
- 「作業系統」模組回答的兩件事：macOS 裝 `web-mac.txt`、什麼都不缺；Windows 裝 `web-win.txt`，並查登錄檔裡有沒有 WebView2 runtime（未經實機驗證，需求檔的版本是 pip 用 `--dry-run` 解出來的，沒有在 Windows 裝過）；Linux 回空字串——pywebview 在 Linux 要系統層的 GTK／WebKit2GTK，pip 裝不了，所以 Linux 沒有網頁面板：不加 `--safe` 啟動，先說一句網頁面板還不支援 Linux，然後開後備的 tkinter 面板（完整範圍）。沒有在真的 Linux 桌面上跑過。
- 網頁面板開著的期間，`run_web` 在 `sys.meta_path` 最前面放一個 `NoTk`：模組 `import tkinter`（`turtle` 也會 import 它）得到的是 `ImportError` 與 `tk_in_web` 那一句（說要用安全模式），不會真的去開視窗。原因：主執行緒被網頁面板的視窗系統佔著，在工作執行緒上開 tkinter 視窗，整個程序會被 macOS 中止、沒有任何訊息（實測結束碼 133）。面板關掉、或根本沒開起來時就拿掉，後備的 tkinter 面板照常 import 得到（`tests/test_main.py::test_module_using_tkinter_under_the_web_panel_gets_a_plain_error`）。matplotlib 的視窗在工作執行緒上也開不了，但它自己會丟一個說得清楚的 `RuntimeError`，程序不會中止（實測）。
- 在開發用的那台 Mac 上量到的（python.org 的 Python 3.14.7、macOS 26.5、arm64）：`lib/` 裝完 36 MB、10 個套件；乾淨下載安裝 1 分 46 秒（看網路）；pip 有快取時 8 秒；`lib/` 在的時候，啟動到視窗出現 0.6 秒；斷網時 pip 重試約 20 秒後失敗，主控台 14 行、沒有 traceback，接著開 tkinter 面板（這幾個數字是 0.4.0 量的，當時開的是安全模式；0.5.0 起開的是後備面板）。需求檔變了的那一種重裝（上面的 `refresh`）斷網時要等多久，沒有另外量過。`installing` 那一句裡的「約 40 MB」是給人看的概數（`main.py` 的 `INSTALL_SIZE`）。

**腳本語意（M1.2，D47；M1.3，D49）。** 按下按鈕 ＝ 在模組自己的資料夾裡執行 `python3 iplot.py`，只是鍵盤和螢幕換成了視窗。課本寫的腳本不改一行就能當模組；`def run(app)` 留給想用 `app` 額外能力的人。`runner.run_module` 在執行模組程式碼之前把程序環境換成腳本的樣子；執行之後——正常結束、出錯、`exit()` 都一樣——一定還原：

| 項目 | 執行期間 | 跑完 |
|---|---|---|
| `__name__` | `"__main__"`，所以 `if __name__ == "__main__":` 底下的會跑。錯誤訊息裡的模組名稱仍是資料夾名稱 | — |
| 工作目錄 | 模組自己的資料夾：`open("x.txt")` 讀寫的是模組資料夾裡的檔案 | 切回原本的 |
| `sys.path` | 最前面插入模組資料夾：`import helper` 找的是旁邊的 `helper.py` | 移除那一筆 |
| `sys.argv` | `[iplot.py 的路徑]` | 還原 |
| `input()` | 跳對話框（就是 `app.ask`；網頁面板是面板內的對話框，tkinter 面板是 tkinter 的對話框），提示字是對話框的文字；上次問完之後 `print` 的東西放在提示前面，像螢幕上問題前面的那幾行（猜數字的「太大」要在下一次問之前看得到）。按取消丟 `EOFError`（訊息「在提問時按了取消」），像真的 `input()` 在 Ctrl-D；模組可以 `except EOFError` 接，不接就以這一句錯誤結束，行號指到呼叫 `input()` 的那一行（D49）。換的是 `builtins.input`，所以模組 import 的 helper 裡呼叫 `input()` 也一樣 | 還原 |
| 旁邊的檔案 | 執行期間不寫 `.pyc`（它的有效性只看秒級的修改時間和檔案大小，同一秒內改成同樣大小的內容會讀到舊的） | 這次執行才從模組資料夾載入的模組（含子資料夾裡的，有沒有 `__init__.py` 都算）清出 `sys.modules`：`helper.py` 改了下次會重讀，維持「每次都是乾淨的」。模組用 `app.run` 跑別的模組時，外層模組的 helper 先收起來、跑完放回去，兩邊同名的 `helper.py` 不會拿錯 |
| 沒有 `run` | 不是錯：最外層程式碼就是動作。只有指定 `on_files` 而模組沒定義時才回 `MissingHandler` | — |

`print`（全部輸出照樣在跑完後逐行進訊息區）、例外、快照、`app.*` 都不變；`exit()` 照上面第 4 條（代碼 0 是正常結束，exit 之前 `print` 的照樣進訊息區）。還原的是 iPLoT 自己換掉的東西；模組自己改的（例如自己 `sys.path.append`）不會被復原。

已知限制：
- 執行模型（D56）仍延後：模組還是在 iPLoT 自己的程序裡執行。網頁面板有工作執行緒（§6.2），所以 `time.sleep` 或長迴圈不會凍住視窗（可以捲、可以看）；但一次只跑一個模組、不能中途停掉，這段時間按的其他動作排隊，關掉視窗會結束整個程序、連同跑到一半的模組（「模組執行中關視窗要不要先確認」決定延後，還沒做）。模組在 `input()` 等回答時關掉視窗，等待中的提問當作按了取消。tkinter 面板（安全模式與後備）沒有工作執行緒，長時間的模組照樣會凍住視窗。`app.background` 還沒做。
- 按取消丟的是 `EOFError`，所以 `except ValueError` 的驗證迴圈出得去；但迴圈裡寫 `except:` 或 `except Exception:`（什麼都接）的會把取消也接走、再問一次，只能輸入一個合法的值或強制結束 iPLoT。真的終端機上這種迴圈遇到 Ctrl-D 也一樣，只是那裡還有 Ctrl-C；要不要讓取消在這種迴圈裡也出得去，待裁定（D49）。
- `if __name__ == "__main__":` 底下的程式碼和 `run(app)` 都會跑（先最外層、再 `run`）；模組自己定義不收參數的 `def run():` 會被當成處理函式呼叫而出錯。

## 8. 面板與滑鼠操作

### 8.1 原則

除了「幫新模組取名字」和「寫模組的程式碼」，其他事情都不碰鍵盤。對話框裡的 Enter、Esc 是附加的，不是必要的。

這一節講的是預設的網頁面板（M2，`ui/index.html`、`app.js`、`style.css`，Python 那一頭是 `ui/web.py`）。tkinter 面板（安全模式與後備）操作不一樣，放在 §8.7。

### 8.2 面板

```
┌──────────────────────────────────────────────┐
│ iPLoT                                        │  麵包屑：進入「開工」後是 iPLoT ▸ 開工，按任一段回去
├──────────────────────────────────────────────┤
│ ● 這一層  modules/                           │  每一組：顏色點、標題、路徑
│                                              │
│  [🧭]▸     [🧬]      [整]●     [＋]          │  一個模組一格：圖示在上、名稱在下
│  開工     打開核心   整理桌面   新模組        │  ▸（右下角）：底下還有模組，按了進去
│           原始碼                             │  ●（右上角的紅點）：檔案有語法錯誤
│                                              │  每一組最後一格是虛線的 ＋
│ ● 上一層  ../                                │
│                                              │
│  [D]▸      [＋]                              │  沒有圖示的模組：名字第一個字
│ Documents  新模組                            │
├──────────────────────────────────────────────┤
│ 開工  每日入口：一鍵打開 iPLoT 資料夾、…      │  狀態列：選到的模組的名稱與說明
├──────────────────────────────────────────────┤
│ • 已掃描 modules/、../，找到 4 個模組         │  訊息區：一行一條，自動捲到底
│ • 開工 完成（0.3 秒）                         │
│ • 模組『整理桌面』第 7 行出錯：…              │  錯誤：白話那一句，
│                        [打開檔案] [詳細]     │  右邊「打開檔案」與「詳細」
└──────────────────────────────────────────────┘
```

- **視窗**：一個原生視窗，標題 `iPLoT v<版本>`，開起來 820×620、最小 480×420。上到下是麵包屑（`iPLoT ▸ …`，按任一段回去）、可捲動的圖示區、狀態列、訊息區。視窗拉寬，格子自動多排幾格。
- **每一組**：顏色點、標題、路徑。顏色按層：`here` 藍、`parent` 紅、`extra` 綠；進到下一層後只有一組，顏色點是紫（`child`）。路徑是 `modules/`、`../`；`extra` 顯示 `config.py` 裡寫的那個字串；下一層顯示「資料夾名/」。一組沒有任何模組時顯示「尚無模組，按 ＋ 新增」；根目錄讀不到（有 `note`）的那一組顯示原因、沒有 ＋：沒有地方可以建。
- **每個模組一格**：圖示、名稱（最多兩行）。檔案有語法錯誤時右上角有紅點；有子模組時右下角有 ▸，按了進入下一層。沒有子模組的模組沒有 ▸，從右鍵新增第一個（D60）。
- **單擊選取、雙擊執行**（D64，推翻 D13）。單擊只選取：狀態列顯示那個模組的名稱與說明（docstring 第一段；檔案有語法錯誤時顯示錯誤），說明第一次有地方顯示（D33）。沒選任何模組時，狀態列是一句提示。雙擊才執行。點空白的地方取消選取。格子另外設了 `title` 屬性（同一段文字）；滑鼠停著時提示會不會跳出來由系統的 WebView 決定，沒有另外驗過。
- **右鍵選單**六項：執行／進入下一層（有子模組才出現，所以沒有子模組的模組是五項）／打開程式碼／在資料夾中顯示／在終端機打開／在這裡新增下一層模組…。
- **＋**：每一組最後一格是虛線的 ＋（D14 修訂：每一組一顆不變，從標題列搬到最後一格）。按了跳對話框問名字；名字不合規則時，對話框裡顯示規則那一句、不關，不用重打整個名字。規則的本尊在 `core/create.py`；`app.js` 裡有同一套先擋，Python 那邊還會再擋一次。
- **訊息區**：`app.log`、`print` 的輸出、「完成」那一行，一行一條。錯誤先顯示白話那一句，右邊兩顆鈕：「打開檔案」（用編輯器打開出錯的檔案；`config.py` 的 `EDITOR` 設成認得行號的編輯器時，會跳到出錯的那一行）與「詳細」（展開 traceback，再按是「收起」）。自動捲到底；最多留 2000 條；文字可以選取複製。啟動時會記一行「已掃描 …，找到 N 個模組」。
- **執行中**：模組開始執行超過四分之一秒，狀態列右邊顯示「執行中：<名稱>…」，跑完消失（`iplot.busy`）。模組的 `print` 要等它結束才進訊息區；沒有這一行，跑得久的模組看起來像沒按到，使用者會再按一次、多排一次。
- **雙擊的規則**：兩下都落在同一個模組的格子上才算。第一下按的是 ▸、選單項目、對話框的按鈕時，畫面會換，第二下落在哪裡都不算；所以頁面不用瀏覽器的 `dblclick` 事件，看的是 `click` 帶的次數。視窗取得焦點的重掃如果內容沒變就不重畫，不會打斷進行中的雙擊。
- **圖示檔不能用時**：空檔、超過 1 MB、讀不到，Python 那一頭就當作沒有（`icon_for`）；內容不是一張讀得出來的圖（壞了、下載到一半），頁面載入失敗時自己換成預設圖示（`app.js` 的 `iconEl`）。兩種都在訊息區記一行 `icon_unusable`，每個檔一次。
- **視窗關掉之後**，排著還沒做的工作不再做；正在執行的那一個模組會跟著程序一起結束（不能中途停，也不會等它，見 §7 的已知限制）。
- **對話框都在面板裡面**，不另開視窗：新模組的名字、`app.ask`、模組的 `input()` 是一個輸入框加取消／確定；`app.confirm` 只有兩顆鈕。Enter 確定、Esc 取消；中文輸入法選字時按的 Enter 不算確定。一次只開一個，後來的排隊。選檔案、選資料夾（`app.choose_files`、`app.choose_folder`）是 pywebview 的原生對話框（D67）。外來模組第一次執行前的那一問（M3，§7 第 7 條）用的就是 `confirm` 這個兩顆鈕的對話框。
- **另開視窗的只有一種**：模組用 `app.page` 開的那一頁（M3，§6.2），例如「工作坊」的清單頁。它是第二個原生視窗，640×520，關掉才回到模組；它開著的時候主面板顯示「執行中」。
- **圖示來源的順序**（D65）：① 模組資料夾裡的 `icon.png` 或 `icon.svg`——檔名要一字不差（`Icon.png` 不算），兩個都有用 png，不超過 1 MB；② `iplot.py` 頂層的 `ICON = "🧩"`，一個 emoji，只認字串常數；③ 都沒有：顯示名稱的第一個字。②、③ 的底色，色相由資料夾名稱算出來，同一個模組每次顏色都一樣。圖檔超過 1 MB 或讀不到：當作沒有（往下用 ②、③），訊息區記一行，每個檔每次啟動只說一次。圖檔換了，點回視窗就換。
- **重掃**：視窗取得焦點就重掃（D11，由頁面的 `focus` 事件觸發）：在檔案總管新增、刪掉、改了模組，點回來就看得到。內容沒變就不重畫。
- **外觀**：深色模式跟系統。`ui/style.css` 開頭是顏色與尺寸的變數，其餘規則只用變數，改顏色、改大小只改那一段。自己的改法放 `iPLoT/custom.css`（跟 `config.py` 同一層；預設沒有這個檔，沒有也沒關係）：它在 `style.css` 之後載入，同名的變數以它為準，更新不會動它。
- **零外部資源**：三個檔沒有任何外部網址——沒有 CDN、沒有網路字型、沒有函式庫；不用框架、不用 build。畫面上的字全部來自 `core/text.py`，啟動時由 Python 整份送進頁面，`app.js` 裡沒有中文字串（註解是中文）。這幾條由 `tests/test_boundaries.py` 擋（§10）。
- **不做**：動畫、拖曳排位置、搜尋。拖檔案到圖示上還沒做（§8.6）。

### 8.3 動作對應

網頁面板的每個動作：頁面呼叫 `Bridge` 的哪個方法（`pywebview.api.<方法>`），那個方法在工作執行緒上再叫 `Core` 的哪個方法。標「還沒做」的列是原本排在 M2、0.4.0 與 0.5.0 都沒有做的，面板上現在沒有這些項目。

| 動作 | 頁面呼叫 `Bridge` 的 | 到 `Core` 發生什麼 | 里程碑 |
|---|---|---|---|
| 單擊模組 | —（只在頁面上） | 選取；狀態列顯示名稱與說明：`ModuleInfo.description`（docstring 第一段），檔案有語法錯誤時顯示錯誤（D33、D64） | M2 |
| 雙擊模組；右鍵 → 執行；焦點在格子上時按 Enter | `press(id)` | `core.press(info)` | M1 是單擊；M2 改成雙擊 |
| 按 ▸；右鍵 → 進入下一層 | `enter(id)` | `core.enter(info)`；麵包屑可回 | M1 |
| 按麵包屑的某一段 | `back(depth)` | `core.back(depth)`；0 是頂層 | M1 |
| 按 ＋ | 對話框問名字 → `create(那一組的 root, 名字)` | `core.create(root, 名字)` → 重掃 → `core.action("edit", …)` 打開新的 `iplot.py` | M1 |
| 錯誤的「打開檔案」 | `open_error(錯誤的編號)` | `core.action("edit", file, editor, line)` | M1 |
| 錯誤的「詳細」／「收起」 | —（只在頁面上） | 展開或收起 traceback | M2 |
| 視窗取得焦點 | `rescan()` | `core.rescan()`。在 Finder 建資料夾、點回來，圖示就在 | M1 |
| 右鍵 → 打開程式碼 | `action("edit", id)` | `core.action("edit", info.file, editor, None)` | M1 |
| 右鍵 → 在資料夾中顯示 | `action("reveal", id)` | `core.action("reveal", info.folder)`（標籤是中性詞，D55） | M1 |
| 右鍵 → 在終端機打開 | `action("terminal", id)` | `core.action("terminal", info.folder)` | M1 |
| 右鍵 → 在這裡新增下一層模組… | 對話框問名字 → `add_child(id, 名字)` | `core.create(模組資料夾, 名字)` → 重掃 → `core.action("edit", …)` 打開新的 `iplot.py`；跟按 ＋ 同一條路，只是建在這個模組的資料夾裡。沒有子模組的模組靠這一項長出第一個子模組，重掃後它的圖示上出現 ▸（D60） | M1 |
| `app.ask`、模組的 `input()`、`app.confirm` 的對話框按確定／取消 | `answer(編號, 值)` | 不經過工作執行緒：直接把答案交給等在 `view.ask`／`view.confirm` 的那一方。新模組取名字的對話框不走這裡：按確定是上面的 `create`／`add_child`，按取消什麼都不呼叫。外來模組第一次執行前的那一問也是 `view.confirm`，走的是這一列（M3） | M2 |
| 右鍵 → 選擇檔案後執行… | 還沒做 | `view.choose_files` → `core.press(info, "on_files", (paths,))`。只在 `accepts_files` 時出現 | M2 後段 |
| 把檔案拖到圖示上 | 還沒做 | 同上。怎麼做見 §8.6 | M2 後段 |
| 右鍵 → 回到上一版… | 還沒做 | 列出 `history.versions`，選一個 → `history.restore` → 重掃 | M2 後段 |
| 右鍵 → 重新命名… | 還沒做 | `view.ask` → 改資料夾名稱 → 重掃 | M2 後段 |
| 右鍵 → 設為／取消自動啟動 | 還沒做 | 在模組資料夾放／拿掉空檔案 `autostart` | M2 後段 |

`Bridge` 的第十個方法 `state()` 回目前的範圍（跟 `iplot.show` 收到的一樣），頁面現在沒有用到。tkinter 面板（安全模式與後備）沒有 `Bridge` 這一層，按鈕直接叫同一個 `Core` 方法；它有哪些動作見 §8.7。

M3 沒有給 `Bridge` 加方法（還是十個），面板本體的三個檔也沒有動。「工作坊」清單頁上的按鈕不在這張表裡：那一頁是模組用 `app.page` 開的第二個視窗，按鈕呼叫的是模組自己給的 `Api.install`，不經過 `Bridge`、也不經過 `Core`（§9.3）。

### 8.4 自動啟動（還沒做，D39）

M1、M2（0.4.0）、M3（0.5.0）都沒做，排在 M2 後段。「空檔案當標記」這一招，0.5.0 先用在 `.unconfirmed` 上了（D73，§7 第 7 條）。設計不變：標記是模組資料夾裡的空檔案 `autostart`：滑鼠切換時核心只建檔或刪檔，不改任何 Python 原始碼；Finder 看得到；`--safe` 一律略過。啟動時 `core.autostart` 對每個有標記的模組逐一 `press`，壞一個不影響其他的；時機在面板畫好之後，所以錯誤進面板（原設計寫的是 tkinter 的 `after(0)`；在網頁面板裡怎麼排，做的時候再定）。

### 8.6 拖放（M2 後段）

把檔案拖到圖示上還沒做，延到 M2 後段：要先看 pywebview 的拖放支援再定做法。同一件事的另一條路——右鍵「選擇檔案後執行…」——也還沒做（§8.3）。

原本的做法是可選依賴 `tkinterdnd2`，那一段程式還留在 `ui/tk.py` 的 `_make_root`：安全模式完全不載入 `tkinterdnd2`；否則 `try: from tkinterdnd2 import TkinterDnD`，成功就以 `TkinterDnD.Tk()` 當主視窗，`ImportError` 就用 `tkinter.Tk`。`TkinterDnD.Tk()` 本身丟 `RuntimeError`／`TclError`（原生 tkdnd 載入失敗）時，視窗其實已經建好，就直接用那個視窗、只是沒有拖放；不 destroy 重建（D42）。0.4.0 的 `main.py` 只會以安全模式開 tkinter 面板，「否則」那一支從 `main.py` 走不到。0.5.0 起後備面板不是安全模式（`Panel(safe=False)`），所以後備面板開起來時會走到這一支：這個 Python 剛好裝了 `tkinterdnd2` 就拿 `TkinterDnD.Tk()` 當主視窗，沒裝就是一般的 `tkinter.Tk`。兩種都一樣沒有拖放——這個面板從來沒有註冊過拖放（`tests/test_tk_smoke.py::test_dnd_skipped_in_safe_mode_and_failure_falls_back` 驗的是：安全模式連 import 都不做；不是安全模式而 `tkinterdnd2` 載入失敗時，直接用建到一半的那個視窗）。

### 8.7 安全模式與後備：tkinter 面板

tkinter 面板（`ui/tk.py`，原 `core/ui.py`）在兩種情況出現。0.4.0 這兩種是同一回事（後備就是安全模式）；0.5.0 起分開（D75）：

| | 安全模式 | 後備面板 |
|---|---|---|
| 怎麼來的 | `python3 main.py --safe` | 網頁面板開不起來時自動改用（§7） |
| 掃哪裡 | 只掃 `modules/` | 完整範圍：上一層與 `ROOTS`，跟網頁面板一樣 |
| 視窗標題 | `iPLoT v<版本>（安全模式）` | `iPLoT v<版本>` |
| `lib/` | 不需要、不檢查、不重裝 | `lib/` 裡的網頁面板開不起來才會到這裡 |
| 訊息區開頭多一行 | 沒有 | 為什麼改用這個面板（`web_failed` 或 `install_failed` 那一句，主控台也印一次） |
| 用途 | 核心或面板改壞了的最後一道門 | 網頁面板裝不起來的電腦、還沒有網頁面板的平台（Linux）照樣能用 |

分開之後，網頁面板裝不起來的電腦與 Linux 上，放在上一層與 `ROOTS` 的模組照樣看得到；0.4.0 在這些情況只看得到 `modules/` 裡的。兩種的操作完全一樣，都跟 0.3.0 一樣，沒有跟著 D64 改——「單擊選取、雙擊執行」只在網頁面板：

```
┌ iPLoT v0.5.0（安全模式）───────────┐
│ [ iPLoT ]                          │   麵包屑：一排按鈕，點任一段回上去；
│ 這一層                        ＋   │   進入「開工」後是 [ iPLoT ] ▸ [ 開工 ]
│   [ 開工            ]  ▸           │   安全模式只有「這一層」這一組（後備面板還有「上一層」等）；＋ 在標題右邊
│   [ 打開核心原始碼  ]              │   ▸ 是獨立的小按鈕：底下還有模組，按下進入
│   [ ⚠ 整理桌面      ]              │   ⚠ 在按鈕文字前：語法錯誤，按下去看錯在哪
├────────────────────────────────────┤
│ …traceback…                        │   訊息區：錯誤和 app.log 都在這；
│ 模組『整理桌面』第 7 行出錯：       │   先 traceback、再白話那一句、
│ NameError，name 'x' is not defined  │   最後「打開檔案」，捲到底看到的是人話
│ [ 打開檔案 ]                        │
└────────────────────────────────────┘
```

- 單一視窗、單一欄的按鈕、可捲動。**單擊就執行**；沒有選取、沒有狀態列、沒有圖示。
- 右鍵四項：打開程式碼／在資料夾中顯示／在終端機打開／在這裡新增下一層模組…。右鍵選單同時綁 `<Button-2>`、`<Button-3>`、`<Control-Button-1>`：macOS 上 Tk 8.6 的右鍵是 Button-2，Tk 9.0 是 Button-3。
- ＋ 在每一組標題的右邊；根目錄讀不到（有 `note`）的那一組不顯示 ＋：沒有地方可以建。一組沒有任何模組時顯示「尚無模組，按 ＋ 新增」。
- 顏色按層：`here` 藍、`parent` 紅、`extra` 綠、`child` 沿用進入前那一層的顏色（安全模式只掃 `modules/`，所以看到的都是藍；後備面板三種都看得到）。
- 對話框是 tkinter 的：`ask` 用 `simpledialog`，`confirm` 用 `messagebox`，選檔案、選資料夾用 `filedialog`。外來模組第一次執行前的那一問（§7 第 7 條）在這裡就是 `messagebox` 的「確定／取消」。
- 沒有頁面（M3）：`app.page` 在這個面板只在訊息區記一行 `page_unsupported`（`tests/test_tk_smoke.py::test_page_logs_unsupported`）。所以在這裡按「工作坊」看不到清單頁；「更新」只用到 `app.confirm` 與 `app.log`，不需要頁面。`page_unsupported` 那一句是「這個面板沒有頁面（安全模式與備用面板都是）；這個功能要在一般的網頁面板裡用」，兩種 tkinter 面板顯示的都是這一句。
- 跟後備面板有關的幾句文字都分清楚了安全模式與後備面板（字面上叫「備用面板」），不再叫人改用安全模式：上面那一句 `page_unsupported`；`install_failed` 的結尾「現在先改用備用面板」；連 tkinter 都沒有時印的 `no_tk`（「這個 Python 沒有 tkinter，安全模式與備用面板都開不了；請用 python.org 的版本」）；Linux 的原因（`modules/作業系統/linux.py`：「這一版的網頁面板還不支援 Linux」）；Windows 缺 WebView2 時的原因（`win.py`：「找不到 WebView2 runtime：請先安裝 Microsoft Edge WebView2 Runtime（Windows 11 內建）」，未經實機驗證）。
- 模組在主視窗的執行緒上執行，跑很久會凍住視窗（§7 已知限制）。
- 需要 tkinter（python.org 的 Python 內含）。這個 Python 沒有 tkinter 時，印一句說明、以代碼 1 結束。

## 9. 版本管理

### 9.1 開發端：git

- iPLoT 自己是一個 git repo，建在 `6000_work/iplot`。老闆的 `iPLoT.py`、`iPLoT.txt` 移到 `docs/original/`，連同 `00_現況分析.md`、`01_從零啟動.md` 與 `docs/original/step1_patched/`（步驟 1 修補實驗的對照組）當第一個 commit，打 tag `v0.0-original`。外層 `6000_work` 若本身是 repo，把 `iplot/` 加進它的 `.gitignore`。
- `main` 永遠可以啟動：合進 `main` 的每個 commit 都要通過 §12 的從零啟動情境，CI 擋。
- 語意化版本：`core/__init__.py` 的 `__version__`，顯示在視窗標題；`CHANGELOG.md` 照 keep-a-changelog；`app.api_version` 獨立計。
- 功能分支短命，合回 `main` 就刪；一個人開發也走 PR，PR 頁面就是設計決定的紀錄。還沒有遠端時（M1）在本地分支 `m1-seed` 開發，v0.1.0 時 `git merge --no-ff` 回 `main` 再打 tag（D30）。
- `.gitignore`：`logs/`、`lib/`（M2：第一次啟動裝進來的套件不進 repo）、`.history/`、`__pycache__/`、`.DS_Store`，以及開發工具的快取。M3 執行時才出現的 `.backup/`、`.update-tmp/`、`.update-old-…`、`modules/.workshop-tmp/`，與工作坊寫的 `.origin`、`.unconfirmed`，沒有列在裡面：在開發用的這個 repo 裡按「更新」或用工作坊裝模組，`.backup/`、裝進來的模組資料夾與它的 `.origin`、`.unconfirmed` 會出現在 `git status`（兩個暫存資料夾做完就清掉，平常看不到；`.update-old-…` 只有換下來的舊版刪不掉時才會留著）。發佈工具的輸出 `交付/` 不進 git，列在這個 repo 自己的 `.git/info/exclude`。

### 9.2 使用者端：`history.py`

- 時機：每次執行前 `snapshot`；每次 `restore` 前也先 `snapshot`，所以復原本身可以再復原。
- 位置：`<模組>/.history/2026-10-02_140905.py`。藏在模組自己的資料夾裡，刪模組就一起消失。
- 去重：跟最新一份比 sha256，相同就不存。保留份數 `HISTORY_KEEP`，超過刪最舊的。只認自己命名的檔案（`YYYY-MM-DD_HHMMSS[_n].py`）；`.history/` 裡別的檔案不比對、不刪（D44）。
- 復原：右鍵「回到上一版…」（§8.3）。
- 範圍：只管模組。核心或面板改壞了靠 git（`git checkout -- core/ ui/`）；第一版不做滑鼠版的核心復原。
- 工作坊覆蓋模組之前存的 `<日期時間>-folder.zip`（M3，§9.3）也放在 `.history/`，但不歸 `history.py` 管：`history.py` 只認自己命名的 `.py`，不會把它列成上一版，也不會因為 `HISTORY_KEEP` 把它刪掉。要拿回來，用手把那個 zip 解開。

### 9.3 更新與工作坊（M3，0.5.0）

§9.1 管開發端的版本，§9.2 管一個模組的上一版。這一節管另外兩件事：核心的新版怎麼進到一台已經在用的 iPLoT（「更新」），別人做的模組怎麼裝進來、怎麼換新版（「工作坊」）。兩件事都由隨附模組做（原則 1），核心不連網；核心為它們加的只有：從 `config.py` 多讀兩個網址（§6.4）、`app.config`、`app.version`、`app.page`（§5.3）與 `.unconfirmed` 的檢查（§7 第 7 條）。原始的設計在 `docs/plans/2026-10-05-M2-網頁面板與更新.md` §13；實作時定下來、跟那份設計不一樣的地方，以這一節與程式為準。

**設定與來源（D71）。** `config.py` 有兩行：`UPDATE_URL`（`update.json` 的網址）、`WORKSHOP_URL`（`index.json` 的網址），預設都是 `None`。

- 平常使用不需要網路。沒設定時，按「更新」或「工作坊」各只在訊息區說一句怎麼設定：不連網、不開頁面、不寫任何檔（`tests/test_bundled.py::test_update_and_workshop_do_nothing_until_a_url_is_set`）。
- 設定了也只有按下去才連網；iPLoT 不會自己去看有沒有新版。
- 網址可以是 `https://` 或 `file://`。網址裡的中文與空白，兩個模組打開之前會先寫成 %XX（`tests/test_update.py::test_fetch_json_from_file_url_with_spaces_and_chinese`）。
- 開網址時兩個模組自己帶一個 `ssl` context（`update._context()`、`workshop._context()`）：python.org 的 macOS Python 預設沒有根憑證（要另外執行「Install Certificates.command」），那樣每個 `https://` 網址都驗證失敗；憑證庫是空的時候改用 macOS 自己的 `/etc/ssl/cert.pem`。驗證本身不關（`tests/test_update.py::test_https_open_brings_a_trust_store`、`tests/test_workshop.py::test_https_open_brings_a_trust_store`）。

**兩個 JSON 的格式。**

```
update.json = {"version": "0.5.1", "zip_url": "…/iPLoT-v0.5.1.zip", "sha256": "<那個 zip 的 sha256>",
               "notes": "這一版改了什麼"}
index.json  = {"modules": [{"name": "整理桌面", "version": "1.0.0", "zip_url": "…/整理桌面.zip",
                            "sha256": "<那個 zip 的 sha256>", "description": "一句話", "icon": "🧹"}, …]}
```

- `update.json`：`version`、`zip_url`、`sha256` 必要，而且都要是文字（`null`、數字都不行；`version` 也不會被轉成字串），`notes` 可省略。這三項在比版本之前就檢查（`update.check`），所以少了一項的 `update.json`，就算已是最新也會說少了哪一項。zip 就是交付用的包：最上層剛好一個資料夾（`iPLoT-vX.Y.Z/`），裡面 `core/`、`ui/`、`main.py`、`requirements/` 四樣都要有。
- `index.json`：每一筆的 `name`、`version`、`zip_url`、`sha256` 必要（任何一筆缺項，整份索引算格式不對，`tests/test_workshop.py::test_read_index`），`name`、`zip_url`、`sha256` 要是文字，`version` 一律當字串讀，同一個名字出現兩次只留第一筆（`::test_read_index_checks_the_types`）；`description`、`icon`、`notes`（這一版改了什麼，D78）可省略。每個模組的 zip 最上層剛好是 `<name>/`，裡面要有 `iplot.py`。
- 版本怎麼比：用 `.` 切開，一段一段當整數比（`0.10.0` 比 `0.9.9` 新）；看不懂的版本號一律當作「不比較新」（`tests/test_update.py::test_newer`）。

**「更新」的流程（`modules/更新`，D69）。**

1. 沒設 `UPDATE_URL` → 說一句，結束。
2. 抓 `update.json`，先檢查三項（`update.check`，見上面）；再拿它的版本跟**磁碟上**的版本（`core/__init__.py` 裡的 `__version__`）比。不比較新 → 「已是最新（x.y.z）」。磁碟上的版本跟執行中的不一樣（剛更新完、還沒重新啟動又按一次）→「已經換成 x.y.z 了，執行「重新啟動」就會用新版」，不再下載、不再備份、不再換一次。
3. 比較新 → `app.confirm` 顯示新版本、現在的版本（磁碟上的那一個）與 `notes`。按取消 → 「已取消更新」，什麼都不動。
4. 按確定 → 下載到 `.backup/download-<版本>.zip`，邊下載邊算 sha256。對不上 → 刪掉下載的檔、說一句，四樣都不動，也不備份。
5. 把現在的 `core/`、`ui/`、`main.py`、`requirements/` 複製到 `.backup/<舊版本>-<日期時間>/`（`__pycache__` 不帶；舊版本也是磁碟上的那一個——剛更新完沒重新啟動時，執行中的 `app.version` 還是更舊的）。
6. 先收拾上一次留下的殘餘（`_restore`）：還有任何 `<名稱>.new`，表示上一次沒換完，留著的 `<名稱>.old` 全部放回去，最後才丟 `.new`（放回的途中又被強制結束，下一次還看得到 `.new`）；一個 `.new` 都沒有，表示上一次已經全部換好、只是舊版沒刪乾淨，那些 `.old` 不放回去，跟著丟掉。把 zip 解到 `.update-tmp/`；四樣各先搬成 `<名稱>.new`，再照 `ui`、`main.py`、`requirements`、`core` 的順序（`ORDER`）逐一改名換上去：舊的先改名成 `<名稱>.old`，新的換上去；四樣全部換完才丟掉 `.old`。丟的做法（`_discard`）：每個 `<名稱>.old` 先在原地改名成 `.update-old-<名稱>-<n>`，再刪掉（改名留在同一層：整個唯讀的資料夾搬不進別的資料夾底下，同一層改名可以）；刪不掉的（例如唯讀的子資料夾）留著那個名字，不再叫 `<名稱>.old`，下一次更新不會把它當成舊版放回去，開頭會再刪一次；換完之後丟舊版出錯不算更新失敗。最後清掉 `.update-tmp/`。換的途中出任何檔案錯誤（`OSError`）：已經換上去的全部放回、`.new` 丟掉，四樣要嘛全新、要嘛全舊（放回本身也出錯時做不到，那一句會照實說），然後那個錯交給 `iplot.py` 說成一句話（見下面）。`core/` 最後換，所以「磁碟上的版本是新的」就代表四樣都換好了，第 2 步那句「已經換成 x.y.z 了」不會騙人。
7. 訊息區：「已更新到 x.y.z，執行「重新啟動」就會用新版。舊版備份在 .backup/…/」。

「更新」的不變量與擋住它的測試（都在 `tests/test_update.py`；在暫存目錄裡的假 iPLoT 上做，來源用 `file://` 網址，不連網）：

| 不變量 | 測試 |

| 只換四樣，而且是整個換掉、不是疊上去；`config.py`、`custom.css`、`modules/`（含各模組的 `.history/`）、`logs/`、`lib/` 逐位元組不變；包裡夾帶的 README、`modules/`、`config.py` 不套用；iPLoT 資料夾以外沒有任何寫入；做完沒有 `.update-tmp/`，也沒有 `.new`、`.old` 殘留 | `test_apply_replaces_only_parts_and_keeps_rest` |

| 換之前的四樣在 `.backup/<舊版本>-…/` 裡；同一秒內備份兩次不會撞名；舊版本用的是磁碟上的版本 | `test_backup_has_old_parts`、`test_run_updates_backs_up_and_says_restart`、`test_backup_is_named_after_the_version_on_disk` |
| sha256 對不上：下載的檔刪掉，四樣都不動，也不備份 | `test_download_verifies_sha`、`test_sha_mismatch_touches_nothing` |
| 包不完整（四樣少一樣）或最上層不只一個資料夾：一樣都不換 | `test_apply_refuses_a_zip_without_all_four_parts`、`test_apply_refuses_a_zip_with_two_top_folders` |

| 已經是最新：不問、不下載、不備份 | `test_run_when_already_latest` |
| 還沒重新啟動又按一次：不再下載、不再備份、不再換 | `test_update_twice_second_is_noop` |
| 出錯是訊息區的一句白話，不是 traceback：`update.json` 不是 JSON、不是一個物件、缺項；`version`、`zip_url`、`sha256` 不是文字（五種：`zip_url` 是 `null` 或數字、`sha256` 是 `null`、`version` 是 `null` 或數字）；連不上；連線到一半斷掉、伺服器沒回話、逾時；網址寫錯；下載到的不是 zip | `test_bad_update_json_is_one_plain_sentence`、`test_wrong_types_in_update_json_are_one_sentence`、`test_unreachable_source_is_one_plain_sentence`、`test_dropped_connection_is_one_plain_sentence`、`test_mistyped_url_is_blamed_on_the_url`、`test_not_a_zip_is_one_plain_sentence` |
| 備份或換上去的時候出檔案錯誤（權限、磁碟滿）也是一句話，照磁碟上的實況說：都放回了就說四樣都還是原來的；放回也出錯就不說放回了，說哪些要用手整理、舊版的備份在哪裡 | `test_a_failed_swap_is_one_sentence_and_everything_is_put_back`、`test_a_failed_backup_is_one_sentence`、`test_when_putting_back_fails_too_the_sentence_does_not_say_it_was_put_back` |
| 開 `https://` 網址時帶著憑證庫，驗證不關 | `test_https_open_brings_a_trust_store` |

- 順序是下載 → 備份 → 換。sha256 在備份之前就驗了；但「不是 zip」「包不完整」要到換的那一步才看得出來，這兩種情況四樣都沒動，`.backup/` 裡會留下剛做的那一份備份與下載的檔。
- 連網那一段（讀 `update.json`、下載）接住的是 `update.NETWORK`（`OSError` 與 `http.client.HTTPException`：連不上、逾時、連到一半斷掉、伺服器沒回話都在裡面），都是一句「連不上更新來源，或下載到一半斷了，沒有更新：…」；網址寫錯（`http.client.InvalidURL`）是「網址寫錯了，沒有更新：…（看 config.py 的 UPDATE_URL，或 update.json 裡的 zip_url）」。`update.json` 少了一項（例如 `zip_url`）是「更新來源的 update.json 少了 'zip_url' 這一項，沒有更新」；三項不是文字是「沒有更新：update.json 裡的 version、zip_url、sha256 應該都是文字（update.json 或下載的檔案有問題）」。換上去那一段的錯（不是 zip、包的內容不對）各是一句。備份或換檔途中的檔案錯誤（`OSError`，例如磁碟滿了、沒有權限、檔案被佔著）也是一句，不是模組錯誤：`apply` 先把換到一半的全部放回，`iplot.py` 再看磁碟上的實況（`update.unfinished(home)`：還在的 `<名稱>.old`、`<名稱>.new`，與不見了的那幾樣）。都沒有 → 「沒有更新：<錯誤>。core/、ui/、main.py、requirements/ 都還是原來的」；有 → 「沒有更新，而且放回原來的版本時出錯了：<錯誤>。<留下的東西，用「、」隔開> 要用手整理（舊版的備份在 .backup/<資料夾>/，做法見 README 的「怎麼回到舊版」）」，備份本身就失敗時括號裡是「這一次沒有做成備份」。
- 不是熱更新：換完之後執行中的程式還是舊的，要執行「重新啟動」才用新版；重新啟動換了一個程序，所以 `app.memory` 是空的，檔案都在。新版的需求檔跟舊的不一樣時，下一次啟動會重裝 `lib/`；那時候沒有網路的處理見 §7。
- 回到舊版：沒有一鍵回溯。把 `.backup/<舊版本>-<日期時間>/` 裡的四樣用手搬回去，再重新啟動。`.backup/` 不會自己清，每更新一次多一份。
- 還留著的缺口：四樣是逐一改名換上去的，不是一次全換。真的在兩次改名之間被強制結束（毫秒級的空檔），磁碟上會暫時是新舊混合，要到下一次按「更新」，開頭的 `_restore` 才收回來（那一段有測試，見上表）；iPLoT 啟動時不檢查這件事。如果剛好停在同一樣的兩次改名之間（舊的已經改名成 `<名稱>.old`、新的還沒換上去），那一樣在原來的名字下是不見的：少的是 `core/`、`ui/` 或 `main.py` 的話，iPLoT 開不起來，也就按不到「更新」，要用手整理：照 README 的「怎麼回到舊版」把 `.backup/` 裡那一份搬回去，留下的 `<名稱>.old`、`<名稱>.new` 刪掉。後面這一種是照程式推的，沒有測試，也沒有實際遇過；決定不改程式、不加啟動時的檢查（記在 `05_使用紀錄.md` 的待辦）。
- 另外兩件還沒處理，也記在 `05_使用紀錄.md` 的待辦：第 5 步的備份在第 6 步收拾殘餘之前，所以上一次換到一半被強制結束的話，這一次的備份是新舊混合、名字卻標成舊版本；iPLoT 資料夾裡自己放的、剛好叫 `core.old`、`ui.new`、`.update-old-…` 這類名字的東西，會被當成「更新」自己的殘餘，換進去或刪掉。
- 「更新」不碰 `modules/`，所以隨附模組（包括「更新」自己）不會跟著核心換。開工、打開核心原始碼、開Terminal、重新啟動的新版可以從工作坊來；「作業系統」「更新」「工作坊」工作坊不覆蓋（見下面「隨附模組與工作坊」），要換新版只能自己把新的資料夾複製進 `modules/`。

**「工作坊」的流程（`modules/工作坊`，D70、D74）。** 按「工作坊」→ 沒設 `WORKSHOP_URL` 就說一句、結束 → 抓 `index.json`（連不上、不是 JSON、格式不對、`WORKSHOP_URL` 寫錯：說一句，不開頁面）→ 用 `app.page` 開清單頁（`page.html`，零外部資源）。清單頁每個模組一列：圖示、名稱、說明、索引的版本、在這台電腦上的狀態、一顆按鈕（「隨附模組」那一列沒有按鈕，多一句說明）。關掉清單頁 → `app.rescan()`，新裝的模組出現在面板上。

六種狀態（`workshop.state`）：

| 程式裡的名字 | 清單頁顯示 | 什麼情況 | 按鈕 |
|---|---|---|---|
| `bundled` | 隨附模組 | 名稱是「作業系統」「更新」「工作坊」之一（`BUNDLED`，iPLoT 自己要用的隨附模組）；最先看這一條，資料夾在不在都一樣 | 沒有；那一列多一句「這是 iPLoT 自己要用的隨附模組，工作坊不覆蓋它；要換新版，自己把新的資料夾複製進 modules/。」 |
| `absent` | 未安裝 | `modules/<name>/` 不存在 | 安裝 |
| `installed` | 已安裝 | 有 `.origin`、當初裝進來的那些檔跟安裝完當下一樣、索引的版本不比它新（一樣，或比較舊） | 沒有 |
| `update` | 可更新 | 有 `.origin`、當初裝進來的那些檔沒變、索引的版本比較新 | 更新 |
| `modified` | 已修改 | 當初裝進來的那些檔有被改過或刪掉（不管版本），或 `.origin` 壞了（讀不懂、缺項） | 覆蓋 |
| `unknown` | 版本未知 | 資料夾在但沒有 `.origin`：自己建的同名模組，或其他四個隨附模組（開工、打開核心原始碼、開Terminal、重新啟動） | 覆蓋 |

- 「有沒有變」比的是當初裝進來的那些檔的摘要（下面的 `digest`）。跑過、確認過都不算變：`.history/`、`__pycache__`、`.unconfirmed` 都不在那份清單裡；模組自己存的設定、資料（清單以外的檔）也不算改過。
- 索引的版本比這台電腦上的舊時算「已安裝」：工作坊不叫人降版。
- 「覆蓋」先在同一列問一次：第一次按，按鈕變成「確定覆蓋」與「取消」，旁邊一句「這會覆蓋現有的模組，舊版會整個存進它的 .history/」；再按「確定覆蓋」才做；按「取消」回到只有原來那一顆按鈕的樣子，字也是原來的（「覆蓋」或「更新」），下次按一樣先問（頁面不重新載入：用 html 字串開的頁，一重新載入就變成空白頁）。這個確認在清單頁裡做，不用面板的 `app.confirm`——那個對話框會開在主視窗，被清單頁擋在後面。Python 這一頭也擋：`Api.install(name, confirmed=False)` 遇到「已修改」「版本未知」而沒帶 `confirmed` 時，回「需要確認」，什麼都不動；頁面收到這個回答就在那一列重新問。
- 「更新」平常直接裝，但包裡的檔放上去會蓋掉或拿掉模組自己存的檔（不在 `.origin` 的 `files` 清單裡的本機檔）時，也先問（D77）：`install` 下載、解開之後看出這件事，丟 `NeedsConfirmation`，`Api.install` 回「需要確認」，模組資料夾一個位元組都不動；清單頁在那一列問，問法跟「覆蓋」一樣；按「確定覆蓋」帶著 `confirmed` 再裝一次（會再下載一次），裝之前整個舊資料夾照舊存進 `.history/`。包裡的檔只蓋到當初裝進來的那些，就不多問。
- 清單頁的 JS 能呼叫的 Python 只有 `Api.install` 一個。它不丟例外：出錯回一句「無法安裝：…」，顯示在那一列，按鈕可以再按。連線到一半斷掉、伺服器沒回話、寫檔出錯（那一句照實說放回原樣了沒有，見下面）、索引那一筆的型別不對、名稱是「作業系統」「更新」「工作坊」之一，都是這樣；JS 那一頭的錯誤也顯示成「無法安裝：…」。
- 兩列同時按會排隊：`Api` 裡有一把鎖，安裝一次只做一個（兩個安裝共用暫存資料夾）。
- 索引是從網路來的：名稱、說明、版本、圖示在清單頁一律當文字顯示，不當 HTML。

**安裝的規則（`workshop.install`）。** 安裝、更新、覆蓋是同一個函式，依序：

1. 名稱要是單純的資料夾名：不是空的、不以 `.` 開頭、不含 `/` 與 `\`。名稱是「作業系統」「更新」「工作坊」之一不裝（「「<名稱>」是 iPLoT 自己要用的隨附模組，工作坊不覆蓋它」）：比對前先 Unicode NFC 正規化、不分大小寫，資料夾在的話再問檔案系統是不是同一個資料夾，所以相容表意字（U+F901 就是「更」）、大小寫不同的寫法也擋得住；這三個資料夾被刪掉了，也不從工作坊裝回來。`modules/<name>` 本身是符號連結就不裝。
2. 下載到 `modules/.workshop-tmp/`，驗 sha256。
3. 看包：每個成員都要在 `<name>/` 底下、路徑裡不能有 `..`、要有 `<name>/iplot.py`。
4. 從工作坊裝過（有 `.origin`）而沒帶 `confirmed`：看包裡的檔放上去，會不會蓋掉或拿掉不在 `.origin` 的 `files` 清單裡的本機檔（`_clashes`）——同名的檔（蓋掉）、同名的資料夾（整個拿掉）、擋在要建資料夾的地方的檔。會的話丟 `NeedsConfirmation`，先問過才裝（D77）。比對的是路徑；只差大小寫的，在 macOS 上也算蓋到。`.origin` 壞了的不看這一步：它是「已修改」，`Api.install` 本來就先問。
5. 資料夾已經在：先把整個資料夾（`.history/` 自己除外）壓成 `modules/<name>/.history/<日期時間>-folder.zip`。這一步出錯（`OSError`）：寫到一半的 zip 刪掉，丟 `NotInstalled`「<錯誤>；沒有裝成，還沒動到資料夾（存快照時出錯）」。
6. 先放標記：包裡與磁碟上（模組資料夾底下）每一個有 `iplot.py` 的資料夾都建空檔案 `.unconfirmed`，然後才放程式。所以下一層的子模組第一次執行前也會問；新的包只帶下一層模組旁邊的 `helper.py`、不帶它的 `iplot.py` 時，那個上一版裝的、確認過的資料夾也重新要問——不然執行它，就不經確認跑了新下載的程式。比對的是資料夾裡實際的檔名 `iplot.py`（跟核心的 `scan.is_module` 一樣）；`.history/`、`__pycache__` 這些不裝的名字底下的不算，不順著符號連結。
7. 把包裡的檔案蓋上去。包裡沒有的舊檔案留著——模組自己產生的資料檔不會因為換版而不見；代價是新版拿掉的檔案也會留著（整個舊資料夾反正在第 5 步的 zip 裡）。包裡夾帶的 `.history/`、`.origin`、`.unconfirmed`、`__pycache__`、`.DS_Store` 不裝，比對時不分大小寫（macOS 的檔案系統上 `.Origin` 跟 `.origin` 是同一個名字）。擋路的東西先拿掉：舊版的某個名字是檔案、新版是資料夾（或反過來），照新版的放；模組資料夾裡本來有符號連結的，拿掉連結本身、換成包裡的檔案，不會順著它寫到 `modules/<name>/` 以外。被拿掉的都在第 5 步的 zip 裡。
8. 寫 `.origin`（多一行 `files`：裝進來的檔的清單），清掉暫存。

第 1–3 步任何一步不對：說一句，模組資料夾不動，暫存清掉。第 4 步要先問：模組資料夾一個位元組都不動，暫存清掉，`Api.install` 回「需要確認」。第 6–8 步途中出任何檔案錯誤（`OSError`：磁碟滿、沒有權限、Finder 裡鎖定的檔…）：照第 5 步的快照把模組資料夾放回裝之前的樣子（`_rollback`），原本沒有這個資料夾就整個拿掉。讓安裝失敗的原因（鎖定的檔、唯讀的子資料夾）通常也讓放回時刪不掉、寫不回去，所以放回遇到錯不停下來：能刪的刪，快照裡每個檔都試著解回去，最後逐檔跟快照比（`.history/` 以外的每一個檔，挑法跟快照一樣），一樣才算放回去了。快照資料夾的名字比對不分大小寫：macOS 上模組資料夾裡本來就有的 `.History/`（使用者或別的工具建的）跟 `.history/` 是同一個資料夾，快照就寫在它裡面，存快照、放回原樣、逐檔比對都不碰它。動手刪之前先確定快照讀得到（`zipfile` 的 `testzip`）；讀不到就一樣都不刪。沒放回去時，留下來的每個有 `iplot.py` 的資料夾都放 `.unconfirmed`（裡面可能有新下載的程式）。`install` 丟 `NotInstalled`（`OSError` 的子類別），清單那一列顯示「無法安裝：」加上照實說的那一句：

- 原本有資料夾：「<錯誤>；沒有裝成，已從快照放回」，或「<錯誤>；沒有裝成，放回時出錯，快照在 <快照 zip 的完整路徑>」；快照讀不到時是「<錯誤>；沒有裝成，快照讀不到、沒有放回，資料夾現在是新舊混合：<資料夾路徑>」。
- 原本沒有資料夾：「<錯誤>；沒有裝成，裝了一半的資料夾已經拿掉」，或「<錯誤>；沒有裝成，裝了一半的資料夾拿不掉：<資料夾路徑>」。

放回仍然是「刪掉、再從快照解回去」，不是在 `modules/.workshop-tmp/<名稱>` 組好完整的新資料夾再整個交換；快照也不是一模一樣的複本（指向資料夾的符號連結不在快照裡：擋路而被拿掉的、放回時跟著被刪掉的都回不來；放回時指向檔案的符號連結變成一般檔，執行權限與空資料夾不會回來；逐檔比對只比檔案內容，這些差別不影響「已從快照放回」那一句）。這兩件記在 `05_使用紀錄.md` 的待辦。從工作坊安裝或覆蓋的模組，不管原本是誰做的，都會帶著 `.unconfirmed`：下一次執行前先問一次（§7 第 7 條）。

**`.origin` 的格式與摘要的算法。** `modules/<name>/.origin` 是純文字，一行一個 `key: value`：

```
url: <zip 的網址>
version: 1.0.0
sha256: <zip 的 sha256>
digest: <安裝完當下，files 列的那些檔的摘要>
files: ["helper.py", "iplot.py"]
installed: 2026-10-05 18:30:00
```

- 六個 key：`url`、`version`、`sha256`、`digest`、`files`、`installed`。`files` 是裝進來的檔的相對路徑清單（JSON）。前五項少任何一項（例如沒有 `files` 這一行的 `.origin`），或有一行讀不懂：整個檔當作壞了，狀態是「已修改」。沒有這個檔：狀態是「版本未知」。
- `digest`（`workshop.digest(folder, files)`）：只算 `files` 列的那些檔，照相對路徑排序，一個一個把「相對路徑（UTF-8，用 `/` 分隔）＋一個 0 位元組＋檔案內容＋一個 0 位元組」餵進 sha256；清單裡的檔不見了也照樣算進去（內容換成一個「不見了」的記號）。改一個字、少一個檔，摘要都會變；清單以外的檔（模組自己存的設定、資料）不算（`test_digest_covers_the_listed_files_only`）。
- 不管在哪一層，名字是 `.history`、`.origin`、`.unconfirmed`、`__pycache__`、`.DS_Store` 的（不分大小寫）都不進包、不會被裝，所以也不在 `files` 清單裡：這些是各台電腦自己的東西。`.DS_Store` 在裡面，是因為 Finder 只要打開過資料夾就會寫它；包裡帶著它的話，裝好的模組看一眼就變成「已修改」。
- `tools/publish.py` 打包時略過的是同一組（`publish.SKIP` 與 `workshop.SKIP`，`test_publish_and_workshop_agree` 擋兩邊一樣）。

**隨附模組與工作坊（D74 與它的修訂）。** 隨附模組不帶 `.origin`，分兩種：

- 「作業系統」「更新」「工作坊」是 iPLoT 自己要用的，工作坊不覆蓋（`workshop.BUNDLED`）：列進索引時狀態是「隨附模組」，那一列沒有按鈕，多一句「這是 iPLoT 自己要用的隨附模組，工作坊不覆蓋它；要換新版，自己把新的資料夾複製進 modules/。」；`install` 也拒絕（安裝規則第 1 步）。這三個要換新版，只能自己把新的資料夾複製進 `modules/`（「更新」不碰 `modules/`，D69）；手動複製進來的資料夾沒有 `.unconfirmed`，執行前不會先問。
- 其他四個（開工、打開核心原始碼、開Terminal、重新啟動）列進索引時狀態是「版本未知」，跟自己建的同名模組一樣處理：覆蓋前先問、先把整個資料夾存進 `.history/`。

為什麼那三個不給覆蓋：從工作坊裝的模組都帶著 `.unconfirmed`。拿「作業系統」來說，帶著它的話，交給它的動作（右鍵動作、「打開檔案」）在面板上確認過一次之前每次先問；啟動時要安裝或重裝介面（§7 第 4、6 步），問它的是主控台那一頭，沒辦法回答（`ConsoleView.confirm` 一律回 `False`），會當作取消——第 6 步的安裝當作「不能裝」、改用後備面板，第 4 步的重裝這一次不做。

**發佈工具與放檔案的地方（`tools/publish.py`，開發端）。**

```
python3 tools/publish.py --version 0.5.0 --base-url <放檔案的地方> --modules 整理桌面 開工
```

在 `交付/發佈/` 產生四種東西，最後印出要填進 `config.py` 的兩行（前面沒有空白，可以直接貼上，`tests/test_publish.py::test_printed_config_lines_can_be_pasted`）：

| 產生的檔 | 內容 |
|---|---|
| `iPLoT-v0.5.0.zip` | 核心的包：`git archive` 那個版本的 tag（`v0.5.0`），最上層是 `iPLoT-v0.5.0/`。還沒打 tag 時加 `--ref HEAD`。那個 ref 裡 `core/__init__.py` 的版本要等於 `--version`，不同就停：一句話、結束碼 1、不產生任何檔（`::test_main_refuses_a_package_whose_core_is_another_version`）——不然會產生一個宣稱新版、包裡卻是舊版的 `update.json`，裝了之後永遠「還有新版」。先寫到 `.part` 再改名，`git archive` 失敗不會把同名的舊 zip 蓋成 0 位元組或寫壞（`::test_failed_archive_does_not_destroy_the_previous_zip`：`git show` 照常讀到那一版、`git archive` 寫了一半就失敗，舊 zip 不變、不留 `.part`） |
| `update.json` | 版本、zip 的網址與 sha256；`notes` 取自 `CHANGELOG.md` 那一版那一節的第一段（摘要），不是整節——它整段顯示在「要更新嗎」的對話框裡；找不到那一版就是空字串（`::test_notes_are_the_summary_paragraph`） |
| `模組/<名稱>.zip` | `--modules` 列的每個模組一包，最上層是 `<名稱>/`；`.history/`、`.origin`、`.unconfirmed`、`__pycache__`、`.DS_Store` 不帶，比對時不分大小寫（`::test_skip_ignores_case`） |
| `index.json` | 每個模組的名稱、版本、網址、sha256，以及用 `core.meta.read_meta` 從它的 `iplot.py` 讀出來的說明與圖示、從它的 `CHANGELOG.md` 讀出來的 `notes`（D78）。沒給 `--modules` 時只發佈核心，原本的 `index.json` 不動（`::test_core_only_run_keeps_the_index`） |

- 模組的版本與 `notes` 取自模組資料夾裡的 `CHANGELOG.md`（D78）：最上面那一節的版本號（`[Unreleased]` 不算），與那一節的第一段。沒有這個檔的模組，版本跟 `--version` 一樣、`notes` 是空字串；要另外指定就寫「名稱=版本」（例如 `--modules 整理桌面=1.2.0`）。兩邊都有又不一樣就停：一句話、結束碼 1、不產生任何檔（`tests/test_publish.py::test_module_version_and_notes_come_from_its_changelog`、`::test_conflicting_versions_stop_before_writing_anything`、`::test_modules_without_a_changelog_follow_the_core_version`）。沒有 `CHANGELOG.md`、也不另外指定的話，每發一版，清單上的那個模組在裝過的電腦上都會顯示「可更新」。
- 寫進 JSON 的網址，中文與空白一律寫成 %XX（`tests/test_publish.py::test_main_end_to_end`）；`file://` 的網址照樣打得開（`::test_main_file_base_url_is_kept_openable`）。
- `modules/` 裡沒有的模組、讀不到那個 ref（例如沒有那個 tag）、`git archive` 失敗：說一句，結束碼 1（`::test_main_unknown_module_is_a_plain_error`、`::test_main_ref_defaults_to_the_version_tag`、`::test_failed_archive_does_not_destroy_the_previous_zip`）。
- 工作目錄有還沒 commit 的改動時多提醒一句：核心的包是從 ref 打的，不含那些改動（模組的包含）（`::test_uncommitted_changes_are_mentioned`）。
- 還留著的缺口：模組的包是從資料夾直接打的，沒 commit 的檔、符號連結指到的內容都會進去；zip 的 sha256 跟檔案時間有關，同樣的內容重打一次，sha256 會變。
- `交付/` 不進 git。

放檔案的地方定為 **GitHub 公開 repo 的 raw 網址**：把 `交付/發佈/` 的內容放進一個公開的 repo（例如放在 `發佈/` 資料夾），`--base-url https://raw.githubusercontent.com/<帳號>/<repo>/<分支>/發佈`，`config.py` 填 `UPDATE_URL = "<base-url>/update.json"`、`WORKSHOP_URL = "<base-url>/index.json"`。其他能用 `https://` 直接取檔的地方技術上也行；Google Drive 的分享連結不是直接取檔，不行。在本機試：`--base-url file:///<絕對路徑>/交付/發佈`。

**驗到哪裡，照實說。**

- 自動測試全部用 `file://` 網址，不連網（上面兩張表）。
- 真的視窗只在 macOS、用 `file://` 走過：清單頁三列、安裝後狀態變「已安裝」、覆蓋先問再存快照、關掉清單頁後格子出現、第一次雙擊先問、取消不執行、確定後執行且標記消失、之後不再問；另外走過：裝一個帶下一層模組的包、按 ▸ 進去雙擊子模組會先問、取消就不執行；清單頁的「覆蓋 → 取消」回到原樣、不變成空白頁；更新會蓋掉模組自己存的檔時，按「更新」→ 同一列問 → 取消回到「更新」→ 再按、確定覆蓋 → 已安裝；「作業系統」那一列沒有按鈕、有那一句說明。這些腳本沒有進 repo。
- **`https://` 只驗過「連得上、憑證過得了」**：同一個 raw.githubusercontent.com 的網址，用 Python 預設的設定在這台機器上驗證失敗（`CERTIFICATE_VERIFY_FAILED`），改用 `/etc/ssl/cert.pem` 就成功。更新與工作坊的完整流程只用 `file://` 驗過，**還沒有對真的 GitHub raw 網址跑過**：那個 repo 還沒建，還沒有真的放過檔案。
- 這一版的人工驗收（`docs/plans/2026-10-05-M2-網頁面板與更新.md` 13.6 的 (a)–(g)）還沒做。
- Windows 未經實機驗證。Linux 沒有網頁面板，所以沒有清單頁：設好網址之後按「工作坊」，只會在訊息區看到 `page_unsupported` 那一句；「更新」不需要頁面，但也沒有在 Linux 上跑過。

**大小。** 這些檔不在 §4.2 的預算內，有效行：`modules/更新/update.py` 131、`iplot.py` 43；`modules/工作坊/workshop.py` 289、`iplot.py` 17、`page.html` 81；`tools/publish.py` 111。

**不做。**

- 更新：自動檢查有沒有新版、差異比較、一鍵回溯、熱更新、清理舊的備份。
- 工作坊：移除模組（搬到垃圾桶的右鍵項排在 M2 後段，§8.3）、降版、評分、留言、自動更新、多個索引。
- 兩邊都沒有簽章。sha256 擋的是「下載到的檔案跟 JSON 裡寫的不一樣」（傳壞了、放錯檔）；JSON 本身是從同一個來源抓的，所以它不能證明來源可信。來源網址要填信得過的地方；裝進來的模組第一次執行前會多問一次，但那不是隔離（§7 第 7 條）。

## 11. 工程規範

- Python ≥ 3.10 加 pip（不必是 python.org 的；Homebrew 的照理也行，但實測只跑過 python.org 的）。tkinter 不再是必要的，只有安全模式與後備需要它（python.org 的版本內含 tkinter）。README 第一行就寫。
- 核心全部型別標註；附錄 B 的資料結構都是 `frozen dataclass`。
- 識別字英文；docstring 與畫面文字繁體中文；畫面文字集中在 `core/text.py`。`core/`（`text.py` 除外）、`ui/*.py` 與 `main.py` 不寫中文字串常數（docstring 與註解除外）；`ui/app.js`、`ui/index.html` 註解以外也沒有中文，畫面文字由 Python 在啟動時整份送進頁面；新模組範本也放在 `text.py` 的 `TEMPLATE`（D32）。M2 起這一條有測試：`tests/test_boundaries.py` 的 `test_no_chinese_string_constants_outside_text`、`test_app_js_has_no_chinese_outside_comments`、`test_index_html_loads_style_then_custom_css_then_script`。
- 禁止：`os.system`、字串拼出來的 shell 指令、任何裸 `except:`；`core/` 的原始碼（含註解與 docstring）出現 `subprocess`、`sys.platform`、`os.name`、`startfile`、`ctypes`（`tests/test_boundaries.py` 擋，D50）；`core/` import `ui/` 或 `lib/` 裡的 pywebview（只有 `ui/web.py` 可以）；面板本體三個檔出現外部網址。`ui/install.py` 可以用 `subprocess` 跑 pip：指令一律是列表，不經 shell。`except Exception` 只在三處：`runner`、`load_config`，以及 `ui/web.py` 的工作執行緒迴圈（M2 加的第三處：一件工作出錯，面板不能就此不動）；`exec` 只在 `runner`。兩者都由 lint 強制，允許的地方加 `# noqa` 並寫理由（D29）。
- 網路（M3）：`core/`、`ui/`、`main.py` 自己不連網，唯一的例外是 `ui/install.py` 跑 pip（第一次安裝，與需求檔變了的重裝）。模組可以用標準庫的 `urllib` 連網，但隨附的模組只在使用者按下去之後才連（「更新」「工作坊」），來源網址沒設定就完全不連；啟動時、背景裡都不連。隨附模組只用標準庫，不 import `core`。下載來的東西一律先驗 sha256 再用；從網路來的字（索引的名稱、說明等）一律當文字顯示。這幾條裡有測試擋的是：沒設網址不連網（`tests/test_bundled.py::test_update_and_workshop_do_nothing_until_a_url_is_set`）、sha256 與當文字顯示（§9.3 的兩張表）；「`core/`、`ui/` 不 import `urllib`」現在沒有測試擋，是寫的時候守的。
- `tools/` 是開發端的工具，不是 iPLoT 執行時的一部分：使用者用不到，核心、面板、模組都不 import 它。`tools/publish.py` 可以用 `subprocess` 跑 `git`（`git show`、`git archive`、`git status`；指令是列表，不經 shell），可以 import `core.meta` 讀模組的說明與圖示。它有測試（`tests/test_publish.py`），不在 §4.2 的行數預算內。
- 文件：`README.md`（安裝、三層、三下做出第一個模組）、`docs/api.md`（`app` 介面）、本文件、`03_設計決定.md`、`04_M1驗收.md`（M1 結束時）、`05_使用紀錄.md`（M1.2 起有第一批，兩週實際使用期間每天記，§13）、`06_架構說明與試用.md`（第一次接觸先看）、`07_接口與邊界.md`（可以換零件的地方與各自的規則）。`01_從零啟動.md` 是原版修補實驗的紀錄，當對照組留著。

## 12. 驗收條件（M1）

這一節是 M1 的驗收條件，留著當紀錄；0.4.0 起照做時要注意的地方寫在各條後面的括號裡。0.4.0（M2）自己的人工驗收另外列在 `docs/plans/2026-10-05-M2-網頁面板與更新.md` 的 §11（(a)–(m) 十三項，macOS）；0.5.0（M3）的在同一份文件的 13.6（(a)–(g) 七項，macOS，用 `file://` 網址，不需要網路）。這兩份人工驗收到現在都還沒做。

每一條都要能在乾淨的暫存目錄裡重現。`tests/smoke.py` 自動跑 1–6 的「啟動後活著、stderr 乾淨」（0.4.0 起這六個情境走 `main.py --safe`，開的是 tkinter 面板；另外多了情境 7 驗預設啟動的網頁面板，只在 macOS 而且 `lib/` 已經裝好時跑，§10）；1–5 按下之後的行為與第 8 條由 `tests/test_startup.py` 用 `FakeView` 驗（D43）；7 手動：

1. `modules/` 空、上一層沒有模組 → 開窗，每組顯示「尚無模組，按 ＋ 新增」，stderr 乾淨。
2. `ROOTS` 含不存在的路徑 → 略過，面板記一行，照常開。（安全模式只掃 `modules/`，不會去看那個路徑，所以 `smoke.py` 的這個情境從 0.4.0 起只驗到「照常開」；「面板記一行」要用預設啟動（或後備面板）才看得到，自動測試在 `tests/test_startup.py`。）
3. `config.py` 語法錯誤 → 用預設值開，面板顯示錯在哪。
4. 只有一個語法錯誤的模組 → 列出並標 ⚠，按下顯示錯誤與「打開檔案」。（網頁面板的標記是圖示右上角的紅點，要雙擊才執行。）
5. 模組 `run` 丟例外 / 呼叫 `exit(1)` → 面板顯示檔案與行號，iPLoT 活著。
6. 沒裝 `tkinterdnd2` → 照常開，拖放關閉，沒有任何錯誤訊息。（`smoke.py` 的這個情境走 `--safe`，安全模式本來就不載入 `tkinterdnd2`；0.5.0 起後備面板不是安全模式，會試著載入它，載入不到照常開；拖放還沒做，§8.6。）
7. 滑鼠三下：按 ＋、打名字、按確定 → 編輯器開了範本、按鈕在面板上、按下去訊息區出現範本的那一行 log。（網頁面板的 ＋ 是每一組最後一格，新模組要雙擊才執行；tkinter 面板照原樣，按一下就執行。）
8. `modules/` 沒有「作業系統」模組（M1.4）→ 按 ＋ 模組照樣建好、按鈕出現，訊息區一行說明為什麼沒開編輯器；其他功能不受影響。情境 1–6 的乾淨副本裡 `modules/` 是空的，本來就沒有這個模組。

## 附錄 D：原版模組的包裝檔（「匯入原版模組」寫入的 `iplot.py`）

這是 M1 時的設計（`api_version` 1），「匯入原版模組」還沒做（§8.5）。0.4.0 拿掉了 `app.window`（D66），網頁面板下模組也不能靠 tkinter 開自己的視窗（D63 的代價），所以下面 `iPLoTWIN` 那一行已經不成立，先改成註解；原版模組裡用到主視窗的部分怎麼辦，要做這個模組時照當時的 `app` 重新設計。其餘各行留著當設計的紀錄。

```python
"""原版 iPLoT 模組的相容包裝。每次按下都重新執行旁邊的 <資料夾名>.txt。"""

def run(app):
    import os, tkinter
    src = app.module.folder / (app.module.name + ".txt")
    names = {
        "__name__": app.module.name,
        "__file__": str(src),
        "os": os,
        "tkinter": tkinter,
        # "iPLoTWIN": app.window,                     # 原版：主視窗。0.4.0 起沒有 app.window（D66），這一行不能用
        "iPLoTHOMEDIR": str(app.home),                # 原版：iPLoT 資料夾
        app.module.name + "HOMEDIR": str(app.module.folder),  # 原版：<名稱>HOMEDIR
    }
    exec(compile(src.read_text(encoding="utf-8"), str(src), "exec"), names)
```

- 提供的名字就是上面這幾個。原版模組用到其他核心內部名字（例如 `DPanel`、`cmdEXCUTE_iPLoT`、`TkinterDnD`）時，面板會顯示「模組『X』第 N 行出錯：NameError，name '…' is not defined」，行號是 `X.txt` 裡的行號（錯誤定位取模組資料夾內最內層的一格），「打開檔案」打開的就是 `X.txt`，缺哪個一目了然；真的有人需要再加進包裝檔，不進核心。
- 包裝檔本身是普通模組，所以快照、復原、自動啟動、右鍵選單對它全部有效。
- `.txt` 還在，`iplot.py` 也在：Finder 裡兩個檔案並排，老闆改 `.txt`，不用碰 `iplot.py`。
