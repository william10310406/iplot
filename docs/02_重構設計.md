## 0. 一句話

一個可以放在任何位置的資料夾。啟動後把周圍（上一層、這一層、下一層）含有 `iplot.py` 的資料夾變成按鈕（面板上一格一格的圖示）；雙擊就執行那個檔案，錯了在面板上用白話說清楚；按「＋」用滑鼠長出新按鈕。核心本身不內建任何用途，連 iPLoT 自己的工具都是模組。

## 1. 目標與不變的原則

三個原則是老闆的想法，每一個設計決定都用它們檢查：

1. **機器本身不為任何功能。** 核心不內建任何「用途」；所有用途都是模組，包括 iPLoT 自己的工具。
2. **所有人都能改原始碼。** 所以原始碼要看得到、小到讀得完、改壞了救得回來。
3. **大多數事情只用滑鼠。** 連「長出新能力」這件事也要能用滑鼠完成，不只是按已經有的按鈕。

三個已確認的需求：

- 滑鼠能做的事越多越好。
- 任何人都要能使用：第一次啟動自動安裝（原本是「零安裝」，D62 取消：需要的套件裝進 iPLoT 自己的 `lib/`，不碰系統的 Python）、雙擊啟動、錯誤用白話顯示、更新核心不動到使用者做的東西。
- 掃上一層、這一層、下一層是想法的一部分，保留，並用一條規則統一三層。

硬限制：Python 端只用標準庫，加上 `lib/` 裡釘死版本的 pywebview（D61、D62）；`core/` 不 import `lib/` 的東西，只有 `ui/web.py` 可以。UI 層可以用 HTML/CSS/JS（D61），不用框架、不用 build、零外部資源。macOS 先行；Windows、Linux 的做法寫在 `modules/作業系統` 裡，但 Windows 未經實機驗證、Linux 沒有在真的桌面上跑過，而且 Linux 這一版沒有網頁面板、只能用安全模式（`--safe`）；文件一律照實標示。

## 2. 範圍與非範圍

**做（M1–M3，見 §13）**：三層掃描、面板、執行模組、錯誤面板、滑鼠新增模組、右鍵選單、拖放（M2 後段，§8.6）、模組快照與復原、自動啟動、安全模式、原版 `X/X.txt` 模組的匯入（用工具模組做，不進核心，見 §8.5 與附錄 D）、作業系統整合做成模組（M1.4，`modules/作業系統`，D50）、網頁面板與第一次啟動的自動安裝（M2，D61–D68）、更新與工作坊（M3，D69、D70）、測試、CI、文件。哪些已經做了、哪些還沒，以 §13 為準。

**這一版不做**：工作情境切換、檔案整理規則、排程自動化、核心的滑鼠版復原、模組間共用狀態（`app.shared`）。這些都是加法，之後需要時再加；現在加進來只會讓核心超過任何人一個下午讀得完的大小。

## 3. 名詞

| 名詞 | 定義 |
|---|---|
| 模組 | 一個資料夾，裡面有一個 `iplot.py`。資料夾名稱就是模組名稱。 |
| 根目錄 | 核心去找模組的資料夾。`config.py` 的 `ROOTS` 清單，相對於 iPLoT 程式資料夾。 |
| 層 | 模組來自哪裡：`here`（`modules/`）、`parent`（`..`）、`extra`（`ROOTS` 另外加的）、`child`（進入某個模組後看到的子模組）。 |
| 處理函式 | 模組裡核心會呼叫的函式：`run(app)` 與 `on_files(app, paths)`，都可省略。沒有 `run` 時，最外層程式碼就是按下的動作（D47）。 |
| 面板 | 主視窗。單一視窗、分組的圖示格（D15 修訂：單一欄改成格狀）。預設是網頁面板：pywebview 開的原生視窗，裡面跑 `ui/index.html`（§8.2）。tkinter 面板是安全模式與後備，仍是單一欄的按鈕（§8.7）。 |
| 圖示 | 模組那一格上的圖。來源依序：模組資料夾裡的 `icon.png`／`icon.svg` → `iplot.py` 頂層的 `ICON` 常數 → 名字第一個字（D65，§8.2）。 |
| 範圍（scope） | 面板目前顯示的那一組模組：頂層是「這一層 + 上一層 + extra」，進入某個模組後是它的子模組。 |
| 快照 | 模組 `iplot.py` 執行前的複本，存在模組自己的 `.history/`。 |
| 作業系統模組 | `modules/` 裡名字剛好是「作業系統」的模組。核心把打開、編輯、顯示、終端機、垃圾桶五個動作交給它（§6.2、D50、D52）；第一次啟動的安裝另外問它兩件事：裝哪一份需求檔、缺不缺前置條件（§7）。 |
| 工作執行緒 | 網頁面板裡替 `Core` 做事的那一條執行緒：頁面送來的動作排隊，一次做一件（§6.2）。`Core` 不知道它的存在。 |
| 安全模式 | `python3 main.py --safe`：開 tkinter 面板、只掃 `modules/`、不需要 `lib/`。網頁面板開不起來時也自動退到它（§7）。 |
| `lib/` | 第一次啟動時用 pip 裝進 iPLoT 資料夾的套件（pywebview 與它的依賴）。不碰系統的 Python；刪掉它，下次啟動會再裝（D62）。 |

### 4.2 核心的六個職責

找（`scan`）、讀但不執行（`meta`）、執行（`runner`）、報錯（`errors`）、新增（`create`）、記住上一版（`history`）。其餘三個檔案是支援：`app` 給模組用、`core` 編排、`text` 文字（另有 `types` 放共用的資料結構）。畫面不在核心：面板在 `ui/`（M2，D61、D63），核心只透過 `View` 跟它說話（§6.2）。碰作業系統的事也不在核心，在 `modules/作業系統`（D50）。

**行數預算**（D68，修訂 D48）：七項各有上限，`tests/test_budget.py` 擋。不含測試。Python 的有效行＝非空白、非純註解、非 docstring 的行；HTML／CSS／JS 的有效行＝非空白、非整行註解的行。

| 項目 | 上限（有效行） | 現在（0.4.0） |
|---|---|---|
| 核心邏輯（`core/` 扣掉 `text.py`） | 500 | 490 |
| `ui/web.py` | 200 | 194 |
| `ui/tk.py` | 180 | 118 |
| `ui/install.py` | 80 | 49 |
| `ui/index.html` | 120 | 30 |
| `ui/app.js` | 400 | 256 |
| `ui/style.css` | 300 | 126 |

這是上限，目標比它低。預算是功能不是細節：「所有人都能改原始碼」只在原始碼讀得完時成立。核心邏輯的上限沒變，仍然是一個下午讀得完的大小。UI 從一個檔變成兩種語言、六個檔，各自訂上限：六個上限合計 1280 行，現在合計 773 行，比原來 `ui.py` 的 150 行上限多很多——這是 D61 的代價，寫明白。

### 4.3 三層掃描，一條規則

**資料夾裡有 `iplot.py` 就是模組。** 三層都用這一條。檔名要一字不差：APFS 不分大小寫，所以比對資料夾裡實際的檔名，原版的 `iPLoT.py` 不算（D34）。

- 上一層：iPLoT 程式資料夾的上一層底下的資料夾。把 iPLoT 放在 `~/`，`Documents`、`Projects` 只要放進一個 `iplot.py` 就變成按鈕。這就是「長在宿主系統上」的具體樣子。
- 這一層：`iPLoT/modules/` 底下的資料夾。
- 下一層：任何模組資料夾裡面再有模組，圖示右下角出現 ▸（安全模式的 tkinter 面板是按鈕旁），點進去看，可以一直往下。
- 根目錄是 `config.py` 的 `ROOTS`，預設 `["modules", ".."]`；要加 `~/Desktop` 自己加一行。
- 掃描只看檔名和用 `ast` 讀原始碼，**不執行任何模組程式碼**。這是核心在模組全壞時照樣能開的保證。
- 以 `.` 開頭的資料夾略過；不跟隨符號連結。讀不到的根目錄在那一組的位置記一行；根目錄底下讀不到的資料夾靜默略過（D35）。

### 4.4 除了核心，全部都是模組

「打開核心原始碼」「開 Terminal」「重新啟動」跟使用者寫的「開工」一樣，都是 `modules/某某/iplot.py`。這是原則 1 的實證：機器自己的工具也是用它自己的機制做的。M1.4 起連「怎麼打開一個檔案」「怎麼開終端機」也是模組（`modules/作業系統`，D50）：核心不知道自己在哪個作業系統上。M2 起「第一次啟動要裝哪一份套件、這台電腦缺不缺前置條件」也是問那個模組（§7）。

### 4.5 核心可整個換掉

更新 iPLoT 就是換四樣：`core/`、`ui/`、`main.py`、`requirements/`（D69）。使用者的東西——`config.py`、`custom.css`、`modules/`、`logs/`、`lib/`、其他層的模組、各模組的 `.history/`——全在這四樣外面。

現在更新是手動換檔案，而且要把隨附的 `modules/作業系統/` 一起換成新的（D50）：0.4.0 它多了兩個函式，沒換的話第一次啟動裝不了介面，會退到安全模式並說明原因。用滑鼠按的「更新」模組（只換那四樣、換之前先備份）與「工作坊」模組（隨附模組的新版從那裡來）是 M3（0.5.0，D69、D70），只定了原則，還沒做。

## 5. 模組契約與 `app` 介面

### 5.1 `iplot.py` 裡核心認得的五樣東西

```python
"""一句話說明這個模組做什麼。"""
# TITLE = "顯示名稱"     # 要讓按鈕文字跟資料夾名稱不同時才打開這一行
# ICON = "🧩"            # 按鈕的圖示：一個 emoji；或在資料夾放 icon.png（M2，D65）

def run(app):             # 可省略：沒有 run 時最外層程式碼就是按下的動作
    app.open(app.home)

def on_files(app, paths): # 可選。有定義，按鈕才接受拖放和右鍵「選擇檔案後執行…」
    for p in paths:
        app.log(f"收到 {p.name}")
```

其他東西隨便寫。對應 HyperCard：`run` 是 `on mouseUp`，`on_files` 是收到拖放的 handler。`on_files` 的兩個入口（拖放、右鍵「選擇檔案後執行…」）都還沒做，現在定義了面板也不會呼叫它（§8.3）。

圖示（M2，D65）：`ICON` 跟 `TITLE` 一樣是頂層的字串常數，核心用 `ast` 讀、不執行。模組資料夾裡放 `icon.png` 或 `icon.svg`（檔名要一字不差）的話，圖檔優先於 `ICON`；兩者都沒有，面板用名字第一個字（§8.2）。圖示只在網頁面板顯示，安全模式的 tkinter 面板不畫圖示。

五樣都可省略。課本寫的腳本不改一行就是模組（腳本語意，§7、D47）——`input()` 跳對話框、`print()` 進訊息區：

```python
x = input("年齡")
print("你的年齡是" + x + "歲")
```

`def run(app)` 留給想用 `app` 額外能力的人；有 `run` 時，最外層程式碼先跑完，再呼叫 `run(app)`。

### 5.2 核心讀這個檔案的兩個階段

**啟動與掃描時：只讀不跑。** `meta.read_meta` 用 `ast` 解析原始碼，取 docstring 第一段、頂層 `TITLE = "..."` 與 `ICON = "..."` 常數、有沒有頂層 `def run`、有沒有頂層 `def on_files`。語法錯誤或解碼錯誤的模組**照樣列在面板上**，有標記（網頁面板是圖示右上角的紅點，tkinter 面板是名稱前的 ⚠），`ModuleInfo.error` 帶錯誤訊息，執行它就顯示錯誤和「打開檔案」。

**按下時：每次重新執行。** `runner.run_module`：
1. 讀檔，`compile(原始碼, 檔案路徑, "exec")`，所以 traceback 會寫出模組檔案的路徑與行號。
2. 在一個乾淨的 dict 裡執行：`{"__name__": "__main__", "__file__": 檔案路徑}`；執行期間程序環境換成腳本的樣子，結束時還原（§7「腳本語意」）。
3. 從 dict 取 `run`（或指定的處理函式），有就呼叫 `run(app)`（或 `on_files(app, paths)`）。沒有 `run` 不是錯：最外層程式碼已經跑完，那就是動作。指定 `on_files` 而模組沒定義才是錯（`MissingHandler`）。
4. 命名空間用完即丟。改完檔案再按一次就是新版本，沒有 reload；模組資料夾裡被 import 的檔案（`helper.py`）也一樣，跑完就從 `sys.modules` 清掉。
5. 執行期間 `print()` 的輸出（stdout 與 stderr）收進 `Result.output`，核心逐行寫到訊息區。任何人都會用 `print()`，用了就要看得到。

語意：
- 跨次執行要保留的東西放 `app.memory`；跨次啟動要保留的寫成檔案放模組自己的資料夾（`app.module.folder`）。
- 同步執行，一次只跑一個模組。網頁面板把執行排在工作執行緒上（§6.2）：模組跑很久時視窗不會凍住，但不能中途停掉，這段時間再按別的要排隊。安全模式的 tkinter 面板在主視窗的執行緒上執行，長時間工作（`time.sleep`、長迴圈）會凍住視窗。`app.background` 還沒做（§7 已知限制）。
- 執行期間工作目錄是模組自己的資料夾，`sys.path` 最前面也是它：`open("x.txt")` 讀寫的是模組資料夾裡的檔案，`import helper` 找的是旁邊的 `helper.py`；跑完還原（§7「腳本語意」）。`app.module.folder / "x.txt"` 照樣可用。
- 模組呼叫 `exit()` / `sys.exit(0)` / `quit()` 是正常結束，就像 `python3 iplot.py`；代碼非零（`exit(1)`、`sys.exit("壞了")`）才算錯誤。兩種都不會關掉 iPLoT（D49）。

### 5.3 `app`：模組看得到的全部

每次執行新建一個 `App`，`module` 與 `memory` 在建立時綁好；其他成員轉呼叫 `core`；`open`、`edit`、`reveal`、`terminal`、`trash` 五個動作由 `core.action` 交給 `modules/作業系統` 執行，沒有那個模組時在訊息區記一行、動作不執行（§6.2）。

### 5.4 名稱

資料夾叫什麼模組就叫什麼：中文、空白都可以，沒有識別字限制。按鈕文字預設是資料夾名稱；只有打開 `TITLE` 那一行時才不同。兩層有同名模組時都顯示。

### 6.2 `Core` 與 `View`

```python
class View(Protocol):              # ui/ 裡的面板實作（web.WebPanel、tk.Panel）；測試用 FakeView
    def show(self, scope: Scope) -> None: ...        # 七個方法；M2 拿掉了 window 屬性（D66）
    def log(self, text: str) -> None: ...
    def report(self, error: ErrorInfo) -> None: ...
    def ask(self, prompt: str, default: str = "") -> str | None: ...
    def confirm(self, prompt: str) -> bool: ...      # M2 新增；app.confirm 轉給它
    def choose_files(self) -> list[Path]: ...
    def choose_folder(self) -> Path | None: ...

class Core:
    def __init__(self, home: Path, config: Config, view: View, safe: bool = False): ...
    scope: Scope                   # 目前顯示的範圍；第一次 rescan 之前是 Scope(("iPLoT",), ())
    memories: dict[Path, dict]     # 各模組的 app.memory
    def roots(self) -> list[Root]  # 要掃的根目錄；safe 時只有 "modules"
    def rescan(self) -> None       # 重掃目前範圍並 view.show；進入過的資料夾不再是模組時，退回仍然存在的那一層
    def enter(self, info: ModuleInfo) -> None   # 進入下一層：一組，label = info.title、root = info.folder、
                                                # level 沿用進入前那一組；子模組的 ModuleInfo.root 仍是頂層根目錄
    def back(self, depth: int) -> None          # 麵包屑回上；0 是頂層
    def all_modules(self) -> tuple[ModuleInfo, ...]   # 目前範圍內的所有模組（app.modules）
    def press(self, info: ModuleInfo, handler="run", args=(), quiet=False) -> Result
                                   # 執行中 busy；期間收到的 rescan 延到執行結束才做（try/finally）
                                   # 快照失敗只在訊息區記一行，模組照樣執行（D40）
                                   # quiet 只省掉「完成（x 秒）」那一行；快照、輸出、錯誤照舊
    def run_by_name(self, name: str | ModuleInfo) -> Result
                                   # 只比對資料夾名稱；比對前先 unicodedata.normalize("NFC")，macOS 的檔名可能是 NFD
                                   # 找不到或不只一個：丟 LookupError，訊息列出所有同名模組的路徑
    def action(self, name: str, *args) -> Any
                                   # 交給 modules/ 裡的「作業系統」模組：press(那個模組, name, args, quiet=True).value
                                   # 沒有那個模組：view.log 一行、回 None；壞了就像任何模組一樣在面板報錯（D50–D52）
    def create(self, parent: Path, name: str) -> Path | None
                                   # 新增後重掃並打開編輯器（self.action("edit", …)）；名稱不對、已存在、建不了（OSError）時寫 view.log、回 None
    def report_internal(self, exc_type, exc, tb) -> None      # 核心自己的錯誤：進面板 + logs/iplot.log
    # 還沒做（M2 後段）：autostart()（safe 時不做；逐一走 press，D39）、rename(info, new_name)、
    #          set_autostart(info, on)、restore(info, version)、trash(info)
```

M2 沒有動 `Core`：`press`、`rescan`、`action`、`create` 都跟 0.3.0 一樣，換的只是誰來實作 `View`。

**依賴方向只有一個**：`ui/`（`web`、`tk`、`install`）和 `main` 在最上面，`core`、`app` 在中間，`scan`、`meta`、`runner`、`errors`、`create`、`history` 在底下，除了上表依賴欄列出的（`scan` → `meta`、`runner` → `errors`）以外互不相識（共用附錄 B 的資料結構與 `text`）。`core/` 的檔案一行 tkinter 都不 import，也不 import `ui/` 和 `lib/` 裡的 pywebview；`tests/test_boundaries.py` 用把 `tkinter` 塞成 `None` 的方式（`test_bottom_layer_never_imports_tkinter`）與檢查每一個 import（`test_core_never_imports_webview`）強制。

**網頁面板與工作執行緒（M2，D61、D63）。** 網頁面板有兩頭：Python 這一頭是 `ui/web.py`，頁面那一頭是 `ui/index.html`、`app.js`、`style.css`，在 pywebview 開的原生視窗裡跑。頁面用 `file://` 網址載入，沒有 HTTP server、沒有 port。兩個方向各一條路：

- 頁面 → Python：JS 呼叫 `pywebview.api.<方法>`，就是 `Bridge` 的公開方法（十個，§6.1；每個動作叫哪一個見 §8.3）。除了 `state`（直接回目前的範圍）與 `answer`（回答等待中的對話框），全部只把一件工作排進佇列、立刻回傳。
- Python → 頁面：`WebPanel` 用 `window.evaluate_js("iplot.<名字>(…)")` 呼叫頁面的七個入口（`init`、`show`、`log`、`report`、`ask`、`confirm`、`busy`）。參數是純 ASCII 的 JSON，模組名稱裡有引號、反斜線、換行都不會壞（`tests/test_web.py::test_show_escapes_names_for_js`）。

排進去的工作由**單一工作執行緒**依序做，一次一件：連按兩個模組，第二個排在第一個後面（`test_jobs_run_one_at_a_time`）。pywebview 的事件迴圈佔住主執行緒、模組在工作執行緒上跑，所以模組跑很久時視窗照樣可以捲、可以看。`Core` 不知道執行緒的存在：所有對 `Core` 的呼叫都在工作執行緒上，`press` 的 `_depth`／`_pending`（執行中收到的重掃延到結束才做）照舊有效。一件工作裡沒接住的例外交給 `core.report_internal`，迴圈繼續做下一件（§7 第 5 條）。

頁面載入完成時，`WebPanel` 先送 `iplot.init`（畫面文字 `T` 整份、版本、是不是安全模式），工作執行緒在那之後才開始，所以頁面拿到文字之前不會收到別的呼叫。`ask` 與 `confirm`：`WebPanel` 給對話框一個編號、推給頁面，然後在 `threading.Event` 上等；頁面用 `answer(編號, 值)` 回來。視窗關掉或頁面重新載入時，等待中的對話框都當作按了取消（`test_close_window_cancels_pending_ask`、`test_page_reload_cancels_pending_ask`）。`choose_files`、`choose_folder` 是 pywebview 的原生對話框（D67）。

`Bridge` 只認目前面板上有的東西。模組的 `id` 是資料夾的絕對路徑，要在目前範圍內、而且那個資料夾還是模組；`create` 的資料夾要是目前某一組的 `root`。找不到（例如模組剛在檔案總管被刪掉）就重掃，不報錯（`test_press_missing_module_rescans`）。`action` 只收 `edit`、`reveal`、`terminal`，其他名稱不做任何事。

給頁面的 JSON（`scope_json`、`error_json`；`WebPanel.report` 另外給每筆錯誤一個編號 `id`，「打開檔案」用它指回來）：

```
init   = {"text": T 整份, "version": "0.4.0", "safe": bool}
scope  = {"crumbs": ["iPLoT", …],
          "groups": [{"label", "level", "path", "root", "note", "modules": [module, …]}]}
module = {"id": "<資料夾絕對路徑>", "name", "title", "description",
          "icon": {"file": "data:image/png;base64,…"} | {"text": "🧩"} | null,
          "has_children": bool, "error": "<字串或 null>"}
error  = {"kind", "message", "file", "line", "traceback", "source", "module", "sentence": describe(error), "id"}
```

**核心零作業系統程式碼（M1.4，D50）。** `Core.action` 把五個動作（打開、編輯、顯示、終端機、垃圾桶）交給 `modules/作業系統`，走的是 `press`——跟 `run`、`on_files` 同一扇門（§7 第 2 條，D51），所以快照、輸出、錯誤回報全部沿用。核心只在 `modules/` 找名字剛好是「作業系統」的模組（D52）。`core/` 的原始碼連 `subprocess`、`sys.platform`、`os.name`、`startfile`、`ctypes` 這幾個字都不能出現，`tests/test_boundaries.py` 用字串掃描強制。要上別的系統，在那個模組裡加一個檔，核心不動。

### 6.3 執行一個模組，資料怎麼流

```
網頁面板：雙擊圖示 → app.js 呼叫 pywebview.api.press(id) → Bridge.press 排一件工作、立刻回傳
          → 工作執行緒：用 id 找回 ModuleInfo → core.press(info)
tkinter 面板（安全模式）：按按鈕 → core.press(info)

core.press(info)
  → history.snapshot(info.file, keep)        內容跟最新一份不同才存
  → runner.run_module(info, App(core, info))
       compile → 換成腳本環境 → exec 進乾淨 dict → 有 run 就呼叫 → 還原環境
       任何例外 → errors.from_exception → Result(ok=False, error=...)
  → ok：view.log(「開工 完成（0.3 秒）」)
  → 錯：view.report(error)
       網頁面板：訊息區一筆錯誤——白話那一句，右邊「打開檔案」（帶著出錯的行號交給編輯器）與「詳細」（展開 traceback）
       tkinter 面板：traceback 在上，最後是白話描述 + 「打開檔案」按鈕（捲到底看到的是人話）
```

模組呼叫 `app.open(p)`（其他四個動作、右鍵選單的「打開程式碼」「在資料夾中顯示」「在終端機打開」、「打開檔案」都一樣；第一次啟動的安裝問 `requirements`、`webview_ready` 走的也是這條路）：

```
模組 A 呼叫 app.open(p)
  → core.action("open", p)
      → modules/作業系統 不是模組 → view.log(一行說明) → 回 None
      → 是模組 → press(作業系統, "open", (p,), quiet=True)
            → history.snapshot（內容沒變就不存）
            → runner：exec iplot.py → import mac（或 win、linux）→ open(app, p) → Popen(["open", p])
            → print 進訊息區；錯誤進面板；不印「完成」
      → 回 Result.value
```

按 ＋：網頁面板是面板內的對話框問名字 → `pywebview.api.create(那一組的 root, 名字)` → 工作執行緒 → `core.create`；tkinter 面板是 `Panel._create` → `core.create`。之後兩邊一樣：`new_module` → `rescan` → `action("edit", …)`。沒有作業系統模組時前面照常，最後一步變成訊息區的一行說明。右鍵「在這裡新增下一層模組…」走同一條路（網頁面板呼叫的是 `add_child(id, 名字)`），只是 `parent` 是那個模組的資料夾（`info.folder`），不是那一組的 `root`。

### 6.4 `config.py` 怎麼載入

`main.py` 呼叫 `core.load_config`，它用 `runpy.run_path` 執行 `config.py`，取出 `ROOTS`、`EDITOR`、`HISTORY_KEEP`，缺的用預設值補。`config.py` 丟任何例外（包括呼叫 `exit()`）或值的型別不對（`ROOTS` 要是字串清單、`EDITOR` 是 `None` 或字串清單、`HISTORY_KEEP` 是 ≥ 1 的整數；`ROOTS` 的每一項都要能 `expanduser`，`"~Desktop"` 這種少了斜線的寫法算壞）：整份用預設值啟動，面板顯示它哪裡壞。安全模式（`--safe`，或網頁面板開不起來時自動退到的那一個，§7）`ROOTS` 強制為 `["modules"]`。

## 7. 錯誤處理

1. **啟動時不執行任何模組程式碼。** 掃描只靠檔名與 `ast`。
2. **進入模組程式碼只有一個門：`runner.run_module`。** 核心其他地方沒有 `exec`。
3. **錯誤是資料。** `ErrorInfo`（種類、訊息、檔案、行號、完整 traceback、來源），由 `errors.describe` 組成一句話，例如「模組『開工』第 7 行出錯：NameError，name 'x' is not defined」。訊息保留 Python 原文，不翻譯（D36）。檔案與行號取 traceback 裡位於模組資料夾內的最內層那一格；模組的錯誤找不到這樣的一格時（例如讀檔就解碼失敗），檔案是模組的 `iplot.py`、不帶行號；traceback 是空的就都不帶；核心與設定的錯誤取最後一格（D37）。
4. **模組呼叫 `exit()` / `sys.exit(0)` / `quit()` 是正常結束；代碼非零才算錯誤**（「模組以 exit(1) 結束」，附檔案與行號）。兩種都不會關掉 iPLoT（`runner` 接 `SystemExit`，代碼是 `None` 或 `0` 就當正常結束，D49；`KeyboardInterrupt` 不接）。
5. **核心自己的錯誤**接到同一個面板，標成「核心錯誤」，並寫進 `logs/iplot.log`。兩種面板各有一個入口，都交給 `core.report_internal`：tkinter 面板是 tkinter 回呼裡丟出來的例外（`Panel.attach` 把主視窗的 `report_callback_exception` 指過去）；網頁面板是工作執行緒迴圈接住的例外——一件工作出錯，回報之後迴圈繼續做下一件（`tests/test_web.py::test_job_exception_goes_to_report_internal`）。
6. **`--safe`（安全模式）**：開 tkinter 面板（§8.7），只掃 `modules`、不自動啟動、不載入拖放套件、不需要 `lib/`。網頁面板開不起來時也自動退到它（見下面「啟動流程」）。核心或面板改壞了這是最後一道門；再壞就是 git 的事（§9）。

**啟動流程與安裝失敗（M2，D62、D63）。** `main.py` 依序做：

```
python3 main.py [--safe]
 1  版本檢查：Python < 3.10 → 印 need_python 那一句，結束
 2  把 iPLoT 資料夾裡的 lib/ 加進 sys.path（排在 iPLoT 自己的資料夾後面、系統的套件前面）；load_config
 3  --safe → tkinter 面板的安全模式；這個 Python 沒有 tkinter → 印 no_tk，代碼 1。到此為止
 4  開網頁面板（run_web）；開得起來 → 視窗關掉，程序結束
 5  開不起來（lib/ 裡沒有 pywebview，或它裝壞了）→ bootstrap：
      問「作業系統」模組：裝哪一份需求檔（requirements）、缺不缺前置條件（webview_ready）
      可以裝 → 刪掉 lib/.installed → 印 installing → pip 裝進 lib/，輸出一行行印在主控台
          成功 → 寫 lib/.installed → 印 install_done → 重啟自己（os.execv，乾淨的程序），從 1 再來
          失敗 → 印 install_failed（pip 說的原因、安裝需要網路、怎麼再試、安全模式怎麼開）→ 安全模式
      不能裝（這個平台沒有網頁面板、缺前置條件、作業系統模組不在或壞了）→ 印 web_failed → 安全模式
 6  剛裝完重啟的那一次還是開不起來 → 不再裝，印 web_failed → 安全模式
```

- 需求：Python ≥ 3.10 加 pip（任何來源都可以）；第一次啟動要網路。tkinter 不再是必要的，只有安全模式與後備需要它。
- pip 的指令是 `python -m pip install --target lib --upgrade --no-input --disable-pip-version-check -r <需求檔>`，列表形式、不經 shell（`ui/install.py`）。裝進 iPLoT 自己的 `lib/`，不碰系統的 Python；把 iPLoT 資料夾丟進垃圾桶就整個消失，「可移除」不變（D62）。需求檔的版本釘死；hash 釘死（`--require-hashes`）還沒做。
- 一次啟動最多裝一次：重啟自己時帶環境變數 `IPLOT_BOOT=1`，每次啟動一開始就把它拿掉；剛重啟的那一次再開不起來就不裝了，不會無限重啟（`tests/test_main.py::test_reinstall_happens_once`、`test_broken_lib_reinstalls_then_falls_back`）。
- 退到安全模式時，原因印在主控台，同一句也寫在 tkinter 面板的訊息區；視窗標題有「（安全模式）」、只掃 `modules/`。連 tkinter 都沒有，就印 `no_tk`、以代碼 1 結束（`test_install_failure_without_tk_exits_1`）。這幾條路都沒有 traceback。
- 「作業系統」模組回答的兩件事：macOS 裝 `web-mac.txt`、什麼都不缺；Windows 裝 `web-win.txt`，並查登錄檔裡有沒有 WebView2 runtime（未經實機驗證，需求檔的版本是 pip 用 `--dry-run` 解出來的，沒有在 Windows 裝過）；Linux 回空字串——pywebview 在 Linux 要系統層的 GTK／WebKit2GTK，pip 裝不了，這一版 Linux 沒有網頁面板，只能用安全模式。
- 網頁面板開著的期間，`run_web` 在 `sys.meta_path` 最前面放一個 `NoTk`：模組 `import tkinter`（`turtle` 也會 import 它）得到的是 `ImportError` 與 `tk_in_web` 那一句（說要用安全模式），不會真的去開視窗。原因：主執行緒被網頁面板的視窗系統佔著，在工作執行緒上開 tkinter 視窗，整個程序會被 macOS 中止、沒有任何訊息（實測結束碼 133）。面板關掉、或根本沒開起來時就拿掉，後備的 tkinter 面板照常 import 得到（`tests/test_main.py::test_module_using_tkinter_under_the_web_panel_gets_a_plain_error`）。matplotlib 的視窗在工作執行緒上也開不了，但它自己會丟一個說得清楚的 `RuntimeError`，程序不會中止（實測）。
- `ui/install.py` 的 `installed()` 會比對 `lib/.installed` 與需求檔內容的 sha256，但現在的啟動流程不看它：`lib/` 裡的 pywebview 開得起來就直接開，開不起來才裝。「需求檔換了，下一次啟動就自動重裝」還沒有接上。
- 在開發用的那台 Mac 上量到的（python.org 的 Python 3.14.7、macOS 26.5、arm64）：`lib/` 裝完 36 MB、10 個套件；乾淨下載安裝 1 分 46 秒（看網路）；pip 有快取時 8 秒；`lib/` 在的時候，啟動到視窗出現 0.6 秒；斷網時 pip 重試約 20 秒後失敗，主控台 14 行、沒有 traceback，接著開安全模式。`installing` 那一句裡的「約 40 MB」是給人看的概數（`main.py` 的 `INSTALL_SIZE`）。

**腳本語意（M1.2，D47；M1.3，D49）。** 按下按鈕 ＝ 在模組自己的資料夾裡執行 `python3 iplot.py`，只是鍵盤和螢幕換成了視窗。課本寫的腳本不改一行就能當模組；`def run(app)` 留給想用 `app` 額外能力的人。`runner.run_module` 在執行模組程式碼之前把程序環境換成腳本的樣子；執行之後——正常結束、出錯、`exit()` 都一樣——一定還原：

| 項目 | 執行期間 | 跑完 |
|---|---|---|
| `__name__` | `"__main__"`，所以 `if __name__ == "__main__":` 底下的會跑。錯誤訊息裡的模組名稱仍是資料夾名稱 | — |
| 工作目錄 | 模組自己的資料夾：`open("x.txt")` 讀寫的是模組資料夾裡的檔案 | 切回原本的 |
| `sys.path` | 最前面插入模組資料夾：`import helper` 找的是旁邊的 `helper.py` | 移除那一筆 |
| `sys.argv` | `[iplot.py 的路徑]` | 還原 |
| `input()` | 跳對話框（就是 `app.ask`；網頁面板是面板內的對話框，安全模式是 tkinter 的對話框），提示字是對話框的文字；上次問完之後 `print` 的東西放在提示前面，像螢幕上問題前面的那幾行（猜數字的「太大」要在下一次問之前看得到）。按取消丟 `EOFError`（訊息「在提問時按了取消」），像真的 `input()` 在 Ctrl-D；模組可以 `except EOFError` 接，不接就以這一句錯誤結束，行號指到呼叫 `input()` 的那一行（D49）。換的是 `builtins.input`，所以模組 import 的 helper 裡呼叫 `input()` 也一樣 | 還原 |
| 旁邊的檔案 | 執行期間不寫 `.pyc`（它的有效性只看秒級的修改時間和檔案大小，同一秒內改成同樣大小的內容會讀到舊的） | 這次執行才從模組資料夾載入的模組（含子資料夾裡的，有沒有 `__init__.py` 都算）清出 `sys.modules`：`helper.py` 改了下次會重讀，維持「每次都是乾淨的」。模組用 `app.run` 跑別的模組時，外層模組的 helper 先收起來、跑完放回去，兩邊同名的 `helper.py` 不會拿錯 |
| 沒有 `run` | 不是錯：最外層程式碼就是動作。只有指定 `on_files` 而模組沒定義時才回 `MissingHandler` | — |

`print`（全部輸出照樣在跑完後逐行進訊息區）、例外、快照、`app.*` 都不變；`exit()` 照上面第 4 條（代碼 0 是正常結束，exit 之前 `print` 的照樣進訊息區）。還原的是 iPLoT 自己換掉的東西；模組自己改的（例如自己 `sys.path.append`）不會被復原。

已知限制：
- 執行模型（D56）仍延後：模組還是在 iPLoT 自己的程序裡執行。網頁面板有工作執行緒（§6.2），所以 `time.sleep` 或長迴圈不會凍住視窗（可以捲、可以看）；但一次只跑一個模組、不能中途停掉，這段時間按的其他動作排隊，關掉視窗會結束整個程序、連同跑到一半的模組。模組在 `input()` 等回答時關掉視窗，等待中的提問當作按了取消。安全模式的 tkinter 面板沒有工作執行緒，長時間的模組照樣會凍住視窗。`app.background` 還沒做。
- 按取消丟的是 `EOFError`，所以 `except ValueError` 的驗證迴圈出得去；但迴圈裡寫 `except:` 或 `except Exception:`（什麼都接）的會把取消也接走、再問一次，只能輸入一個合法的值或強制結束 iPLoT。真的終端機上這種迴圈遇到 Ctrl-D 也一樣，只是那裡還有 Ctrl-C；要不要讓取消在這種迴圈裡也出得去，待裁定（D49）。
- `if __name__ == "__main__":` 底下的程式碼和 `run(app)` 都會跑（先最外層、再 `run`）；模組自己定義不收參數的 `def run():` 會被當成處理函式呼叫而出錯。

## 8. 面板與滑鼠操作

### 8.1 原則

除了「幫新模組取名字」和「寫模組的程式碼」，其他事情都不碰鍵盤。對話框裡的 Enter、Esc 是附加的，不是必要的。

這一節講的是預設的網頁面板（M2，`ui/index.html`、`app.js`、`style.css`，Python 那一頭是 `ui/web.py`）。安全模式的 tkinter 面板操作不一樣，放在 §8.7。

### 8.2 面板

```
┌──────────────────────────────────────────────┐

├──────────────────────────────────────────────┤

│  開工     打開核心   整理桌面   新模組        │  ▸（右下角）：底下還有模組，按了進去
│           原始碼                             │  ●（右上角的紅點）：檔案有語法錯誤
│                                              │  每一組最後一格是虛線的 ＋
│ ● 上一層  ../                                │
│                                              │

│ • 已掃描 modules/、../，找到 4 個模組         │  訊息區：一行一條，自動捲到底

└──────────────────────────────────────────────┘
```

- **視窗**：一個原生視窗，標題 `iPLoT v<版本>`，開起來 820×620、最小 480×420。上到下是麵包屑（`iPLoT ▸ …`，按任一段回去）、可捲動的圖示區、狀態列、訊息區。視窗拉寬，格子自動多排幾格。
- **每一組**：顏色點、標題、路徑。顏色按層：`here` 藍、`parent` 紅、`extra` 綠；進到下一層後只有一組，顏色點是紫（`child`）。路徑是 `modules/`、`../`；`extra` 顯示 `config.py` 裡寫的那個字串；下一層顯示「資料夾名/」。一組沒有任何模組時顯示「尚無模組，按 ＋ 新增」；根目錄讀不到（有 `note`）的那一組顯示原因、沒有 ＋：沒有地方可以建。
- **每個模組一格**：圖示、名稱（最多兩行）。檔案有語法錯誤時右上角有紅點；有子模組時右下角有 ▸，按了進入下一層。沒有子模組的模組沒有 ▸，從右鍵新增第一個（D60）。
- **單擊選取、雙擊執行**（D64，推翻 D13）。單擊只選取：狀態列顯示那個模組的名稱與說明（docstring 第一段；檔案有語法錯誤時顯示錯誤），說明第一次有地方顯示（D33）。沒選任何模組時，狀態列是一句提示。雙擊才執行。點空白的地方取消選取。格子另外設了 `title` 屬性（同一段文字）；滑鼠停著時提示會不會跳出來由系統的 WebView 決定，沒有另外驗過。
- **右鍵選單**六項：執行／進入下一層（有子模組才出現，所以沒有子模組的模組是五項）／打開程式碼／在資料夾中顯示／在終端機打開／在這裡新增下一層模組…。
- **＋**：每一組最後一格是虛線的 ＋（D14 修訂：每一組一顆不變，從標題列搬到最後一格）。按了跳對話框問名字；名字不合規則時，對話框裡顯示規則那一句、不關，不用重打整個名字。規則的本尊在 `core/create.py`；`app.js` 裡有同一套先擋，Python 那邊還會再擋一次。
- **訊息區**：`app.log`、`print` 的輸出、「完成」那一行，一行一條。錯誤先顯示白話那一句，右邊兩顆鈕：「打開檔案」（用編輯器打開出錯的檔案；`config.py` 的 `EDITOR` 設成認得行號的編輯器時，會跳到出錯的那一行）與「詳細」（展開 traceback，再按是「收起」）。自動捲到底；最多留 2000 條；文字可以選取複製。啟動時會記一行「已掃描 …，找到 N 個模組」。
- **執行中**：模組開始執行超過四分之一秒，狀態列右邊顯示「執行中：<名稱>…」，跑完消失（`iplot.busy`）。模組的 `print` 要等它結束才進訊息區；沒有這一行，跑得久的模組看起來像沒按到，使用者會再按一次、多排一次。
- **雙擊的規則**：兩下都落在同一個模組的格子上才算。第一下按的是 ▸、選單項目、對話框的按鈕時，畫面會換，第二下落在哪裡都不算；所以頁面不用瀏覽器的 `dblclick` 事件，看的是 `click` 帶的次數。視窗取得焦點的重掃如果內容沒變就不重畫，不會打斷進行中的雙擊。
- **圖示檔不能用時**：空檔、超過 1 MB、讀不到，Python 那一頭就當作沒有（`icon_for`）；內容不是一張讀得出來的圖（壞了、下載到一半），頁面載入失敗時自己換成預設圖示（`app.js` 的 `iconEl`）。兩種都在訊息區記一行 `icon_unusable`，每個檔一次。
- **視窗關掉之後**，排著還沒做的工作不再做；正在執行的那一個模組會跟著程序一起結束（不能中途停，也不會等它，見 §7 的已知限制）。
- **對話框都在面板裡面**，不另開視窗：新模組的名字、`app.ask`、模組的 `input()` 是一個輸入框加取消／確定；`app.confirm` 只有兩顆鈕。Enter 確定、Esc 取消；中文輸入法選字時按的 Enter 不算確定。一次只開一個，後來的排隊。選檔案、選資料夾（`app.choose_files`、`app.choose_folder`）是 pywebview 的原生對話框（D67）。
- **圖示來源的順序**（D65）：① 模組資料夾裡的 `icon.png` 或 `icon.svg`——檔名要一字不差（`Icon.png` 不算），兩個都有用 png，不超過 1 MB；② `iplot.py` 頂層的 `ICON = "🧩"`，一個 emoji，只認字串常數；③ 都沒有：顯示名稱的第一個字。②、③ 的底色，色相由資料夾名稱算出來，同一個模組每次顏色都一樣。圖檔超過 1 MB 或讀不到：當作沒有（往下用 ②、③），訊息區記一行，每個檔每次啟動只說一次。圖檔換了，點回視窗就換。
- **重掃**：視窗取得焦點就重掃（D11，由頁面的 `focus` 事件觸發）：在檔案總管新增、刪掉、改了模組，點回來就看得到。內容沒變就不重畫。
- **外觀**：深色模式跟系統。`ui/style.css` 開頭是顏色與尺寸的變數，其餘規則只用變數，改顏色、改大小只改那一段。自己的改法放 `iPLoT/custom.css`（跟 `config.py` 同一層；預設沒有這個檔，沒有也沒關係）：它在 `style.css` 之後載入，同名的變數以它為準，更新不會動它。
- **零外部資源**：三個檔沒有任何外部網址——沒有 CDN、沒有網路字型、沒有函式庫；不用框架、不用 build。畫面上的字全部來自 `core/text.py`，啟動時由 Python 整份送進頁面，`app.js` 裡沒有中文字串（註解是中文）。這幾條由 `tests/test_boundaries.py` 擋（§10）。
- **不做**：動畫、拖曳排位置、搜尋。拖檔案到圖示上還沒做（§8.6）。

### 8.3 動作對應

網頁面板的每個動作：頁面呼叫 `Bridge` 的哪個方法（`pywebview.api.<方法>`），那個方法在工作執行緒上再叫 `Core` 的哪個方法。標「還沒做」的列是原本排在 M2、0.4.0 沒有做的，面板上現在沒有這些項目。

| 動作 | 頁面呼叫 `Bridge` 的 | 到 `Core` 發生什麼 | 里程碑 |
|---|---|---|---|
| 單擊模組 | —（只在頁面上） | 選取；狀態列顯示名稱與說明：`ModuleInfo.description`（docstring 第一段），檔案有語法錯誤時顯示錯誤（D33、D64） | M2 |
| 雙擊模組；右鍵 → 執行；焦點在格子上時按 Enter | `press(id)` | `core.press(info)` | M1 是單擊；M2 改成雙擊 |
| 按 ▸；右鍵 → 進入下一層 | `enter(id)` | `core.enter(info)`；麵包屑可回 | M1 |
| 按麵包屑的某一段 | `back(depth)` | `core.back(depth)`；0 是頂層 | M1 |
| 按 ＋ | 對話框問名字 → `create(那一組的 root, 名字)` | `core.create(root, 名字)` → 重掃 → `core.action("edit", …)` 打開新的 `iplot.py` | M1 |
| 錯誤的「打開檔案」 | `open_error(錯誤的編號)` | `core.action("edit", file, editor, line)` | M1 |
| 錯誤的「詳細」／「收起」 | —（只在頁面上） | 展開或收起 traceback | M2 |
| 視窗取得焦點 | `rescan()` | `core.rescan()`。在 Finder 建資料夾、點回來，圖示就在 | M1 |
| 右鍵 → 打開程式碼 | `action("edit", id)` | `core.action("edit", info.file, editor, None)` | M1 |
| 右鍵 → 在資料夾中顯示 | `action("reveal", id)` | `core.action("reveal", info.folder)`（標籤是中性詞，D55） | M1 |
| 右鍵 → 在終端機打開 | `action("terminal", id)` | `core.action("terminal", info.folder)` | M1 |
| 右鍵 → 在這裡新增下一層模組… | 對話框問名字 → `add_child(id, 名字)` | `core.create(模組資料夾, 名字)` → 重掃 → `core.action("edit", …)` 打開新的 `iplot.py`；跟按 ＋ 同一條路，只是建在這個模組的資料夾裡。沒有子模組的模組靠這一項長出第一個子模組，重掃後它的圖示上出現 ▸（D60） | M1 |
| `app.ask`、模組的 `input()`、`app.confirm` 的對話框按確定／取消 | `answer(編號, 值)` | 不經過工作執行緒：直接把答案交給等在 `view.ask`／`view.confirm` 的那一方。新模組取名字的對話框不走這裡：按確定是上面的 `create`／`add_child`，按取消什麼都不呼叫 | M2 |
| 右鍵 → 選擇檔案後執行… | 還沒做 | `view.choose_files` → `core.press(info, "on_files", (paths,))`。只在 `accepts_files` 時出現 | M2 後段 |
| 把檔案拖到圖示上 | 還沒做 | 同上。怎麼做見 §8.6 | M2 後段 |
| 右鍵 → 回到上一版… | 還沒做 | 列出 `history.versions`，選一個 → `history.restore` → 重掃 | M2 後段 |
| 右鍵 → 重新命名… | 還沒做 | `view.ask` → 改資料夾名稱 → 重掃 | M2 後段 |
| 右鍵 → 設為／取消自動啟動 | 還沒做 | 在模組資料夾放／拿掉空檔案 `autostart` | M2 後段 |
| 右鍵 → 移到垃圾桶 | 還沒做 | 確認對話框 → `core.action("trash", info.folder)`（各系統自己的垃圾桶，D53）。永遠不 `rm` | M2 後段 |

`Bridge` 的第十個方法 `state()` 回目前的範圍（跟 `iplot.show` 收到的一樣），頁面現在沒有用到。安全模式的 tkinter 面板沒有 `Bridge` 這一層，按鈕直接叫同一個 `Core` 方法；它有哪些動作見 §8.7。

### 8.4 自動啟動（還沒做，D39）

M1 與 M2（0.4.0）都沒做，排在 M2 後段。設計不變：標記是模組資料夾裡的空檔案 `autostart`：滑鼠切換時核心只建檔或刪檔，不改任何 Python 原始碼；Finder 看得到；`--safe` 一律略過。啟動時 `core.autostart` 對每個有標記的模組逐一 `press`，壞一個不影響其他的；時機在面板畫好之後，所以錯誤進面板（原設計寫的是 tkinter 的 `after(0)`；在網頁面板裡怎麼排，做的時候再定）。

### 8.6 拖放（M2 後段）

把檔案拖到圖示上還沒做，延到 M2 後段：要先看 pywebview 的拖放支援再定做法。同一件事的另一條路——右鍵「選擇檔案後執行…」——也還沒做（§8.3）。

原本的做法是可選依賴 `tkinterdnd2`，那一段程式還留在 `ui/tk.py` 的 `_make_root`：安全模式完全不載入 `tkinterdnd2`；否則 `try: from tkinterdnd2 import TkinterDnD`，成功就以 `TkinterDnD.Tk()` 當主視窗，`ImportError` 就用 `tkinter.Tk`。`TkinterDnD.Tk()` 本身丟 `RuntimeError`／`TclError`（原生 tkdnd 載入失敗）時，視窗其實已經建好，就直接用那個視窗、只是沒有拖放；不 destroy 重建（D42）。但 0.4.0 的 `main.py` 只會以安全模式開 tkinter 面板，所以「否則」那一支從 `main.py` 走不到，只有測試直接建 `Panel(safe=False)` 時會經過（`tests/test_tk_smoke.py::test_dnd_skipped_in_safe_mode_and_failure_falls_back`）；它從來沒有註冊過拖放。

### 8.7 安全模式與後備：tkinter 面板

tkinter 面板（`ui/tk.py`，原 `core/ui.py`）現在只以安全模式出現：`python3 main.py --safe`，或網頁面板開不起來時自動退到它（§7）。視窗標題有「（安全模式）」，只掃 `modules/`。它的操作跟 0.3.0 一樣，沒有跟著 D64 改——「單擊選取、雙擊執行」只在網頁面板：

```
┌ iPLoT v0.4.0（安全模式）───────────┐
│ [ iPLoT ]                          │   麵包屑：一排按鈕，點任一段回上去；
│ 這一層                        ＋   │   進入「開工」後是 [ iPLoT ] ▸ [ 開工 ]
│   [ 開工            ]  ▸           │   安全模式只有「這一層」這一組；＋ 在標題右邊
│   [ 打開核心原始碼  ]              │   ▸ 是獨立的小按鈕：底下還有模組，按下進入
│   [ ⚠ 整理桌面      ]              │   ⚠ 在按鈕文字前：語法錯誤，按下去看錯在哪
├────────────────────────────────────┤
│ …traceback…                        │   訊息區：錯誤和 app.log 都在這；
│ 模組『整理桌面』第 7 行出錯：       │   先 traceback、再白話那一句、
│ NameError，name 'x' is not defined  │   最後「打開檔案」，捲到底看到的是人話
│ [ 打開檔案 ]                        │
└────────────────────────────────────┘
```

- 單一視窗、單一欄的按鈕、可捲動。**單擊就執行**；沒有選取、沒有狀態列、沒有圖示。
- 右鍵四項：打開程式碼／在資料夾中顯示／在終端機打開／在這裡新增下一層模組…。右鍵選單同時綁 `<Button-2>`、`<Button-3>`、`<Control-Button-1>`：macOS 上 Tk 8.6 的右鍵是 Button-2，Tk 9.0 是 Button-3。
- ＋ 在每一組標題的右邊；根目錄讀不到（有 `note`）的那一組不顯示 ＋：沒有地方可以建。一組沒有任何模組時顯示「尚無模組，按 ＋ 新增」。
- 顏色按層：`here` 藍、`parent` 紅、`extra` 綠、`child` 沿用進入前那一層的顏色（安全模式只掃 `modules/`，所以平常看到的是藍）。
- 對話框是 tkinter 的：`ask` 用 `simpledialog`，`confirm` 用 `messagebox`，選檔案、選資料夾用 `filedialog`。
- 模組在主視窗的執行緒上執行，跑很久會凍住視窗（§7 已知限制）。
- 需要 tkinter（python.org 的 Python 內含）。這個 Python 沒有 tkinter 時，印一句說明、以代碼 1 結束。

## 9. 版本管理

### 9.1 開發端：git

- iPLoT 自己是一個 git repo，建在 `6000_work/iplot`。老闆的 `iPLoT.py`、`iPLoT.txt` 移到 `docs/original/`，連同 `00_現況分析.md`、`01_從零啟動.md` 與 `docs/original/step1_patched/`（步驟 1 修補實驗的對照組）當第一個 commit，打 tag `v0.0-original`。外層 `6000_work` 若本身是 repo，把 `iplot/` 加進它的 `.gitignore`。
- `main` 永遠可以啟動：合進 `main` 的每個 commit 都要通過 §12 的從零啟動情境，CI 擋。
- 語意化版本：`core/__init__.py` 的 `__version__`，顯示在視窗標題；`CHANGELOG.md` 照 keep-a-changelog；`app.api_version` 獨立計。
- 功能分支短命，合回 `main` 就刪；一個人開發也走 PR，PR 頁面就是設計決定的紀錄。還沒有遠端時（M1）在本地分支 `m1-seed` 開發，v0.1.0 時 `git merge --no-ff` 回 `main` 再打 tag（D30）。
- `.gitignore`：`logs/`、`lib/`（M2：第一次啟動裝進來的套件不進 repo）、`.history/`、`__pycache__/`、`.DS_Store`，以及開發工具的快取。

### 9.2 使用者端：`history.py`

- 時機：每次執行前 `snapshot`；每次 `restore` 前也先 `snapshot`，所以復原本身可以再復原。
- 位置：`<模組>/.history/2026-10-02_140905.py`。藏在模組自己的資料夾裡，刪模組就一起消失。
- 去重：跟最新一份比 sha256，相同就不存。保留份數 `HISTORY_KEEP`，超過刪最舊的。只認自己命名的檔案（`YYYY-MM-DD_HHMMSS[_n].py`）；`.history/` 裡別的檔案不比對、不刪（D44）。
- 復原：右鍵「回到上一版…」（§8.3）。
- 範圍：只管模組。核心或面板改壞了靠 git（`git checkout -- core/ ui/`）；第一版不做滑鼠版的核心復原。

## 11. 工程規範

- Python ≥ 3.10 加 pip（不必是 python.org 的；Homebrew 的照理也行，但實測只跑過 python.org 的）。tkinter 不再是必要的，只有安全模式與後備需要它（python.org 的版本內含 tkinter）。README 第一行就寫。
- 核心全部型別標註；附錄 B 的資料結構都是 `frozen dataclass`。
- 識別字英文；docstring 與畫面文字繁體中文；畫面文字集中在 `core/text.py`。`core/`（`text.py` 除外）、`ui/*.py` 與 `main.py` 不寫中文字串常數（docstring 與註解除外）；`ui/app.js`、`ui/index.html` 註解以外也沒有中文，畫面文字由 Python 在啟動時整份送進頁面；新模組範本也放在 `text.py` 的 `TEMPLATE`（D32）。M2 起這一條有測試：`tests/test_boundaries.py` 的 `test_no_chinese_string_constants_outside_text`、`test_app_js_has_no_chinese_outside_comments`、`test_index_html_loads_style_then_custom_css_then_script`。

3. `config.py` 語法錯誤 → 用預設值開，面板顯示錯在哪。
4. 只有一個語法錯誤的模組 → 列出並標 ⚠，按下顯示錯誤與「打開檔案」。（網頁面板的標記是圖示右上角的紅點，要雙擊才執行。）
5. 模組 `run` 丟例外 / 呼叫 `exit(1)` → 面板顯示檔案與行號，iPLoT 活著。
6. 沒裝 `tkinterdnd2` → 照常開，拖放關閉，沒有任何錯誤訊息。（0.4.0 起 tkinter 面板只以安全模式出現，安全模式本來就不載入 `tkinterdnd2`；拖放還沒做，§8.6。）
7. 滑鼠三下：按 ＋、打名字、按確定 → 編輯器開了範本、按鈕在面板上、按下去訊息區出現範本的那一行 log。（網頁面板的 ＋ 是每一組最後一格，新模組要雙擊才執行；安全模式的 tkinter 面板照原樣，按一下就執行。）
8. `modules/` 沒有「作業系統」模組（M1.4）→ 按 ＋ 模組照樣建好、按鈕出現，訊息區一行說明為什麼沒開編輯器；其他功能不受影響。情境 1–6 的乾淨副本裡 `modules/` 是空的，本來就沒有這個模組。

```python
    roots: tuple[str, ...]     # 附錄 C 的 ROOTS
    editor: tuple[str, ...] | None
    history_keep: int

@dataclass(frozen=True)
class Group:
    label: str                 # 頂層同 Root.label；進入某個模組後是那個模組的 title
    level: Level
    root: Path                 # 頂層是根目錄；進入某個模組後是那個模組的資料夾（＋ 建在這裡）
    modules: tuple[ModuleInfo, ...]
    note: str | None = None    # 根目錄讀不到時的說明，顯示在這一組的位置

@dataclass(frozen=True)
class Scope:
    crumbs: tuple[str, ...]    # 麵包屑，頂層是 ("iPLoT",)
    groups: tuple[Group, ...]

@dataclass(frozen=True)
class ErrorInfo:
    kind: str                  # 例外類別名稱
    message: str
    file: Path | None
    line: int | None
    traceback_text: str
    source: Source
    module: str | None         # 模組名稱；核心錯誤時 None

@dataclass(frozen=True)
class Result:
    ok: bool
    error: ErrorInfo | None
    duration: float            # 秒
    output: str                # 執行期間 print 到 stdout / stderr 的內容
    value: Any = None          # 處理函式的回傳值（M1.4）；沒有處理函式或出錯時是 None

DEFAULT_CONFIG = Config(roots=("modules", ".."), editor=None, history_keep=20)   # 附錄 C 的預設值
```

## 附錄 D：原版模組的包裝檔（「匯入原版模組」寫入的 `iplot.py`）

這是 M1 時的設計（`api_version` 1），「匯入原版模組」還沒做（§8.5）。0.4.0 拿掉了 `app.window`（D66），網頁面板下模組也不能靠 tkinter 開自己的視窗（D63 的代價），所以下面 `iPLoTWIN` 那一行已經不成立，先改成註解；原版模組裡用到主視窗的部分怎麼辦，要做這個模組時照當時的 `app` 重新設計。其餘各行留著當設計的紀錄。

```python
"""原版 iPLoT 模組的相容包裝。每次按下都重新執行旁邊的 <資料夾名>.txt。"""

def run(app):
    import os, tkinter
    src = app.module.folder / (app.module.name + ".txt")
    names = {
        "__name__": app.module.name,
        "__file__": str(src),
        "os": os,
        "tkinter": tkinter,
        # "iPLoTWIN": app.window,                     # 原版：主視窗。0.4.0 起沒有 app.window（D66），這一行不能用
        "iPLoTHOMEDIR": str(app.home),                # 原版：iPLoT 資料夾
        app.module.name + "HOMEDIR": str(app.module.folder),  # 原版：<名稱>HOMEDIR
    }
    exec(compile(src.read_text(encoding="utf-8"), str(src), "exec"), names)
```

- 提供的名字就是上面這幾個。原版模組用到其他核心內部名字（例如 `DPanel`、`cmdEXCUTE_iPLoT`、`TkinterDnD`）時，面板會顯示「模組『X』第 N 行出錯：NameError，name '…' is not defined」，行號是 `X.txt` 裡的行號（錯誤定位取模組資料夾內最內層的一格），「打開檔案」打開的就是 `X.txt`，缺哪個一目了然；真的有人需要再加進包裝檔，不進核心。
- 包裝檔本身是普通模組，所以快照、復原、自動啟動、右鍵選單對它全部有效。
- `.txt` 還在，`iplot.py` 也在：Finder 裡兩個檔案並排，老闆改 `.txt`，不用碰 `iplot.py`。
