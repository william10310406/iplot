# iPLoT 待辦

**這是目前所有該做的事的唯一清單。** `/下一步` 會讀它、更新它；`/日誌` 的「留下的」是它的來源之一。

**兩週使用期間的規則**（起始日寫在 [README.md](README.md) 頂端）：期間**不排新功能**，只排修補、驗收、使用。新冒出來的功能點子一律放到最底下的「兩週後才排」，不排進期間。

- 狀態只有四種：**未開始**／**進行中**／**等我驗收**／**完成**。
- 優先順序：P1 現在就做；P2 排在 P1 之後、兩週內做完；P3 有空再做；P4 先放著。
- 需要使用者本人決定的事，在「做什麼」裡寫成「需要問他：…」，由助理轉問。
- 預估是粗估：助理或 Claude Code 做的時間，與使用者自己動手的時間分開寫。

最後更新：2026-11-06（T01–T04 標為完成、T03 起始日 2026-11-09；T07 補決定；T14、T15 註明路徑可公開（D149），T15 只剩 `iplot-modules` 的過時註解）。前一次：2026-11-05（第二次更新：加 T21）。資料來源：`docs/reports/2026-11-05-現況盤點報告.md` 第 8 節、分支 `fix/safety-and-vision`（5 個 commit，還沒合進 main）、日誌裡的「留下的」。

## 五、兩週後才排（期間不碰）

新功能與還沒決定要不要做的方向，先記在這裡，不排進期間。

- 匯入原版模組（D26；唯一一條「已確認需求」沒兌現的）。
- M7b「上傳」模組：在 iPLoT 裡有通往上傳表單的入口。
- M8b：在 iPLoT 裡看討論（D116，只評估過）。
- 「M2 後段」那批滑鼠操作：回到上一版、重新命名、移到垃圾桶、拖放、自動啟動（回到上一版與移到垃圾桶的底層早就有，只差右鍵選單）。
- 不需要「強制打開」的啟動方式（macOS 簽章）。
- 行事曆的待辦：上傳到學校的網頁空間、匯入舊資料、週檢視與提醒、多台電腦同步（`docs/05_使用紀錄.md`）。
- 學生程式的沙箱；`app.secret`（D58）。
- 方向問題：iPLoT 要繼續是「老闆課程的工具」，還是回到「接手日常」（檔案整理、工作情境）？看兩週使用紀錄再決定。
