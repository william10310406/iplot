# iPLoT 每日日誌

**兩週使用期間起始日：未設定**

（設定方式：第一次跑 `/日誌`，指令會問今天是不是第 1 天；回答是，就把上面這一行改成 `**兩週使用期間起始日：YYYY-MM-DD**`。之後 `/日誌` 在第 7 天與第 14 天會提醒做檢視。）

## 這是什麼

一天一個檔：`docs/日誌/YYYY-MM-DD.md`。記的是當天發生的事，不是 commit 訊息的複製——要的是「隔了一個月再看，還知道那天做了什麼、決定了什麼、用了什麼、卡在哪」。沒有任何 commit 或文件活動的日子不建檔。

2026-10-02 到 2026-11-05 的日誌是事後補寫的，資料來源是 `git log --all`、`docs/plans/` 各里程碑的設計／工作單／回報、`CHANGELOG.md` 與各模組的 `CHANGELOG.md`、`docs/05_使用紀錄.md`、`docs/reports/2026-11-05-現況盤點報告.md`。從 11-05 以後的日誌由 `/日誌` 每天整理。

## 每篇的格式

```
# YYYY-MM-DD
## 做了什麼        用白話寫做了什麼（不是貼 commit 訊息），每條後面附相關 commit 短 hash
## 決定            當天定下的設計決定，附 D 編號；沒有就省略這一節
## iPLoT 使用紀錄  當天實際「使用」iPLoT 做了什麼、卡在哪；沒有就寫「無」
## 想要但做不到    每條註明：只要加模組／需要動核心；沒有就省略這一節
## 留下的          沒做完、延後、待驗收的事
```

幾條規矩：

- **使用不等於開發。**「iPLoT 使用紀錄」只寫有證據的使用（`docs/05_使用紀錄.md` 的紀錄、驗收紀錄、當事人說的）。開發時為了驗證而跑的測試、探針、驗收腳本，不算使用；補寫的過去日子，大部分是「無」，照實寫。
- **repo 是公開的。** 日誌裡不放本機路徑（家目錄、外接硬碟的路徑）、不放帳號以外的人名、不放學生的任何資料。人一律用角色稱呼：老闆、研究助理、上傳者、同事。
- **不確定是哪天發生的**，寫在最接近的那天並標「（日期推定）」。沒有證據的事不編。
- 同一天已有日誌時，`/日誌` 是合併進去，不覆蓋。

## 怎麼用 `/日誌`

每天收工前在 Claude Code 裡打一次：

```
/日誌
```

它會依序做：

1. 讀今天（Asia/Taipei 時區）的 `git log --all`、今天改過的 `docs/` 檔案、工作樹裡還沒 commit 的變更（只列檔名）。
2. 一次問三個問題（可以回「無」）：今天有沒有實際用 iPLoT 做事、做了什麼、卡在哪；有沒有想做但 iPLoT 做不到的事；還有什麼沒反映在 commit 裡的工作或決定。
3. 寫（或合併進）今天的 `docs/日誌/YYYY-MM-DD.md`，更新這份索引。
4. 檢查沒有本機路徑、沒有學生資料。
5. 只 commit `docs/日誌/` 底下的檔，訊息是「日誌：YYYY-MM-DD」；其他變更不碰。
6. 如果今天是兩週使用期間的第 7 天或第 14 天，提醒做檢視，並列出這段期間「想要但做不到」的彙整，按「只加模組」與「需要動核心」分組。

指令本身寫在 `.claude/commands/日誌.md`。
