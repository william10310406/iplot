# iPLoT 的接口與邊界

## 0. 一句話

iPLoT 有哪幾個可以換零件的地方、每個地方的規則是什麼、哪個測試擋住那條規則。寫給五種人：想改核心的人、想改面板的長相或換一個面板的人、想把 iPLoT 搬到別的作業系統的人、想讓模組接網路的人、想發佈新版或把模組放上工作坊的人。

每一節先說「這是什麼」，再說「怎麼改」「怎麼造」。規格在 `02_重構設計.md`，每個決定的理由在 `03_設計決定.md`（這份文件引用的是 D07、D10、D24、D32、D50–D59、0.4.0 的 D61–D68、0.5.0 的 D69–D79、0.5.1 的 D80–D93、「科學計算」的 D94–D99，與 0.5.2 的 D100–D108）。第 10、11 節是 0.5.0 加的「更新」與「工作坊」；第 12、13 節是 0.5.1 加的「面板外執行（互通）」與「工作坊模組可以依賴的核心介面」；0.5.2 起第 11 節也講 `iplot-modules` 的上傳（第 1 節的「上傳」、第 7 節的「開放上傳」也是）。

## 2. 「作業系統」模組

**這是什麼。** `modules/作業系統/` 是一個普通的模組，裡面四個檔：

- `iplot.py`：選擇器。看現在是哪個作業系統，匯入旁邊的 `mac.py`、`win.py` 或 `linux.py`，把七個函式轉出來。執行它，訊息區會說現在用的是哪一個檔。
- `mac.py`、`win.py`、`linux.py`：各自用那個系統的做法實作同樣的七個函式。

核心需要碰作業系統時（`app.open`、右鍵選單、按 ＋ 之後打開編輯器、錯誤訊息的「打開檔案」），會到 `modules/` 找名字剛好是「作業系統」的模組，執行它對應的函式——跟執行任何模組走的是同一扇門，只是不印「完成」那一行。啟動時網頁面板開不起來、要安裝介面的時候（通常是第一次啟動），`ui/install.py` 也是走這扇門問它兩件事：裝哪一份、缺什麼（下表最後兩列）；需求檔換過、啟動時要重裝 `lib/` 的時候（第 1 節「安裝」那一列），問的也是這兩件事。只在 `modules/` 找；上一層或 `ROOTS` 其他位置的同名資料夾不算（D52）。安全模式（`--safe`）照樣有。

**七個函式。** 三個檔的簽名完全一樣（測試會比）。前五個是「做一件事」，模組透過 `app` 用得到；後兩個是「回答一個問題」，只有要安裝介面的時候才會問：

| 函式 | macOS（`mac.py`） | Windows（`win.py`，未經實機驗證） | Linux（`linux.py`） |
|---|---|---|---|
| `open(app, path)` | `open <路徑>` | `os.startfile` | `xdg-open <路徑>` |
| `edit(app, path, editor, line)` | `editor` 是 `None` 用 `open -t`（系統預設文字編輯器），否則照 `config.py` 的 `EDITOR`；資料夾一律改走 `open` | `None` 用記事本；其餘同左，但會先找出編輯器指令的完整路徑（`code` 在 Windows 是 `code.cmd`） | `None` 用 `xdg-open`；其餘同左 |
| `reveal(app, path)` | `open -R`：在 Finder 顯示並選取 | `explorer /select,<路徑>` | `xdg-open <上一層資料夾>`（沒有「選取」） |
| `terminal(app, path)` | `open -a Terminal <路徑>` | 有 Windows Terminal（`wt`）就用它，沒有就開新的 `cmd` 視窗 | 依序找 `x-terminal-emulator`、`gnome-terminal`、`konsole`、`xfce4-terminal`、`xterm`，用第一個找得到的；都沒有就報錯並列出試過的名字 |
| `trash(app, path)` | 搬到 `~/.Trash`，同名加「 2」「 3」…；回傳搬到哪 | 資源回收筒（`SHFileOperationW`）；資源回收筒沒有路徑，回 `None` | 照 XDG 規範搬到 `~/.local/share/Trash/files/`，並在 `info/` 寫一個 `.trashinfo` 記原本的位置與時間；回傳搬到哪 |
| `requirements(app)` | 回 `"web-mac.txt"` | 回 `"web-win.txt"` | 回空字串：這一版 Linux 沒有網頁面板 |
| `webview_ready(app)` | 回 `None`：macOS 內建 WebKit，什麼都不缺 | 查登錄檔三個位置有沒有 WebView2 runtime 的版本號（`pv`）：任一個有就回 `None`；都沒有就回一句話：「找不到 WebView2 runtime：請先安裝 Microsoft Edge WebView2 Runtime（Windows 11 內建）」。這個檢查只用假的 `winreg` 驗過 | 回一句話：「這一版的網頁面板還不支援 Linux」 |

`requirements` 回的是 `requirements/` 裡的檔名（一份釘死版本的套件清單）；回空字串表示這個平台沒有網頁面板。`webview_ready` 回 `None` 表示可以裝；回一句話表示缺了 pip 裝不了的東西。這兩種「裝不了」都不跑 pip，直接退到後備的 tkinter 面板（不是安全模式：照常掃上一層與 `ROOTS`），原因印在主控台、也寫進那個面板的訊息區（`tests/test_main.py::test_platform_without_web_panel_falls_back_without_pip`）。

啟動外部程式一律用 `subprocess.Popen([...])` 傳清單、啟動後不等（記事本、`cmd` 會一直開著，等它的話後面排著的工作全部卡住，tkinter 面板則是整個凍住），不拼字串。系統上缺那個執行檔時，面板會顯示「模組『作業系統』第 N 行出錯：FileNotFoundError，…」，N 是後端檔案（例如 `linux.py`）裡的行號，不是核心的。

**沒有這個模組會怎樣。** 介面已經裝好（`lib/` 在）的話，啟動不受影響，其他功能全部正常。需要它的動作各自在訊息區記一行說明，動作不執行：按 ＋ 時模組照樣建好、面板上照樣出現，只是不會自動打開編輯器（右鍵「在這裡新增下一層模組…」走同一條路，也一樣）；右鍵的「打開程式碼」「在資料夾中顯示」「在終端機打開」、錯誤訊息的「打開檔案」、`app.open` 等五個 `app` 方法都是記一行、回 `None`。介面還沒裝的時候少了它，第一次啟動不知道要裝哪一份：不跑 pip，同樣那一行印在主控台，然後退到後備的 tkinter 面板（`tests/test_main.py::test_missing_system_module_falls_back_without_pip`）。

**改壞了會怎樣、怎麼救。** 跟任何壞掉的模組一樣：每次動作在面板報一次錯，附檔案與行號，iPLoT 不會死。`iplot.py` 有語法錯誤時，它那一格的右上角會有紅點（tkinter 面板是在按鈕上標 ⚠）；`mac.py` 這類後端檔壞了不會標，但每次動作一樣會報錯。已知限制：這時右鍵「打開程式碼」和錯誤訊息的「打開檔案」自己也壞了（它們也是交給這個模組做的），要自己用檔案總管打開 `modules/作業系統/` 底下的檔案改回來。`iplot.py` 在 `.history/` 有上一版；`mac.py`、`win.py`、`linux.py` 沒有快照（快照只存 `iplot.py`），改之前自己留一份，或從 iPLoT 的壓縮檔、git 拿回原本的。

**怎麼改。** 例：macOS 上想把 Terminal 換成 iTerm。右鍵「作業系統」→「在資料夾中顯示」，打開 `mac.py`，把 `terminal` 函式裡的 `"Terminal"` 改成 `"iTerm"`，存檔。不用重啟：下一次右鍵「在終端機打開」就是新的行為。（右鍵「打開程式碼」開的是選擇器 `iplot.py`，後端檔在同一個資料夾。）

**怎麼加一個作業系統。** 例：FreeBSD。

1. 把 `linux.py` 複製成 `bsd.py`，改 `NAME` 和七個函式。簽名不要動。`requirements` 與 `webview_ready` 這兩個也要回答：新平台沒有網頁面板，就照 `linux.py` 的樣子回空字串、回一句說這個平台還沒有網頁面板的話（後面接的是「已改用備用面板」，所以不要叫人用安全模式）；有的話，在 `requirements/` 加一份釘死版本的清單，`requirements` 回它的檔名。
2. `iplot.py` 加一個分支：`elif sys.platform.startswith("freebsd"): import bsd as backend`。
3. `tests/test_bundled.py` 加一個 `test_bsd_argv`（照 `test_linux_argv` 的樣子，用假的 `Popen` 驗參數），把 `"bsd"` 加進 `test_backends_have_same_seven_functions` 與 `test_selector_picks_backend_by_platform`，並在 `test_requirements_and_ready_per_backend` 補上新平台的兩個答案。加了需求檔的話，`tests/test_install.py::test_requirements_are_pinned` 的檔名清單也加上它。

核心一行都不用動。

## 3. 怎麼加一個動作

**這是什麼。** 「動作」是模組想請作業系統做的一件事。現在有五個（上一節表格的前五列）。

**怎麼造。** 例：`app.clipboard(text)`，把文字放進剪貼簿。

1. 三個後端各加一個同簽名的函式 `clipboard(app, text)`。
2. `modules/作業系統/iplot.py` 轉出函式的那幾行加上 `clipboard`（核心是在 `iplot.py` 裡找函式的，沒轉出來就找不到）。
3. `core/app.py` 加一個一行的方法，帶繁體中文 docstring：`self._core.action("clipboard", text)`。
4. `docs/api.md` 的表加一列。
5. 測試：`tests/test_bundled.py` 的 `NAMES` 加上 `"clipboard"`（簽名一致的測試就會涵蓋它）並為三個後端各加參數的斷言；`tests/test_app.py` 加一個「轉呼叫 `core.action`」的斷言。

核心其他地方不用動：`Core.action(name, *args)` 不認識動作的名字，只負責找到模組、執行同名的函式、把回傳值傳回來。這是加法，`api_version` 不用升。

以上是讓模組用得到新動作。要讓面板的右鍵選單也能叫它，是另外一件事：網頁面板的頁面只能透過 `Bridge.action(name, id)` 要求動作，而它只收 `edit`、`reveal`、`terminal` 三個名字，其餘一律不做（`tests/test_web.py::test_action_rejects_names_the_page_has_no_business_calling`）。所以還要兩步：在 `ui/web.py` 的 `ACTIONS` 加上名字——`ACTIONS` 裡的名字，`Bridge` 會拿那個模組的資料夾當參數去叫 `core.action(name, info.folder)`，參數不一樣的要像 `edit` 那樣另寫一個分支；再在 `ui/app.js` 的 `menuFor` 加一項，選單上的字加在 `core/text.py`。tkinter 面板要有同一項的話，在 `ui/tk.py` 的 `_row` 加一行 `menu.add_command`。

## 4. 面板

**這是什麼。** 核心只透過 `View` 跟面板說話（`core/core.py`）：

```python
class View(Protocol):
    def show(self, scope: Scope) -> None: ...     # 把目前範圍畫出來
    def log(self, text: str) -> None: ...         # 訊息區加一行
    def report(self, error: ErrorInfo) -> None: ...   # 顯示一個錯誤
    def ask(self, prompt: str, default: str = "") -> str | None: ...   # 問一個字串；取消回 None
    def confirm(self, prompt: str) -> bool: ...   # 問「確定／取消」；確定回 True
    def page(self, title: str, html: str, api: object | None) -> None: ...   # 另開一頁 HTML，關掉才回來
    def choose_files(self) -> list[Path]: ...
    def choose_folder(self) -> Path | None: ...
```

八個方法，沒有屬性；第八個 `page` 是 0.5.0 加的（D72）。做到這八個方法的類別現在有四個：

| 類別 | 在哪 | 什麼時候用 | `page` 怎麼做 |
|---|---|---|---|
| `WebPanel` | `ui/web.py` | 預設的面板：pywebview 開的原生視窗，裡面跑 `ui/index.html`、`app.js`、`style.css`（D61、D63） | 開第二個 pywebview 視窗：`html` 整頁當字串交給它，`api` 當那個視窗的 `js_api`；那個視窗關掉才回傳（`tests/test_web.py::test_page_blocks_until_closed`） |
| `Panel` | `ui/tk.py` | tkinter 面板。兩種時候出現：啟動時加 `--safe`（安全模式，只掃 `modules/`，標題有「（安全模式）」）；或網頁面板開不起來時的後備（掃完整範圍，不是安全模式，D75） | 沒有頁面：在訊息區記一行 `T["page_unsupported"]` 就回傳（`tests/test_tk_smoke.py::test_page_logs_unsupported`） |
| `ConsoleView` | `ui/install.py` | 安裝或重裝介面時視窗還沒開，核心要說的話印在主控台 | 沒有畫面：什麼都不做 |
| `FakeView` | `tests/conftest.py` | 測試用：不開視窗，把事件記進一個清單 | 記一筆事件 |

兩個面板的操作不一樣：網頁面板是單擊選取、雙擊執行、右鍵最多六項（「進入下一層」只有有子模組的才有；D64），每組最後一格是 ＋；tkinter 面板是按一下就執行、右鍵四項、＋ 在每組標題的右邊。

**網頁面板的兩頭。** Python 那一頭是 `ui/web.py`：`WebPanel` 把 `show`、`log`、`report`、`ask`、`confirm` 翻成對頁面的呼叫；`Bridge` 是頁面呼叫 Python 的入口。頁面那一頭是 `ui/` 裡的三個檔：`index.html`（骨架）、`style.css`（外觀）、`app.js`（行為），不用框架、不用 build。頁面用 `file://` 網址從 iPLoT 的資料夾載入，沒有 HTTP server、沒有 port（`tests/test_web.py::test_window_is_created_from_a_file_url`）。兩頭之間講好的名字就這些：

| 方向 | 怎麼叫 | 名字 |
|---|---|---|
| 頁面 → Python | `app.js` 裡的 `api().<方法>(…)`，也就是 `pywebview.api.<方法>` | `Bridge` 的十個方法：`state`、`press`、`enter`、`back`、`create`、`add_child`、`action`、`open_error`、`rescan`、`answer` |
| Python → 頁面 | `ui/web.py` 裡的 `self._js("<名字>", …)`（對話框是 `self._dialog`），送出去的是 `iplot.<名字>(JSON)` | `app.js` 最下面的七個入口：`iplot.init`、`show`、`log`、`report`、`ask`、`confirm`、`busy` |

**怎麼改外觀。** 打開 `ui/style.css`。開頭的 `:root { … }` 那一段是顏色與尺寸的變數（選取的顏色 `--accent`、圖示的邊長 `--icon`、一格最窄的寬度 `--tile`、訊息區的高度 `--log-height` 等等），多半附了註解；緊接著的 `@media (prefers-color-scheme: dark)` 是深色模式的顏色。下面的規則不直接寫顏色、只用變數（測試擋著），所以改顏色只改這兩段；圖示、格子、圓角、訊息區這幾個主要的尺寸也在這裡。改完重新啟動 iPLoT。

想讓自己的改法留得住：在 iPLoT 資料夾（跟 `config.py` 同一層）建一個 `custom.css`，把要改的變數寫在裡面，例如 `:root { --accent: #e0703d; --icon: 64px; }`。它在 `style.css` 之後載入，同名的變數以它為準；沒有這個檔也沒關係。它不在 `ui/` 裡，換新版的 `ui/` 不會動到它。

**怎麼改行為。** 打開 `ui/app.js`，改完重新啟動 iPLoT。頁面受幾條規則管，前四條有測試擋著（沒寫檔名的都在 `tests/test_boundaries.py`）：

- 畫面上的字不寫在 `app.js`：加在 `core/text.py` 的 `T`，`app.js` 裡用 `T.<key>`（啟動時 `iplot.init` 把 `T` 整份送進頁面）。註解可以寫中文。測試：`test_app_js_has_no_chinese_outside_comments`、`test_app_js_uses_only_text_keys_that_exist`。
- 頁面呼叫的方法必須是 `Bridge` 有的，`Bridge` 的方法頁面也都要用到（`state` 除外）。要加一個：`Bridge` 加方法、`app.js` 呼叫它，兩邊一起改。測試：`test_app_js_calls_exactly_the_bridge_methods`；`tests/test_web.py::test_bridge_exposes_only_its_methods` 列著那十個名字，也要跟著改。
- Python 呼叫頁面的入口剛好七個：`ui/web.py` 用到的每個名字，`app.js` 都要有一行 `iplot.<名字> = …`，不能多也不能少。測試：`test_app_js_defines_every_entry_python_calls`。
- `index.html` 裡不寫行內的 JS（`onclick=` 這類屬性、沒有 `src` 的 `<script>`），JS 全部在 `app.js`；除了註解也不寫中文字。測試：`test_index_html_loads_style_then_custom_css_then_script`。
- 模組的名稱、輸出、錯誤訊息放進頁面時用 `textContent`（`app.js` 的 `el()` 就是這樣做的），不要用 `innerHTML`（第 7 節）。這一條沒有測試，靠規範。

頁面本身沒有自動測試；上面的測試只釘住它跟 Python 那一頭對得上。改了 `app.js` 之後，要自己開面板把改到的地方按一遍。改壞到面板出不來時，用 `python3 main.py --safe` 開 tkinter 面板——它不用這三個檔。

**怎麼換一個面板。** 寫一個做到 `View` 八個方法的類別，在 `main.py` 選它：照 `run_web` 或 `run_tk` 的樣子，建面板、建 `Core(home, config, 面板, safe)`、把 `core` 交給面板、叫一次 `core.rescan()` 畫出第一個畫面、進入面板自己的事件迴圈。`page` 做不出來的面板，照 tkinter 面板的樣子記一行就回傳：對呼叫 `app.page` 的模組來說，就是頁面沒開過、接著往下跑。面板要把使用者的動作交回核心：

| 使用者做了什麼 | 叫核心的哪個方法 |
|---|---|
| 執行一個模組 | `core.press(info)` |
| 進入下一層 | `core.enter(info)` |
| 按麵包屑的某一段 | `core.back(depth)`，0 是頂層 |
| 按 ＋、取了名字 | `core.create(parent, name)`，`parent` 是那一組的資料夾；右鍵「在這裡新增下一層模組…」也是，`parent` 給那個模組自己的資料夾 |
| 右鍵「打開程式碼」 | `core.action("edit", info.file, core.config.editor, None)` |
| 右鍵「在資料夾中顯示」「在終端機打開」 | `core.action("reveal", info.folder)`、`core.action("terminal", info.folder)` |
| 錯誤訊息的「打開檔案」 | `core.action("edit", error.file, core.config.editor, error.line)` |
| 視窗取得焦點 | `core.rescan()`：在檔案總管新增、刪掉、改了模組，點回來就看得到 |
| 面板自己的程式出錯 | `core.report_internal(type(exc), exc, exc.__traceback__)`：寫進 `logs/iplot.log`，再顯示在面板 |

**執行緒的規則。** `Core` 不知道執行緒的存在，也沒有鎖：它的方法要都在同一條執行緒上呼叫，一次一件。怎麼做到是面板的事，兩個面板各有做法：

- `ui/tk.py`：所有事都在 tkinter 的主執行緒上，按鈕的回呼直接叫 `core`。所以模組執行多久，這個面板就凍多久。
- `ui/web.py`：主執行緒被 pywebview 的視窗佔著，頁面每呼叫一次 `Bridge`，pywebview 又各開一條執行緒。所以 `Bridge` 的方法只把工作排進佇列、立刻回傳，由唯一一條工作執行緒依序做，一次一件；連按兩個模組，第二個排隊（`tests/test_web.py::test_jobs_run_one_at_a_time`）。不排隊的只有兩個：`state`（只讀目前的範圍）與 `answer`（叫醒在等回答的對話框），它們不呼叫 `Core` 的方法。工作裡沒接住的例外交給 `core.report_internal`，迴圈繼續做下一件（`::test_job_exception_goes_to_report_internal`）。
- 網頁面板的 `ask`、`confirm` 是模組在工作執行緒上呼叫的，要等人回答：`WebPanel` 推一個對話框給頁面，自己停下來等，頁面用 `answer(編號, 值)` 回來。視窗關掉時，還在等的一律當作按了取消（`::test_close_window_cancels_pending_ask`）。
- 網頁面板的 `page` 也是模組在工作執行緒上呼叫的：開了第二個視窗就停在那裡，等那個視窗關掉（`::test_page_blocks_until_closed`）。所以那一頁開著的期間，模組算是還在執行，排著的工作都不會動。

新的面板照同一條規則：要嘛所有事都在一條執行緒上，要嘛自己排隊。

**`app.window` 已經拿掉。** 0.3.0 的 `View` 有一個 `window` 屬性，`app.window` 把 tkinter 的主視窗直接交給模組，讓模組自己畫東西。網頁面板沒有 tkinter 主視窗可以給，所以 0.4.0 把這兩個都拿掉了，`api_version` 升到 2（D66；`tests/test_app.py::test_no_window`）。用到 `app.window` 的模組要改；隨附的模組都沒用到它。模組要有自己的畫面，0.5.0 起用下面的 `app.page`。

**模組自己的一頁：`app.page`。** `app.page(title, html, api=None)` 另開一個視窗顯示一頁 HTML，視窗關掉才回傳，像對話框（0.5.0，`api_version` 3，D72；`tests/test_app.py::test_api_version_is_3`、`::test_page_goes_to_view`）。隨附的「工作坊」是現成的例子，它的 `run` 最後三行就是全部的用法：

```python
template = (Path(__file__).parent / "page.html").read_text(encoding="utf-8")
app.page("工作坊", workshop.render(entries, modules_dir, template), workshop.Api(app, entries, modules_dir))
app.rescan()  # 頁面關掉之後：新裝的模組出現在面板上
```

- **`html` 是一整頁 HTML 的字串**，不是檔名、也不是網址。工作坊把頁面寫在旁邊的 `page.html`，執行時讀進來，把裡面的 `{rows}` 換成一列列的模組（`workshop.render`），再整頁交出去。樣式與 JS 都直接寫在那一頁裡。
- **`api` 是一個普通的物件**：它的公開方法，那一頁的 JS 用 `pywebview.api.<方法>(…)` 呼叫，回傳值在 JS 那一頭用 `.then(…)` 接。工作坊的 `Api` 只有一個公開方法 `install(name, confirmed=False)`，回一個字串——新的狀態、「需要確認」（要覆蓋、或更新會蓋掉模組自己存的檔，而還沒確認過，第 11 節），或「無法安裝：」開頭的一句話；預期中的錯誤它自己接住，不往外丟例外（`tests/test_workshop.py::test_api_install_error_is_a_sentence`）。不需要 JS 叫 Python 的頁面，`api` 不給就好。
- **`api` 的屬性用底線開頭。** pywebview 會把 `api` 的公開屬性一路攤開給那一頁的 JS，跟主面板的 `Bridge` 一樣。工作坊的 `Api` 手上拿著 `app`，存成 `self._app`；寫成 `self.app` 的話，`app` 的方法就跟著攤出去了。所以 `Api` 的四個屬性都以底線開頭，攤出去的只有 `install`（`tests/test_workshop.py::test_api_exposes_only_install`）。這是整潔，不是安全邊界（第 7 節）。
- **頁面零外部資源，由模組自己負責。** `tests/test_boundaries.py::test_ui_has_no_external_urls` 只管 `ui/` 的三個檔，管不到模組的頁面。工作坊的 `page.html` 沒有任何外部網址：沒有 CDN、沒有網路字型、沒有函式庫，另有兩個測試釘著（`tests/test_bundled.py::test_update_and_workshop_keep_their_logic_beside_iplot_py`、`tests/test_workshop.py::test_run_opens_the_page_then_rescans`）。自己的模組沒有人替它擋，要自己守。
- **外來的字要先跳脫。** 這一頁是模組自己用字串拼出來的。拼進去的字如果來自外面——工作坊的索引是從網路抓的——要先過 `html.escape`；不這樣做，索引裡寫一段 `<script>` 就會在那一頁裡執行，而且叫得到 `api` 的方法。`workshop.render` 把名稱、說明、版本、圖示都跳脫過（`tests/test_workshop.py::test_render_escapes_what_came_from_the_index`）；JS 那一頭，Python 回來的字串用 `textContent` 放進頁面。
- **那一頁開著的期間，模組還在執行。** `app.page` 回傳之前，面板上其他的動作都排在後面（上面「執行緒的規則」）；`api` 的方法就是在這段期間被那一頁叫的。工作坊的做法是：`api` 的方法只動檔案、回字串；要動面板的事（`app.rescan()`）等視窗關掉、回到 `run` 之後才做。需要「確定／取消」也在那一頁裡做——面板的對話框會開在主視窗，被這一頁擋住（工作坊的「覆蓋」，與會蓋掉模組自己存的檔的「更新」，就是這樣處理的，第 11 節）。
- **沒有頁面的地方。** tkinter 面板（安全模式與後備）沒有頁面，所以這一版的 Linux 也沒有：`app.page` 只在訊息區記一行（`T["page_unsupported"]`）就回傳，模組接著往下跑。`app.page` 後面的程式，要在「頁面根本沒開過」的情況下也說得通；工作坊後面只有一次 `app.rescan()`。
- 頁面裡的 JS 沒有自動測試，跟面板的頁面一樣：測試只釘住 Python 這一頭。改了頁面，要自己開一次、把改到的地方按一遍。

## 5. 怎麼加一種事件

**這是什麼。** 「事件」是核心在某個時機呼叫模組裡某個名字的函式。`runner.run_module(info, app, handler, args)` 的 `handler` 就是那個名字：執行 `iplot.py` 之後，找叫這個名字的函式，有就呼叫 `handler(app, *args)`。

現成的例子有三個：執行模組是 `run`；`on_files(app, paths)` 的執行路徑已經在（`core.press(info, "on_files", (paths,))`，面板上觸發它的拖放與右鍵還沒做，拖放排在 M2 後段）；「作業系統」模組的七個函式也是同一條路（`core.action` 就是 `press(作業系統模組, "open", (path,), quiet=True)`）。

**怎麼造。** 例：`on_start`（iPLoT 啟動時執行）。

1. 讓掃描知道哪些模組有它：`core/meta.py` 已經收集了頂層函式的名字，在 `Meta` 與 `ModuleInfo` 各加一個欄位（像 `accepts_files` 那樣）。
2. 在對的時機呼叫：`core.press(info, "on_start")`。

執行機制（`runner`）不用改；快照、輸出進訊息區、錯誤進面板都自動沿用。指定的函式不存在時是 `MissingHandler` 錯誤（`run` 例外：沒有 `run` 不是錯）。

## 6. 模組要用網路

**這是什麼。** 模組是普通的 Python。`urllib.request`、`http.server`、`socket` 直接用，核心不用動，也不用宣告。

**要知道的兩件事。**

- **一次一件，中途停不了。** 網頁面板把模組放在一條工作執行緒上執行（第 4 節），所以模組在下載大檔、等別人連進來、`serve_forever()` 的時候，視窗不會凍住：可以捲、可以看訊息、可以選別的模組看說明。但工作一次只做一件——這段時間雙擊別的模組、右鍵的動作、按 ＋，都排在它後面，等它結束才輪到；也沒有辦法叫它中途停下來，只能關掉視窗，整個 iPLoT 一起結束。執行中要讓人看到進度就用 `app.log`，它立刻出現在訊息區；`print` 的輸出要等模組結束才一起出現。短的請求（抓一個網頁）沒問題；會一直跑下去的（開一個伺服器）要等第 8 節的事定下來。tkinter 面板（安全模式與後備）沒有那條工作執行緒，模組執行多久它就凍多久。
- **秘密不要寫在 `iplot.py`。** token、密碼寫在 `iplot.py` 裡有兩個後果：每次執行前它會被原樣存進 `.history/`；把模組資料夾複製給別人時會一起帶走。先這樣做：放在模組資料夾裡另一個檔案（例如 `secret.txt`），程式用 `open("secret.txt")` 讀（執行期間工作目錄就是模組資料夾）；分享模組時不要附上它，用 git 的話把它加進 `.gitignore`。由作業系統的鑰匙圈保管的 `app.secret()` 是之後的事（D58）。

**兩個現成的例子。** 隨附的「更新」（`modules/更新/update.py`）與「工作坊」（`modules/工作坊/workshop.py`）是會連網的模組，核心沒有為它們多開任何門。自己的模組要連網，可以照它們的做法：

- **按了才連網。** 兩個模組都只在自己被執行的期間連網（「工作坊」的下載，是在清單頁上按了按鈕之後）；iPLoT 啟動、掃描、重畫的時候不會連，也沒有「自動檢查有沒有新版」。平常使用不需要網路。
- **網址來自設定，不寫死在程式裡。** 「更新」讀 `app.config.update_url`，「工作坊」讀 `app.config.workshop_url`，也就是 `config.py` 的 `UPDATE_URL`、`WORKSHOP_URL`。隨附的 `config.py` 填的是正式網址（D71 修訂）。兩個網址在兩個 repo：「更新」讀只有研究助理能寫的 `iplot-workshop`，「工作坊」讀誰都能上傳的 `iplot-modules`（D101）。網址是 `None`（`Config` 的預設值）就在訊息區說一句怎麼設定，不連網、不寫任何檔（`tests/test_bundled.py::test_update_and_workshop_do_nothing_until_a_url_is_set`）。`app.config` 只有那五個值，放不進別的；自己的模組要有可以改的網址，寫在模組資料夾裡自己的檔案。
- **用標準庫。** `urllib.request.urlopen(網址, timeout=…, context=…)`，`https://` 與 `file://` 都能開——這兩個模組的測試都不連網，來源用 `file://`。網址裡的中文與空白要先寫成 `%XX`（兩個模組各有一個 `_open` 做這件事），`urllib` 只收 ASCII 的網址。
- **開 `https://` 要自己帶憑證。** python.org 的 macOS Python 預設沒有根憑證（要另外執行「Install Certificates.command」），不處理的話每個 `https://` 網址都驗證失敗（`[SSL: CERTIFICATE_VERIFY_FAILED]`，在開發用的 Mac 上實際遇到）。兩個模組的 `_context()` 建一個 `ssl` 的 context 交給 `urlopen`：憑證庫是空的時候，改用 macOS 自己的 `/etc/ssl/cert.pem`；驗證本身不關（`tests/test_update.py::test_https_open_brings_a_trust_store`、`tests/test_workshop.py::test_https_open_brings_a_trust_store`，用的是替身的 `urlopen`，不連網）。實測：同一個 raw.githubusercontent.com 的網址，用預設的設定驗證失敗，改用 `/etc/ssl/cert.pem` 就成功。這只驗過「連得上、憑證過得了」；從 GitHub Pages 上的 `iplot-workshop` 真的下載、更新、安裝，2026-10-06 在 macOS 上用 `tests/acceptance_workshop.py` 走過一次（全部通過；確認框的長相、用瀏覽器看那一頁、沒有網路時的那一句，要人眼看的部分還沒做）（第 9 節）；Windows 上未經實機驗證。
- **設逾時，錯誤變成一句話。** 讀 json 是 15 秒，下載 zip 是 60 秒：對方這麼久沒有回應就放棄。連不上、逾時、連到一半斷掉、伺服器沒回話都接住，在訊息區（工作坊的安裝是在清單頁的那一列）說一句，不是 traceback。只接 `urllib.error.URLError` 不夠：連到一半斷掉（`ConnectionResetError`）、伺服器沒回話（`http.client.RemoteDisconnected`）、下載不完整（`http.client.IncompleteRead`）、逾時（`TimeoutError`）都不是它；兩個模組接的是 `OSError` 與 `http.client.HTTPException`（各自的 `NETWORK`）。「更新」另外把網址寫錯（`http.client.InvalidURL`）說成「網址寫錯了…」，叫人去看 `UPDATE_URL` 或 `zip_url`。測試：`tests/test_update.py::test_unreachable_source_is_one_plain_sentence`、`::test_dropped_connection_is_one_plain_sentence`（四種）、`::test_mistyped_url_is_blamed_on_the_url`、`tests/test_workshop.py::test_run_with_unreadable_index_is_one_sentence`、`::test_api_install_turns_any_download_trouble_into_a_sentence`。
- **下載的東西先驗 sha256 再用。** 邊下載邊算，跟 json 裡寫的對不上，就把下載的檔刪掉、什麼都不動（`tests/test_update.py::test_download_verifies_sha`、`::test_sha_mismatch_touches_nothing`、`tests/test_workshop.py::test_install_rejects_bad_sha`）。工作坊對不上時丟 `ShaMismatch`（`ValueError` 的一種），那一列說「清單可能剛更新過，關掉工作坊再開一次」：開放上傳之後模組更新得多，清單頁開著的時候那個模組剛好部署了新版，也會對不上（`tests/test_workshop.py::test_api_install_says_the_list_may_have_just_changed`）。這只防壞檔：下載到一半、傳輸中壞掉、放錯了檔。它不防來源本身被換掉——sha256 就寫在同一個來源的 json 裡（第 7 節）。
- **先下載到暫存的地方，驗過才動真的東西。** 「更新」下載到 `.backup/`、解到 `.update-tmp/`；「工作坊」下載並解到 `modules/.workshop-tmp/`。`.update-tmp/` 與 `modules/.workshop-tmp/` 做完都清掉；「更新」下載的那個 zip 留在 `.backup/` 裡。

## 7. 安全：能保證什麼、不能保證什麼

**能保證的。**

- 掃描只讀不執行：面板列出模組時只看檔名、用 `ast` 讀原始碼，不跑任何模組程式碼（D07）；資料夾裡的圖示檔只當圖片顯示。放進一個來路不明的模組資料夾，在執行它之前，它的程式碼一行都不會跑。工作坊裝進來的也一樣：安裝只是把檔案放進資料夾。
- 模組程式碼只在有人動手時執行：有人執行它（網頁面板是雙擊、右鍵選「執行」，或焦點在那一格時按 Enter；tkinter 面板是按一下）、或別的模組用 `app.run` 叫它。「作業系統」模組另外會在右鍵選單、＋、「打開檔案」、`app.open` 等動作時執行；啟動時網頁面板開不起來、要安裝介面的時候也會執行，問它裝哪一份、缺什麼——通常只有第一次啟動，但在裝不了網頁面板的環境（例如這一版的 Linux），照程式是每一次不加 `--safe` 的啟動都會問；需求檔換過之後、啟動時要重裝 `lib/` 的那幾次也會問。0.5.1 裝了「互通」之後，動手的方式多了三種：點「互通」做的捷徑（Spotlight、Dock）、打那一行指令、在模組資料夾直接 `python3 iplot.py`（第 12 節）——都是有人動手才跑。這一版沒有自動啟動、沒有背景程式。
- 沒有字串拼出來的 shell 指令：`core/` 裡沒有任何啟動外部程式的程式碼；隨附的「作業系統」模組啟動外部程式、`ui/install.py` 跑 pip，一律用清單傳參數、不經過 shell（D50，取代 D10；`tests/test_install.py::test_install_argv_is_list_no_shell`）。
- 每次執行前 `iplot.py` 有快照，改壞了找得回來。
- 接住「所有例外」的地方只有三處（`except Exception`）：`core/runner.py`（模組的錯，變成面板上的錯誤訊息）、`core/core.py` 的 `load_config`（`config.py` 的錯，用預設值啟動並說哪裡壞）、`ui/web.py` 的工作執行緒迴圈（一件工作出錯，記進 `logs/iplot.log`、顯示在面板，接著做下一件）；第三處是 0.4.0 加的。其他地方不這樣寫，ruff 的 BLE001 擋著，這三處各帶一行註記。

**網頁面板的頁面這一面，能保證的。**

- 頁面本身不連網：`ui/index.html`、`app.js`、`style.css` 沒有任何外部網址（`tests/test_boundaries.py::test_ui_has_no_external_urls`）。頁面用 `file://` 從 iPLoT 自己的資料夾載入，iPLoT 自己不開 HTTP server、不聽任何 port；頁面跟 Python 之間走的是 pywebview 的 `js_api`，不是網路。自己寫的 `custom.css` 不在這個檢查裡。
- 模組印出來的東西一律當文字顯示：模組的名稱、說明、`print` 與 `app.log` 的輸出、錯誤訊息與 traceback，頁面都用 `textContent` 放進去，不當 HTML 解讀——模組印出 `<script>` 就是顯示那幾個字。Python 送給頁面的資料一律是純 ASCII 的 JSON，名稱裡有引號、反斜線、換行都不會變成程式碼（`tests/test_web.py::test_show_escapes_names_for_js`）。
- 頁面能叫 Python 做的事是列死的：`app.js` 只呼叫 `Bridge` 的十個方法，攤進 `pywebview.api` 的也只有這十個（`tests/test_web.py::test_bridge_exposes_only_its_methods`、`tests/test_boundaries.py::test_app_js_calls_exactly_the_bridge_methods`）。這擋的是頁面自己的程式寫錯，不是擋惡意的頁面——pywebview 是照名字去找方法的，別的程式碼只要進得了這個頁面，就叫得到更多東西；所以真正的邊界是上一條：頁面不載入任何外來的內容。模組只認目前面板上有的，新增模組的位置只認目前顯示的那幾組與面板上的模組，動作只認 `edit`、`reveal`、`terminal` 三個名字；對不上的一律不做，頂多重掃一次，當作畫面過期了（`::test_unknown_id_rescans`、`::test_press_missing_module_rescans`、`::test_create_outside_shown_roots_does_nothing`、`::test_action_rejects_names_the_page_has_no_business_calling`）。
- 安裝只裝列好的東西：pip 只裝 `requirements/` 那一份清單裡的套件，每一個都釘死版本（`tests/test_install.py::test_requirements_are_pinned`），裝進 iPLoT 自己的 `lib/`，不裝進系統的 Python。

**「更新」與「工作坊」這一面，能保證的。** 0.5.0 多了兩個會從網路下載程式碼的隨附模組：「更新」換掉核心，「工作坊」把模組寫進 `modules/`（第 10、11 節）。

- 不設定就不連網：`UPDATE_URL`、`WORKSHOP_URL` 是 `None`（`Config` 的預設值）時，按下去只說一句怎麼設定；隨附的 `config.py` 填好了正式網址，改成 `None` 就回到這樣；設定了也只有按下去才連，不會自己去檢查（`tests/test_bundled.py::test_update_and_workshop_do_nothing_until_a_url_is_set`）。
- 下載到的檔案跟 json 寫的一樣：sha256 對不上就刪掉，不換、不裝（`tests/test_update.py::test_sha_mismatch_touches_nothing`、`tests/test_workshop.py::test_install_rejects_bad_sha`）。這句話保證的就只有這麼多，見下面。
- 「更新」先問一次才動手，而且只換 `core/`、`ui/`、`main.py`、`requirements/` 四樣：`config.py`、`custom.css`、`modules/`、`logs/`、`lib/` 逐位元組不變，iPLoT 資料夾以外沒有任何寫入；換之前，舊的四樣先備份到 `.backup/`（`tests/test_update.py::test_apply_replaces_only_parts_and_keeps_rest`、`::test_backup_has_old_parts`、`::test_run_cancelled_at_the_confirmation_touches_nothing`）。換到一半出錯，已經換上去的全部放回，四樣要嘛全新、要嘛全舊（`::test_apply_rolls_back_when_a_swap_fails`）；訊息區是一句話，看過磁碟上的實況才說「都還是原來的」，放回時也出錯就照實說哪幾樣要用手整理、備份在哪裡（`::test_a_failed_swap_is_one_sentence_and_everything_is_put_back`、`::test_when_putting_back_fails_too_the_sentence_does_not_say_it_was_put_back`）。只有在兩次改名之間被強制結束，或放回時也出錯，才會新舊混合（第 10 節）。
- 「工作坊」的安裝只寫進 `modules/<名稱>/`（與做完就清掉的暫存資料夾）：名稱必須是單純的資料夾名，zip 裡每一條路徑都要在 `<名稱>/` 底下、不能有 `..`，不符合就不裝（`tests/test_workshop.py::test_install_writes_only_its_folder`、`::test_install_rejects_names_that_are_not_a_plain_folder_name`、`::test_install_rejects_wrong_top_folder`）。覆蓋之前，舊的資料夾整個存進它自己的 `.history/`；已修改、版本未知的要確認過才覆蓋，更新時包裡的檔會蓋掉或拿掉模組自己存的檔也一樣（D77；`::test_install_snapshots_existing_folder`、`::test_api_install_asks_before_overwrite`、`::test_update_asks_before_overwriting_a_file_the_module_made`）。「作業系統」「更新」「工作坊」這三個 iPLoT 自己要用的隨附模組，工作坊不覆蓋（`::test_workshop_never_overwrites_iplots_own_modules`）。不順著符號連結寫到外面：模組資料夾裡本來就放著指到外面的符號連結（例如 `data` 連到別的資料夾）時，安裝把連結本身拿掉、換成包裡的檔案；`modules/<名稱>` 本身是符號連結就不裝（`::test_symlinks_in_the_target_are_not_followed`、`::test_a_symlinked_module_folder_is_refused`）。蓋到一半出錯（磁碟滿、權限不對、Finder 鎖定的檔），照覆蓋前存的那份快照把資料夾放回裝之前的樣子；原本沒有這個資料夾就整個拿掉（`::test_failed_install_puts_the_old_folder_back`、`::test_failed_first_install_leaves_no_folder`）。放回時遇到刪不掉、寫不回去的東西也做完，最後逐檔跟快照比；放不回去就照實說，說快照（原本沒有資料夾的話，是裝了一半的那個資料夾）在哪裡，留下來的每個模組資料夾都放 `.unconfirmed`（`::test_rollback_goes_on_past_a_read_only_folder`、`::test_when_the_rollback_cannot_finish_the_sentence_says_where_the_snapshot_is`、`::test_a_rollback_that_cannot_finish_leaves_every_module_folder_asking`）。

**開放上傳（`iplot-modules`）這一面，能保證的。** 0.5.2 起工作坊的清單在另一個公開 repo `iplot-modules`，有 GitHub 帳號的人都能從那裡的「上傳模組」表單放模組上去（D100–D104；第 11 節）。下面幾條由 iplot-modules 的機器人與它的 `tests/` 擋著。

- 上傳碰不到核心：模組與 `update.json` 在不同的 repo，機器人的 token 只屬於 `iplot-modules`。
- 一個名字只有第一次傳它的帳號能更新；iPLoT 自己要用的三個名字誰都不能傳；隨附模組的名字歸研究助理。看起來一樣的寫法（零寬字元、全形、特別的空白、混用的字母）也一樣。
- 機器人不執行任何上傳的程式碼：只解壓、`ast.parse`、寫檔。zip 一條一條看過：沒有 `..`、絕對路徑、只差大小寫的兩個檔，符號連結略過，大小有上限。
- issue 的字不進 shell；回覆裡的名稱、帳號名、檔名都放在程式碼裡，不會變成連結或 @ 到人。
- repo 放的是解開的原始檔：每一次上傳改了什麼，誰都看得到 diff。

**不能保證的。**

- 模組跟 iPLoT 在同一個程序裡、用同一個使用者的權限執行。Python 沒有可靠的程序內沙箱，所以任何模組——包括「作業系統」模組——都能做這個使用者能做的任何事：讀寫檔案、連網路、執行別的程式。上面頁面那幾條管的是頁面，不是模組：模組不必經過頁面，本來就什麼都能做。
- iPLoT 只對一種模組多問一句：工作坊裝進來的，第一次執行前問一次（D59）。其他的都不問——自己複製進來的、解壓縮出來的、用 git 拉下來的，按下去就執行。而且那一次只是問一句，iPLoT 不檢查模組的內容：按了確定之後，它跟任何模組一樣，能做這個使用者能做的任何事。執行一個模組，就是用自己的權限執行那個檔案，跟在終端機打 `python3 iplot.py` 一樣。執行之前看一眼程式碼。
- 安裝的套件只釘版本、還沒釘 hash（D62）：pip 照它自己的設定去下載那個版本，iPLoT 不核對下載回來的檔案內容。
- sha256 不是簽章。它只保證「下載到的 zip 跟 json 寫的一樣」，擋的是壞檔。json 與 zip 來自同一個地方——zip 的網址就寫在 json 裡——改得了那份 json 的人，可以把 zip 和 sha256 一起換掉，檢查照樣通過。所以真正被信任的，是 `config.py` 裡填的那個網址，以及改得了那個網址上內容的人（放在 GitHub 的話，就是推得進那個 repo 的人）。程式也不檢查網址是不是 `https://`：填 `http://` 的話，連線路上的人同樣可以整份換掉。沒有簽章，沒有第二個來源可以對照。
- 「更新」換的是核心本身。除了按下去之後那一次「要更新嗎？」的確認和 sha256 的核對，沒有別的防線；換上去的 `core/`、`ui/`、`main.py`，下一次啟動就用這個使用者的權限執行，換上去的 `requirements/` 則決定下一次啟動時 pip 要裝什麼。填一個不是自己管的 `UPDATE_URL`，等於讓對方決定這台電腦上的 iPLoT 是什麼。
- `modules/互通/.python` 記的是捷徑與 `run.py` 會拿來執行的 Python 路徑。改得了 `modules/` 的人本來就能用這個使用者的權限執行任何東西（這一節的第一條），這不是新的一類風險，但它是一個會被執行的路徑，寫在一個普通的檔案裡。
- 捷徑交給 Python 自己的 Python.app 開（D86）：iPLoT 放在「文件」「桌面」「下載項目」裡時，macOS 會問一次要不要讓「Python」讀那個資料夾；放在家目錄底下時，`ROOTS` 預設的 `".."` 就是家目錄，掃描碰到這三個資料夾也可能會問（推測，沒在乾淨的 Mac 上看過）。按了允許之後，任何用這個 Python 跑的程式都讀得到那個資料夾，不只 iPLoT。
- 工作坊顯示的「已安裝」「已修改」是給人看狀態用的，不是防竄改：它比的是當初裝進來的那些檔（`.origin` 的 `files` 列的）現在的摘要和 `.origin` 裡記的那一個，資料夾裡另外多出來的檔不算；而 `.origin` 是模組資料夾裡的普通檔案，任何模組都改得了。

- 「行事曆」的 `發佈/` 一旦放上網路，知道網址的人都看得到，沒有密碼；noindex 只是請搜尋引擎不要收，不是門鎖。本機的資料夾是一般的文字檔與圖片，用得了這台電腦（或拿得到它的備份）的人都讀得到；打開「公開」之前那一天的字與照片要自己看過。
- 「科學計算」的新格式作業，`iplot.py` 就是作業本身。按下去時，核心先在面板的程序裡執行整個檔，`run(app)` 才另開程序。所以那個檔最上層的程式——`REQUIRES`、`hk_page.ensure`、最上層的 `import`，以及學生另外寫在最上層的任何一行——會先用 iPLoT 的 Python、在面板的程序裡跑一次。`ensure` 在那裡不裝、不改檔（上面那一條），其他的它擋不住：寫在最上層的長計算，面板上別的動作都排在它後面，也停不下來（第 6 節「一次一件，中途停不了」）；收作業時的檢查（`--check`）也不看最上層多寫了什麼。舊格式沒有這個問題：面板裡跑的只是墊片，學生的 `HKn.txt` 只在另開的程序裡跑。

- **任何有 GitHub 帳號的人，都能讓自己的程式出現在每個人的工作坊清單上，這一版沒有人審查。** iPLoT 這邊唯一的關卡跟現在一樣：裝進來的模組第一次執行前問一次（D59），那只是提醒；按了確定，它就用這個使用者的權限做任何事（這一節「不能保證的」第一、二條）。多的只有：清單上看得到上傳者與 `notice`。
- 名字的主人帳號被盜，盜的人就能更新那個名字的模組。
- 下架只擋新的安裝；已經裝了的不會被拿掉。
- 機器人自己的程式在公開 repo 裡：研究助理合併了有問題的 PR，上傳的規矩就可能被改掉。被信任的是研究助理的帳號與 GitHub。
- 被核可的 PR 帶的 workflow 跟機器人共用 concurrency group，可以取消或卡住機器人的那一次跑；研究助理核可之前要看 `.github/`。
- 傳上去的檔進了 git 歷史：下架刪資料夾拿不掉。傳錯、含個資的，要照 GitHub 的〈Removing sensitive data from a repository〉改寫歷史。
- 第一次上傳被退的話，名字還沒登記；附件是公開的，改好之前別人可能先傳同名的。不加保留期：保留期本身就能拿來佔名字。
- sha256 那一條照舊：不是簽章，`index.json` 與 zip 來自同一個地方。

要改變前兩條，只有一條路：程序邊界。那是下一節。

## 8. 執行模型：這一題還沒選

**這是什麼。** 「執行模型」是模組的程式碼在哪裡跑。現在是程序內：`runner` 在 iPLoT 自己的程序裡 `exec` 模組的檔案。另一條路是子程序：每次執行真的啟動一個 `python3 iplot.py`。網路、安全、跑到一半能不能停，這幾件事都卡在這一個選擇上（D56）。

**0.4.0 改了什麼、沒改什麼。** 網頁面板多了一條工作執行緒（第 4 節），模組在那條執行緒上執行，不在視窗的主執行緒上。所以 0.3.0 的「模組執行多久面板就凍多久」在網頁面板消失了：模組跑很久時，視窗照樣可以捲、可以看。但執行模型沒有換：模組仍然在 iPLoT 的程序裡執行，`runner` 沒有動，下面其餘的問題都還在。tkinter 面板（安全模式與後備）沒有那條執行緒，還是會凍。

| | 程序內 `exec`（現在） | 子程序 `python3 iplot.py` |
|---|---|---|
| 好處 | 簡單；`app` 是普通的物件，方法直接呼叫、回傳值直接拿；一執行就開始跑 | 跑太久可以停掉；每次都是真的乾淨的程序；有了程序邊界，之後才談得上限制模組能做什麼 |
| 代價 | 一次只跑一個，跑到一半停不下來；模組留下的東西會留在 iPLoT 裡；沒有任何隔離 | `app` 的每個方法都要變成跨程序的訊息；`input()` 要另外接；核心估計多約 100 行；每次執行多一次直譯器啟動的時間 |

`app.window` 不在這張表裡了：0.4.0 已經把它拿掉（D66，第 4 節），選哪一邊都一樣。模組現在是在工作執行緒上跑、主執行緒被面板的視窗佔著，所以模組也不能自己開 tkinter 視窗（D63 記下的代價）。模組要有自己的畫面，0.5.0 起用 `app.page` 開一頁 HTML（第 4 節，D72）；這跟執行模型無關，模組仍然在 iPLoT 的程序裡執行。

現在已知、而且會在子程序路線自然消失的問題：

- 一次只跑一個，而且停不下來：`time.sleep`、長迴圈、等網路的模組執行期間，別的模組與動作都在排隊；要它停只能關掉視窗，整個 iPLoT 一起結束。
- 模組自己改的 `sys.path` 不會被復原。
- 模組用 `logging.basicConfig()` 設的輸出會留在 iPLoT 的程序裡、綁著那一次執行，下一次執行的 log 看不到。
- 執行期間 `sys.modules["__main__"]` 是 iPLoT 的 `main.py` 不是模組，所以模組裡定義的函式與類別不能 pickle（`multiprocessing` 會壞）。

0.4.0 與 0.5.0 都刻意不選（D56 延後）：`runner` 沒有動。

## 9. Windows、Linux 現況

**現況。**

- 三個後端檔都在，啟動器三個都在（`iPLoT.command`、`iPLoT.bat`、`iPLoT.sh`）。網頁面板的需求檔有兩份：`requirements/web-mac.txt`、`web-win.txt`；Linux 沒有。
- **macOS**：開發與測試都在這裡做，也是唯一真的開過網頁面板的平台（第一次啟動的安裝、裝完自己重啟、開出視窗，都在這裡實際跑過）。
- **Linux**：這一版沒有網頁面板，只有 tkinter 面板。pywebview 在 Linux 要系統層的 GTK／WebKit2GTK，pip 裝不了，所以 `linux.py` 的 `requirements` 回空字串：啟動時不跑 pip，主控台說一句原因，開後備的 tkinter 面板。0.5.0 起，後備面板不是安全模式（D75）：它照常掃上一層與 `ROOTS`，標題沒有「（安全模式）」；只有加 `--safe` 才只看得到 `modules/` 裡的模組（0.4.0 是不加也只看得到 `modules/`）。沒有網頁面板就沒有 `app.page`，所以 Linux 上沒有工作坊的清單頁：網址設好之後按「工作坊」，它照樣會去抓索引，但清單頁開不出來，訊息區出現的是 `T["page_unsupported"]` 那一句（「這個面板沒有頁面（安全模式與備用面板都是）；這個功能要在一般的網頁面板裡用」），裝不了模組。「更新」不用頁面，照程式在 tkinter 面板上也能用，但沒有在 Linux 上試過。`open`、`edit`、`reveal`、`terminal` 的參數由測試驗過（用假的 `Popen`）；垃圾桶的搬移與 `.trashinfo` 的內容在暫存目錄裡真的跑過。但測試是在 macOS 上跑的，沒有在真的 Linux 桌面上按過。
- **Windows：未經實機驗證。** `win.py` 只用假的 `Popen`、`os.startfile`、`ctypes.windll`、`winreg` 驗過參數與結構，沒有任何一行在 Windows 上跑過。網頁面板這一段也一樣：`requirements/web-win.txt` 的版本是用 pip 的 `--dry-run --platform win_amd64` 解出來的，沒有在 Windows 上裝過；`webview_ready` 查 WebView2 的登錄檔檢查沒有對過真的登錄檔；`iPLoT.bat` 沒有被雙擊過。
- **CI**：`.github/workflows/ci.yml` 在 GitHub 上跑 macOS、Windows、Ubuntu × Python 3.10／3.12 六個 job：ruff、pytest、smoke。pytest 加 `-rs`，每個跳過都印出原因；Linux 的 pytest 與 smoke 在 `xvfb-run -a` 底下跑（tkinter 面板的測試要顯示器）。2026-10-23 第一次真的跑時，Windows 與 Ubuntu 冒出 44 個失敗：42 個是測試寫死了 macOS 的行為（換行、路徑的分隔符、`file://` 網址、主控台的編碼），修的是測試；2 個是程式在 Windows 上真的不對（「~名字」被猜成別人的家目錄，見 `CHANGELOG.md` 的 [Unreleased]）。截至 2026-10-23，最後一次六個 job 全綠是 run `39932409945`（`1eaf8dc`）。Windows 的 log 裡，`-rs` 印的跳過理由是 `\uXXXX` 的跳脫字、路徑的反斜線也變成兩個：runner 上 pytest 的輸出接到管線，編碼是 cp1252，印不出中文，pytest 的 TerminalWriter 遇到 `UnicodeEncodeError` 就改用 unicode-escape 印。CI 刻意不設 `PYTHONIOENCODING`：它會傳給測試開的子行程，藏住「程式把中文印到 cp1252／cp950 的管線就崩潰」這類 bug，真的 Windows 使用者不會設它（`ci.yml` 那一步有註解）。只在 macOS 才有的功能（.app 捷徑、把開著的面板叫到最前面、AppKit 等）的測試在別的平台跳過，理由寫在 skip 裡。CI 只裝開發用的套件，不裝 pywebview：測試用的是假的 pywebview（`tests/conftest.py` 的 `FakeWebview`），`tests/smoke.py` 裡真的開網頁面板的情境 7 只在 macOS、而且旁邊有裝好的 `lib/` 時才跑（CI 上會印出跳過與原因），所以 CI 驗不到真的網頁面板。
- **「更新」與「工作坊」**：只在 macOS 驗過，大部分用 `file://` 網址。兩個模組的自動測試全部在暫存資料夾裡做，來源是 `file://`，不連網；工作坊的清單頁另外在真的視窗裡用 `file://` 走過（安裝、覆蓋、「取消」、關掉之後格子出現、第一次執行前的確認，包括進到下一層執行子模組時的確認；「更新」會蓋掉模組自己存的檔時在同一列先問、「取消」回到「更新」；「作業系統」那一列沒有按鈕）。`https://` 只驗過「連得上、憑證過得了」：同一個 raw.githubusercontent.com 的網址，用 Python 預設的設定驗證失敗，改用 `/etc/ssl/cert.pem` 就成功（第 6 節）。從 GitHub Pages 上的 `iplot-workshop` 真的下載、更新、安裝，2026-10-06 在 macOS 上用 `tests/acceptance_workshop.py` 走過一次（全部通過；確認框的長相、用瀏覽器看那一頁、沒有網路時的那一句，要人眼看的部分還沒做）（第 11 節）。0.5.0 的人工驗收（在真的面板上把「更新」「工作坊」各按一遍）也還沒有做。Windows 上這兩個模組未經實機驗證，Linux 上也沒有跑過。

**怎麼在 Windows 上驗。** 裝 python.org 的 Python（要有 pip；安裝時勾 tcl/tk，安全模式與後備面板要用它），確認有 WebView2 Runtime（Windows 11 內建），接上網路，然後：

1. 雙擊 `iPLoT.bat`。第一次啟動要安裝介面：主控台出現「第一次啟動：正在安裝介面」開頭的一行和 pip 的進度，裝完印「安裝完成，重新啟動中…」，接著視窗自己出現，標題是 `iPLoT v0.5.0`。記下裝了多久、`lib/` 多大。如果出來的是 tkinter 面板（後備面板，標題沒有「（安全模式）」），原因印在主控台、也寫在訊息區的最上面，把那幾行記下來。
2. 關掉視窗，再雙擊一次：直接開視窗，不再安裝。
3. 雙擊「作業系統」：訊息區說「作業系統：Windows，用的是 win.py」。
4. 右鍵任一模組，選單有「執行」「打開程式碼」「在資料夾中顯示」「在終端機打開」「在這裡新增下一層模組…」（有子模組的還多一項「進入下一層」）。後四項各按一次：「打開程式碼」開記事本、「在資料夾中顯示」開檔案總管並選取、「在終端機打開」開終端機、「在這裡新增下一層模組…」在面板裡問名字，取一個之後記事本開了範本、那個模組的圖示右下角多了 ▸（按 ▸ 進去是新模組）。再找一個路徑含空白的資料夾試「在資料夾中顯示」——`explorer /select,<路徑>` 現在是當成一個參數傳的；如果含空白時沒有選到，把 `win.py` 的 `reveal` 改成 `["explorer", "/select,", str(path)]`。
5. 按任一組最後那一格虛線的 ＋，取個名字：記事本開了範本。
6. 做一個模組呼叫 `app.trash(某個測試檔)`：檔案進資源回收筒，可以還原。
7. 從命令提示字元執行 `iPLoT.bat --safe`：開的是 tkinter 面板，標題有「（安全模式）」，只看得到 `modules/` 裡的模組。
8. 「更新」與「工作坊」：照第 10、11 節「在本機試」的做法，用 `file://` 網址各走一遍（Windows 上 `file://` 網址的寫法，例如 `file:///C:/…`，也是沒試過的一項）。「更新」要特別看：四樣是不是都換成了新的、`.backup/` 裡有沒有舊的四樣、iPLoT 資料夾裡有沒有留下 `core.new`、`ui.old` 這類名字或 `.update-tmp/`、`.update-old-…`、執行「重新啟動」之後標題是不是新版本。「工作坊」要看：清單頁開不開得出來、按鈕按了有沒有反應、關掉之後新的格子有沒有出現。

**Linux 驗的是 tkinter 面板。** 先裝發行版的 `python3-tk` 套件，執行 `./iPLoT.sh`：主控台說網頁面板開不起來（這一版還不支援 Linux）、已改用備用面板，然後 tkinter 面板出現，標題沒有「（安全模式）」，上一層與 `ROOTS` 其他位置的模組也看得到。再執行一次 `./iPLoT.sh --safe`：標題有「（安全模式）」，只剩 `modules/` 裡的。接著是上面的第 3 到第 6 步，開出來的換成 Linux 上對應的程式（第 2 節的表），操作換成 tkinter 面板的：按一下就執行；右鍵只有四項（沒有「執行」與「進入下一層」），問名字是另外跳出來的小視窗；▸ 在按鈕的右邊；＋ 在每組標題的右邊。

**Windows 上還沒辦法確認、驗的時候要特別看的幾點**（都是讀程式推出來的疑點，不是實測結果）：

- `explorer /select,<路徑>` 遇到含空白的路徑可能選不到（上面第 4 步）。
- 資源回收筒不適用的位置（網路磁碟、超過回收筒容量的檔案）：`win.py` 現在的旗標可能讓 Windows 直接刪除而不問。試一次；真的會的話，在 `trash` 的旗標加上 `0x4000`（刪除前警告），並把測試裡的 `0x454` 一起改。
- `EDITOR` 設成 `code` 這類 `.cmd` 指令時，路徑裡有 `&` 或 `%` 會被 `cmd.exe` 另外解讀。
- 雙擊 `iPLoT.bat` 時，如果 Python 太舊，「需要 Python 3.10 以上」那一句會隨著視窗一起關掉、來不及看；要看得到就從命令提示字元執行它。
- 第一次啟動裝完之後的重啟、隨附的「重新啟動」，用的都是 `os.execv`，在 Windows 上的行為跟 macOS 不同，沒有驗過。讀程式推出來的疑點：Windows 的 `os.execv` 不會替參數加引號，iPLoT 資料夾的路徑含空白時，裝完之後的那一次重啟可能失敗（這時再啟動一次就會直接開）。
- `requirements/` 裡的兩個檔只寫 ASCII：Python 3.10、3.11 安裝檔附的舊版 pip 用系統的編碼讀需求檔，在中文 Windows（cp950）上，檔案裡有 UTF-8 的中文註解就讀不進來，介面永遠裝不起來。`tests/test_install.py::test_requirements_files_are_ascii` 擋這件事；這個推論同樣沒有在 Windows 上驗過。
- `webview_ready` 只用假的 `winreg` 驗過：明明有 WebView2 卻被說成沒有的話，要改的是 `win.py` 的這個函式；這時會退到後備的 tkinter 面板，照樣能用。
- 頁面是用 `file://` 網址載入的，`custom.css` 靠相對路徑 `../custom.css` 找到。這在 macOS 的 WebKit 上成立，在 Windows 的 WebView2 上沒試過。
- 「更新」是在 iPLoT 還開著的時候，把它自己的 `core/`、`ui/` 整個資料夾改名、換上新的（第 10 節）。macOS 這類系統允許把使用中的檔案與資料夾改名；Windows 上只要有程式還開著裡面的某個檔（例如 WebView2 還抓著 `ui/` 裡的頁面檔，或防毒軟體正在掃），改名可能被拒絕。真的被拒絕的話，照程式，已經換上去的會放回去，四樣仍是舊版，訊息區是一句「沒有更新：<錯誤>。core/、ui/、main.py、requirements/ 都還是原來的」（第 10 節）。放回去用的也是改名，同樣可能被拒絕；放不回去時那一句改說「放回原來的版本時出錯了」、列出要用手整理的名字，照第 10 節用 `.backup/` 回到舊版。會不會發生，沒有驗過。
- `app.page` 開的第二個視窗（工作坊的清單頁）只在 macOS 的 WebKit 上開過；在 WebView2 上沒試過。

**驗過之後。** 把這份文件、`README.md`、`CHANGELOG.md`、`win.py` 開頭的「未經實機驗證」拿掉，並在 `03_設計決定.md` 的 D53、D57 補上驗證的日期與環境。`requirements/web-win.txt` 開頭也有同一句，`tests/test_install.py::test_windows_requirements_say_unverified` 釘著它，要拿掉就連測試一起改。

更新 iPLoT：從 0.5.0 起可以用隨附的「更新」模組（第 10 節），它換的是 `core/`、`ui/`、`main.py`、`requirements/` 四樣；前提是有人把新版放到某個網址上、`config.py` 的 `UPDATE_URL` 填好。手動更新的話，要帶的也是這四樣，再加上那一版有改到的隨附模組（例如 `modules/作業系統/`）——「更新」不碰 `modules/`；工作坊不覆蓋「作業系統」「更新」「工作坊」這三個，它們的新版只能手動複製進 `modules/`，其他隨附模組可以從工作坊覆蓋，或手動複製。從 0.4.0 手動更新到 0.5.0：換掉那四樣，把 `modules/更新`、`modules/工作坊` 複製進 `modules/`，`config.py` 加上 `UPDATE_URL`、`WORKSHOP_URL` 兩行（不加也能用，等於沒設定）。`lib/` 不用帶：它是每台機器第一次啟動時自己裝的，需求檔換過的話，下次啟動會自己重裝（第 1 節「安裝」那一列）。

## 10. 更新

**這是什麼。** `modules/更新/` 是一個普通的隨附模組（圖示 ⬆️，D69），兩個檔：

- `iplot.py`：只負責問、說、把步驟串起來。
- `update.py`：做法。`fetch_json`、`check`、`newer`、`installed_version`、`download`、`backup`、`apply`、`unfinished`，都是普通的函式。

核心不知道有「更新」這回事。這個模組用到的只有 `app.config`、`app.version`、`app.home`、`app.confirm`、`app.log`，跟任何模組一樣；把它的資料夾刪掉，iPLoT 照常運作，只是少了這個功能。

執行它（按下去）會做的事：

1. `config.py` 的 `UPDATE_URL` 是 `None`：訊息區說一句怎麼設定，結束。不連網。（隨附的 `config.py` 填好了正式網址，D71 修訂。）
2. 抓 `UPDATE_URL` 指到的 `update.json`，先看 `version`、`zip_url`、`sha256` 三項（`update.check`）：少了一項，或不是文字（`null`、數字），說一句、結束——這一步在比版本之前，所以就算已是最新，少了 `zip_url` 也是說少了這一項。磁碟上那一份核心的版本（`core/__init__.py` 的 `__version__`）不比它舊：說「已是最新（x.y.z）」，結束。剛更新完、還沒重新啟動又按一次，說的是「已經換成 x.y.z 了，執行「重新啟動」就會用新版」，不會再下載、再備份、再換一次。
3. 比較新：跳出確認，顯示新的版本、現在的版本（磁碟上的那一份）與 `update.json` 裡的 `notes`。取消就結束，什麼都不動。
4. 把 zip 下載到 `.backup/download-<版本>.zip`，核對 sha256。對不上：刪掉下載的檔，說一句，什麼都不動。
5. 把現在的四樣複製到 `.backup/<舊版本>-<日期時間>/`（`<舊版本>` 也是磁碟上那一份的版本：剛更新完、沒重新啟動時，執行中的 `app.version` 還是更舊的）。
6. 先收上一次留下的殘餘（`_restore`）。還有任何 `<名稱>.new`，表示上一次換到一半被強制結束（`core` 最後換，換完就沒有 `.new` 了）：留著的 `<名稱>.old` 全部放回去，最後才丟 `.new`（放回的途中又被強制結束，下一次還看得到 `.new`，會接著收）。沒有 `.new`，表示上一次已經全部換好、只是舊版沒刪乾淨：那些 `.old` 不放回去，照下面丟舊版的做法清掉。接著把 zip 解到 `.update-tmp/`；四樣各先搬成 `<名稱>.new`，再照 `ui`、`main.py`、`requirements`、`core` 的順序一樣一樣改名換上去：舊的先改名成 `<名稱>.old`。`core/` 帶著版本號，最後才換，所以「磁碟上的版本是新的」就代表四樣都換好了。全部換完才丟舊版（`_discard`）：每個 `<名稱>.old` 先在原地改名成 `.update-old-<名稱>-<n>`，再刪掉（改名留在同一層：整個唯讀的舊資料夾搬不進別的資料夾底下，同一層改名可以）；刪不掉的（例如舊 `core/` 裡有唯讀的子資料夾）留著那個名字，已經不叫 `<名稱>.old`，下一次更新不會把它當成舊版放回去，開頭會再刪一次。丟不掉不算更新失敗。最後清掉 `.update-tmp/`。
7. 訊息區：「已更新到 x.y.z，執行「重新啟動」就會用新版。舊版備份在 .backup/…/」。

第 5、6 步遇到檔案系統的錯（權限不對、磁碟滿、檔案被佔著；包的內容不對、不是 zip 是另外的一句話，見下面的表）：錯在換的過程中的話，`apply` 先把已經換上去的全部放回、`.new` 丟掉。接著 `iplot.py` 看磁碟上的實況（`update.unfinished`：還在的 `<名稱>.old`、`<名稱>.new`，與不見了的那幾樣），在訊息區說一句話，不是模組錯誤：

- 都沒有：「沒有更新：<錯誤>。core/、ui/、main.py、requirements/ 都還是原來的」。
- 有：「沒有更新，而且放回原來的版本時出錯了：<錯誤>。<留下的名字，用「、」隔開> 要用手整理（舊版的備份在 .backup/<資料夾>/，做法見 README 的「怎麼回到舊版」）」。備份本身就失敗時，括號裡的「舊版的備份在 .backup/<資料夾>/」換成「這一次沒有做成備份」。

這不是熱更新：換完之後，開著的這個 iPLoT 還是舊的程式，要執行「重新啟動」才用新版，`app.memory` 會清空。新版的需求檔如果不一樣，重新啟動時會先重裝 `lib/`（第 1 節「安裝」那一列，D76）；那時沒有網路，就先用現有的 `lib/` 開，之後每次啟動再試。這條路還沒有在真的換版本時走過：0.4.0 到 0.5.0 的需求檔沒有變，自動測試裡的 pip 是替身。

「更新」只在 macOS 驗過（`file://` 網址，與 2026-10-06 對 GitHub Pages 的一次，`tests/acceptance_workshop.py`）；Windows 未經實機驗證，換掉執行中程式自己的資料夾這一步在 Windows 上有疑點（第 9 節）。

- `.backup/` 不會自己清：每更新一次多一個下載的 zip 和一份舊版。舊的可以自己刪。
- 開頭收殘餘時，連把 `<名稱>.old` 改名成 `.update-old-…` 都失敗的話，這時還沒換任何東西，但那個 `<名稱>.old` 還在，所以訊息區是上面的第二種說法（「放回原來的版本時出錯了」，列出它）。
- 備份（第 5 步）在收殘餘（第 6 步）之前。上一次換到一半被強制結束的話，這一次存進 `.backup/<舊版本>-<日期時間>/` 的是新舊混合的四樣，名字卻是舊版本（`05_使用紀錄.md`「0.5.0 審查留下的待辦」第 2 條）。
- `<名稱>.old`、`<名稱>.new`、以 `.update-old-` 開頭的名字是「更新」自己用的名字。iPLoT 資料夾裡自己放了叫這些名字的東西（例如一個叫 `core.old` 的資料夾），下一次更新會把它當成上一次留下的殘餘，換進去或刪掉（同上，第 5 條）。

**怎麼造：做一個 `update.json`。** 「更新」讀的就是這一個檔，加上它指到的 zip：

```json
{
  "version": "0.5.1",
  "zip_url": "https://<帳號>.github.io/iplot-workshop/iPLoT-v0.5.1.zip",
  "sha256": "<那個 zip 的 sha256，64 個十六進位字>",
  "notes": "這一版改了什麼"
}
```

`version`、`zip_url`、`sha256` 少一項就不更新，三項都要是文字：`version` 寫成 `"0.5.1"`，寫成數字或 `null` 也不更新；`notes` 可以沒有，它只是顯示在確認的對話框裡。zip 的最上層要剛好是一個資料夾（交付用的包是 `iPLoT-vX.Y.Z/`），裡面 `core/`、`ui/`、`main.py`、`requirements/` 四樣都要有；多帶的東西沒關係，不會被套用。

不用手寫，`tools/publish.py` 會產生（下面的 0.5.1 是舉例）：

```
python3 tools/publish.py --version 0.5.1 --base-url <放檔案的地方> --modules-site https://<帳號>.github.io/iplot-modules/
```

它在 `交付/發佈/` 產生 `iPLoT-v0.5.1.zip`（用 `git archive` 打包 `v0.5.1` 這個 tag；還沒打 tag 就加 `--ref HEAD`）與 `update.json`（sha256 是算出來的，`notes` 取自 `CHANGELOG.md` 裡 `## [0.5.1]` 那一節的第一段——摘要，不是整節，因為它會整段顯示在確認的對話框裡；找不到那一節就是空的），並印出要填進 `config.py` 的 `UPDATE_URL` 那一行（前面沒有空白，可以直接貼上），接著一句「WORKSHOP_URL 照 config.py，不改（模組在 <網址>）。」打包的那個 ref 裡 `core/__init__.py` 的版本要剛好是 `--version`，不同就說一句、什麼檔都不產生：不然 `update.json` 會宣稱一個包裡沒有的版本，裝了之後永遠「還有新版」。`git archive` 先寫成 `.part` 再改名，打包失敗不會把同名的舊 zip 蓋掉。工作目錄有還沒 commit 的改動時會提醒一句：核心的包是從那個 ref 打的，不含那些改動（模組的包含）。像上面這樣給了 `--modules-site`（跟 `--modules` 互斥），原本的 `index.json` 不動；給了 `--modules` 才整份重寫（第 11 節）。兩個都沒給、而那個 ref 裡 `config.py` 的 `WORKSHOP_URL` 不在 `--base-url` 底下，就停下來說要加 `--modules-site`，一個檔都不產生。`--base-url` 是 `交付/發佈/` 放上去之後對應的網址，寫法見第 11 節「放在 GitHub」。

在本機試，不用網路：`--base-url` 給 `file:///<絕對路徑>/交付/發佈`，`config.py` 填 `UPDATE_URL = "file:///<絕對路徑>/交付/發佈/update.json"`。要看到「有新版」，這台 iPLoT 的版本得比 `update.json` 寫的舊；試的時候可以把 `core/__init__.py` 的版本暫時改小，再開面板。注意它是真的會換：在開發用的資料夾裡試，`core/`、`ui/`、`main.py`、`requirements/` 會被換成包裡的那一份，還沒 commit 的修改只剩 `.backup/` 裡的備份。用另外解開的一份 iPLoT 來試比較保險。

**怎麼從 `.backup/` 回到舊版。** 沒有一鍵回溯，用手搬：

1. 關掉 iPLoT。
2. 在 iPLoT 資料夾裡找到 `.backup/<舊版本>-<日期時間>/`（名字以點開頭，macOS 的 Finder 與多數 Linux 的檔案管理員預設不顯示），裡面是更新前的 `core/`、`ui/`、`main.py`、`requirements/`。
3. 把 iPLoT 資料夾裡現在的這四樣移走（連同更新中途留下的 `core.new` 這類名字，如果有的話），再把備份裡的四樣複製回來。先移走再放，不要直接疊上去：疊上去的話，新版多出來的檔案會留在 `core/` 裡。
4. 啟動。視窗標題是舊的版本號。兩版的需求檔不一樣、而且 `lib/` 在更新之後已經照新的需求檔重裝過的話，這一次啟動會照舊的需求檔再重裝一次 `lib/`（要網路），跟更新之後是同一個機制。

這幾步是照程式寫的，還沒有實際走過一遍。

`config.py`、自己的模組、`custom.css` 在更新時沒有被動過，回到舊版也不用管它們。

**怎麼改：想多換或少換一樣。** `update.py` 最上面的這兩行：

```python
PARTS = ("core", "ui", "main.py", "requirements")  # 更新會換掉的東西；其他都是使用者的
ORDER = ("ui", "main.py", "requirements", "core")  # 換上去的順序：core 帶著版本號，最後才換
```

`backup` 與 `apply` 都照 `PARTS` 做，所以改它，就同時改了「備份哪幾樣」「換哪幾樣」「包裡一定要有哪幾樣」。`ORDER` 是同樣幾樣換上去的順序，改 `PARTS` 要一起改它，`core` 留在最後（`test_core_is_swapped_last` 會比兩者是不是同樣幾樣、`core` 是不是最後）。要一起改的：`tests/test_update.py` 開頭的 `OLD`、`NEW`、`MINE`（哪些該被換、哪些該留著）、兩個檔的 docstring、`03_設計決定.md` 的 D69、這一節。動手之前先想三件事：

- **清單是這台電腦上的「更新」模組說了算，不是下載來的包。**「更新」自己在 `modules/` 裡，不在四樣之內，更新不會換掉它。所以某一版想多換一樣，各台電腦要先拿到新的「更新」模組（手動複製進 `modules/`；工作坊不覆蓋「更新」，第 11 節），那一版的包才會照新的清單套用。
- **使用者的東西不要放進去。**`config.py`、`custom.css`、`modules/`、`logs/`、`lib/` 永遠不碰，是 D69 的保證，也是 `test_apply_replaces_only_parts_and_keeps_rest` 擋的事。
- **啟動器現在不在清單裡。**`iPLoT.command`、`iPLoT.bat`、`iPLoT.sh` 在包裡，但不會被換；`README.md`、`docs/`、`tests/`、`tools/` 也一樣。哪一版改了啟動器，要另外說明怎麼手動換，或把它們加進 `PARTS`。

改完不用重新啟動：模組每次執行都重讀自己資料夾裡的檔案，下一次按「更新」就是新的行為。

## 11. 工作坊

**這是什麼。** `modules/工作坊/` 是一個普通的隨附模組（圖示 🧰，D70、D74），三個檔：

- `iplot.py`：把步驟串起來。
- `workshop.py`：做法。`read_listing`（`read_index` 包著它，只回清單）、`state`、`digest`、`install`、`snapshot`、`render`，以及清單頁用的 `Api`。
- `page.html`：清單那一頁，樣式與 JS 都在裡面，沒有任何外部資源。

跟「更新」一樣，核心不知道有它：它用的是 `app.config`、`app.home`、`app.log`、`app.page`、`app.rescan`。核心為外來的模組做的事只有一件，而且不認得工作坊——資料夾裡有 `.unconfirmed` 就先問（第 1 節「外來模組」那一列）。

執行它（按下去）會做的事：`WORKSHOP_URL` 沒設定就說一句怎麼設定，不連網；設定了就用 `read_listing` 讀它指到的 `index.json`：有 `uploads` 讀它，沒有讀 `modules`；頂層 `notice` 放在清單最上面（原本那一句提示之後、表格之前，一行字，不是表格的一列）。接著用 `app.page` 開一頁，清單裡每個模組一列：圖示、名稱、上傳者（有 `author` 的，名稱底下一行「上傳者：@<author>」；不是 GitHub 帳號名的寫法，例如「帳號已刪除」，照寫、不加 @）、說明（有 `notes` 的，底下多一行「這一版：<notes>」，D78；有 `warning` 的，再一行紅字「⚠ <warning>」）、索引上的版本、在這台電腦上的狀態、一顆按鈕。關掉那一頁，面板重掃一次，新裝的格子就出現。這一頁只在網頁面板上開得出來：tkinter 面板與 Linux 沒有清單頁（第 4 節、第 9 節）。工作坊只在 macOS 驗過（`file://` 網址，與 2026-10-06 對 GitHub Pages 的一次，`tests/acceptance_workshop.py`）；Windows 未經實機驗證。

**六種狀態怎麼算。** `workshop.state` 由上往下看，先符合的算：

| 順序 | 這台電腦上的情況 | 狀態 | 清單頁上的字 | 按鈕 |
|---|---|---|---|---|
| 1 | 名稱是「作業系統」「更新」「工作坊」之一（`BUNDLED`）：iPLoT 自己要用的隨附模組，資料夾在不在都一樣 | `bundled` | 隨附模組 | 沒有按鈕，那一列多一句說明 |
| 2 | `modules/<名稱>/` 不存在 | `absent` | 未安裝 | 安裝 |
| 3 | 資料夾在，但沒有 `.origin`：自己建的同名模組，或上面三個以外的隨附模組（隨附模組不帶 `.origin`，D74） | `unknown` | 版本未知 | 覆蓋 |
| 4 | 有 `.origin`，但當初裝進來的那些檔有改過、刪掉的（摘要跟 `.origin` 記的不一樣）；或 `.origin` 讀不懂、缺項（缺 `files` 那一行也算） | `modified` | 已修改 | 覆蓋 |
| 5 | 內容沒變，索引上的版本比 `.origin` 記的新 | `update` | 可更新 | 更新 |
| 6 | 內容沒變，索引上的版本一樣或比較舊 | `installed` | 已安裝 | 沒有按鈕 |

- **工作坊不覆蓋「作業系統」「更新」「工作坊」。** 這三個是 iPLoT 自己要用的：覆蓋之後它們會帶著 `.unconfirmed`：在面板上確認過之前，「作業系統」的右鍵動作、「打開檔案」每次先問，啟動時要安裝介面卻沒辦法回答。所以索引裡有這三個名字時，那一列的狀態是「隨附模組」、沒有按鈕，多一句「這是 iPLoT 自己要用的隨附模組，工作坊不覆蓋它；要換新版，自己把新的資料夾複製進 modules/。」；`workshop.install` 也拒絕（「「<名稱>」是 iPLoT 自己要用的隨附模組，工作坊不覆蓋它」）。比對之前先做 Unicode 的 NFC 正規化、不分大小寫，所以相容表意字（U+F901 正規化之後就是「更」）、大小寫不同的寫法也擋得住；資料夾在的話，再問檔案系統是不是同一個資料夾。這三個資料夾被刪掉了，也不從工作坊裝回來。要換新版，只能自己把新的資料夾複製進 `modules/`（「更新」不碰 `modules/`，D69）；手動複製進來的資料夾沒有 `.unconfirmed`，不會先問。其他四個隨附模組（開工、打開核心原始碼、開Terminal、重新啟動）照舊是「版本未知」，可以「覆蓋」（D74）。
- **`.origin`** 是安裝時寫在模組資料夾裡的來源記錄，一行一個 `key: value`，六項：

  ```
  url: <這個模組的 zip 是從哪個網址來的>
  version: 1.0.0
  sha256: <那個 zip 的 sha256>
  digest: <安裝完當下，裝進來的那些檔的摘要>
  files: ["helper.py", "iplot.py"]
  installed: 2026-10-05 14:30:00
  ```

  `files` 是從包裡裝進來的檔的相對路徑清單（JSON）。

- **內容摘要（`digest`）**：只算 `files` 列的那些檔，照相對路徑排序，「路徑＋內容」一個個餵進 sha256。改了其中一個字、刪了其中一個檔都會變。清單以外的檔不算：模組執行時自己存的設定、資料，以及 `.history`、`.origin`、`.unconfirmed`、`__pycache__`、`.DS_Store` 這些各台電腦自己的東西（安裝時就不會裝進來，也就不在清單上）。所以執行過（多了 `.history/`、自己存了檔）、確認過（少了 `.unconfirmed`）都不算「已修改」；在資料夾裡另外加一個檔也不算。「已修改」的意思就是：當初裝進來的檔有被改過或刪掉，或 `.origin` 壞了。
- **改過的優先。** 內容變過的模組，就算索引上有新版，看到的也是「已修改」與「覆蓋」，不是「可更新」。
- **不降版。** 索引上的版本比裝著的舊，算「已安裝」，沒有按鈕。版本的比法跟「更新」一樣；看不懂的版本號當作不比較新。
- **「覆蓋」要按兩次。** 第一次按，按鈕變成「確定覆蓋」與「取消」，旁邊一句「這會覆蓋現有的模組，舊版會整個存進它的 .history/」；再按才做；按「取消」回到只有一顆「覆蓋」的樣子，頁面不重新載入（這一頁是用 html 字串開的，一重新載入就變成空白頁）。確認是在清單那一頁做的，不是面板的對話框。Python 這一頭也擋著：`Api.install(name, confirmed=False)` 遇到已修改、版本未知的，沒帶 `confirmed` 就什麼都不動，回「需要確認」，頁面看到它就在那一列重新問。
- **「更新」會蓋掉模組自己存的檔時也先問（D77）。** 「已修改」只看當初裝進來的檔，所以模組自己存的檔（`.origin` 的 `files` 以外的）不影響狀態；但新版的包裡剛好有同名的東西時，照舊直接裝就會把它蓋掉。所以有 `.origin` 的模組按「更新」，下載、解開之後先看包裡的檔放上去，會不會蓋掉或拿掉不在 `files` 清單裡的本機檔——同名的檔（蓋掉）、同名的資料夾（整個拿掉）、擋在要建資料夾的地方的檔。會的話 `workshop.install` 丟 `NeedsConfirmation`，`Api.install` 回「需要確認」，模組資料夾一個位元組都不動；清單頁在同一列問，跟「覆蓋」一樣（「確定覆蓋」「取消」與那一句說明）。按「確定覆蓋」帶著 `confirmed` 再裝一次，會再下載一次；按「取消」回到那一顆按鈕原來的字（「更新」或「覆蓋」），下次按一樣先問。包裡的檔只蓋到當初裝進來的那些，就不多問，直接更新。比對的是路徑：只差大小寫時，在 macOS 上也算蓋到。清單頁那一句沒有說會蓋到哪一個檔。

**安裝做了什麼**（`workshop.install`；安裝、更新、覆蓋是同一條路）：

1. 名稱不是單純的資料夾名（空的、含 `/` 或 `\`、以 `.` 開頭）、是「作業系統」「更新」「工作坊」之一，或 `modules/<名稱>` 本身是符號連結：不裝。
2. 把 zip 下載到 `modules/.workshop-tmp/`，核對 sha256。對不上：不裝。
3. 看 zip 的內容：每一條路徑都要在 `<名稱>/` 底下、不能有 `..`，裡面要有 `<名稱>/iplot.py`。不符合：不裝。
4. 從工作坊裝過（有讀得懂的 `.origin`）、又沒有帶 `confirmed`：包裡的檔放上去會蓋掉或拿掉不在 `files` 清單裡的本機檔，就丟 `NeedsConfirmation`，不裝，先問（上面 D77 那一條）。
5. `modules/<名稱>/` 已經在的話，先把整個資料夾（最上層的 `.history/` 自己除外）壓成 `modules/<名稱>/.history/<日期時間>-folder.zip`。這一步出錯（磁碟滿、`.history/` 不能寫）：寫到一半的 zip 刪掉，不裝，清單頁那一列是「無法安裝：<錯誤>；沒有裝成，還沒動到資料夾（存快照時出錯）」。
6. 先在包裡與磁碟上每一個有 `iplot.py` 的資料夾（最上層，與下面各層的子模組）放好空檔案 `.unconfirmed`，再把包裡的檔案蓋上去：標記在程式之前就在。磁碟上的也要，是因為包可能只帶了下一層模組旁邊的 `helper.py`、沒帶它的 `iplot.py`：那個資料夾是上一版裝的、已經確認過，不放標記的話，執行它就不經確認跑了新下載的程式。比對的是實際的檔名 `iplot.py`（跟核心認模組的方式一樣）；`.history/`、`__pycache__` 這些名字底下的不算，不順著符號連結找。包裡沒有的舊檔案留著（模組自己存的資料不會因為更新而不見）；包裡夾帶的 `.history`、`.origin` 那五個名字不裝，比對不分大小寫（`.Origin` 也不裝）。舊版的某個名字是檔案、新版是資料夾（或反過來），照新版的放；本來是指到外面的符號連結，把連結本身拿掉、換成包裡的檔案，不順著它寫到外面。被拿掉的舊東西在第 5 步的快照裡（指向資料夾的符號連結除外，見下面）。
7. 寫 `.origin`（六項，含裝進來的檔的清單 `files`），清掉 `modules/.workshop-tmp/`。

第 6、7 步出錯（磁碟滿、權限不對、Finder 鎖定的檔）：照第 5 步的快照把資料夾放回裝之前的樣子，原本沒有這個資料夾就整個拿掉。讓安裝失敗的原因（鎖定的檔、唯讀的子資料夾）通常也讓刪除失敗，所以放回時遇到刪不掉、寫不回去的東西不停下來：能刪的刪，快照裡每個檔都試著解回去，最後逐檔跟快照比（最上層的 `.history/` 以外的每一個檔，比內容），一樣才算放回去了。快照資料夾的名字比對不分大小寫：macOS 上模組資料夾裡本來就有的 `.History/`（使用者或別的工具建的）跟 `.history/` 是同一個資料夾，快照就寫在它裡面，存快照、放回原樣、逐檔比對都不碰它（下一層子模組自己的 `.history/` 是核心替它存的上一版，跟著進快照、放回來；第三輪審查 I3，`::test_rollback_keeps_the_history_of_a_module_one_level_down`）。動手刪之前先確定快照讀得到（`zipfile` 的 `testzip`）；讀不到就一樣都不刪。沒放回去時，留下來的每個有 `iplot.py` 的資料夾都放 `.unconfirmed`，因為裡面可能有新下載的程式。清單頁那一列是「無法安裝：<錯誤>；」接著照實說的一句：

- 原本有資料夾：「沒有裝成，已從快照放回」，或「沒有裝成，放回時出錯，快照在 <快照 zip 的完整路徑>」；快照讀不到時是「沒有裝成，快照讀不到、沒有放回，資料夾現在是新舊混合：<資料夾路徑>」。
- 原本沒有資料夾：「沒有裝成，裝了一半的資料夾已經拿掉」，或「沒有裝成，裝了一半的資料夾拿不掉：<資料夾路徑>」。

放回去了的時候，資料夾回到裝之前的樣子，只有 `.history/` 裡多了那份快照。但快照不是一模一樣的複本，比對也只比檔案的內容：指向資料夾的符號連結不在快照裡，指向檔案的符號連結放回來變成一般檔，執行權限與空資料夾不會回來（`05_使用紀錄.md`「0.5.0 審查留下的待辦」第 4 條）。更穩的做法——在 `modules/.workshop-tmp/<名稱>` 組好完整的新資料夾，再整個交換——還沒做（同上，第 1 條）。

「不裝」的時候（第 1–3 步），清單頁那一列顯示「無法安裝：」開頭的一句話，模組資料夾不動；第 4 步回的是「需要確認」，在同一列問。連線到一半斷掉、伺服器沒回話、索引那一筆的型別不對，也是「無法安裝：」開頭的一句話。下載的 zip 跟清單的 sha256 對不上（`ShaMismatch`）是「無法安裝：下載的檔案跟清單對不上。清單可能剛更新過，關掉工作坊再開一次；再不行就是檔案有問題」：清單頁開著的時候那個模組剛好部署了新版，也會這樣。清單頁可以連按兩列：安裝一次做一個（`Api` 裡有一把鎖，兩個安裝共用暫存資料夾），第二個排在後面。

**怎麼造：做一個索引與模組的 zip。** 工作坊讀的是一個 `index.json`，加上它指到的每個模組一個 zip：

```json

  "notice": "這裡的模組是大家上傳的，沒有人審查。",
  "modules": [],
  "uploads": [
    {
      "name": "整理桌面",
      "version": "1.0.0",
      "zip_url": "https://<帳號>.github.io/iplot-modules/模組/整理桌面.zip",
      "sha256": "<那個 zip 的 sha256>",
      "description": "一句話說它做什麼",
      "icon": "🧹",
      "notes": "這一版改了什麼（一段）",
      "author": "someone",
      "warning": "給用的人的一句提醒"

}
```

清單在 `uploads` 或 `modules`：有 `uploads` 這個鍵就讀它（空的就是空的清單，不退回 `modules`），沒有才讀 `modules`。新的清單（iplot-modules 的 build 產生）放在 `uploads`、`modules` 是空的：0.5.1 的工作坊只讀 `modules`，看到的是空清單，不是一份沒有上傳者、沒有 `notice` 的開放清單（D107）。凍結的舊清單（`iplot-workshop` 的 `index.json`）只有 `modules`，新的工作坊照常讀。每一筆的 `name`、`version`、`zip_url`、`sha256` 是必要的，任何一筆少一項，整份索引就算格式不對；`description`、`icon`、`notes` 可以沒有（沒有 `notes` 的舊索引照常讀）。頂層的 `notice` 與每一筆的 `author`、`warning` 都可以沒有，不是字串（或只有空白）就當沒有；`author` 是 GitHub 帳號名（不含 @，清單頁會加上），帳號刪了是「帳號已刪除」。`name` 就是裝進去之後的資料夾名。zip 的最上層要剛好是 `<名稱>/`，裡面是模組資料夾的內容，至少有 `iplot.py`。

`tools/publish.py` 兩樣都會產生（iPLoT 自己不再用它發模組，留給本機試；模組從 iplot-modules 的上傳表單發，見下面）：

```
python3 tools/publish.py --version 0.5.0 --base-url <放檔案的地方> --modules 整理桌面 開工
```

- 在 `交付/發佈/`（或 `--out` 指的資料夾）產生 `模組/整理桌面.zip`、`模組/開工.zip` 與 `index.json`，還有給還沒裝 iPLoT 的人看的一頁 `index.html` 與空檔 `.nojekyll`（D79）；同一次也產生核心的 zip 與 `update.json`（第 10 節），所以 `--version` 一定要給，那個版本的 tag 要在（或加 `--ref HEAD`），而且那個 ref 裡核心的版本要剛好是 `--version`（第 10 節）。「整理桌面」是舉例的名字，隨附的模組裡沒有它；換成 `modules/` 裡真的有的。它寫的 `index.json` 是舊的樣子（只有 `modules`，沒有 `notice`、`author`、`warning`）。
- `--modules` 後面的名字是 iPLoT 資料夾裡 `modules/` 底下的資料夾名；不在那裡、或裡面沒有 `iplot.py`，就說一句、什麼都不產生。
- `description` 取自模組 `iplot.py` 的 docstring 第一段，`icon` 取自它的 `ICON` 常數；都沒寫就是空的。
- 模組的版本與 `notes` 取自模組資料夾裡的 `CHANGELOG.md`（D78）：格式跟 iPLoT 的 `CHANGELOG.md` 一樣，`## [1.2.0] - 2026-10-06` 一節一版，最新的寫在最上面；版本取最上面那一節的版本號（`[Unreleased]` 不算），`notes` 取那一節的第一段。沒有 `CHANGELOG.md` 的模組，版本跟 `--version` 一樣、`notes` 是空字串；要另外指定就寫「名稱=版本」，例如 `--modules 整理桌面=1.2.0`。兩邊都有又不一樣，工具說一句就停，不產生任何檔；`CHANGELOG.md` 讀不出最上面那一版（不是 UTF-8、沒有任何一節、版本寫成 `1.0.0-beta.1` 或 `v1.0.0`）也一樣。
- 打包時略過 `.history`、`.origin`、`.unconfirmed`、`__pycache__`、`.DS_Store`，跟工作坊安裝時略過的是同一組，比對不分大小寫。包只收那個模組資料夾裡 git 追蹤的檔（`git ls-files`，`tracked`）：還沒 commit 的新檔、模組自己產生的檔（例如「互通」的捷徑與紀錄）不會進去；一個 git 追蹤的檔都沒有就說一句、什麼都不產生。追蹤的檔裡有指到檔案的符號連結，會把它指到的內容打進去。zip 的 sha256 跟檔案時間有關：同樣的內容重打一次，sha256 也會變。
- 寫進 json 的網址，中文與空白會寫成 `%XX`（`https://` 的網址只能是 ASCII）；`name` 照原樣寫中文。
- 給了 `--modules`，`index.json` 就整份重寫：這一次沒列在 `--modules` 的模組，就不在清單上。沒給 `--modules`（只發佈核心），原本的 `index.json` 不動。所以不要對 `iplot-workshop` 的 clone 給 `--modules`：凍結的舊清單會整份被換掉，0.5.1 的人清單上其他的模組都不見；發核心用 `--modules-site`（下面「放在 GitHub Pages」），它跟 `--modules` 互斥，一起給就停、一個檔都不產生。

在本機試，不用網路：`--base-url` 給 `file:///<絕對路徑>/交付/發佈`，`config.py` 填 `WORKSHOP_URL = "file:///<絕對路徑>/交付/發佈/index.json"`。自動測試與目前的實測都是這樣做的。

**怎麼把自己的模組放上去。** 0.5.2 起模組放在 iplot-modules，有 GitHub 帳號就能傳，不用經過研究助理（D100、D102）：

## 12. 面板外執行（互通）

**這是什麼。** 0.5.1 起，任何模組都能從面板以外打開，打開之後跟在面板裡一樣拿得到 `app`；任何模組都能用 `app.run("主控面板")` 叫出面板。做這兩件事的是兩個工作坊模組：「互通」（`modules/互通/`）與「主控面板」（`modules/主控面板/`）。核心只多了一件事：`app.run` 在目前這一層找不到時退到最上層（D83）。＋ 的範本仍是 0.5.0 的樣子，不帶「那一小段」（D84 修訂）。其餘都在這兩個模組裡，要改就改模組，核心不動（D80）。

四種開法，最後都進同一個入口 `Core.press`：

| 開法 | 路徑 |
|---|---|
| Spotlight、Dock 上的捷徑 | `modules/互通/捷徑/<名稱>.app` → `open -n -a <Python.app> --args <run.py> <模組資料夾>`（沒有 Python.app 的 Python 直接執行） |
| 在模組資料夾 `python3 iplot.py [檔案…]` | 檔頭那一小段 → `<同一個 Python> <run.py> <模組資料夾> [檔案…]` |
| 一行指令（終端機、捷徑 App、快捷鍵） | `<Python> <iPLoT>/modules/互通/run.py <名稱或路徑> [檔案…]` |
| 面板裡雙擊 | 跟以前一樣 |

面板外的每一次執行都是一個獨立的程序：不連開著的面板，`app.memory` 不共用，訊息不進面板；iPLoT 照樣不聽任何 port（第 7 節）。

**`run.py`：面板外唯一的入口。** 目標是模組資料夾的路徑、`iplot.py` 的路徑，或最上層模組的名稱（名稱不找下一層）；後面的參數當作檔案路徑（以呼叫時的工作目錄為準），交給模組的 `on_files(app, paths)`，沒有參數就執行 `run(app)`。結束碼：0 模組跑完沒出錯；1 模組出錯、取消執行、找不到模組、按了停止；2 開不起來。依序做的事：

1. 確認 Python（`boot.py`，只用 Python 3.8 的語法，舊 Python 也拿得到一句話）：iPLoT 在 `run.py` 往上兩層；這個 Python 要 3.10 以上、載得進 `core` 與 `lib/` 的 pywebview。不行的話，`modules/互通/.python` 記著別的、存在的 Python，又還沒換過，就換成它重跑一次（`os.execv`，環境變數 `IPLOT_INTEROP_REEXEC` 記著換過）；換過還不行、或沒有紀錄，就跳提示框說一句、結束碼 2（D86）。
2. 核對核心版本：互通 0.1.0 支援核心 0.5.x、`app.api_version` ≥ 3；不合就說「到工作坊看看互通有沒有新版」、結束碼 2。
3. 記下這個 Python（跟記著的是同一個就不寫：`bin/python3` 與它的 Python.app 裡的執行檔算同一個）。
4. 擋住 `import tkinter`（跟面板一樣：主執行緒被 pywebview 佔著，模組在別的執行緒開 tkinter 視窗，整個程序會被作業系統中止）。
5. 讀 `config.py`（壞了就用預設值，在小視窗說哪裡壞），開小視窗，建 `Core`，重掃（在面板外一律是最上層），找目標，`Core.press(…, quiet=True)`：快照、`input()` 變對話框、工作坊裝來的模組先問一次、錯誤回報，都是 `Core.press` 原本就做的事。
6. 跑完同步一次（見下面）。小視窗要等同步做完才真的關；最後用 `os._exit` 結束，模組自己開的執行緒不能讓程序賴著不走。

**彈出式視窗**（`popup.py`、`popup.html`）照核心的 `View` 做八個方法（第 13 節）。它一開始藏著，這些時候才出來：模組寫了訊息（`app.log`、`print`，`print` 的輸出在模組跑完時才一行行送進來）、出錯、問問題（`app.ask`、`input()`、`app.confirm`）、選檔案或資料夾（小視窗原本藏著、選的期間又沒有別的話要說，選完就藏回去），或模組跑了 1 秒還沒結束（顯示「執行中：<名稱>…」和「停止」）。`app.page` 另開一個 640×520 的視窗，不會把小視窗叫出來：頁面開著的期間，跑再久也不出現「執行中」；那段期間小視窗若因為別的事出來了，關掉它只是把它藏起來、不結束程序（要結束就關掉頁面的視窗；⌘Q、登出、關機照常）——行事曆整天開著，關掉多出來的小視窗不能把行事曆一起關掉（D93）。跑完時：小視窗沒出現過就直接結束；出現過就在底下倒數「完成（x 秒），3 秒後關閉」，在視窗裡按任何一下就停下來、換成「關閉」；出錯就留著，底下是「出錯了」和「關閉」，錯誤那一行有「打開檔案」（跳到出錯的那一行）與「詳細」。跑完、小視窗還在的時候，底下那一列在「關閉」旁邊多一個回去鈕（模組還在跑時不出現）：最上層剛好有一個「行事曆」、而且跑的不是它，鈕上是「行事曆」（D93）；否則最上層剛好有一個「主控面板」、而且跑的不是它，鈕上是「主控面板」（D88）；都沒有就不給。按下去先停住倒數，等模組與同步做完，在同一個 `Core` 上跑那個模組，沒出錯就關掉小視窗，出錯照一般的錯誤顯示、小視窗留著；程序的結束碼仍然是原本那個模組的。按「停止」或在執行中關掉視窗，結束的是這一個程序（結束碼 1），面板不受影響。藏著的期間這個程序不進 Dock（pywebview 一開始就把程序登記成會出現在 Dock 的 App，所以先改成不進 Dock，顯示時才改回來）；從捷徑開時，Python.app 一啟動就被登記，Dock 會閃一下 Python 的圖示（2026-10-07 在 Mac 上量過，約半秒）。

**那一小段**（D84）是模組 `iplot.py` 檔頭的 22 行，頭尾兩行是記號 `# ── 互通 ──`。在 iPLoT 裡執行時（面板、或 `run.py`，`core.runner` 已經載入）它不做事；直接 `python3 iplot.py` 時，它從模組資料夾往上一層層找，每一層看它自己和它底下每個資料夾有沒有 `modules/互通/run.py`，找到就用同一個 Python 交給它（參數原樣往後傳、結束碼原樣傳回）；找不到就在 stderr 說一句「找不到 iPLoT 的「互通」…照一般的 python3 iplot.py 跑」，然後照一般的腳本繼續跑（跟 0.5.0 一樣）。環境變數 `IPLOT_DIRECT=1` 時一律不交出去、不說話，照一般的腳本跑——在編輯器裡直接 Run／Debug 一個模組時設它，中斷點才停得到。所以模組放在 iPLoT 資料夾裡（任何一層）、或放在 iPLoT 旁邊（`ROOTS` 的 `".."`，連同它的下一層）都找得到；`ROOTS` 另外加的資料夾（例如 `~/Desktop`）找不到。核心的 ＋ 範本不帶它（D84 修訂）：新模組跟舊模組一樣，要在「互通」的狀態頁按「加上」才有（D87，見下面），插在 docstring、`from __future__`、開頭連續的 import 之後（沒有 `run` 的模組直接執行時，最外層才不會先跑一次），接在 import 後面時空一行（ruff 的 I001）。

**同步**（`sync.py`）只在兩個時機做：`run.py` 每次跑完、在面板按「互通」。沒有背景程式。同一時間只有一個在做（`modules/互通/.lock`，超過 120 秒的當作上次沒清掉）。它不改任何模組檔案（D87），只做兩件事：

- 捷徑（只在 macOS）：`ROOTS` 底下每個模組一個（一路往下到每一層），「作業系統」除外。
- 問題（一個一句）寫進 `.sync-error`，覆蓋上一次的；沒問題就刪掉它。紀錄先寫暫存檔再換上去，不會寫到一半。

**加上那一小段**（D87）：模組（＋ 新建的也一樣）要能直接 `python3 iplot.py`，在面板按「互通」，狀態頁有一區「可以加上那一小段的模組」，逐一列出名稱與 `iplot.py` 的完整路徑，下面一個按鈕「加上（N 個檔）」；沒有可以加的就不顯示這一區。可以加的是：在 iPLoT 的 `modules/` 這個根目錄底下（包括它底下各層）、不是工作坊裝來的、不是三個隨附模組、`iplot.py` 不是符號連結、沒用 tkinter 或 turtle、還沒有記號、讀得懂（`ast`）。上一層（`..`）與 `ROOTS` 另外加的資料夾裡的一律不列，狀態頁寫「在 iPLoT 外面，不改」或「在 ROOTS 另外加的資料夾裡」。按鈕呼叫 `iplot.py` 的 `Api.patch()`：它不收任何參數，在 Python 這邊重新算一次可以加的（不信任頁面），每一個用 `snippet.add` 加上——加之前先在那個模組的 `.history/` 存快照——回傳加了哪些、問題（一個一句），頁面用 `textContent` 重畫。再按一次不會再改（已經有記號的不是候選）。

**捷徑**（`shortcut.py`）放在 `modules/互通/捷徑/`：Spotlight 搜得到（2026-10-07 在 Mac 上驗過，`mdfind` 列得出來、索引成「應用程式」），把整個資料夾拖到 Dock 就是一排按鈕；刪掉「互通」，捷徑跟著不見。名稱是模組的顯示名稱，下一層是「父 › 子」；`/` 換成 `／`、`:` 換成 `：`，重名（不分大小寫）依序加「 2」「 3」，超過 200 bytes 截短、結尾加「…」。每個 `.app` 裡是 `Info.plist`（自己的六個鍵 `IPLoTInterop`、`IPLoTModule`、`IPLoTPython`、`IPLoTApp`、`IPLoTRun`、`IPLoTIcon`）與一個指令稿：記下的 Python、`run.py`、Python.app 有一樣不在了（換了 Python、iPLoT 搬了家、刪了互通），就跳提示框說「在面板按一次「互通」，捷徑會重新整理」；否則交給那個 Python 的 Python.app 開 `run.py`。交給 Python.app 而不直接執行 Python，是因為 macOS 的隱私權保護（TCC）會把讀檔算在「開檔的那個 App」頭上：iPLoT 放在「文件」「桌面」「下載項目」裡時，直接執行的話每個捷徑各要一次允許（2026-10-07 在 Mac 上看到的：讀檔卡在系統的同意對話框，或直接 `Operation not permitted`），交給 Python.app 就只問「Python」一次（D86）。模組有 `icon.png` 就用 `sips` 轉成捷徑的圖示。同步時：要的跟已有的比，指向的模組不在了或改了名就拿掉、新的就做、`IPLoTModule`、`IPLoTPython`、`IPLoTApp`（Python.app 的路徑：Homebrew 的 Python 升小版本時會換）、`IPLoTRun`、`IPLoTIcon` 有一個不一樣就重做；`Info.plist` 裡沒有 `IPLoTInterop` 的東西一律不碰。

**「主控面板」**（`modules/主控面板/iplot.py`，D82）：在面板的程序裡，把自己叫到最前面；在面板外，找開著的面板（`ps` 的指令裡有 python 也有 `main.py`；有 `<iPLoT>/main.py` 就算，只寫 `main.py` 的再用 `lsof` 看工作目錄是不是 iPLoT），找到就叫到最前面，找不到就用同一個 Python 開一個（跟這個程序分開）。`ps` 一定用 UTF-8 的 locale 叫：從 Spotlight、Dock 開的程式沒有設定 locale，`ps` 會把中文路徑寫成 `M-fM^H…` 這種跳脫字（2026-10-07 在 Mac 上看到的）。macOS 14 起，自己不在最前面的 App 叫別人到最前面會被拒絕；被拒絕時交給一個一般的 python 子程序去叫（2026-10-07 量過：從捷徑開、從終端機開，面板都到了最前面）。在面板外叫的時候，小視窗會先跳出來說一句、3 秒後關掉，關掉之後面板在最前面。macOS 以外不叫到最前面，一律開一個新的。

**「行事曆」**（`modules/行事曆/`，D89–D93）：以行事曆為主控的工作坊模組。它的頁面只在它自己另開的程序裡開：在面板裡雙擊、別的模組 `app.run("行事曆")`、小視窗的回去鈕、Dock 捷徑，一律經過 `run.py` 另開一個程序（`<python> <run.py> <行事曆資料夾>`，環境變數 `IPLOT_CALENDAR=1` 當記號，那個程序一開始就把它拿掉），叫它的程序馬上回來，面板不會因為它排隊。已經開著（`modules/行事曆/.pid` 記的程序還活著，而且 `ps` 看到它的指令裡有 `run.py` 與行事曆的資料夾，兩邊都換成 NFC 再比）就叫到最前面，做法照抄「主控面板」；`.pid` 過期（程序不在、或那個號碼被別的程序拿去用）就開新的。在面板外叫的時候，小視窗會先說一句「打開行事曆」或「行事曆已經開著」、3 秒後關掉。行事曆上方的模組列在頁面載入時與視窗重新拿到焦點時才重掃（`core.scan`，第 13 節），點一個就同樣經 `run.py` 另開程序跑它；最右邊的「圖示面板」只在最上層有「主控面板」時出現。頁面的每個 `Api` 呼叫抓同一把鎖：pywebview 每個呼叫各開一條執行緒，而 `app.open`、`app.trash` 走 `Core.press`，執行期間會改整個程序的工作目錄、`sys.path` 與標準輸出。macOS 上，第一次要資料時把 Dock 圖示換成 `icon.png`（Dock 上的名字仍然是「Python」）。資料、網頁與發佈見 D90–D92 與 README 的「行事曆」。
（2026-10-14 在 Mac 上量過：面板式、Dock 捷徑式、小視窗顯示著時另開的行事曆視窗都在最前面；Dock 式開兩次只有一個行事曆；`<img src="file://…">` 在 `app.page` 的頁面裡顯示不出來，所以畫面上的縮圖用 `sips -Z 320` 做到那一天的 `.縮圖/`、以 data URL 傳給頁面。）

**自己產生的檔。** 都在 `modules/互通/`：`捷徑/`、`.python`、`.sync-error`、`.lock`（0.5.1 開發途中用過的 `.patched` 已經不用了，磁碟上有的話程式不讀它，`.gitignore` 照樣蓋住它）。它們在 `.gitignore` 裡；`tools/publish.py` 打模組的包只收 git 追蹤的檔，所以不會被發出去。工作坊更新「互通」時，包裡沒有的檔會留著，捷徑與紀錄不會因為更新而不見。

**怎麼改。**

- 捷徑放哪裡：`shortcut.py` 的 `FOLDER`（相對於 `modules/互通/`）。名稱的長度上限：`MAX_NAME_BYTES`。
- 小視窗多久跳出「執行中」：`run.py` 建 `Popup` 時的 `busy_after`（預設 1 秒）；倒數幾秒：`popup.html` 的 `let left = 3`；小視窗的大小：`popup.py` 的 `create_window`；長相：`popup.html` 最上面的 `<style>`（不引用面板的 `ui/style.css`，`ui/` 是核心的一部分）。
- 不要那一小段：把檔頭兩行 `# ── 互通 ──` 之間那一段整段刪掉。沒有任何東西會自動加回去；它會重新出現在狀態頁「可以加上」的清單裡，不按就不改。
- 那一小段的文字：`snippet.py` 的 `TEXT`，「互通」自己寫死，到 1.0.0 一字不改（`tests/test_interop.py::test_snippet_text_is_fixed_and_no_longer_comes_from_the_core_template` 用 sha256 擋），已經加過的模組才認得出來。那一小段叫 `run.py` 的方式是 `<python> <run.py> <模組資料夾> [參數…]`，「互通」的每一版都要接受（D84）。
- 支援哪一版的核心：`boot.py` 的 `SUPPORTED` 與 `MIN_API`。核心出大版本（D80）時，「互通」「主控面板」同時出新版。
- 擋住它的測試：`tests/test_interop.py`（144 個）、`tests/test_open_panel.py`（17 個）、`tests/test_calendar.py`（102 個，「行事曆」）、`tests/test_create.py::test_new_module_has_no_interop_snippet`（＋ 的範本不帶那一小段）、`tests/test_boundaries.py::test_core_has_no_os_code`（核心連範本裡都沒有 `subprocess`）、`tests/test_core.py` 的 `test_run_by_name_*`（7 個，其中 4 個是 0.5.1 加的）。

**限制。** 捷徑、提示框、叫到最前面只在 macOS。`run.py` 與小視窗在有 pywebview 的系統上照樣跑（Windows 未經實機驗證）；這一版的 Linux 沒有網頁面板，`lib/` 裡沒有 pywebview，`run.py` 說一句就結束（結束碼 2）。`ROOTS` 另外加的資料夾裡的模組直接 `python3 iplot.py` 時找不到 iPLoT，照一般的腳本跑（從捷徑與指令照樣打得開）。檔案裡用了舊 Python 看不懂的語法（例如 `match`）時，用舊 Python 直接執行會在讀檔階段就出錯，輪不到那一小段換 Python。換了 Python 之後要在面板按一次「互通」重新記下。iPLoT 搬了家，舊的捷徑會說找不到，跑一次任何模組（或在面板按「互通」）之後重新整理。

## 13. 工作坊模組可以依賴的核心介面

**這是什麼。** 從 0.5.1 起，核心只在大版本（1.0.0、2.0.0…）才真正修改，新功能以工作坊模組上線（D80）。有些功能模組只用 `app` 做不到，得自己用核心的零件：「互通」在面板外自己建一個 `Core`、自己做一個 `View`（彈出式視窗），還要讀設定、掃模組、存快照、把錯誤講成一句話。這些零件是下面這張清單；清單上的每一項跟 `app` 一樣是承諾：到 1.0.0 之前只加不改（D85）。清單以外的核心內部（例如 `Core.enter`、`runner._running`、`ui/` 的任何東西）隨時可能改，工作坊模組不要用。

| 介面 | 釘住的是什麼 |
|---|---|
| `core.__version__`、`core.app.App.api_version` | 版本字串；`api_version` ≥ 3 |
| `core.core.Core(home, config, view, safe=False)` | 建構子的參數；方法 `rescan()`、`all_modules()`、`roots()`、`press(info, handler="run", args=(), quiet=False) -> Result`、`run_by_name(name)`、`action(name, *args)`；屬性 `home`、`config`、`scope` |
| `core.core.View` | 八個方法：`show`、`log`、`report`、`ask(prompt, default="")`、`confirm`、`page(title, html, api)`、`choose_files`、`choose_folder` |
| `core.core.load_config(path)` | 回 `(Config, ErrorInfo | None)`；檔案不在回 `(預設值, None)` |
| `core.scan` | `module_info(folder, root, level)`、`find_modules(roots)`、`find_children(folder, root)`、`roots_from_config(home, roots)`、`is_module(folder)`、`home_path(s)`（「~」「~/…」換成家目錄，「~名字」回 None） |
| `core.history.snapshot(file, keep)` | 存一份快照 |
| `core.errors.describe(error) -> str` | 錯誤講成一句話 |
| `core.types` | `Config`、`ErrorInfo`、`ModuleInfo`、`Result`、`Scope`、`Group`、`Root` 這七個型別，與它們現有的欄位 |
| `core.text` | `T["not_found"]`、`T["ambiguous"]`（含 `{name}`、`{paths}`）；`SYSTEM_MODULE`（`"作業系統"`） |
| 執行時的兩件事實 | 模組執行期間 `"core.runner"` 在 `sys.modules` 裡；面板的程序裡 `"ui.web"` 或 `"ui.tk"` 在 `sys.modules` 裡 |

擋住它的測試：`tests/test_interfaces.py`。函式與方法用 `inspect.signature` 比參數名與預設值；型別比「現有的欄位都還在」（多了新欄位不算違反）；`"core.runner"` 那一條真的用 `run_module` 跑一個模組看。
