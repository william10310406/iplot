# iPLoT 的接口與邊界

## 0. 一句話

iPLoT 有哪幾個可以換零件的地方、每個地方的規則是什麼、哪個測試擋住那條規則。寫給三種人：想改核心的人、想把 iPLoT 搬到別的作業系統的人、想讓模組接網路的人。

每一節先說「這是什麼」，再說「怎麼改」「怎麼造」。規格在 `02_重構設計.md`，每個決定的理由在 `03_設計決定.md`（這份文件引用的是 D50–D59）。

## 1. 邊界地圖

「接縫」是兩塊程式碼之間講好的介面：守住介面，兩邊可以各自換掉。

| 接縫 | 在哪 | 規則 | 擋住它的測試 |
|---|---|---|---|
| 模組契約 | 每個模組的 `iplot.py` | 資料夾裡有 `iplot.py` 就是模組。核心只認四樣：docstring、`TITLE`、`run(app)`、`on_files(app, paths)`，都可省略。掃描只讀不執行。空檔案 `autostart`（自動啟動的標記）是 M2 的事 | `tests/test_scan.py`、`tests/test_meta.py` |
| `app` | `core/app.py` | 模組看得到的全部。只加不減；要拿掉東西就升 `api_version`（現在是 1） | `tests/test_app.py` |
| 執行 | `core/runner.py` 的 `run_module` | 進入模組程式碼唯一的門。核心其他地方沒有 `exec` | ruff 的 S102（`exec` 只准出現在 `runner.py` 那一行）、`tests/test_runner.py` |
| 畫面 | `core/core.py` 的 `View` | 核心不碰 tkinter；畫面只要做到 `View` 的六個方法 | `tests/test_boundaries.py::test_bottom_layer_never_imports_tkinter` |
| 作業系統 | `modules/作業系統/` | 核心一行作業系統的程式碼都沒有；打開、編輯、顯示、終端機、垃圾桶都交給這個模組 | `tests/test_boundaries.py::test_core_has_no_os_code`、`tests/test_bundled.py` |
| 文字 | `core/text.py` | 所有畫面文字在這一個檔；核心其他檔不寫中文字串常數 | 沒有測試，靠規範（D24、D32） |
| 設定 | `config.py` | 三個值：`ROOTS`、`EDITOR`、`HISTORY_KEEP`。改壞了用預設值啟動並說哪裡壞 | `tests/test_startup.py` |
| 快照 | 各模組的 `.history/` | 每次執行前存一份 `iplot.py`；內容沒變就不存 | `tests/test_history.py` |
| 啟動器 | `iPLoT.command`、`iPLoT.bat`、`iPLoT.sh` | 只做一件事：切到自己的資料夾，執行 `main.py` | `tests/smoke.py`（直接跑 `main.py`，不經過啟動器） |

另外兩條量得出來的界線：核心邏輯不超過 500 有效行、`ui.py` 不超過 150（`tests/test_budget.py`）。

## 2. 「作業系統」模組

**這是什麼。** `modules/作業系統/` 是一個普通的模組，裡面四個檔：

- `iplot.py`：選擇器。看現在是哪個作業系統，匯入旁邊的 `mac.py`、`win.py` 或 `linux.py`，把五個函式轉出來。按它的按鈕，訊息區會說現在用的是哪一個檔。
- `mac.py`、`win.py`、`linux.py`：各自用那個系統的做法實作同樣的五個函式。

核心需要碰作業系統時（`app.open`、右鍵選單、按 ＋ 之後打開編輯器、錯誤訊息的「打開檔案」），會到 `modules/` 找名字剛好是「作業系統」的模組，執行它對應的函式——跟按下任何模組按鈕走的是同一扇門，只是不印「完成」那一行。只在 `modules/` 找；上一層或 `ROOTS` 其他位置的同名資料夾不算（D52）。安全模式（`--safe`）照樣有。

**五個函式。** 三個檔的簽名完全一樣（測試會比）：

| 函式 | macOS（`mac.py`） | Windows（`win.py`，未經實機驗證） | Linux（`linux.py`） |
|---|---|---|---|
| `open(app, path)` | `open <路徑>` | `os.startfile` | `xdg-open <路徑>` |
| `edit(app, path, editor, line)` | `editor` 是 `None` 用 `open -t`（系統預設文字編輯器），否則照 `config.py` 的 `EDITOR`；資料夾一律改走 `open` | `None` 用記事本；其餘同左，但會先找出編輯器指令的完整路徑（`code` 在 Windows 是 `code.cmd`） | `None` 用 `xdg-open`；其餘同左 |
| `reveal(app, path)` | `open -R`：在 Finder 顯示並選取 | `explorer /select,<路徑>` | `xdg-open <上一層資料夾>`（沒有「選取」） |
| `terminal(app, path)` | `open -a Terminal <路徑>` | 有 Windows Terminal（`wt`）就用它，沒有就開新的 `cmd` 視窗 | 依序找 `x-terminal-emulator`、`gnome-terminal`、`konsole`、`xfce4-terminal`、`xterm`，用第一個找得到的；都沒有就報錯並列出試過的名字 |
| `trash(app, path)` | 搬到 `~/.Trash`，同名加「 2」「 3」…；回傳搬到哪 | 資源回收筒（`SHFileOperationW`）；資源回收筒沒有路徑，回 `None` | 照 XDG 規範搬到 `~/.local/share/Trash/files/`，並在 `info/` 寫一個 `.trashinfo` 記原本的位置與時間；回傳搬到哪 |

啟動外部程式一律用 `subprocess.Popen([...])` 傳清單、啟動後不等（記事本、`cmd` 會一直開著，等它會凍住面板），不拼字串。系統上缺那個執行檔時，面板會顯示「模組『作業系統』第 N 行出錯：FileNotFoundError，…」，N 是後端檔案（例如 `linux.py`）裡的行號，不是核心的。

**沒有這個模組會怎樣。** 其他功能全部正常，啟動也不受影響。需要它的動作各自在訊息區記一行說明，動作不執行：按 ＋ 時模組照樣建好、按鈕照樣出現，只是不會自動打開編輯器；右鍵三項、「打開檔案」、`app.open` 等五個 `app` 方法都是記一行、回 `None`。

**改壞了會怎樣、怎麼救。** 跟任何壞掉的模組一樣：每次動作在面板報一次錯，附檔案與行號，iPLoT 不會死。`iplot.py` 有語法錯誤時按鈕會標 ⚠；`mac.py` 這類後端檔壞了按鈕不會標，但每次動作一樣會報錯。已知限制：這時右鍵「打開程式碼」和錯誤訊息的「打開檔案」自己也壞了（它們也是交給這個模組做的），要自己用檔案總管打開 `modules/作業系統/` 底下的檔案改回來。`iplot.py` 在 `.history/` 有上一版；`mac.py`、`win.py`、`linux.py` 沒有快照（快照只存 `iplot.py`），改之前自己留一份，或從 iPLoT 的壓縮檔、git 拿回原本的。

**怎麼改。** 例：macOS 上想把 Terminal 換成 iTerm。右鍵「作業系統」→「在資料夾中顯示」，打開 `mac.py`，把 `terminal` 函式裡的 `"Terminal"` 改成 `"iTerm"`，存檔。不用重啟：下一次右鍵「在終端機打開」就是新的行為。（右鍵「打開程式碼」開的是選擇器 `iplot.py`，後端檔在同一個資料夾。）

**怎麼加一個作業系統。** 例：FreeBSD。

1. 把 `linux.py` 複製成 `bsd.py`，改 `NAME` 和五個函式。簽名不要動。
2. `iplot.py` 加一個分支：`elif sys.platform.startswith("freebsd"): import bsd as backend`。
3. `tests/test_bundled.py` 加一個 `test_bsd_argv`（照 `test_linux_argv` 的樣子，用假的 `Popen` 驗參數），並把 `"bsd"` 加進 `test_backends_have_same_five_functions` 與 `test_selector_picks_backend_by_platform`。

核心一行都不用動。

## 3. 怎麼加一個動作

**這是什麼。** 「動作」是模組想請作業系統做的一件事。現在有五個（上一節的表）。

**怎麼造。** 例：`app.clipboard(text)`，把文字放進剪貼簿。

1. 三個後端各加一個同簽名的函式 `clipboard(app, text)`。
2. `modules/作業系統/iplot.py` 轉出函式的那兩行加上 `clipboard`（核心是在 `iplot.py` 裡找函式的，沒轉出來就找不到）。
3. `core/app.py` 加一個一行的方法，帶繁體中文 docstring：`self._core.action("clipboard", text)`。
4. `docs/api.md` 的表加一列。
5. 測試：`tests/test_bundled.py` 的 `NAMES` 加上 `"clipboard"`（簽名一致的測試就會涵蓋它）並為三個後端各加參數的斷言；`tests/test_app.py` 加一個「轉呼叫 `core.action`」的斷言。

核心其他地方不用動：`Core.action(name, *args)` 不認識動作的名字，只負責找到模組、執行同名的函式、把回傳值傳回來。這是加法，`api_version` 不用升。

## 4. 怎麼換畫面

**這是什麼。** 核心只透過 `View` 跟畫面說話（`core/core.py`）：

```python
class View(Protocol):
    window: Any                                   # 主視窗；沒有就給 None
    def show(self, scope: Scope) -> None: ...     # 把目前範圍畫出來
    def log(self, text: str) -> None: ...         # 訊息區加一行
    def report(self, error: ErrorInfo) -> None: ...   # 顯示一個錯誤
    def ask(self, prompt: str, default: str = "") -> str | None: ...
    def choose_files(self) -> list[Path]: ...
    def choose_folder(self) -> Path | None: ...
```

現在的實作是 `core/ui.py` 的 `Panel`（tkinter）。`tests/conftest.py` 的 `FakeView` 是最小的實作：不開視窗，把事件記進一個清單。

**怎麼換。** 寫一個做到這六個方法和 `window` 屬性的類別，在 `main.py` 組裝時用它取代 `Panel`。畫面要把使用者的動作交回核心：按按鈕叫 `core.press(info)`、進入下一層叫 `core.enter(info)`、麵包屑叫 `core.back(depth)`、＋ 叫 `core.create(parent, name)`、右鍵三項與「打開檔案」叫 `core.action(...)`。

要注意的一件事：`app.window` 是直接把畫面的主視窗交給模組。換成不是 tkinter 的畫面（例如網頁版）之後，自己畫 tkinter 介面的模組就不能用了；那時 `window` 給 `None`，並在 `docs/api.md` 標明。

## 5. 怎麼加一種事件

**這是什麼。** 「事件」是核心在某個時機呼叫模組裡某個名字的函式。`runner.run_module(info, app, handler, args)` 的 `handler` 就是那個名字：執行 `iplot.py` 之後，找叫這個名字的函式，有就呼叫 `handler(app, *args)`。

現成的例子有三個：按下按鈕是 `run`；`on_files(app, paths)` 的執行路徑已經在（`core.press(info, "on_files", (paths,))`，面板上觸發它的拖放與右鍵是 M2 的事）；上面的五個動作也是同一條路（`core.action` 就是 `press(作業系統模組, "open", (path,), quiet=True)`）。

**怎麼造。** 例：`on_start`（iPLoT 啟動時執行）。

1. 讓掃描知道哪些模組有它：`core/meta.py` 已經收集了頂層函式的名字，在 `Meta` 與 `ModuleInfo` 各加一個欄位（像 `accepts_files` 那樣）。
2. 在對的時機呼叫：`core.press(info, "on_start")`。

執行機制（`runner`）不用改；快照、輸出進訊息區、錯誤進面板都自動沿用。指定的函式不存在時是 `MissingHandler` 錯誤（`run` 例外：沒有 `run` 不是錯）。

## 6. 模組要用網路

**這是什麼。** 模組是普通的 Python。`urllib.request`、`http.server`、`socket` 直接用，核心不用動，也不用宣告。

**要知道的兩件事。**

- **會凍住。** 模組在主視窗的執行緒上執行。下載一個大檔、等別人連進來、`serve_forever()`——執行多久，面板就凍住多久。短的請求（抓一個網頁）沒問題；長的要等第 8 節的事定下來。
- **秘密不要寫在 `iplot.py`。** token、密碼寫在 `iplot.py` 裡有兩個後果：每次執行前它會被原樣存進 `.history/`；把模組資料夾複製給別人時會一起帶走。先這樣做：放在模組資料夾裡另一個檔案（例如 `secret.txt`），程式用 `open("secret.txt")` 讀（執行期間工作目錄就是模組資料夾）；分享模組時不要附上它，用 git 的話把它加進 `.gitignore`。由作業系統的鑰匙圈保管的 `app.secret()` 是之後的事（D58）。

## 7. 安全：能保證什麼、不能保證什麼

**能保證的。**

- 掃描只讀不執行：面板列出模組時只看檔名、用 `ast` 讀原始碼，不跑任何模組程式碼（D07）。放進一個來路不明的模組資料夾，在按下它之前什麼都不會發生。
- 模組程式碼只在有人動手時執行：按下按鈕、或別的模組用 `app.run` 叫它。「作業系統」模組另外會在右鍵選單、＋、「打開檔案」、`app.open` 等動作時執行。這一版沒有自動啟動。
- 沒有字串拼出來的 shell 指令：核心裡沒有任何啟動外部程式的程式碼；隨附的「作業系統」模組一律用清單傳參數（D50，取代 D10）。
- 每次執行前 `iplot.py` 有快照，改壞了找得回來。

**不能保證的。**

- 模組跟 iPLoT 在同一個程序裡、用同一個使用者的權限執行。Python 沒有可靠的程序內沙箱，所以任何模組——包括「作業系統」模組——都能做這個使用者能做的任何事：讀寫檔案、連網路、執行別的程式。
- iPLoT 不問模組從哪裡來（D59）。按下一個模組，就是用自己的權限執行那個檔案，跟在終端機打 `python3 iplot.py` 一樣。按之前看一眼程式碼。

要改變第二組，只有一條路：程序邊界。那是下一節。

## 8. 執行模型是 M2 的第一題

**這是什麼。** 「執行模型」是模組的程式碼在哪裡跑。現在是程序內：`runner` 在 iPLoT 自己的程序裡 `exec` 模組的檔案。另一條路是子程序：每次按下真的啟動一個 `python3 iplot.py`。網路、安全、不凍住這三件事都卡在這一個選擇上（D56）。

| | 程序內 `exec`（現在） | 子程序 `python3 iplot.py` |
|---|---|---|
| 好處 | 簡單；`app` 是普通的物件，模組可以直接拿 `app.window` 畫自己的介面；按下去立刻執行 | 面板不會凍住；跑太久可以停掉；每次都是真的乾淨的程序；有了程序邊界，之後才談得上限制模組能做什麼 |
| 代價 | 模組執行多久面板就凍多久；模組留下的東西會留在 iPLoT 裡；沒有任何隔離 | `app` 的每個方法都要變成跨程序的訊息；`app.window` 沒了（模組要畫介面得自己開視窗）；`input()` 要另外接；核心估計多約 100 行；每次按下多一次直譯器啟動的時間 |

現在已知、而且會在子程序路線自然消失的問題：

- `time.sleep`、長迴圈、等網路會凍住面板。
- 模組自己改的 `sys.path` 不會被復原。
- 模組用 `logging.basicConfig()` 設的輸出會留在 iPLoT 的程序裡、綁著那一次執行，下一次執行的 log 看不到。
- 執行期間 `sys.modules["__main__"]` 是 iPLoT 的 `main.py` 不是模組，所以模組裡定義的函式與類別不能 pickle（`multiprocessing` 會壞）。

這一版刻意不選：`runner` 沒有動。M2 開工的第一件事是選這一題。

## 9. Windows、Linux 現況

**現況。**

- 三個後端檔都在，啟動器三個都在（`iPLoT.command`、`iPLoT.bat`、`iPLoT.sh`）。
- **macOS**：開發與測試都在這裡做。
- **Linux**：參數由測試驗過（用假的 `Popen`）；垃圾桶的搬移與 `.trashinfo` 的內容在暫存目錄裡真的跑過。但測試是在 macOS 上跑的，沒有在真的 Linux 桌面上按過。
- **Windows：未經實機驗證。** `win.py` 只用假的 `Popen`、`os.startfile`、`ctypes.windll` 驗過參數與結構，沒有任何一行在 Windows 上跑過。`iPLoT.bat` 也沒有被雙擊過。
- **CI**：`.github/workflows/ci.yml` 設了 macOS、Windows、Ubuntu 三個平台，但這個 repo 沒有遠端，CI 一次都沒有跑過。第一次真的跑時，Windows 與 Ubuntu 上可能會冒出測試本身只在 macOS 成立的假設（路徑的寫法、符號連結），那時要修的是測試。

**怎麼在 Windows 上驗。** 裝 python.org 的 Python（安裝時勾 tcl/tk），然後：

1. 雙擊 `iPLoT.bat`，面板出現。
2. 按「作業系統」：訊息區說「作業系統：Windows，用的是 win.py」。
3. 右鍵任一模組，三項各按一次：「打開程式碼」開記事本、「在資料夾中顯示」開檔案總管並選取、「在終端機打開」開終端機。再找一個路徑含空白的資料夾試「在資料夾中顯示」——`explorer /select,<路徑>` 現在是當成一個參數傳的；如果含空白時沒有選到，把 `win.py` 的 `reveal` 改成 `["explorer", "/select,", str(path)]`。
4. 按 ＋ 取個名字：記事本開了範本。
5. 做一個模組呼叫 `app.trash(某個測試檔)`：檔案進資源回收筒，可以還原。

Linux 一樣的五步，啟動改成 `./iPLoT.sh`（先裝發行版的 `python3-tk` 套件）。

**Windows 上還沒辦法確認、驗的時候要特別看的幾點**（都是讀程式推出來的疑點，不是實測結果）：

- `explorer /select,<路徑>` 遇到含空白的路徑可能選不到（上面第 3 步）。
- 資源回收筒不適用的位置（網路磁碟、超過回收筒容量的檔案）：`win.py` 現在的旗標可能讓 Windows 直接刪除而不問。試一次；真的會的話，在 `trash` 的旗標加上 `0x4000`（刪除前警告），並把測試裡的 `0x454` 一起改。
- `EDITOR` 設成 `code` 這類 `.cmd` 指令時，路徑裡有 `&` 或 `%` 會被 `cmd.exe` 另外解讀。
- 雙擊 `iPLoT.bat` 時，如果 Python 太舊，「需要 Python 3.10 以上」那一句會隨著視窗一起關掉、來不及看；要看得到就從命令提示字元執行它。
- 隨附的「重新啟動」用的是 `os.execv`，在 Windows 上的行為跟 macOS 不同，沒有驗過。
