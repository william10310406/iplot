# iPLoT v0.2.1：新架構說明與試用

寫給老闆。想法是您的，程式碼和架構是我重做的；每一個可以推翻的設計決定都寫在 `docs/03_設計決定.md`，附理由和沒選的做法。您看了哪一條不同意，改那裡，不要只改程式。

## 一、保留了什麼

您的三個原則一個字沒動，是所有決定的檢查標準：

1. **機器本身不為任何功能。** 核心不內建任何用途，連 iPLoT 自己的四個工具（開工、打開核心原始碼、開Terminal、重新啟動）都是模組，刪掉也不影響核心。
2. **所有人都能改原始碼。** 所以核心要看得到、小到一個下午讀得完、改壞了救得回來。
3. **大多數事情只用滑鼠。** 連「長出新能力」都要滑鼠能做。

三層掃描（上一層／這一層／下一層）、資料夾就是按鈕、雙擊啟動、零安裝——都保留。

## 三、怎麼在上面搭東西

分三種人，三種深度，彼此不衝突：

**只想做用途的人（大多數時候是您）。** 按 ＋、取名、貼程式、按下去。不用知道 `core/` 存在。改完檔案再按一次就是新版本，不用重啟。

**想用 iPLoT 給的能力的人。** 寫 `def run(app)`，`app` 能做的事全部在 `docs/api.md` 一頁：寫訊息區、開檔案、開編輯器、跑別的模組、問人、選檔案、`app.memory` 跨次記東西、`app.window` 自己畫介面。介面只加不減。

**想改核心的人。** `core/` 任一檔改完按「重新啟動」。每個檔開頭的 docstring 說它做什麼；規格在 `docs/02_重構設計.md`，理由在 `docs/03_設計決定.md`。新用途一律做成模組，不進核心——500 行的上限就是為了逼這件事。

前例一句話：Emacs 的核心很小、所有功能都是可改的 Lisp；HyperCard 讓人用滑鼠長出卡片和按鈕；Smalltalk 裡一切都是可以當場改的物件。iPLoT 想做的是這三者在 macOS 上、用 Python、給不開 Terminal 的人用的版本。

## 四、還沒做的

拖放檔案到按鈕上、匯入原版 `X/X.txt` 模組、自動啟動——這三件在 M2（規格 §13）。背景執行（現在 `time.sleep` 和長迴圈會凍住視窗）也在 M2（規格 §7、§13），先後由這兩週的使用紀錄決定。工作情境切換、檔案整理規則是更後面的事。

## 五、試用：三步看到新東西

1. 要有 python.org 的 Python 3.10 以上（Homebrew 或系統內建的沒有 tkinter，不能用）。把 iPLoT 資料夾放到 `~/iPLoT`（不要留在「下載項目」），雙擊 `iPLoT.command`；第一次 macOS 問要不要打開，選「打開」。
2. 按「這一層」右邊的 ＋，名字打「猜數字」，確定。編輯器開了範本，全部刪掉，貼上這段，存檔：

```python
import random
答案 = random.randint(1, 10)
while True:
    try:
        n = int(input("猜 1 到 10"))
    except ValueError:
        print("要輸入數字")
        continue
    if n == 答案:
        print("對了！")
        break
    print("太大" if n > 答案 else "太小")
exit()
```

3. 回 iPLoT 按「猜數字」。`input()` 變對話框，上一輪印的「太大」出現在下一個問題上面；猜對後訊息區出現全部輸出；結尾 `exit()` 不算錯。按一次「取消」：模組停，訊息區說「模組『猜數字』第 N 行出錯：EOFError，在提問時按了取消」。

已知會踩到的：長迴圈或 `time.sleep` 會凍住視窗；驗證迴圈寫什麼都接的 `except:` 按取消出不去（請接 `except ValueError`）；「重新啟動」後 Terminal 多一行 `Task policy set failed`，沒影響。
