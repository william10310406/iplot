
### M3：用真實路徑排除自己（原 txt:202 → 新 txt:212）

### E1：模組在按鈕 callback 裡出錯時跳出錯誤視窗（插在原 txt:98 之後 → 新 txt:99-108）

```diff
        iPLoTWIN.geometry('150x600+0+0')
        iPLoTWIN.after(3000000,iPLoTWIN.destroy)
+       def iPLoT_report_error(exc,val,tb):
+           import sys,traceback
+           text=''.join(traceback.format_exception(exc,val,tb))
+           sys.stderr.write(text)
+           w=tkinter.Toplevel()
+           w.title('iPLoT：模組執行失敗')
+           t=tkinter.Text(w,width=90,height=20)
+           t.insert('1.0',text)
+           t.pack(fill='both',expand=True)
+       iPLoTWIN.report_callback_exception=iPLoT_report_error
```

理由：模組是在按鈕 callback 裡用 `exec` 執行的，tkinter 預設只把例外印到 stderr 然後繼續跑，使用者只會看到「按了沒反應」（§4b-4、§7.2 第 5 點）。用 Toplevel 加 Text 而不用 messagebox，是為了讓錯誤文字可以選取、複製。縮排沿用這個 else 區塊的 7 格，函式本體 +4 格。

### E2：exec 時帶上檔名，traceback 才會指出是哪個檔案（新 txt:52、新 txt:132、iPLoT.py 新第 7 行）

```diff
-       exec(open(filename,'r',encoding='utf-8').read(),globals())
+       exec(compile(open(filename,'r',encoding='utf-8').read(),filename,'exec'),globals())
```

```diff
-           exec(open(iPLoTEditTxT,'r',encoding='utf-8').read(),globals())
+           exec(compile(open(iPLoTEditTxT,'r',encoding='utf-8').read(),iPLoTEditTxT,'exec'),globals())
```

iPLoT.py 的那一處見 M4 的 diff。

理由：原本 traceback 一律顯示 `File "<string>"`，分不出是主程式還是哪個模組（§4b-4、§6.1、§7.2 第 5 點）。`exec(cmds,globals())` 那幾行沒有動。

另外，iPLoT.txt 新第 74、193、227、238、249 行還有 `exec(open(a,...).read(),globals())`，但它們都在 `#B.configure(...)` **註解**裡。依照「不清理註解」的規則，這幾行保留原樣。

## 驗收腳本 `tests/step1.sh`

執行方式：

```bash
bash tests/step1.sh
```

- 每個情況都用背景執行 `&`，`sleep 8` 之後用 `kill -0` 判斷是否還活著；還活著就 `kill` 掉再 `wait`。每次執行都帶 `PYTHONUNBUFFERED=1`。
- 每個情況都會印出：是否還活著、結束碼、stdout、stderr，以及自動判定的 PASS/FAIL 和原因。全部通過時結束碼是 0，否則是 1。
- 情況 1、2、4、5 用 `mktemp -d` 建立 `<T>/iPLoT/`，從 `/Users/waiheng/Documents/6000_work/iplot` 複製**當下的** `iPLoT.py` 和 `iPLoT.txt`。腳本結束時用 `trap … EXIT` 刪掉所有暫存目錄和暫存檔。
- 情況 5 先檢查 `tkinterdnd2.__file__` 是否在 `site.getusersitepackages()` 底下。是就用 `python3 -s`，不是就用 `sys.modules['tkinterdnd2']=None` 加上 `runpy`。這台機器上它在 user site，所以用的是 `python3 -s`。
- 情況 1 會在啟動 3 秒後執行 `screencapture -x <T>/s1.png`；如果設定了 `STEP1_SHOT_DIR`，截圖會複製到那個目錄。
- 結束碼的注意事項：被 `kill` 的行程，`wait` 取得的是 1，這不是程式自己的結束碼，腳本輸出裡有另外標註。

## 畫面確認：截圖失敗，改用 widget 樹確認

`screencapture -x` 兩次都輸出 `could not create image from display`。這是因為執行這個環境的 app 沒有 macOS 的「螢幕錄影」權限，所以這一輪**沒有拿到截圖**。

改用一支放在 scratchpad 的探查腳本 `inspect_tk.py`（不在專案裡，也沒有修改專案檔案）。它攔截 `tkinter.Misc.mainloop`，在 mainloop 開始 2 秒後印出整棵 widget 樹，再用 `runpy.run_path` 執行 `iPLoT.py`：

```python
# 用法：python3 inspect_tk.py <iPLoT.py 的路徑>
# 攔截 mainloop，2 秒後印出整棵 widget 樹（類別、文字、標題、是否顯示、幾何、Text 內容）
import os, sys, runpy, tkinter
target = os.path.abspath(sys.argv[1])
_orig = tkinter.Misc.mainloop
def _dump(root):
    def walk(w, depth):
        for c in w.winfo_children():
            info = {'class': c.winfo_class(), 'mapped': c.winfo_ismapped(), 'geom': c.winfo_geometry()}
            if c.winfo_class() == 'Toplevel': info['title'] = c.title()
            try: info['text'] = c.cget('text')
            except tkinter.TclError: pass
            if c.winfo_class() == 'Label': info['reqwh'] = (c.winfo_reqwidth(), c.winfo_reqheight())
            if c.winfo_class() == 'Text': info['content'] = c.get('1.0', 'end-1c')
            print('[inspect]' + '  ' * depth, info, flush=True)
            walk(c, depth + 1)
    print('[inspect] root title=%r geometry=%s' % (root.title(), root.winfo_geometry()), flush=True)
    walk(root, 0)
def _mainloop(self, n=0):
    self.after(2000, lambda: _dump(self._root()))
    return _orig(self, n)
tkinter.Misc.mainloop = _mainloop
os.chdir(os.path.dirname(target))
runpy.run_path(target, run_name='__main__')
```
