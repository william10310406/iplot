# iPLoT 設計決定

每一條都是「幾個做法都說得通，挑了一個」的決定，不是三個原則逼出來的。所以每一條都可以推翻；推翻時在這裡改狀態、寫理由，不要只改程式碼。對應設計見 `02_重構設計.md`。

格式：決定 / 理由 / 沒選的做法 / 狀態。

---

**D01 核心只做六件事，其他全是模組。**
理由：原則 1 的實證。連「打開核心原始碼」都是模組，證明模組機制夠用。
沒選：把常用工具寫死在核心裡（原版的 iPloTEdit、Terminal、Space 按鈕）。
狀態：採用。

**D02 模組的標記檔固定叫 `iplot.py`，不是「資料夾 X 裡放 X.py」。**
理由：在 Finder 改資料夾名稱就等於改模組名稱，不會壞；不會把硬碟上隨便一個有 `main.py` 的專案誤認成模組；任何人只要記一個檔名。
沒選：`X/X.py`（原版慣例的延伸）。缺點是改名要改兩處。
狀態：採用。

**D03 「這一層」是 `iPLoT/modules/`，不是把模組跟 `core/` 混放在 `iPLoT/` 裡。**
理由：更新核心只換 `core/`，使用者的東西全在外面；`iPLoT/` 根目錄不會被模組塞滿。
沒選：模組直接放 `iPLoT/` 底下（原版做法）。
狀態：採用。

**D04 `run(app)` 是必要的函式，不是「檔案從頭跑到尾」。**
理由：`on_files` 這種有參數的入口才放得進來；頂層只放常數時，掃描階段的 `ast` 靜態讀取才可靠。
沒選：exec 整個檔案就是執行（原版做法）。
狀態：2026-10-03 由 D47 放寬——`run` 可省略，沒有時最外層程式碼就是動作；有參數的入口（`on_files`）與掃描階段的靜態讀取照舊。

**D05 命名空間每次用完即丟；狀態只在 `app.memory` 和檔案。**
理由：改完檔案再按一次就是新版本，沒有 reload；模組之間不會互相蓋名字。
沒選：importlib 真模組 + reload（reload 語意難懂）；共用全域（原版做法，沒有防護）。
狀態：採用。

**D06 不提供 `app.shared`。**
理由：加比拿掉容易；要共用先走檔案或 `app.run`。
沒選：一開始就給共用 dict。
狀態：採用，需要時再加。

**D07 掃描階段只用 `ast` 靜態讀，不執行任何模組程式碼。**
理由：核心在模組全壞時照樣能開，這是「從零啟動」的保證。
沒選：import 模組讀常數（會執行頂層程式碼）。
狀態：採用。

**D08 語法錯誤的模組照樣列在面板上，標 ⚠。**
理由：壞掉的東西要看得到，不然任何人都找不到自己改壞了什麼。
沒選：掃描時略過壞模組。
狀態：採用。

**D09 `App` 每次執行新建一個。**
理由：`module` 與 `memory` 在建立時綁好，`runner` 和 `app` 不開視窗就能測。
沒選：一個全域 `app`，執行前換 `module`。
狀態：採用。

**D10 `actions.py` 是唯一碰 macOS 的地方，全部走 `subprocess.run` 列表形式。**
理由：換作業系統只換一個檔；沒有字串拼接就沒有注入。
沒選：各處直接呼叫 `os.system`（原版做法）。
狀態：採用。**2026-10-04 由 D50 推翻**：核心已無 `actions.py`，碰作業系統的事在 `modules/作業系統`；「傳清單、不拼字串」這一半保留在那個模組裡。

**D11 視窗取得焦點就自動重掃。**
理由：在 Finder 建好資料夾、點回 iPLoT，按鈕就在，不用找「重新整理」。
沒選：只靠手動重掃或檔案監看（多一個依賴）。
狀態：採用。

**D12 `logs/` 放在 iPLoT 資料夾裡，不放 `~/Library/Logs`。**
理由：看得見、刪得掉，符合「可移除」。
沒選：系統慣例位置。
狀態：採用。

**D13 單擊執行、右鍵開選單，沒有雙擊。**
理由：一個動作一個意思；雙擊會跟單擊打架。
沒選：單擊選取、雙擊執行（Finder 慣例）。
狀態：採用。

**D14 ＋ 每一組一顆。**
理由：按下去就知道新模組會長在哪一層，不用再問。
沒選：一顆 ＋ 再問放哪。
狀態：採用。沒有子模組的模組進不去，按不到它那一組的 ＋；第一個子模組見 D60。

**D15 面板是單一視窗、單一欄。**
理由：核心的 UI 最小化；模組要自己開視窗用 `app.window`。
沒選：多視窗（原版的 Toplevel 子視窗）。
狀態：採用。

**D16 自動啟動用模組資料夾裡的空檔案 `autostart` 當標記。**
理由：滑鼠切換時只建檔或刪檔，不改 Python 原始碼；Finder 看得到。
沒選：`config.py` 裡的清單（程式改原始碼很脆弱）；寫死在主程式（原版做法）。
狀態：採用。

**D17 刪除 = 搬到 `~/.Trash`，永遠不 `rm`。**
理由：任何人都會誤按。
沒選：確認後直接刪除。
狀態：採用。2026-10-04 起各作業系統用各自的系統垃圾桶（D53）。

**D18 範本裡的 `TITLE` 預設註解掉，按鈕文字用資料夾名稱。**
理由：否則在 Finder 改了資料夾名，按鈕還是舊名字，任何人都會困惑。
沒選：範本直接寫 `TITLE = "<資料夾名>"`。
狀態：採用。

**D19 快照存在模組自己的 `.history/`，執行前與復原前各存一次。**
理由：刪模組就一起消失；每一個跑過的版本都在；復原本身可以再復原。
沒選：集中存在 `iPLoT/history/`；用 git 管模組。
狀態：採用。

**D20 第一版的核心復原只靠 git，不做滑鼠版。**
理由：先把模組的滑鼠復原做穩；核心改壞的人目前只有維護者。
沒選：核心也做 `.history/`。
狀態：採用，M3 之後再評估。

**D21 repo 建在 `6000_work/iplot`，原版移入 `docs/original/`，第一個 commit 打 tag `v0.0-original`。**
理由：來源留在歷史裡，報告裡「原版做了什麼、新版改了什麼」有憑有據。
沒選：另開資料夾；把原版刪掉。
狀態：採用。

**D22 tkinter 當 UI；`tkinterdnd2` 可選，沒裝就降級，可用模組安裝。**
理由：使用者端零依賴，「從零啟動」要真的零安裝。
沒選：PyQt / PySide（功能強但要安裝）；網頁式 UI（不是純 Python 的心智模型）。
狀態：採用。

**D23 行數預算：核心邏輯 400 行以內、`ui.py` 150 行以內。**
理由：「所有人都能改原始碼」只在讀得完時成立。數字從 300 修到 400 是把 `core.py` 編排層算進來之後的誠實估計。
沒選：不設預算。
狀態：採用，是上限不是目標。上限在 D41 調為 450；上限在 D48 調為 500。

**D24 畫面文字集中在 `core/text.py`。**
理由：之後要換語言換一個檔；測試可以比對鍵而不是比對中文字串。
沒選：字串散在各處。
狀態：採用。

**D25 預設 `ROOTS` 不含 `~/Desktop`。**
理由：桌面是每個人最亂的地方，預設掃它會讓第一次開的人看到一堆不相干的東西；要掃自己加一行。
沒選：跟原版一樣預設掃桌面。
狀態：採用，2026-10-02 確認。

**D26 原版 `X/X.txt` 模組的相容用工具模組「匯入原版模組」加包裝檔做，不進核心。**
理由：核心還是只認 `iplot.py` 一條規則；包裝檔每次重新執行旁邊的 `.txt`，老闆照舊編輯 `.txt`；用到沒準備的名字時面板直接指出缺哪個。相容是模組，符合 D01。
沒選：核心同時認 `X/X.txt`（兩條規則，而且原版腳本需要的全域名字得塞進核心）；要求老闆改寫成 `iplot.py`。
狀態：採用，2026-10-02。

**D27 ＋ 輸入一個已存在但沒有 `iplot.py` 的資料夾名稱，就把那個資料夾變成模組。**
理由：在上一層按 ＋ 打 `Documents`，使用者要的就是「讓 Documents 變成按鈕」，不是「我要一個新資料夾」。已經有 `iplot.py` 才算重複。
沒選：資料夾存在一律報錯。
狀態：採用，2026-10-02。

**D28 模組執行期間的 `print()` 收進訊息區。**
理由：任何人都會用 `print()` 看結果；雙擊啟動時 stdout 沒人看得到。
沒選：只提供 `app.log`。
狀態：採用，2026-10-02。

**D29 lint 規則集明列在 `pyproject.toml`，不吃工具預設；S102 與 BLE001 把規格 §7 的規則變成機器強制；`docs/original` 排除。**
理由：ruff 0.16 的預設規則從 E4/E7/E9/F 擴大到四百多條，工具一升版「乾淨」的意思就變了，明列才穩定。S102（`exec`）與 BLE001（`except Exception`）讓「進入模組程式碼只有一個門」「裸 except 只在允許的地方」由 lint 擋下，不靠人記；規格允許的例外（`core/runner.py` 的 `exec`；runner 與 `load_config` 的 `except Exception`；`Core.report_internal` 只接收例外，本身沒有 `except`）各加一行 `# noqa` 並寫理由，其他地方出現就失敗。`docs/original` 是老闆的原版存檔，一個字不改，所以不檢查。
沒選：沿用工具預設（升版就變）；釘死 ruff 舊版（擋不住 `exec` 與 `except Exception`）；改原版檔案讓它過 lint（存檔就不再是原版）。
狀態：採用，2026-10-02。

**D30 M1 在本地分支 `m1-seed` 開發，v0.1.0 時 `git merge --no-ff` 回 `main` 再打 tag。**
理由：§9.1 要求 `main` 永遠可以啟動，但 `main.py` 到 M1 後段才出現，前面的 commit 都啟動不了；放在分支上，`main` 只會從原版直接跳到能啟動的 v0.1.0。還沒有遠端，所以沒有 PR，`--no-ff` 的合併 commit 代替 PR 頁面當「一整批合進來」的記號。
沒選：直接 commit 到 `main`（中間十幾個 commit 都不能啟動）；先建遠端走 PR（這一版不建遠端）。
狀態：採用，2026-10-02。有遠端之後回到 §9.1 的 PR 流程。

**D31 覆蓋率用 `pytest-cov` 量，目標 90%，不設 fail-under。**
理由：§10 的 90% 不量就只是一句話；`pytest-cov` 是開發端工具，使用者端零依賴不變。M1 先看數字，不讓它擋 CI，等核心穩定再決定要不要設門檻。
沒選：不量（目標無法驗證）；直接設 `--cov-fail-under=90`（M1 還在長，會為了數字寫測試）。
狀態：採用，2026-10-02。

**D32 「不寫中文字串常數」只管 `core/`（`text.py` 除外）與 `main.py`；新模組範本放在 `text.py` 的 `TEMPLATE`。**
理由：D24 的目的是換語言只換一個檔，範本裡的中文註解換語言時也要跟著換，所以跟畫面文字放在一起；放在 `text.py` 也不吃核心的行數預算。測試、隨附模組、`smoke.sh` 本來就是給人看的中文內容，模組也拿不到 `core.text`，限制它們沒有意義。
沒選：限制套用到所有檔案（計畫原文，連計畫自己的測試都違規）；範本留在 `create.py`（約佔 11 行預算，換語言要改兩個檔）。
狀態：採用，2026-10-02。

**D33 按鈕的提示文字（滑鼠停在按鈕上顯示 docstring）延到 M2；範本的 docstring 不再承諾它。**
理由：tkinter 沒有內建 tooltip，自己寫要用掉 `ui.py` 約 10–15 行，而 M1 的 150 行已經很緊。範本原本寫「會顯示成按鈕的提示文字」，M1 做不到就不該寫進每一個新模組，所以改成「一句話說明這個模組做什麼。」；`ModuleInfo.description` 照樣讀，M2 加上提示文字時直接用。
沒選：M1 就做 tooltip（壓縮 `ui.py` 其他功能）；範本保留那句話（對使用者說謊）。
狀態：採用，2026-10-02。

**D34 模組判定比對資料夾裡實際的檔名，`iplot.py` 要一字不差；根目錄去重用 `os.path.samefile`。**
理由：APFS 預設不分大小寫，`(folder / "iplot.py").is_file()` 在只有 `iPLoT.py` 的資料夾也回 True。老闆原版的擺法正是 `iPLoT/iPLoT.py`，新舊 iPLoT 放在一起時舊的會變成一顆按鈕，按下去在同一個程序裡跑起整個舊程式。同理，`["modules", "Modules"]` 解析成兩個字串不同的路徑，只有 `samefile` 認得是同一個資料夾；路徑不存在時才退回比 resolve 後的字串。
沒選：用 `is_file()`（大小寫不分，誤認舊版）；接受現況、寫進文件（使用者不會讀到）。
狀態：採用，2026-10-02。

**D35 讀不到的根目錄在那一組記一行；根目錄底下讀不到的資料夾靜默略過。**
理由：`Group` 只有一個 `note`，子資料夾沒有回報管道；iPLoT 放在 `~` 時，`..` 底下常有受 macOS 隱私保護而讀不到的資料夾，逐一報出來只會是雜訊。根目錄讀不到才是使用者要知道的事（例如 `ROOTS` 打錯）。根目錄本身是個檔案時算「讀不到」。
沒選：每個讀不到的資料夾都記一行（`note` 要累積多行，面板被雜訊淹沒）；讀不到就讓掃描失敗（一個資料夾拖垮整組）。
狀態：採用，2026-10-02。

**D36 錯誤訊息保留 Python 原文，不翻譯。**
理由：只翻 `NameError` 會讓面板一半中文一半英文；其他例外的訊息種類太多，翻不完。會讀 Python 的人看得懂原文，原文也能直接拿去搜尋。白話的部分由外框負責：「模組『開工』第 7 行出錯：」說清楚是哪個模組、哪一行。
沒選：只翻譯 `NameError`（用 `exc.name` 加一個文字鍵）；整套翻譯表。
狀態：採用，2026-10-02。

**D37 錯誤定位取「模組資料夾內」最內層的一格；找不到時指向模組的 `iplot.py`、不帶行號。**
理由：原規則「屬於模組檔案的那一格，沒有就取最後一格」在模組讀檔就解碼失敗時，會指到標準庫的 `utf_8_sig.py` 第 69 行，「打開檔案」打開的是標準庫。改成資料夾內：一般錯誤結果不變；解碼錯誤改成指向模組本身；附錄 D 的包裝檔 exec 旁邊的 `X.txt` 時，定位會落在 `X.txt` 的那一行。traceback 是空的就都不帶；核心與設定的錯誤沒有模組資料夾，照舊取最後一格。
沒選：只比對 `iplot.py`（附錄 D 的錯誤只會指到 exec 那一行）；一律取最後一格（常指到標準庫）。
狀態：採用，2026-10-02。

**D38 `actions.edit` 遇到資料夾一律改用 `open`（Finder）。**
理由：`EDITOR = None` 時 `edit` 執行 `open -t <資料夾>`，TextEdit 開不了資料夾，而且 `check=False` 讓失敗不會浮上來，面板還顯示「完成」。「打開核心原始碼」原本就踩到這一點，改成 `app.open` 之外，在 `edit` 加一行擋住，以後任何模組 `app.edit(某資料夾)` 都不會再靜靜失敗。不論有沒有設定 `EDITOR` 都一樣，行為好預測。
沒選：只改「打開核心原始碼」這個模組（別的模組還會再踩）；只在 `EDITOR = None` 時改（有些編輯器能開資料夾，但 `{file}:{line}` 這種範本套在資料夾上結果難料）。
狀態：採用，2026-10-02。2026-10-04 起這條規則寫在 `modules/作業系統` 三個後端各自的 `edit` 裡（D50）。

**D39 自動啟動（`Core.autostart` 與 `main.py` 的呼叫）整個放到 M2。**
理由：規格 §13 把「自動啟動」列在 M2，但 §4.1、§6.1、§6.2 又把 `autostart` 寫成 M1 的介面，兩邊打架。設定標記的右鍵選單本來就在 M2，M1 只有 `autostart()` 沒有任何人能設定標記；放在一起做，行為才完整。§7.6 的「`--safe` 不自動啟動」在 M2 生效。
沒選：M1 先做 `autostart()`（約 5 行，但沒有滑鼠可以設定標記，只能手動建檔）。
狀態：採用，2026-10-02。

**D40 按下模組時，快照存不了只在訊息區記一行，模組照樣執行。**
理由：快照是保險，不是執行的前提。模組放在唯讀的地方（例如別人的資料夾）、`.history` 剛好是一個檔案，都會讓快照失敗；這時擋下執行，使用者只會覺得按鈕壞了。記一行「無法存上一版：…」讓人知道這次沒有備份。`press` 用 try/finally 收尾，任何一步出錯都不會讓之後的重掃永遠卡住。
沒選：快照失敗就不執行（把保險變成門檻）；靜默略過（使用者以為有備份）。
狀態：採用，2026-10-02。


**D41 核心邏輯行數上限從 400 調為 450；不為了湊數改寫法。**

**D47 腳本語意：按下按鈕 ＝ 在模組自己的資料夾裡執行 `python3 iplot.py`；`run` 可省略。**
理由：「怎麼寫都行」是承諾。2026-10-03 的使用紀錄（`05_使用紀錄.md`）：模組裡寫 `input()` 整個視窗凍住、面板沒提示；「要用 `app.ask` 才能問問題，感覺無法自由發揮」。課本教的是 `input()`、`print()`、`open("x.txt")`、`import helper`、`if __name__ == "__main__":`，這些要原樣能用：執行期間 `__name__` 是 `"__main__"`、工作目錄與 `sys.path[0]` 是模組資料夾、`sys.argv` 是 `[iplot.py]`、`builtins.input` 接到 `app.ask`（原本取消 → 空字串，2026-10-03 由 D49 改為 EOFError），跑完在 `finally` 還原，並把這次從模組資料夾載入的模組清出 `sys.modules`。Jupyter 把 `input()` 接到瀏覽器是同一招。`def run(app)` 留給想用 `app` 的人。模組合約只放寬不收緊，`api_version` 不變。
沒選：只在命名空間放一個 `input`（模組 import 的 helper 裡呼叫 `input()` 還是會凍住）；要求一定要 `def run`（D04 原本的做法，課本的腳本得先改寫才能用）。
執行時補的兩點：（一）執行期間 `sys.dont_write_bytecode = True`——`.pyc` 的有效性只看秒級的修改時間和檔案大小，同一秒內把 `helper.py` 改成同樣大小的內容會讀到舊的（實測 200 次連續修改有 179 次讀到舊值）；順便不在模組資料夾留下 `__pycache__`。（二）清 `sys.modules` 只清這次執行才載入的——iPLoT 放在某個模組的資料夾裡時，`core` 自己的檔案也在那個資料夾底下，不能清。另外「重新啟動」模組在 `execv` 前先 `os.chdir(app.home)`，新的 iPLoT 才不會以模組資料夾當工作目錄起來。
最終審查補的三點：（三）沒有 `__init__.py` 的子資料夾（`from utils import tools`）沒有 `__file__`，清 `sys.modules` 時要連 `__path__` 一起看，不然改了不會重讀。（四）模組用 `app.run` 跑別的模組時，外層模組的 helper 先從 `sys.modules` 收起來、跑完放回去——不然裡面那個模組 `import helper` 會拿到外層的（D05：模組之間不會互相蓋名字）。（五）對話框的文字是「上次問完之後 `print` 的東西 + 提示字」——簡報寫 `print` 不變，但猜數字這種「印回饋、再問」的課本程式，回饋要等整個腳本跑完才進訊息區，等於看不到；輸出本身照舊在跑完後進訊息區。
取消的行為：原本取消 → 空字串（研究助理裁定），2026-10-03 由 D49 改為 EOFError。
狀態：採用，2026-10-03。放寬 D04。`input()` 按取消與 `exit()` 的行為由 D49 修改。

**D49 `input()` 按取消丟 `EOFError`；`exit()` 代碼 0 是正常結束。**
理由：兩件事都是把 D47 的「就像 `python3 iplot.py`」做完。（一）取消：原本 `runner._dialog` 回 `app.ask(...) or ""`，課本最常見的驗證迴圈 `while True: try: n = int(input()) except ValueError: continue` 按取消永遠出不去，只能強制結束 iPLoT，違反 M1 的承諾「壞了要說哪裡壞」。真的 `input()` 在鍵盤關掉（Ctrl-D）時丟的就是 `EOFError`：`app.ask` 回 `None` 時 runner 丟 `EOFError("在提問時按了取消")`，不接住它，面板顯示「模組『X』第 N 行出錯：EOFError，在提問時按了取消」，行號指到呼叫 `input()` 的那一行；模組自己 `except EOFError` 可以接。`app.ask` 不變，照舊回 `None`。（二）`exit()`：原本 runner 接 `SystemExit` 一律變錯誤（「模組呼叫了 exit()，已忽略」）。初學者常在腳本結尾寫 `exit()`，而 `python3 iplot.py` 跑這種腳本是正常結束、狀態 0。現在 `exc.code` 是 `None` 或 `0` 就不是錯誤（輸出照常進訊息區）；其他值還是錯誤，訊息是「模組以 exit({code}) 結束」，code 是字串時照 Python 的做法把字串當訊息。`KeyboardInterrupt` 照舊不接；`config.py` 裡的 `exit()` 照舊算壞（§6.4，沒動）。
已知限制（最終審查）：迴圈裡寫 `except:` 或 `except Exception:` 的會把 `EOFError` 也接走，按取消還是出不去（實測取消 5 次問了 6 次）；真的終端機上也一樣，只是那裡有 Ctrl-C。規格 §7 已知限制有寫。要不要用程式補（例如同一次執行連續第二次取消時丟一個 `BaseException` 的子類別、由 runner 接成錯誤，約 5 行），留給研究助理裁定。
沒選：取消回空字串（困住驗證迴圈）；取消回 `None`（不是 `str`，課本程式會在 `.strip()` 炸掉）；`exit()` 一律算錯誤（跟「就像 `python3 iplot.py`」矛盾）。
狀態：採用，2026-10-03（研究助理裁定）。修改 D47 的取消行為。與 0.2.0 不相容：按取消的模組現在會以 EOFError 停止；`exit()` 不再顯示錯誤。

代價：要右鍵才找得到。兩週使用期間若有人找不到，就改成每個模組都顯示 ▸（刪掉 `if info.has_children:` 那一行，沒有子模組的 ▸ 用灰色）。
沒選：每個模組都顯示 ▸（每一列多一個符號，▸ 的提示意義消失）。
狀態：採用，2026-10-04。
