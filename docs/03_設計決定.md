# iPLoT 設計決定

每一條都是「幾個做法都說得通，挑了一個」的決定，不是三個原則逼出來的。所以每一條都可以推翻；推翻時在這裡改狀態、寫理由，不要只改程式碼。對應設計見 `02_重構設計.md`。

格式：決定 / 理由 / 沒選的做法 / 狀態。

---

**D01 核心只做六件事，其他全是模組。**
理由：原則 1 的實證。連「打開核心原始碼」都是模組，證明模組機制夠用。
沒選：把常用工具寫死在核心裡（原版的 iPloTEdit、Terminal、Space 按鈕）。
狀態：採用。

**D02 模組的標記檔固定叫 `iplot.py`，不是「資料夾 X 裡放 X.py」。**
理由：在 Finder 改資料夾名稱就等於改模組名稱，不會壞；不會把硬碟上隨便一個有 `main.py` 的專案誤認成模組；任何人只要記一個檔名。
沒選：`X/X.py`（原版慣例的延伸）。缺點是改名要改兩處。
狀態：採用。

**D03 「這一層」是 `iPLoT/modules/`，不是把模組跟 `core/` 混放在 `iPLoT/` 裡。**
理由：更新核心只換 `core/`，使用者的東西全在外面；`iPLoT/` 根目錄不會被模組塞滿。
沒選：模組直接放 `iPLoT/` 底下（原版做法）。
狀態：採用。2026-10-05：面板搬到 `ui/` 之後，更新要換的不只 `core/`，是 `core/`、`ui/`、`main.py`、`requirements/` 四樣（D69）；使用者的東西照舊全在這四樣以外（隨附的 `modules/作業系統/` 見 D50）。

**D04 `run(app)` 是必要的函式，不是「檔案從頭跑到尾」。**
理由：`on_files` 這種有參數的入口才放得進來；頂層只放常數時，掃描階段的 `ast` 靜態讀取才可靠。
沒選：exec 整個檔案就是執行（原版做法）。
狀態：2026-10-03 由 D47 放寬——`run` 可省略，沒有時最外層程式碼就是動作；有參數的入口（`on_files`）與掃描階段的靜態讀取照舊。

**D05 命名空間每次用完即丟；狀態只在 `app.memory` 和檔案。**
理由：改完檔案再按一次就是新版本，沒有 reload；模組之間不會互相蓋名字。
沒選：importlib 真模組 + reload（reload 語意難懂）；共用全域（原版做法，沒有防護）。
狀態：採用。

**D06 不提供 `app.shared`。**
理由：加比拿掉容易；要共用先走檔案或 `app.run`。
沒選：一開始就給共用 dict。
狀態：採用，需要時再加。

**D07 掃描階段只用 `ast` 靜態讀，不執行任何模組程式碼。**
理由：核心在模組全壞時照樣能開，這是「從零啟動」的保證。
沒選：import 模組讀常數（會執行頂層程式碼）。
狀態：採用。

**D08 語法錯誤的模組照樣列在面板上，標 ⚠。**
理由：壞掉的東西要看得到，不然任何人都找不到自己改壞了什麼。
沒選：掃描時略過壞模組。
狀態：採用。2026-10-05：網頁面板標的是圖示右上角的紅點，選到它時狀態列顯示那個錯誤（D64）；安全模式的 tk 面板仍是 ⚠。

**D09 `App` 每次執行新建一個。**
理由：`module` 與 `memory` 在建立時綁好，`runner` 和 `app` 不開視窗就能測。
沒選：一個全域 `app`，執行前換 `module`。
狀態：採用。

**D10 `actions.py` 是唯一碰 macOS 的地方，全部走 `subprocess.run` 列表形式。**
理由：換作業系統只換一個檔；沒有字串拼接就沒有注入。
沒選：各處直接呼叫 `os.system`（原版做法）。
狀態：採用。**2026-10-04 由 D50 推翻**：核心已無 `actions.py`，碰作業系統的事在 `modules/作業系統`；「傳清單、不拼字串」這一半保留在那個模組裡。

**D11 視窗取得焦點就自動重掃。**
理由：在 Finder 建好資料夾、點回 iPLoT，按鈕就在，不用找「重新整理」。
沒選：只靠手動重掃或檔案監看（多一個依賴）。
狀態：採用。2026-10-05：規則不變；網頁面板由頁面 JS 的 `focus` 事件觸發（`ui/app.js` 呼叫 `Bridge.rescan`，D63），掃完內容沒變就不重畫；安全模式的 tk 面板照舊用 tkinter 的 `<FocusIn>`。

**D12 `logs/` 放在 iPLoT 資料夾裡，不放 `~/Library/Logs`。**
理由：看得見、刪得掉，符合「可移除」。
沒選：系統慣例位置。
狀態：採用。

**D13 單擊執行、右鍵開選單，沒有雙擊。**
理由：一個動作一個意思；雙擊會跟單擊打架。
沒選：單擊選取、雙擊執行（Finder 慣例）。
狀態：推翻，見 D64（2026-10-05）；安全模式的 tk 面板仍是單擊執行。

**D14 ＋ 每一組一顆。**
理由：按下去就知道新模組會長在哪一層，不用再問。
沒選：一顆 ＋ 再問放哪。
狀態：採用。沒有子模組的模組進不去，按不到它那一組的 ＋；第一個子模組見 D60。2026-10-05：仍是每組一顆；網頁面板把它放在該組最後一格（虛線的 ＋），安全模式的 tk 面板仍在組標題右邊。

**D15 面板是單一視窗、單一欄。**
理由：核心的 UI 最小化；模組要自己開視窗用 `app.window`。
沒選：多視窗（原版的 Toplevel 子視窗）。
狀態：採用。2026-10-05：單一視窗不變；網頁面板把「單一欄」改成格狀（一格一個模組，視窗拉寬就自動重排），安全模式的 tk 面板仍是單一欄。`app.window` 已經拿掉（D66），模組不能再用它自己開 tk 視窗。

**D16 自動啟動用模組資料夾裡的空檔案 `autostart` 當標記。**
理由：滑鼠切換時只建檔或刪檔，不改 Python 原始碼；Finder 看得到。
沒選：`config.py` 裡的清單（程式改原始碼很脆弱）；寫死在主程式（原版做法）。
狀態：採用。

**D17 刪除 = 搬到 `~/.Trash`，永遠不 `rm`。**
理由：任何人都會誤按。
沒選：確認後直接刪除。
狀態：採用。2026-10-04 起各作業系統用各自的系統垃圾桶（D53）。

**D18 範本裡的 `TITLE` 預設註解掉，按鈕文字用資料夾名稱。**
理由：否則在 Finder 改了資料夾名，按鈕還是舊名字，任何人都會困惑。
沒選：範本直接寫 `TITLE = "<資料夾名>"`。
狀態：採用。

**D19 快照存在模組自己的 `.history/`，執行前與復原前各存一次。**
理由：刪模組就一起消失；每一個跑過的版本都在；復原本身可以再復原。
沒選：集中存在 `iPLoT/history/`；用 git 管模組。
狀態：採用。

**D20 第一版的核心復原只靠 git，不做滑鼠版。**
理由：先把模組的滑鼠復原做穩；核心改壞的人目前只有維護者。
沒選：核心也做 `.history/`。
狀態：採用，M3 之後再評估。

**D21 repo 建在 `6000_work/iplot`，原版移入 `docs/original/`，第一個 commit 打 tag `v0.0-original`。**
理由：來源留在歷史裡，報告裡「原版做了什麼、新版改了什麼」有憑有據。
沒選：另開資料夾；把原版刪掉。
狀態：採用。

**D22 tkinter 當 UI；`tkinterdnd2` 可選，沒裝就降級，可用模組安裝。**
理由：使用者端零依賴，「從零啟動」要真的零安裝。
沒選：PyQt / PySide（功能強但要安裝）；網頁式 UI（不是純 Python 的心智模型）。
狀態：採用。2026-10-05 由 D61–D63 修訂：預設的面板改成網頁面板，tkinter 面板搬到 `ui/tk.py`，只在安全模式與後備出現，tkinter 不再是必要的；「零安裝」由 D62 取消，改成第一次啟動自動安裝。`tkinterdnd2` 那一支在 0.4.0 從 `main.py` 走不到（當時 tk 面板一律以安全模式開）；0.5.0 起後備面板不是安全模式（D75），有裝 `tkinterdnd2` 的話，後備時會用它建視窗。拖放仍然沒做。

**D23 行數預算：核心邏輯 400 行以內、`ui.py` 150 行以內。**
理由：「所有人都能改原始碼」只在讀得完時成立。數字從 300 修到 400 是把 `core.py` 編排層算進來之後的誠實估計。
沒選：不設預算。
狀態：採用，是上限不是目標。上限在 D41 調為 450；上限在 D48 調為 500。面板的上限在 D68 改寫（2026-10-05）：`ui.py` 搬成 `ui/tk.py`，`ui/` 六個檔各有上限。

**D24 畫面文字集中在 `core/text.py`。**
理由：之後要換語言換一個檔；測試可以比對鍵而不是比對中文字串。
沒選：字串散在各處。
狀態：採用。

**D25 預設 `ROOTS` 不含 `~/Desktop`。**
理由：桌面是每個人最亂的地方，預設掃它會讓第一次開的人看到一堆不相干的東西；要掃自己加一行。
沒選：跟原版一樣預設掃桌面。
狀態：採用，2026-10-02 確認。

**D26 原版 `X/X.txt` 模組的相容用工具模組「匯入原版模組」加包裝檔做，不進核心。**
理由：核心還是只認 `iplot.py` 一條規則；包裝檔每次重新執行旁邊的 `.txt`，老闆照舊編輯 `.txt`；用到沒準備的名字時面板直接指出缺哪個。相容是模組，符合 D01。
沒選：核心同時認 `X/X.txt`（兩條規則，而且原版腳本需要的全域名字得塞進核心）；要求老闆改寫成 `iplot.py`。
狀態：採用，2026-10-02。

**D27 ＋ 輸入一個已存在但沒有 `iplot.py` 的資料夾名稱，就把那個資料夾變成模組。**
理由：在上一層按 ＋ 打 `Documents`，使用者要的就是「讓 Documents 變成按鈕」，不是「我要一個新資料夾」。已經有 `iplot.py` 才算重複。
沒選：資料夾存在一律報錯。
狀態：採用，2026-10-02。

**D28 模組執行期間的 `print()` 收進訊息區。**
理由：任何人都會用 `print()` 看結果；雙擊啟動時 stdout 沒人看得到。
沒選：只提供 `app.log`。
狀態：採用，2026-10-02。

**D29 lint 規則集明列在 `pyproject.toml`，不吃工具預設；S102 與 BLE001 把規格 §7 的規則變成機器強制；`docs/original` 排除。**
理由：ruff 0.16 的預設規則從 E4/E7/E9/F 擴大到四百多條，工具一升版「乾淨」的意思就變了，明列才穩定。S102（`exec`）與 BLE001（`except Exception`）讓「進入模組程式碼只有一個門」「裸 except 只在允許的地方」由 lint 擋下，不靠人記；規格允許的例外（`core/runner.py` 的 `exec`；runner 與 `load_config` 的 `except Exception`；`Core.report_internal` 只接收例外，本身沒有 `except`）各加一行 `# noqa` 並寫理由，其他地方出現就失敗。`docs/original` 是老闆的原版存檔，一個字不改，所以不檢查。
沒選：沿用工具預設（升版就變）；釘死 ruff 舊版（擋不住 `exec` 與 `except Exception`）；改原版檔案讓它過 lint（存檔就不再是原版）。
狀態：採用，2026-10-02。2026-10-05：允許的 `except Exception` 多了第三處，在 `ui/web.py` 的工作執行緒迴圈（D63），同樣加一行 `# noqa: BLE001` 並寫理由。

**D30 M1 在本地分支 `m1-seed` 開發，v0.1.0 時 `git merge --no-ff` 回 `main` 再打 tag。**
理由：§9.1 要求 `main` 永遠可以啟動，但 `main.py` 到 M1 後段才出現，前面的 commit 都啟動不了；放在分支上，`main` 只會從原版直接跳到能啟動的 v0.1.0。還沒有遠端，所以沒有 PR，`--no-ff` 的合併 commit 代替 PR 頁面當「一整批合進來」的記號。
沒選：直接 commit 到 `main`（中間十幾個 commit 都不能啟動）；先建遠端走 PR（這一版不建遠端）。
狀態：採用，2026-10-02。有遠端之後回到 §9.1 的 PR 流程。

**D31 覆蓋率用 `pytest-cov` 量，目標 90%，不設 fail-under。**
理由：§10 的 90% 不量就只是一句話；`pytest-cov` 是開發端工具，使用者端零依賴不變。M1 先看數字，不讓它擋 CI，等核心穩定再決定要不要設門檻。
沒選：不量（目標無法驗證）；直接設 `--cov-fail-under=90`（M1 還在長，會為了數字寫測試）。
狀態：採用，2026-10-02。2026-10-05：「使用者端零依賴」由 D62 取消（網頁面板要的套件在第一次啟動時裝進 `lib/`）；`pytest-cov` 仍然只是開發端工具（`requirements-dev.txt`），不在 `requirements/` 裡。

**D32 「不寫中文字串常數」只管 `core/`（`text.py` 除外）與 `main.py`；新模組範本放在 `text.py` 的 `TEMPLATE`。**
理由：D24 的目的是換語言只換一個檔，範本裡的中文註解換語言時也要跟著換，所以跟畫面文字放在一起；放在 `text.py` 也不吃核心的行數預算。測試、隨附模組、`smoke.sh` 本來就是給人看的中文內容，模組也拿不到 `core.text`，限制它們沒有意義。
沒選：限制套用到所有檔案（計畫原文，連計畫自己的測試都違規）；範本留在 `create.py`（約佔 11 行預算，換語言要改兩個檔）。
狀態：採用，2026-10-02。2026-10-05：範圍多了 `ui/*.py`（面板搬出 `core/` 之後照樣適用），而且現在有測試釘住：`tests/test_boundaries.py::test_no_chinese_string_constants_outside_text` 查 `core/`（`text.py` 除外）、`ui/*.py`、`main.py` 的字串常數，註解與 docstring 不算。

**D33 按鈕的提示文字（滑鼠停在按鈕上顯示 docstring）延到 M2；範本的 docstring 不再承諾它。**
理由：tkinter 沒有內建 tooltip，自己寫要用掉 `ui.py` 約 10–15 行，而 M1 的 150 行已經很緊。範本原本寫「會顯示成按鈕的提示文字」，M1 做不到就不該寫進每一個新模組，所以改成「一句話說明這個模組做什麼。」；`ModuleInfo.description` 照樣讀，M2 加上提示文字時直接用。
沒選：M1 就做 tooltip（壓縮 `ui.py` 其他功能）；範本保留那句話（對使用者說謊）。
狀態：採用，2026-10-02。2026-10-05：0.4.0 的網頁面板單擊模組時，狀態列顯示它的說明（docstring 第一段，D64）；安全模式的 tk 面板仍然沒有。

**D34 模組判定比對資料夾裡實際的檔名，`iplot.py` 要一字不差；根目錄去重用 `os.path.samefile`。**
理由：APFS 預設不分大小寫，`(folder / "iplot.py").is_file()` 在只有 `iPLoT.py` 的資料夾也回 True。老闆原版的擺法正是 `iPLoT/iPLoT.py`，新舊 iPLoT 放在一起時舊的會變成一顆按鈕，按下去在同一個程序裡跑起整個舊程式。同理，`["modules", "Modules"]` 解析成兩個字串不同的路徑，只有 `samefile` 認得是同一個資料夾；路徑不存在時才退回比 resolve 後的字串。
沒選：用 `is_file()`（大小寫不分，誤認舊版）；接受現況、寫進文件（使用者不會讀到）。
狀態：採用，2026-10-02。

**D35 讀不到的根目錄在那一組記一行；根目錄底下讀不到的資料夾靜默略過。**
理由：`Group` 只有一個 `note`，子資料夾沒有回報管道；iPLoT 放在 `~` 時，`..` 底下常有受 macOS 隱私保護而讀不到的資料夾，逐一報出來只會是雜訊。根目錄讀不到才是使用者要知道的事（例如 `ROOTS` 打錯）。根目錄本身是個檔案時算「讀不到」。
沒選：每個讀不到的資料夾都記一行（`note` 要累積多行，面板被雜訊淹沒）；讀不到就讓掃描失敗（一個資料夾拖垮整組）。
狀態：採用，2026-10-02。

**D36 錯誤訊息保留 Python 原文，不翻譯。**
理由：只翻 `NameError` 會讓面板一半中文一半英文；其他例外的訊息種類太多，翻不完。會讀 Python 的人看得懂原文，原文也能直接拿去搜尋。白話的部分由外框負責：「模組『開工』第 7 行出錯：」說清楚是哪個模組、哪一行。
沒選：只翻譯 `NameError`（用 `exc.name` 加一個文字鍵）；整套翻譯表。
狀態：採用，2026-10-02。

**D37 錯誤定位取「模組資料夾內」最內層的一格；找不到時指向模組的 `iplot.py`、不帶行號。**
理由：原規則「屬於模組檔案的那一格，沒有就取最後一格」在模組讀檔就解碼失敗時，會指到標準庫的 `utf_8_sig.py` 第 69 行，「打開檔案」打開的是標準庫。改成資料夾內：一般錯誤結果不變；解碼錯誤改成指向模組本身；附錄 D 的包裝檔 exec 旁邊的 `X.txt` 時，定位會落在 `X.txt` 的那一行。traceback 是空的就都不帶；核心與設定的錯誤沒有模組資料夾，照舊取最後一格。

**D47 腳本語意：按下按鈕 ＝ 在模組自己的資料夾裡執行 `python3 iplot.py`；`run` 可省略。**
理由：「怎麼寫都行」是承諾。2026-10-03 的使用紀錄（`05_使用紀錄.md`）：模組裡寫 `input()` 整個視窗凍住、面板沒提示；「要用 `app.ask` 才能問問題，感覺無法自由發揮」。課本教的是 `input()`、`print()`、`open("x.txt")`、`import helper`、`if __name__ == "__main__":`，這些要原樣能用：執行期間 `__name__` 是 `"__main__"`、工作目錄與 `sys.path[0]` 是模組資料夾、`sys.argv` 是 `[iplot.py]`、`builtins.input` 接到 `app.ask`（原本取消 → 空字串，2026-10-03 由 D49 改為 EOFError），跑完在 `finally` 還原，並把這次從模組資料夾載入的模組清出 `sys.modules`。Jupyter 把 `input()` 接到瀏覽器是同一招。`def run(app)` 留給想用 `app` 的人。模組合約只放寬不收緊，`api_version` 不變。
沒選：只在命名空間放一個 `input`（模組 import 的 helper 裡呼叫 `input()` 還是會凍住）；要求一定要 `def run`（D04 原本的做法，課本的腳本得先改寫才能用）。
執行時補的兩點：（一）執行期間 `sys.dont_write_bytecode = True`——`.pyc` 的有效性只看秒級的修改時間和檔案大小，同一秒內把 `helper.py` 改成同樣大小的內容會讀到舊的（實測 200 次連續修改有 179 次讀到舊值）；順便不在模組資料夾留下 `__pycache__`。（二）清 `sys.modules` 只清這次執行才載入的——iPLoT 放在某個模組的資料夾裡時，`core` 自己的檔案也在那個資料夾底下，不能清。另外「重新啟動」模組在 `execv` 前先 `os.chdir(app.home)`，新的 iPLoT 才不會以模組資料夾當工作目錄起來。
最終審查補的三點：（三）沒有 `__init__.py` 的子資料夾（`from utils import tools`）沒有 `__file__`，清 `sys.modules` 時要連 `__path__` 一起看，不然改了不會重讀。（四）模組用 `app.run` 跑別的模組時，外層模組的 helper 先從 `sys.modules` 收起來、跑完放回去——不然裡面那個模組 `import helper` 會拿到外層的（D05：模組之間不會互相蓋名字）。（五）對話框的文字是「上次問完之後 `print` 的東西 + 提示字」——簡報寫 `print` 不變，但猜數字這種「印回饋、再問」的課本程式，回饋要等整個腳本跑完才進訊息區，等於看不到；輸出本身照舊在跑完後進訊息區。
取消的行為：原本取消 → 空字串（研究助理裁定），2026-10-03 由 D49 改為 EOFError。
狀態：採用，2026-10-03。放寬 D04。`input()` 按取消與 `exit()` 的行為由 D49 修改。

**D49 `input()` 按取消丟 `EOFError`；`exit()` 代碼 0 是正常結束。**
理由：兩件事都是把 D47 的「就像 `python3 iplot.py`」做完。（一）取消：原本 `runner._dialog` 回 `app.ask(...) or ""`，課本最常見的驗證迴圈 `while True: try: n = int(input()) except ValueError: continue` 按取消永遠出不去，只能強制結束 iPLoT，違反 M1 的承諾「壞了要說哪裡壞」。真的 `input()` 在鍵盤關掉（Ctrl-D）時丟的就是 `EOFError`：`app.ask` 回 `None` 時 runner 丟 `EOFError("在提問時按了取消")`，不接住它，面板顯示「模組『X』第 N 行出錯：EOFError，在提問時按了取消」，行號指到呼叫 `input()` 的那一行；模組自己 `except EOFError` 可以接。`app.ask` 不變，照舊回 `None`。（二）`exit()`：原本 runner 接 `SystemExit` 一律變錯誤（「模組呼叫了 exit()，已忽略」）。初學者常在腳本結尾寫 `exit()`，而 `python3 iplot.py` 跑這種腳本是正常結束、狀態 0。現在 `exc.code` 是 `None` 或 `0` 就不是錯誤（輸出照常進訊息區）；其他值還是錯誤，訊息是「模組以 exit({code}) 結束」，code 是字串時照 Python 的做法把字串當訊息。`KeyboardInterrupt` 照舊不接；`config.py` 裡的 `exit()` 照舊算壞（§6.4，沒動）。
已知限制（最終審查）：迴圈裡寫 `except:` 或 `except Exception:` 的會把 `EOFError` 也接走，按取消還是出不去（實測取消 5 次問了 6 次）；真的終端機上也一樣，只是那裡有 Ctrl-C。規格 §7 已知限制有寫。要不要用程式補（例如同一次執行連續第二次取消時丟一個 `BaseException` 的子類別、由 runner 接成錯誤，約 5 行），留給研究助理裁定。
沒選：取消回空字串（困住驗證迴圈）；取消回 `None`（不是 `str`，課本程式會在 `.strip()` 炸掉）；`exit()` 一律算錯誤（跟「就像 `python3 iplot.py`」矛盾）。
狀態：採用，2026-10-03（研究助理裁定）。修改 D47 的取消行為。與 0.2.0 不相容：按取消的模組現在會以 EOFError 停止；`exit()` 不再顯示錯誤。

沒選：每個模組都顯示 ▸（每一列多一個符號，▸ 的提示意義消失）。
狀態：採用，2026-10-04。（0.4.0 起這個檔是 `ui/tk.py`；網頁面板照同一條規則，在 `ui/app.js` 的 `if (m.has_children)`：有子模組才有 ▸，第一個子模組靠右鍵項。）

**D61 UI 層可以用 HTML/CSS/JS；Python 端仍只用標準庫，加上 `lib/` 裡釘死版本的套件。**
理由：要「圖示有個性、介面有現代感」，tkinter 的上限是 2010 年的 Finder，自己用 Canvas 畫，估計 400–600 行也到不了；CSS 一行就有圓角、hover、深色模式。面板只是顯示器，原則 1、2、3 都不受影響：`Core` 這個類別沒有為了換面板改一行（`core/core.py` 只動了 `View` 的定義，D66），`core/` 也不 import `lib/` 裡的任何東西，只有 `ui/web.py` 可以（`tests/test_boundaries.py::test_core_never_imports_webview`）。面板本體是 `ui/index.html`、`ui/app.js`、`ui/style.css` 三個檔，不用框架、不用 build、零外部資源（沒有 CDN、沒有網路字型；`test_ui_has_no_external_urls`）；畫面文字照舊全在 `core/text.py`，由 Python 整份送進頁面（D24、D32）。

狀態：採用，2026-10-05。推翻 `02` §1 原本的硬限制「全部 Python」；D22 沒選的「網頁式 UI」現在選了。

**D62 取消零安裝：第一次啟動自動把需要的套件裝進 `lib/`。**
理由：零安裝只剩兩條路（tkinter、瀏覽器），都達不到要的介面。裝進 iPLoT 自己的 `lib/`（`ui/install.py` 跑 `python -m pip install --target lib …`，指令是列表、不經 shell），不碰系統的 Python；把 iPLoT 拖進垃圾桶，裝的東西跟著消失，「可移除」不變。裝哪一份需求檔、缺不缺前置條件，問「作業系統」模組（`requirements`、`webview_ready`；D50 的延續），pip 本身不分作業系統。裝不起來的人不能卡在門口：這個平台沒有網頁面板、缺前置條件、「作業系統」模組不在，或 pip 失敗（例如沒有網路）時，主控台用白話說原因（pip 失敗時還說怎麼再試；0.4.0 當時還說怎麼先用安全模式，0.5.0 起改成說「現在先改用備用面板」），沒有 traceback，然後自動退到後備的 tk 面板（0.4.0 當時是以安全模式開：標題有「（安全模式）」、只掃 `modules/`；0.5.0 起後備面板掃完整範圍，見 D75），同一句原因寫在訊息區；連 tkinter 都沒有，才印一句、以代碼 1 結束。裝好就重啟自己；重啟後還是開不起來就不再裝，直接退到後備面板——這條路每次啟動最多裝一次，不會無限重啟（`tests/test_main.py::test_reinstall_happens_once`）。
沒選：要求使用者先 `pip install`（裝不起來的人正是最需要照顧的）；裝進系統 site-packages（權限、污染）。
代價：需求從「Python ≥ 3.10、含 tkinter（python.org 的版本）」變成「Python ≥ 3.10 加 pip」（哪裡來的 Python 都可以，不必是 python.org 的；Homebrew 的照理也行，但實測只跑過 python.org 的）；tkinter 反而不再是必要的，只有安全模式與後備用到。第一次啟動要網路、要等。在一台 Mac 上實測（python.org 3.14.7、macOS 26.5、arm64）：`lib/` 裝完 36 MB、10 個套件；乾淨下載安裝 1 分 46 秒（看網路），pip 有快取時 8 秒；之後 `lib/` 在，啟動到視窗出現 0.6 秒；沒有網路時 pip 重試約 20 秒後失敗。pip 另外會照它平常的做法，在使用者的快取資料夾留下下載過的檔案（指令沒有加 `--no-cache-dir`），那一份不在 iPLoT 資料夾裡。版本釘死（`requirements/web-mac.txt`、`web-win.txt`，每一行都是 `==`）；**hash 釘死延後**——wheel 的 hash 依 Python 版本不同，要列出所有支援版本的 hash 才能用 `--require-hashes`，等有需要再做。Windows 那一份需求檔的版本是用 pip 的 `--dry-run --platform win_amd64` 解出來的，未經實機驗證；Linux 這一版沒有網頁面板（D63），不會安裝任何東西。
狀態：採用，2026-10-05。`02` §1 的「零安裝」改成「第一次啟動自動安裝」；D22 的「零安裝」到此為止。2026-10-05（0.5.0）改了兩處：退到的 tk 面板不再是安全模式，掃完整範圍（D75）；需求檔變了，下次啟動會在開面板之前重裝 `lib/`（D76）——那是另一條路，不算在上面的「最多裝一次」裡。

**D63 面板用 pywebview 開原生視窗；tkinter 面板降級為安全模式與後備。**
理由：pywebview 用 macOS 內建的 WebKit，打開就是一個自己的視窗（標題是「iPLoT v」加版本號），不是瀏覽器分頁；頁面的 JS 用 `pywebview.api.<方法>` 直接呼叫 Python（`ui/web.py` 的 `Bridge`），Python 用 `evaluate_js` 呼叫頁面，不用 server。頁面用 `file://` 網址載入（`Path.as_uri()`），所以真的沒有 server、沒有 port——實測程序沒有任何在聽的 TCP port。給 pywebview（6.2.1）一般的檔案路徑的話，它會自己起一個 127.0.0.1 的 HTTP server，而且讀不到上一層的 `custom.css`；所以 `tests/test_web.py::test_window_is_created_from_a_file_url` 釘住「開視窗時給的一定是 `file://` 網址」。tk 面板只有 120 行（`ui/tk.py`），留著當 `--safe` 和「網頁面板開不起來」的出口，成本低。0.4.0 當後備時也是以安全模式開（只掃 `modules/`）；0.5.0 起後備面板掃完整範圍，只有 `--safe` 才是安全模式（D75）。
沒選：Chrome 的 `--app` 模式（沒裝 Chrome 的人沒有）；Safari「加入 Dock」（要手動一次、網址要固定）。
代價：pywebview 的事件迴圈佔住主執行緒，所以模組的程式碼搬到單一工作執行緒上執行：一次只做一件，連按兩個模組，第二個排隊（`tests/test_web.py::test_jobs_run_one_at_a_time`）；`Core` 不知道執行緒的存在。工作裡沒接住的例外交給 `core.report_internal`，這是允許的第三處 `except Exception`（D29）。模組不能再靠 tkinter 開自己的視窗（主執行緒被 Cocoa 佔走，`app.window` 也拿掉了，D66）：在工作執行緒上開 tkinter 視窗（`turtle` 也算），整個程序會被 macOS 中止、沒有任何訊息（實測結束碼 133），所以面板開著時 `import tkinter` 直接變成一句白話的錯誤，說要用安全模式（`main.py` 的 `NoTk`）；模組要有自己的畫面，用 0.5.0 加的 `app.page`（D72）；0.4.0 還沒有。Windows 要 WebView2 runtime（Windows 11 內建；有沒有，由「作業系統」模組的 `webview_ready` 檢查），未經實機驗證。Linux 這一版沒有網頁面板：pywebview 在 Linux 要系統層的 GTK／WebKit2GTK，pip 裝不了，只有 tkinter 面板可用（0.4.0 只能用 `--safe`；0.5.0 起不加 `--safe` 開的是後備面板，掃完整範圍，D75），而且沒有在真的桌面上跑過。
狀態：採用，2026-10-05。2026-10-05（0.5.0）：後備面板不再是安全模式，見 D75；模組自己的頁面見 D72。

**D64 單擊選取、雙擊執行；推翻 D13。**
理由：照 macOS／Windows 的習慣；單擊就執行等於一按錯就跑程式。單擊只是選取，沒有副作用，所以不像 D13 擔心的那樣跟雙擊打架；視窗剛取得焦點時的重掃（D11），內容沒變就不重畫，不會打斷進行中的雙擊。單擊選到的模組，名稱與說明（docstring 第一段）顯示在下方狀態列，`description` 第一次有地方顯示（D33）；檔案有語法錯誤的模組，狀態列顯示的是那個錯誤。

**D65 圖示來源的順序：模組資料夾裡的 `icon.png` 或 `icon.svg` → `iplot.py` 頂層的 `ICON = "🧩"` 常數 → 名字第一個字、顏色由名字決定。**
理由：資料夾放圖檔跟 autostart 標記（D16）同一種思路，Finder 看得到、滑鼠拖得進去；`ICON` 常數跟 `TITLE` 一樣用 ast 讀（只認字串常數），零成本就有一個 emoji；預設圖示是最重要的那一個——每個新模組一開始都沒有圖示，預設如果是灰方塊，活力就死在最需要的地方。所以預設是顯示名稱的第一個字，底色的色相由資料夾名稱算出來，同一個模組每次都一樣。HyperCard 1987 年的按鈕就有「Icon…」對話框從圖庫挑圖示。圖檔的規則：檔名要一字不差（比對資料夾裡實際的檔名，`Icon.png` 不算，跟 D34 同一套）；兩個都有時 png 優先；上限 1 MB，由 `ui/web.py` 變成 data URI 送給頁面，檔案沒變就用上次讀的。超過 1 MB 或讀不到，就當作沒有這個圖檔（接著看 `ICON`，再來才是預設），訊息區記一行（`icon_unusable`），每個檔每次啟動只說一次，不影響其他模組（`tests/test_web.py::test_bad_icon_falls_back`）。
沒選：只支援圖檔（新模組全是灰的）；由面板隨機配色（同一個模組每次顏色不同）。
代價：掃描時每個模組多看一次資料夾裡的檔名；`ModuleInfo` 多兩個欄位（`icon`、`icon_file`），`Meta` 多 `icon`。圖示只在網頁面板顯示，安全模式的 tk 面板沒有。
狀態：採用，2026-10-05。

**D66 拿掉 `app.window`；`api_version` 1 → 2。**

**D69 更新只換 `core/`、`ui/`、`main.py`、`requirements/`；永遠不碰 `config.py`、`custom.css`、`modules/`、`logs/`、`lib/`，也不碰 iPLoT 資料夾以外的任何東西；換之前先備份，換的時候先解到暫名再改名交換。**（M3）
理由：「更新核心不動到使用者做的東西」是已確認的需求。使用者的東西全在那四樣以外。改名交換是為了中途當機也不會留下半套的 `core/`。0.4.0 先照這條原則擺東西：第一次啟動裝的套件在 `lib/`（D62），自己改的外觀放 `custom.css`（跟 `config.py` 同一層，`ui/index.html` 在 `style.css` 之後載入它），都在那四樣以外。
做法（0.5.0）：隨附模組「更新」（`modules/更新`：`iplot.py` 只負責問、說、串起來，做法在旁邊的 `update.py`）。`config.py` 的 `UPDATE_URL`（D71）指到一個 `update.json`：`{"version", "zip_url", "sha256", "notes"}`；zip 就是交付用的那一包，最上層是 `iPLoT-vX.Y.Z/`。按下去的流程：沒設網址 → 說一句怎麼設定；抓 json；先看 `version`、`zip_url`、`sha256` 三項（`update.check`）：少了一項 →「更新來源的 update.json 少了 '<那一項>' 這一項，沒有更新」，不是文字（null、數字）→「沒有更新：update.json 裡的 version、zip_url、sha256 應該都是文字（update.json 或下載的檔案有問題）」——在比版本之前就看，所以少了 `zip_url` 時就算已是最新也說少了這一項，`version` 也要本來就是字串，不再用 `str()` 轉（2026-10-06 改，獨立審查 M1）；磁碟上的版本不比它舊 → 「已是最新（x.y.z）」；比較新 → `app.confirm` 顯示版本與 `notes`（`tools/publish.py` 只取 CHANGELOG 那一版那一節的第一段，也就是摘要，不是整節），取消就什麼都不動；確定 → 下載到 `.backup/download-<版本>.zip`、驗 sha256 → 把現在的四樣複製到 `.backup/<舊版本>-<日期時間>/` → zip 解到 `.update-tmp/`，四樣各自先搬成 `<名稱>.new`，再照 `ui/`、`main.py`、`requirements/`、`core/` 的順序逐一改名換上去（舊的先改名成 `<名稱>.old`，全部換完才丟） → 清掉暫存 → 訊息區說「已更新到 x.y.z，執行「重新啟動」就會用新版」和舊版備份在哪裡。換的過程中出錯（`OSError`）：已經換上去的全部放回、`.new` 丟掉，四樣要嘛全新、要嘛全舊。`core/` 最後換，所以磁碟上的版本是新的，就代表四樣都換好了，「已經換成 x.y.z 了」不會騙人。按了才連網，不會自己檢查有沒有新版。
備份或換上去出錯（`OSError`：權限、磁碟滿、檔案被佔著）是訊息區一句話，照磁碟上的實況說（`update.unfinished(home)` 看還在的 `<名稱>.old`、`<名稱>.new` 與不見了的那幾樣）：都沒有 →「沒有更新：<錯誤>。core/、ui/、main.py、requirements/ 都還是原來的」；有 →「沒有更新，而且放回原來的版本時出錯了：<錯誤>。<留下的東西，用「、」隔開> 要用手整理（舊版的備份在 .backup/<資料夾>/，做法見 README 的「怎麼回到舊版」）」，備份本身就失敗時括號裡是「這一次沒有做成備份」。0.5.0 第一次寫好時這個錯是往上丟的，面板上是「模組『更新』第 … 行出錯：PermissionError，…」那種模組錯誤（2026-10-06 改，獨立審查 I2）。
換下來的舊版怎麼丟（`update._discard`）：每個 `<名稱>.old` 先在原地改名成 `.update-old-<名稱>-<n>`，再刪掉（改名留在同一層：整個唯讀的舊資料夾搬不進別的資料夾底下，同一層改名可以）；刪不掉的（例如舊 `core/` 裡有唯讀的子資料夾）留著那個名字，不再叫 `<名稱>.old`，下一次更新開頭再刪一次。更新成功之後丟舊版出錯不算失敗。上一次留下的殘餘，下一次更新在換上去之前先收（`update._restore`）：還有任何 `<名稱>.new`，就是上一次沒換完（`core` 最後換，換完就沒有 `.new`）→ 留著的 `<名稱>.old` 全部放回去，最後才丟 `.new`，四樣回到完整的舊版（放回的途中又被強制結束，下一次還看得到 `.new`，會接著收）；沒有任何 `.new`，就是上一次已經全部換好、只是舊的沒刪乾淨 → 那些 `.old` 不放回去，交給 `_discard`。開頭收殘餘時就出錯（例如連改名搬開都失敗），會停在那裡，新版一樣都還沒換上去；留著的 `<名稱>.old`、`<名稱>.new` 會列在上面那一句「要用手整理」裡。0.5.0 第一次寫好時是看到 `.old` 就放回：上一次已經全部換好、只是 `core.old` 刪掉一部分，下一次更新的包又有問題時，殘缺的 `core.old` 會被換回 `core/`，iPLoT 開不起來，訊息卻說沒有更新（2026-10-06 改，獨立審查 I1）。
不變量與擋它的測試（`tests/test_update.py`，在暫存資料夾裡用假的 iPLoT、假的 zip、`file://` 網址）：只換那四樣，zip 裡夾帶的其他東西（`README`、`modules/`、`config.py`）不套用；`config.py`、`custom.css`、`modules/`（含各模組的 `.history/`）、`logs/`、`lib/` 逐位元組不變；iPLoT 資料夾以外沒有任何寫入；`.update-tmp/` 與 `.new`、`.old` 做完都不在（`::test_apply_replaces_only_parts_and_keeps_rest`）。`.backup/` 裡有舊版的四樣（`::test_backup_has_old_parts`）。sha256 不符：刪掉下載的檔、說一句、一個檔都不動，也不備份（`::test_sha_mismatch_touches_nothing`；`.backup/` 原本不在的話，會留下一個空的資料夾）。包不完整（四樣少一樣）或最上層不只一個資料夾：一樣都不換（`::test_apply_refuses_a_zip_without_all_four_parts`、`::test_apply_refuses_a_zip_with_two_top_folders`）。換到一半出錯全部放回、`core/` 最後換、上次換到一半的殘留下次收回（`::test_apply_rolls_back_when_a_swap_fails`、`::test_core_is_swapped_last`、`::test_apply_recovers_from_a_swap_that_was_killed_half_way`）。上一次已經全部換好、只剩沒刪掉的 `.old`：下一次不放回去（`::test_leftover_old_without_new_is_not_put_back`）；舊版刪不掉時先改名搬開，留下的不會還叫 `core.old`（`::test_old_that_cannot_be_deleted_is_renamed_before_it_is_cleared`，只在 POSIX、非 root 時跑）。備份或換上去出錯：訊息區一句話，真的都放回去了才說「都還是原來的」，放回時也出錯就列出要用手整理的東西與備份在哪裡（`::test_a_failed_swap_is_one_sentence_and_everything_is_put_back`、`::test_a_failed_backup_is_one_sentence`、`::test_when_putting_back_fails_too_the_sentence_does_not_say_it_was_put_back`）。連不上、連到一半斷掉、伺服器沒回話、逾時、網址寫錯、json 缺項、json 裡那三項不是文字、不是 JSON、不是 zip：訊息區一句話，不是 traceback；網址寫錯的那一句叫人看 `config.py` 的 `UPDATE_URL` 或 update.json 裡的 `zip_url`（`::test_unreachable_source_is_one_plain_sentence`、`::test_dropped_connection_is_one_plain_sentence`、`::test_mistyped_url_is_blamed_on_the_url`、`::test_bad_update_json_is_one_plain_sentence`、`::test_wrong_types_in_update_json_are_one_sentence`（null 與數字共五種）、`::test_not_a_zip_is_one_plain_sentence`）。其中「不是 zip」「包不完整」「最上層不只一個資料夾」都是下載、備份之後解開時才發現的：四樣沒動，但 `.backup/` 裡已經多了下載的檔與一份備份。
還沒重新啟動又按一次：比的是磁碟上 `core/__init__.py` 寫的版本，不是執行中的 `app.version`（程序沒換，它還是舊的）。所以不會再下載、再備份、再換一次，只說「已經換成 x.y.z 了，執行「重新啟動」就會用新版」（`::test_update_twice_second_is_noop`）。確認對話框裡的「現在是 …」與 `.backup/` 那一份的版本，用的也是磁碟上的版本（`::test_backup_is_named_after_the_version_on_disk`）。
不是熱更新：換完要執行「重新啟動」模組才會用新版；`app.memory` 會清空，檔案都在。`requirements/` 也換了的話，下次啟動會重裝 `lib/`（D76）。要回到舊版：把 `.backup/<舊版本>-…/` 裡的四樣用手搬回去。不做：自動檢查、差異比較、一鍵回溯。
代價：隨附模組在 `modules/` 裡，更新也不碰它們；它們的新版走工作坊或手動複製，其中「作業系統」「更新」「工作坊」工作坊不覆蓋，只能手動複製（D70、D74）。四樣是逐一改名換上去的，不是一次全換：不會有只寫了一半的 `core/`，換的過程中出錯也會全部放回（放回時也出錯，那一句照實列出要用手整理的東西）；還留著的缺口是真的在兩次改名之間被強制結束（毫秒級）——磁碟上會暫時是新舊混合，正在換的那一樣可能只留下 `<名稱>.old` 與 `<名稱>.new`（剛好停在 `ui/`、`main.py` 或 `core/` 那一步的話，iPLoT 會開不起來），要到下一次按「更新」、換上去之前才會收回來；iPLoT 啟動時不檢查這件事，2026-10-06 決定維持不改程式（README 的「怎麼回到舊版」照實寫了怎麼救）。開不起來時，把留著的 `<名稱>.old` 都改回原名（同名的新版先移開），或把 `.backup/` 裡那一份用手搬回去。下一次更新是先備份、才收上一次的殘餘，所以那種情況下的那一份備份可能是新舊混合的四樣，名字卻標成舊版本。`<名稱>.old`、`<名稱>.new`、`.update-old-…` 是更新自己用的名字：iPLoT 資料夾裡本來就叫這些名字的東西，會被當成更新的殘餘換進去或刪掉。這兩件記在 `05_使用紀錄.md` 的待辦，沒有改。`.backup/` 每更新一次多一份舊版的四樣和一個下載的 zip，iPLoT 不會自己清。
狀態：採用，2026-10-05；0.5.0 已實作（0.4.0 時只是原則，換版本要手動換檔案）。整個流程只在 macOS 上驗過，大部分用 `file://` 網址；從 GitHub Pages 上的 `iplot-workshop` 真的下載、更新、安裝，2026-10-06 在 macOS 上用 `tests/acceptance_workshop.py` 走過一次（全部通過；確認框的長相、用瀏覽器看那一頁、沒有網路時的那一句，要人眼看的部分還沒做）（D71、D79）；Windows 未經實機驗證，規格 13.6 的人工驗收還沒做。2026-10-06：0.5.0 的獨立審查之後改了三處——不放回已經換好的那一次留下的 `.old`、刪不掉的舊版先改名成 `.update-old-<名稱>-<n>`（I1），備份與換上去出錯是一句照實說的話（I2），update.json 三項要是文字（M1）；這三處的自動測試在 macOS 上跑過。從 0.4.0 換到 0.5.0 仍要手動換（0.4.0 沒有這個模組）；0.5.0 之後的版本才能按「更新」，前提是有人把檔案放上去、`UPDATE_URL` 填好。設計原文在 `docs/plans/2026-10-05-M2-網頁面板與更新.md` 第 13 節；跟這裡不一致的地方，以這裡和程式為準。

**D70 模組的下載與更新由隨附模組「工作坊」做；索引是一個 JSON；來源記在模組資料夾的 `.origin`；覆蓋前整個資料夾存進 `.history/`。**（M3）
理由：原則 1——模組的商店也是模組。Steam 工作坊的做法：訂閱、更新、不碰存檔。
做法（0.5.0）：隨附模組「工作坊」（`modules/工作坊`：`iplot.py` 串起來，做法在 `workshop.py`，清單頁是 `page.html`，沒有任何外部資源）。按「工作坊」→ 抓索引 → 用 `app.page`（D72）開一頁，每個模組一列：圖示、名稱、說明（有 `notes` 的，底下多一行「這一版：<notes>」，D78）、索引的版本、在這台電腦上的狀態、一顆按鈕。關掉清單頁 → `app.rescan()`，新裝的格子出現在面板上。按了才連網。
索引：`config.py` 的 `WORKSHOP_URL`（D71）指到一個 `index.json`：`{"modules": [{"name", "version", "zip_url", "sha256", "description", "icon", "notes"}]}`，每一筆至少要有前四項（`notes` 是這一版改了什麼，D78），`name`、`zip_url`、`sha256` 要是文字，`version` 一律當字串，同名的只留第一筆（`tests/test_workshop.py::test_read_index_checks_the_types`）；每個 zip 最上層是 `<name>/`。打開工作坊時網址寫錯、或讀不懂索引，訊息區一句「讀不懂工作坊的清單（index.json），或 WORKSHOP_URL 寫錯了：…」。索引是從網路來的，裡面的字（名稱、說明、版本、圖示、`notes`）在清單頁一律當文字顯示，不當 HTML（`tests/test_workshop.py::test_render_escapes_what_came_from_the_index`、`::test_page_shows_the_notes_as_text`）。
六種狀態與按鈕（`workshop.state`）：隨附模組（`bundled`，名稱是「作業系統」「更新」「工作坊」之一，資料夾在不在都一樣，D74）→ 沒有按鈕，那一列多一句「這是 iPLoT 自己要用的隨附模組，工作坊不覆蓋它；要換新版，自己把新的資料夾複製進 modules/。」；未安裝（`absent`，沒有這個資料夾）→ 安裝；已安裝（`installed`，有 `.origin`、內容沒變、索引的版本不比它新）→ 沒有按鈕；可更新（`update`，內容沒變、索引的版本比較新）→ 更新；已修改（`modified`，當初裝進來的檔有改過或刪掉，或 `.origin` 壞了）→ 覆蓋；版本未知（`unknown`，資料夾在但沒有 `.origin`：自己建的同名模組，或另外四個隨附模組，D74）→ 覆蓋。索引的版本比較舊也算「已安裝」，工作坊不叫人降版（`::test_state_five_cases`、`::test_broken_origin_counts_as_modified`、`::test_workshop_never_overwrites_iplots_own_modules`）。`bundled` 是 2026-10-06 加的第六種，在這之前是五種。
`.origin` 與 `digest`：來源記在 `modules/<name>/.origin`，一行一個 `key: value`，六個 key：`url`、`version`、`sha256`（zip 的）、`digest`（安裝完當下那些檔的摘要）、`files`（裝進來的檔的相對路徑清單，JSON）、`installed`（日期時間）。`digest` 只算 `files` 列的那些檔：照路徑排序，把「路徑＋內容」一個個餵進 sha256，少了一個也算改過。清單以外的檔都不算：`.history/`、`.origin`、`.unconfirmed`、`__pycache__`、`.DS_Store` 是各台電腦自己的東西，不會在清單裡；模組執行時自己存在資料夾裡的設定、資料也不在。所以光是跑過（存了上一版）、確認過、在 Finder 打開過、模組自己存了資料，都不會變成「已修改」；改了裝進來的檔、刪掉其中一個才會（`::test_digest_covers_the_listed_files_only`、`::test_edit_makes_modified`、`::test_running_it_does_not_make_it_modified`、`::test_a_modules_own_data_does_not_make_it_modified`、`::test_origin_lists_the_installed_files`）。`.origin` 缺 `files` 這一行，一律算「已修改」。那五個名字比對時不分大小寫（macOS 的檔案系統上 `.Origin` 跟 `.origin` 是同一個名字）；`tools/publish.py` 打包時略過同一組，一樣不分大小寫（`::test_publish_and_workshop_agree`、`tests/test_publish.py::test_skip_ignores_case`）。
安裝（`workshop.install`）：下載到 `modules/.workshop-tmp/`、驗 sha256；從工作坊裝過（有 `.origin`）、又沒有確認過的，先看包裡的檔會不會蓋掉或拿掉模組自己存的檔，會就先不裝、回去問（D77）；資料夾已經在的話，先把整個資料夾（最上層的 `.history/` 自己除外）壓成 `modules/<name>/.history/<日期時間>-folder.zip`（存快照本身出錯（磁碟滿、`.history/` 不能寫）時還沒動到資料夾：寫到一半的 zip 刪掉，那一列是「<錯誤>；沒有裝成，還沒動到資料夾（存快照時出錯）」，`::test_a_failed_snapshot_is_one_sentence_and_leaves_no_half_zip`）；先在包裡與磁碟上（模組資料夾底下）每一個有 `iplot.py` 的資料夾建空檔案 `.unconfirmed`（D59、D73），再把包裡的檔案蓋上去，包裡沒有的舊檔案留著——模組自己存的資料不會因為更新而消失（包裡剛好有同名的檔要蓋掉它時先問，D77）；寫 `.origin`；清掉暫存。標記在放程式之前就建好，下一層的子模組也有（`::test_case_variants_of_local_names_cannot_switch_off_the_question`、`::test_nested_modules_are_asked_about_too`）。磁碟上已經在的也算（`workshop._module_dirs`）：新的包可能只帶下一層模組旁邊的 `helper.py`、不帶它的 `iplot.py`，那個資料夾是上一版裝的、確認過的，沒有標記的話，執行它就不經確認跑了新下載的程式。比對的是實際的檔名 `iplot.py`（跟核心認模組一樣），`.history/`、`__pycache__` 這些各台電腦自己的名字底下的不算（2026-10-06 補上，獨立審查 C1，`::test_module_folders_already_on_disk_are_asked_about_too`）。舊版的某個名字是檔案、新版是資料夾（或反過來）不算錯：照新版的放，舊的在快照裡（`::test_file_versus_folder_between_versions`）。模組資料夾裡本來有指到外面的符號連結：把連結本身拿掉、換成包裡的檔案，不會順著它寫到 `modules/<name>/` 以外（`::test_symlinks_in_the_target_are_not_followed`）。只寫進 `modules/<name>/` 與暫存，其他資料夾逐位元組不變（`::test_install_writes_only_its_folder`、`::test_install_snapshots_existing_folder`）。清單頁可以連按兩列：兩個安裝共用暫存資料夾，所以一次只做一個，第二個排隊（`::test_two_installs_at_once_both_finish`）。
蓋檔的過程中任何 `OSError`（磁碟滿、權限、Finder 鎖定的檔…）：照覆蓋前存的那份快照把資料夾放回裝之前的樣子，原本沒有這個資料夾就整個拿掉（`workshop._rollback`）。讓安裝失敗的原因通常也讓刪除失敗，所以放回時遇到刪不掉、寫不回去的不停下來：能刪的刪、快照裡每個檔都試著解回去，最後逐檔跟快照比（挑法跟存快照時一樣：最上層的 `.history/` 以外的每一個檔），一樣才算放回去了。快照資料夾的名字比對不分大小寫：macOS 上模組資料夾裡本來就有的 `.History/`（使用者或別的工具建的）跟 `.history/` 是同一個資料夾，快照就寫在它裡面，存快照、放回原樣、逐檔比對都不碰它（下一層子模組自己的 `.history/` 是核心替它存的上一版，跟著進快照、放回來；第三輪審查 I3，`::test_rollback_keeps_the_history_of_a_module_one_level_down`）。動手刪之前先確定快照讀得到（`zipfile` 的 `testzip`）；讀不到就一樣都不刪。然後丟 `NotInstalled`（`OSError` 的一種），清單頁那一列是「無法安裝：」加上照實說的一句：原本有資料夾是「<錯誤>；沒有裝成，已從快照放回」或「<錯誤>；沒有裝成，放回時出錯，快照在 <快照 zip 的完整路徑>」，快照讀不到時是「<錯誤>；沒有裝成，快照讀不到、沒有放回，資料夾現在是新舊混合：<資料夾路徑>」；原本沒有是「<錯誤>；沒有裝成，裝了一半的資料夾已經拿掉」或「<錯誤>；沒有裝成，裝了一半的資料夾拿不掉：<資料夾路徑>」。沒放回去時，留下來的每個有 `iplot.py` 的資料夾都放 `.unconfirmed`（裡面可能有新下載的程式）。0.5.0 第一次寫好時是第一個錯就停：快照放不回去，留下新舊混合，還可能刪掉包根本沒碰的檔，那一列卻只說「無法安裝：<錯誤>」（2026-10-06 改，獨立審查 I3 的最小版）。同一天第二輪審查 R2 又補兩件：以前用精確的 `.history` 認快照資料夾，資料夾裡本來就有 `.History/` 時，放回原樣會把它連快照一起刪掉，那一句說的路徑已經不在；快照讀不到時也是先刪了才發現。測試：`::test_failed_install_puts_the_old_folder_back`、`::test_failed_first_install_leaves_no_folder`、`::test_rollback_goes_on_past_a_read_only_folder`（POSIX、非 root 才跑）、`::test_rollback_with_a_locked_file`（macOS／BSD 的 `chflags`）、`::test_when_the_rollback_cannot_finish_the_sentence_says_where_the_snapshot_is`（POSIX、非 root 才跑）、`::test_rollback_that_cannot_write_a_file_back_does_not_say_it_put_it_back`、`::test_a_rollback_that_cannot_finish_leaves_every_module_folder_asking`、`::test_rollback_keeps_the_snapshot_when_the_folder_already_has_dot_History`（只在不分大小寫的檔案系統上跑）、`::test_rollback_does_not_delete_anything_when_the_snapshot_is_unreadable`。
覆蓋的確認在清單頁做：「已修改」「版本未知」第一次按「覆蓋」，按鈕變成「確定覆蓋」與「取消」，旁邊一句「這會覆蓋現有的模組，舊版會整個存進它的 .history/」，再按才真的做；按「取消」回到只有原來那一顆按鈕的樣子，頁面不重新載入（清單頁是用 html 字串開的，一重新載入就變成空白頁）。從工作坊裝過的模組按「更新」、包裡的檔會蓋掉或拿掉模組自己存的檔時，也在同一列這樣問，按「取消」回到原來那一顆「更新」（D77；以前「取消」一律變成「覆蓋」，`::test_cancel_puts_back_the_buttons_own_label`）。Python 這一頭也擋：`Api.install(name, confirmed=False)` 沒帶「確認過」就回「需要確認」，什麼都不動——「已修改」「版本未知」先看狀態就回，D77 的情況是 `workshop.install` 丟 `NeedsConfirmation`（`::test_api_install_asks_before_overwrite`）；頁面收到「需要確認」就重新問一次，頁面的 JS 出錯也顯示成「無法安裝：…」、按鈕恢復可按（`::test_page_does_not_reload_and_handles_failures`）。不用面板的 `app.confirm`：那個對話框開在主視窗，會被正在操作的清單頁擋住。
不裝的情況（清單頁那一列顯示一句「無法安裝：…」，資料夾不動）：sha256 不符；zip 最上層不是 `<name>/`；包裡沒有 `iplot.py`；路徑裡有 `..`；索引裡的名稱不是單純的資料夾名（空的或只有空白、含 `/` 或 `\`、以 `.` 開頭）；`modules/<name>` 本身是符號連結；名稱是「作業系統」「更新」「工作坊」之一（「「<名稱>」是 iPLoT 自己要用的隨附模組，工作坊不覆蓋它」，D74）。包裡夾帶的 `.history/`、`.origin`、`.unconfirmed`、`__pycache__`、`.DS_Store`（不分大小寫）不會被裝進去（`::test_install_rejects_bad_sha`、`::test_install_rejects_wrong_top_folder`、`::test_install_rejects_names_that_are_not_a_plain_folder_name`、`::test_a_symlinked_module_folder_is_refused`、`::test_package_cannot_bring_its_own_local_files`、`::test_api_install_error_is_a_sentence`、`::test_workshop_never_overwrites_iplots_own_modules`）。連線到一半斷掉、伺服器沒回話、寫檔出錯（那一句會說放回原樣了沒有，見上面）、索引那一筆的型別不對，也一律是那一列的一句「無法安裝：…」（`::test_api_install_turns_any_download_trouble_into_a_sentence`）。
不做：移除模組、降版、評分、留言、自動更新、多個索引。
代價：包裡沒有的舊檔案留著，所以新版拿掉的檔案，舊的那一份還會在資料夾裡（整個舊資料夾另外在 `.history/` 的 zip 裡）。`…-folder.zip` 不是 `history` 自己命名的快照（D44），不算進 `HISTORY_KEEP`，iPLoT 不會自己刪；要拿回舊的，自己解開那個 zip。模組的版本與這一版改了什麼寫在模組自己的 `CHANGELOG.md`（D78，2026-10-06；在這之前模組沒有地方寫自己的版本）；沒有這個檔的模組，`tools/publish.py` 拿核心的版本當它的版本，每發一版，索引裡列到它就會顯示「可更新」，就算內容沒變。裝到一半出錯時，放回原樣仍是「刪掉、再從快照解回去」，不是整個資料夾交換；在 `modules/.workshop-tmp/<名稱>` 組好完整的新資料夾再整個交換，這一版沒做（`05_使用紀錄.md` 的待辦）。「已從快照放回」比的是每個檔的內容；快照本身不是一模一樣的複本，指向資料夾的符號連結不在快照裡、放回時也沒有，指向檔案的符號連結放回來會變成一般檔，執行權限與空資料夾不會回來（同一份待辦）。快照讀不到（寫壞了、沒有權限讀）時放回原樣一樣都不刪：資料夾留在新舊混合的樣子，每個有 `iplot.py` 的資料夾帶著 `.unconfirmed`，要自己用手整理。
狀態：採用，2026-10-05；0.5.0 已實作（0.4.0 時只是方向，沒有這個模組，也沒有 `.origin` 與索引）。整個流程只在 macOS 上驗過，大部分用 `file://` 網址，包含在真的視窗裡跑過安裝、覆蓋、第一次執行前確認、進到下一層執行子模組先問、清單頁的「取消」；`https://` 只驗過連得上、憑證過得了；從 GitHub Pages 上的 `iplot-workshop` 真的下載、更新、安裝，2026-10-06 在 macOS 上用 `tests/acceptance_workshop.py` 走過一次（全部通過；確認框的長相、用瀏覽器看那一頁、沒有網路時的那一句，要人眼看的部分還沒做）（D71、D79）；Windows 未經實機驗證；Linux 沒有網頁面板，所以沒有清單頁，按「工作坊」只會看到 `page_unsupported` 那一句；規格 13.6 的人工驗收還沒做。2026-10-06：0.5.0 的獨立審查之後改了四處——磁碟上已經在的模組資料夾也放 `.unconfirmed`（C1），裝到一半出錯時放回原樣遇錯繼續做完、照實說（I3 的最小版），更新會蓋掉模組自己存的檔時先問（I4，D77），「作業系統」「更新」「工作坊」不覆蓋（D74 的修訂）；後兩項在 macOS 真的清單頁上跑過，前兩項只有自動測試。D59 跟著採用。設計原文在同一份文件的第 13 節；跟這裡不一致的地方，以這裡和程式為準。

**D71 更新與工作坊的來源網址放在 `config.py`：`UPDATE_URL`、`WORKSHOP_URL`，預設 `None`，沒設定就不連網；放檔案的地方定為 GitHub 公開 repo 的 raw 網址。（2026-10-06 修訂：隨附的 `config.py` 帶正式網址；放檔案的地方改成 GitHub Pages，D79。見下面「修訂」。）**
理由：平常使用不需要網路。要不要接上網路，是填不填這兩行的事，跟 `ROOTS`、`EDITOR` 一樣看得到、改得掉。兩個網址沒設定時，「更新」「工作坊」各說一句怎麼設定，不連網、不開頁面、不寫任何檔（`tests/test_bundled.py::test_update_and_workshop_do_nothing_until_a_url_is_set`）；設定了也只有按下去才連，不會自己檢查。`Config` 多 `update_url`、`workshop_url` 兩個欄位；`load_config` 驗型別（`None` 或字串），不對就整份用預設值並回報，跟 `ROOTS` 一樣（`tests/test_startup.py::test_config_urls_default_none_and_type_checked`）；模組從 `app.config` 讀（D72）。放檔案的地方只要能用網址直接取到檔案本身就行：GitHub 公開 repo 的 raw 網址（`https://raw.githubusercontent.com/<帳號>/<repo>/<分支>/<路徑>/update.json`）可以，不用另外架站。`https://` 要驗憑證，而 python.org 的 macOS Python 預設沒有根憑證（要另外執行「Install Certificates.command」），那樣每個 `https://` 網址都驗證失敗；所以「更新」與「工作坊」開網址時自己帶一個 `ssl` 設定（`update._context()`、`workshop._context()`），憑證庫是空的時候改用 macOS 自己的 `/etc/ssl/cert.pem`，驗證本身不關（`tests/test_update.py::test_https_open_brings_a_trust_store`、`tests/test_workshop.py::test_https_open_brings_a_trust_store`）。`tools/publish.py` 的 `--base-url` 填到放 `update.json` 的那一層，它會產生要上傳的檔案，並印出要填進 `config.py` 的兩行。Google Drive 的分享連結不是直接取檔，不行。
沒選：把網址寫死在核心裡（`core/` 是更新會換掉的四樣之一，換一個放檔案的地方就得改核心，也沒辦法「不設」；`config.py` 則是更新不碰的）；啟動時自動檢查有沒有新版（那樣平常使用就會連網）。

**D72 `app` 多三樣：`app.page(title, html, api=None)`、`app.config`、`app.version`；`api_version` 2 → 3，只加不減。**
理由：「更新」「工作坊」是模組（原則 1），它們要的東西得從 `app` 拿。來源網址在 `app.config`（唯讀的 `Config`：`roots`、`editor`、`history_keep`、`update_url`、`workshop_url`）；現在的核心版本是 `app.version`（字串，跟 `api_version` 放在一起的類別屬性）；工作坊的清單要一個自己的畫面，用 `app.page`。`page` 開第二個 pywebview 視窗顯示一頁 HTML，那個視窗關掉才回傳，像對話框；`api` 的公開方法給那一頁的 JS 用 `pywebview.api.<方法>` 呼叫。這也補上 D63 留下的缺口：網頁面板下模組不能開 tkinter 的視窗，在這之前模組沒有辦法有自己的畫面。`View` 跟著多第八個方法 `page`（現在是 `show`、`log`、`report`、`ask`、`confirm`、`page`、`choose_files`、`choose_folder`），`ui/install.py` 的 `ConsoleView` 與測試用的 `FakeView` 也有。安全模式與後備的 tkinter 面板沒有頁面：`page` 只在訊息區記一行（`T["page_unsupported"]`）就回來，不丟例外。`api_version` 升到 3：沒有拿掉任何東西，既有模組不用改；要用這三樣的模組可以先看 `app.api_version >= 3`。測試：`tests/test_app.py::test_api_version_is_3`、`::test_config_and_version`、`::test_page_goes_to_view`、`tests/test_web.py::test_page_blocks_until_closed`、`tests/test_tk_smoke.py::test_page_logs_unsupported`。在 macOS 真的網頁面板裡跑過：模組開出第二個視窗、那一頁的 JS 呼叫到 `api`、關掉之後模組繼續。

代價：那一頁的 HTML 由模組自己負責，核心不檢查內容；面板本體「零外部資源」的規則（D61）管不到模組的頁面，工作坊的 `page.html` 是自己守著（`tests/test_bundled.py::test_update_and_workshop_keep_their_logic_beside_iplot_py`）。頁面的 JS 用的是 `pywebview.api` 這個名字，等於模組的頁面認得 pywebview。沒有頁面的地方——安全模式、後備面板、Linux——用到 `page` 的模組只會留下一行訊息，工作坊在那裡開不了清單。Windows 未經實機驗證。

**D73 「第一次執行前確認」的標記是模組資料夾裡的空檔案 `.unconfirmed`；核心不解析任何格式。**
理由：跟 D16 為自動啟動設想的 `autostart` 是同一招：有這個檔就是「還沒確認過」，沒有就是確認過，建檔與刪檔就是全部的操作。核心只問「這個檔在不在」（`Core.press` 裡的 `marker.exists()`），不讀內容，也不用認識工作坊。標記跟著模組資料夾走：刪掉模組它就一起消失，不會留下對不上的記錄。工作坊每次安裝都會建，而且在放程式之前就建好，所以更新、覆蓋之後的第一次執行也會問；包裡與模組資料夾裡已經在磁碟上的每一個有 `iplot.py` 的資料夾都放一個，所以下一層的子模組也會問，新的包只帶了它旁邊的檔、沒帶它的 `iplot.py` 也一樣（磁碟上的那一半是 2026-10-06 補上的，獨立審查 C1，見 D70）。裝到一半出錯、沒能放回原樣時，留下來的每個有 `iplot.py` 的資料夾也都放一個（D70）。它不在 `.origin` 的 `files` 清單裡、不算進 `digest`，確認過不會讓模組變成「已修改」（D70）。

**D75 後備面板不是安全模式：網頁面板開不起來時退到的 tkinter 面板掃完整範圍（上一層與 `ROOTS`）；只有 `--safe` 才只掃 `modules/`。**

**D76 需求檔變了，下次啟動在開面板之前重裝 `lib/`；沒有網路就先用現有的 `lib/` 開，之後每次啟動再試。**

代價：需求檔變了之後的那一次啟動要網路、要等。沒有網路時，每次啟動都要先等 pip 放棄才開面板。先用舊 `lib/` 開的那段時間，`ui/` 是新的、套件是舊的；真的開不起來，走的是 D62 原本那條路（重裝一次，再不行就退到後備面板）。0.4.0 到 0.5.0 的需求檔沒有變，這條路還沒有在真的換版本時走過；自動測試裡的 pip 是替身。Windows 未經實機驗證。

**D77 工作坊的「已修改」只看當初裝進來的檔；更新時包裡的檔要蓋掉或拿掉模組自己存的檔，先問一次。修正規格 13.3。**
原規格（`docs/plans/2026-10-05-M2-網頁面板與更新.md` 13.3）：`.origin` 的 `digest` 涵蓋整個模組資料夾（略過 `.history/`、`.origin`、`.unconfirmed`、`__pycache__`）；`digest` 跟現在的內容不同就是「已修改」，按鈕是「覆蓋」，先確認；`digest` 相同、索引的版本比較新是「可更新」，按「更新」不問就裝。
改了什麼：第一步在 0.5.0 的審查修正（`4405419`）：`.origin` 多一行 `files`（裝進來的檔的相對路徑清單），`digest` 只算這些檔，模組執行時自己存在資料夾裡的檔不算改過（D70）。第二步（2026-10-06）：從工作坊裝過（有 `.origin`）的模組按「更新」時，下載、解開之後先看包裡的檔放上去，會不會蓋掉或拿掉不在 `files` 清單裡的本機檔——同名的檔、同名的資料夾（整個會被拿掉）、擋在要建資料夾的地方的檔。會的話 `workshop.install` 丟 `NeedsConfirmation`，`Api.install` 回「需要確認」，模組資料夾一個位元組都不動；清單頁在那一列問一次（「確定覆蓋」「取消」，旁邊一句「這會覆蓋現有的模組，舊版會整個存進它的 .history/」），按「確定覆蓋」才裝，裝之前整個舊資料夾照舊存進 `.history/`。按「取消」回到原來那一顆「更新」，下次按一樣先問。其他情況照第一步：包裡的檔只蓋到當初裝進來的那些，就不多問。「已修改」「版本未知」本來就要先確認，不變。

沒選：回到規格的寫法（模組自己存的資料讓它一直是「已修改」）；維持第一步、不問（會不經確認蓋掉資料）；每一次更新都先問（大部分更新根本碰不到模組自己的檔，問多了就不看了）。
代價：要下載、解開之後才知道會不會蓋到，所以按「更新」有時直接裝好，有時才變成「確定覆蓋」；確定之後會再下載一次。清單頁那一句沒有說會蓋到哪一個檔。比對的是路徑：包裡的路徑跟本機的只差大小寫時，在 macOS 上也算蓋到（寧可多問）。沒有 `.origin`、或 `.origin` 壞了的模組不走這一條，它們本來就是「版本未知」「已修改」，要先確認。
狀態：採用，2026-10-06。修正規格 13.3 與 D70 的「已修改」。
