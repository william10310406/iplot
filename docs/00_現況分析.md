1. **在目前位置啟動會直接當掉**：`txt:203` 把「桌面」算成 `os.path.dirname(iPLoTHOMEDIR)/Desktop`，也就是 `/Users/waiheng/Documents/6000_work/Desktop`。這個目錄不存在，所以 `txt:204` 的 `os.listdir` 拋出 `FileNotFoundError`。程式**根本不會去讀 `~/Desktop`**，所以也不會跳出 macOS 的權限視窗。

4. **少了 `tkinterdnd2` 時程式完全靜默**：`py:11-12` 的 `except ImportError: pass` 會把錯誤吞掉，結束碼是 0，沒有任何輸出（§4c）。`tkinterdnd2` 其實只被拿來建立視窗，拖放功能一行都沒用到。

6. 模組是 `exec(原始碼, globals())`，**所有模組和主程式共用同一個 `__main__` 命名空間**。`<資料夾名>HOMEDIR` 這個變數是用字串拼出 Python 原始碼再 `exec` 的，所以資料夾名稱必須是合法的 Python 識別字，含空白、連字號、`.`，或以數字開頭都會 `SyntaxError`（已實測，§6）。

### 2.2 顏色的意義

藍色是 iPLoT 自己資料夾裡的模組，紅色是跟 iPLoT 同一層的模組，綠色是「桌面」上的模組。三種按鈕按下去呼叫的都是同一個 `cmdEXCUTE_iPLoT`，顏色只用來標示來源。

### 2.3 位置是怎麼推出來的

`iPLoTHOMEDIR` 是 `iPLoT.py` 所在的目錄（py:5，之後在 txt:92 被覆寫成同一個值）。三個位置都是從它推出來的。`Desktop` 是 `dirname(iPLoTHOMEDIR)/Desktop`，**不是** `~/Desktop`。由此可以推斷，作者預期的擺法是：

```
~/                       ← DIRP（紅）：家目錄底下所有 X/X.txt
~/iPLoT/iPLoT.py
~/iPLoT/iPLoT.txt        ← DIRC（藍）：~/iPLoT/X/X.txt
~/iPLoT/iPLoTSpace/      ← Space 按鈕、iPLoTEdit.txt
~/Desktop/               ← DIRPP（綠）：~/Desktop/X/X.txt
```

只有當 iPLoT **直接放在家目錄底下**時，`dirname(iPLoTHOMEDIR)/Desktop` 才會剛好等於真正的桌面。照這個擺法，紅色掃描會對 `~/Documents/Documents.txt`、`~/Downloads/Downloads.txt` 這類路徑做 `exists`，綠色掃描會列出 `~/Desktop`，這些都可能觸發 macOS 的 TCC 權限詢問。

## 6. 模組的執行模型

### 6.1 怎麼執行

`exec(open(filename,'r',encoding='utf-8').read(), globals())`（txt:52）。`globals()` 是 `cmdEXCUTE_iPLoT` 所屬的命名空間；因為整個 `iPLoT.txt` 都是在 py:8 用 `iPLoT.py` 的 `globals()` exec 的，這個命名空間就是 **`__main__.__dict__`**。主程式、所有模組、分支 B 重新載入的主程式，**全部共用同一個字典**。

實測確認（§4b-4）：

- `__file__` 是 `…/iPLoT.py`，模組無法用 `__file__` 找到自己的位置，只能靠 `<名稱>HOMEDIR`。
- `__name__` 是 `'__main__'`，所以模組裡的 `if __name__ == '__main__':` 區塊**會被執行**。
- cwd 是 `iPLoTHOMEDIR`（txt:27），不是模組自己的資料夾。
- `sys.path[0]` 是 iPLoT.py 所在的目錄，模組資料夾裡的 `.py` 不能直接 `import`。
- 例外由 Tk 的 `report_callback_exception` 印到 stderr，GUI 上沒有任何提示。traceback 的檔名一律是 `"<string>"`。
- 每按一次就整份重新 exec 一次，不會 cache；會再開新視窗、再定義一次所有東西。

### 6.2 會不會互相覆蓋：會，而且沒有任何保護

- 模組裡任何頂層賦值都會直接寫進主程式的命名空間。只要模組定義了 `iPLoTWIN`、`DPanel`、`cmdEXCUTE_iPLoT`、`os`、`tkinter`、`B`、`myName`、`iPLoTHOMEDIR` 等名稱，就會改變主程式之後的行為。
- 模組之間也一樣：兩個模組都用 `data`、`win` 之類的名稱時，後執行的會蓋掉先執行的。
- 主程式自己也會蓋：分支 B 會把 `iPLoTWIN` 改掉（實測 §4b-5）。
- 名叫 `iPLoT` 的模組資料夾（例如 `~/Desktop/iPLoT/`）會在 txt:49 把 `iPLoTHOMEDIR` 改掉，之後的 Edit、Space 都會指到錯的地方。
- 不同位置的同名模組（例如藍、綠各一個 `David`）共用同一個 `DavidHOMEDIR`，最後按的那個說了算。txt:67-72 在**列出**子資料夾時就會寫入，還沒按就已經覆蓋了。

### 6.3 全域變數名稱怎麼產生

txt:46-51（txt:67-72 相同）：

```python
cmds='global '+myName+'HOMEDIR';          exec(cmds,globals())   # 在模組層級沒有作用
cmds=myName+'HOMEDIR="'+subDIR+'"';       exec(cmds,globals())   # 真正的賦值
```

用字串拼出原始碼再 exec，所以名稱和路徑都會被 Python 解析。

規則整理：
- **資料夾名稱必須是合法的 Python 識別字**：只能用英文字母、數字、底線、中文等 Unicode 字母，不能以數字開頭。空白、`-`、`.`、`.` 開頭、數字開頭都會 `SyntaxError`。

- 在子目錄視窗（txt:54、67-72）裡更糟：列出按鈕的當下就會 exec，而且**沒有過濾隱藏資料夾**，只要有一個 `.git`、`.venv` 或含空白的子資料夾，整個子視窗就會建到一半中斷。
- **路徑**（不是名稱）含 `"` 會 `SyntaxError`；含 `\` 會被當成跳脫字元，例如 `\t` 變成 Tab，存進去的是錯的路徑，而且不會報錯。
- 名稱和 Python 識別字一樣分大小寫，但檔案系統不分，所以 `david` 和 `David` 對檔案系統是同一個資料夾，對變數卻是兩個。
- 名稱剛好是 `iPLoT` 時，會覆蓋主程式的 `iPLoTHOMEDIR`。
