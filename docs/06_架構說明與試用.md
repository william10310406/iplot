# iPLoT v0.3.0：架構說明與試用

想法來自原版 iPLoT；程式碼與架構是新的。每一個可以推翻的設計決定都在 `docs/03_設計決定.md`，附理由和沒選的做法；不同意哪一條，改那裡，不要只改程式。

## 一、保留了什麼

三個原則一個字沒動，是所有決定的檢查標準：

1. **機器本身不為任何功能。** 核心不內建任何用途，連 iPLoT 自己隨附的五個模組（開工、打開核心原始碼、開Terminal、重新啟動、作業系統）都是模組。刪掉它們核心照樣能開；刪掉「作業系統」會少掉打開檔案、開終端機這類動作，面板會說為什麼。
2. **所有人都能改原始碼。** 所以核心要看得到、小到一個下午讀得完、改壞了救得回來。
3. **大多數事情只用滑鼠。** 連「長出新能力」都要滑鼠能做。

三層掃描（上一層／這一層／下一層）、資料夾就是按鈕、雙擊啟動、零安裝——都保留。

## 二、改了什麼，為什麼

| 原版 | 現在 | 為什麼 |
|---|---|---|
| 兩個檔：`iPLoT.py` 載入 `iPLoT.txt`，用字串 `exec` | 一個資料夾 `core/`，12 個小檔（含只放版本號的 `__init__.py`），每個只做一件事；核心邏輯（扣掉畫面 `ui.py` 和文字 `text.py`）合計不超過 500 有效行、`ui.py` 不超過 150（測試會擋），現在 479 和 117 | 原則 2：讀得完、改得動。原版 traceback 檔名是 `<string>`，錯了找不到位置 |
| 資料夾 `X` 裡放 `X.txt` 才是模組 | 資料夾裡有 `iplot.py` 就是模組，叫什麼都行 | 在檔案總管改資料夾名稱就是改模組名稱，不會壞；原版要改兩處。原版的 `X/X.txt` 之後用一個「匯入」工具模組轉過來，不進核心 |
| 所有模組 `exec` 進同一個命名空間，互相蓋變數；資料夾名稱必須是合法的 Python 識別字 | 每次按下都在乾淨的命名空間重跑 `iplot.py`，就像在模組資料夾裡打 `python3 iplot.py` | 模組之間不會互相干擾；中文、空白、數字開頭的名字都可以 |
| 課本程式要改寫才能當模組；`input()` 會把整個視窗凍住 | 課本怎麼寫就怎麼貼：`input()` 變對話框、`print()` 進訊息區、`open("x.txt")` 讀寫模組自己的資料夾、`import helper` 找旁邊的檔案、`exit()` 是正常結束 | 來自 2026-10-03 的使用紀錄：「要用 app.ask 才能問問題，感覺無法自由發揮」（D47、D49） |
| 錯誤靜默：少套件就無聲退出、50 分鐘後視窗自毀、模組出錯整個程式死 | 任何錯誤變成面板上一句白話＋檔案＋行號＋「打開檔案」按鈕；iPLoT 不會死 | 原則 2 的下半：改壞了要知道哪裡壞 |
| 空無一物時無法啟動（除以零） | 空的也能開；按 ＋ 用滑鼠長第一個模組 | 原則 3 |
| 改壞了沒有退路 | 每次執行前 `iplot.py` 存一份到模組自己的 `.history/`；核心改壞了 `python3 main.py --safe`，再不行 `git checkout -- core/` | 原則 2 |
| 工具按鈕寫死在主程式 | 設定只有 `config.py` 三個值（掃哪裡、用哪個編輯器、留幾份快照）；改壞了用預設值啟動並說哪裡壞 | 核心不為任何功能 |
| 碰作業系統的事寫死在主程式 | 都在模組 `modules/作業系統`，macOS、Windows、Linux 各一個檔；核心零作業系統程式碼（測試會擋） | 原則 1；要換系統、要換終端機程式，改的是模組不是核心（D50） |

## 三、怎麼在上面搭東西

分三種人，三種深度，彼此不衝突：

**只想做用途的人。** 按 ＋、取名、貼程式、按下去。不用知道 `core/` 存在。改完檔案再按一次就是新版本，不用重啟。

**想用 iPLoT 給的能力的人。** 寫 `def run(app)`，`app` 能做的事全部在 `docs/api.md` 一頁：寫訊息區、開檔案、開編輯器、在資料夾中顯示、開終端機、搬到垃圾桶、跑別的模組、問人、選檔案、`app.memory` 跨次記東西、`app.window` 自己畫介面。介面只加不減。

**想改核心、或想換掉一塊零件的人。** `core/` 任一檔改完按「重新啟動」。每個檔開頭的 docstring 說它做什麼；規格在 `docs/02_重構設計.md`，理由在 `docs/03_設計決定.md`；哪些地方可以整塊換掉（畫面、作業系統、動作、事件）、各自的規則與擋住規則的測試，在 `docs/07_接口與邊界.md`。改完跑 `python -m pytest`（現在 206 個測試）。新用途一律做成模組，不進核心——500 行的上限就是為了逼這件事。

前例一句話：Emacs 的核心很小、所有功能都是可改的 Lisp；HyperCard 讓人用滑鼠長出卡片和按鈕；Smalltalk 裡一切都是可以當場改的物件。iPLoT 想做的是這三者用 Python、給不開終端機的人用的版本。

## 四、還沒做的

- 拖放檔案到按鈕上、匯入原版 `X/X.txt` 模組、自動啟動——這三件在 M2（規格 §13）。
- 背景執行（現在 `time.sleep` 和長迴圈會凍住視窗）也在 M2（規格 §7、§13）；它跟「模組在哪裡執行」是同一題，見 `docs/07_接口與邊界.md` 第 8 節。
- **Windows、Linux 的實機驗證。** Windows 的做法只用假的系統呼叫驗過參數，沒有在 Windows 上跑過；Linux 沒有在真的桌面上按過；CI 設了三個平台，但沒有遠端，一次都沒跑過。怎麼驗見 `docs/07_接口與邊界.md` 第 9 節。
- 工作情境切換、檔案整理規則是更後面的事。

## 五、試用：四步看到新東西

1. 要有 Python 3.10 以上、含 tkinter（macOS 用 python.org 的版本，Homebrew 或系統內建的沒有 tkinter，不能用）。把 iPLoT 資料夾放到 `~/iPLoT`（不要留在「下載項目」），雙擊 `iPLoT.command`；第一次 macOS 問要不要打開，選「打開」。Windows 是雙擊 `iPLoT.bat`、Linux 是 `./iPLoT.sh`，這兩個未經實機驗證。
2. 按「這一層」右邊的 ＋，名字打「猜數字」，確定。編輯器開了範本，全部刪掉，貼上這段，存檔：

```python
import random
答案 = random.randint(1, 10)
while True:
    try:
        n = int(input("猜 1 到 10"))
    except ValueError:
        print("要輸入數字")
        continue
    if n == 答案:
        print("對了！")
        break
    print("太大" if n > 答案 else "太小")
exit()
```

3. 回 iPLoT 按「猜數字」。`input()` 變對話框，上一輪印的「太大」出現在下一個問題上面；猜對後訊息區出現全部輸出；結尾 `exit()` 不算錯。按一次「取消」：模組停，訊息區說「模組『猜數字』第 N 行出錯：EOFError，在提問時按了取消」。
4. 按「作業系統」：訊息區說現在用的是哪個檔（macOS 上是 `mac.py`）。右鍵它 →「打開程式碼」看到的是選擇器 `iplot.py`；打開檔案、開終端機、垃圾桶的五個函式在旁邊的 `mac.py`（右鍵 →「在資料夾中顯示」）。改了存檔，下一次動作就生效。

已知會踩到的：

- 長迴圈或 `time.sleep` 會凍住視窗。
- 驗證迴圈寫什麼都接的 `except:` 按取消出不去（請接 `except ValueError`）。
- 「重新啟動」後終端機多一行 `Task policy set failed`，沒影響。
- 改壞「作業系統」模組時，右鍵「打開程式碼」和錯誤訊息的「打開檔案」自己也會壞（它們也是交給這個模組做的）；用檔案總管打開 `modules/作業系統/` 底下的檔案改回來。
- Windows 未經實機驗證。

## 六、怎麼回報

試用時碰到的事記進 `docs/05_使用紀錄.md`，一件事一行：哪天、按了什麼、卡在哪或哪裡多餘。交付 0.3.0 那天（2026-10-05）起算兩週（到 2026-10-19）不更新版本；自己做的模組都在 `modules/` 裡，更新核心不會動到。兩週後一起看三個問題：有沒有真的用它啟動東西、想做但面板上沒有的事怎麼繞、有沒有哪次壞了但沒說哪裡壞。
