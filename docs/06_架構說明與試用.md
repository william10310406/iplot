# iPLoT v0.5.0：架構說明與試用

想法來自原版 iPLoT；程式碼與架構是新的。每一個可以推翻的設計決定都在 `docs/03_設計決定.md`，附理由和沒選的做法；不同意哪一條，改那裡，不要只改程式。

## 一、保留了什麼

三個原則一個字沒動，是所有決定的檢查標準：

1. **機器本身不為任何功能。** 核心不內建任何用途，連 iPLoT 自己隨附的七個模組（開工、打開核心原始碼、開Terminal、重新啟動、作業系統、更新、工作坊）都是模組。刪掉它們核心照樣能開；刪掉「作業系統」會少掉打開檔案、開終端機這類動作，面板會說為什麼（介面還沒裝過的話，第一次啟動要裝哪一份也是問它，沒有它就只能開後備的 tkinter 面板）；刪掉「更新」「工作坊」就只是少了這兩個功能——換新版、裝別人做的模組，都不是核心的事。
2. **所有人都能改原始碼。** 所以核心要看得到、小到一個下午讀得完、改壞了救得回來。
3. **大多數事情只用滑鼠。** 連「長出新能力」都要滑鼠能做。

三層掃描（上一層／這一層／下一層）、資料夾就是按鈕、雙擊啟動——都保留。

「零安裝」這一項改了（D62）：第一次啟動時 iPLoT 自己把介面要用的套件裝進資料夾裡的 `lib/`，那一次要網路；之後平常啟動都不用網路。正常使用下會再連網的只有兩種時候，都是有人按了才發生：按「更新」或「工作坊」的那一下；以及用「更新」換了版本、新版要的套件跟舊版不一樣時，下一次啟動會把 `lib/` 重裝一次（沒有網路就先用現有的開，下次啟動再試；D76）。`lib/` 被刪掉或壞了的話，等於回到第一次啟動，也會再裝一次。裝好的套件只在 iPLoT 自己的資料夾裡，不碰系統的 Python；整個資料夾丟進垃圾桶就移除乾淨（pip 自己的下載快取不在這個資料夾裡，那是 pip 的）。

## 二、改了什麼，為什麼

| 原版 | 現在 | 為什麼 |

| 工具按鈕寫死在主程式 | 設定只有 `config.py` 五個值（掃哪裡、用哪個編輯器、留幾份快照，加上「更新」與「工作坊」各一個來源網址）；改壞了用預設值啟動並說哪裡壞 | 核心不為任何功能 |

## 三、怎麼在上面搭東西

分四種人，由淺到深，彼此不衝突：

**只想做用途的人。** 按 ＋、取名、貼程式、雙擊。不用知道 `core/` 存在。改完檔案再雙擊一次就是新版本，不用重啟。

**想改面板長相的人。** 顏色、圖示多大、一格多寬、訊息區多高，都是 `ui/style.css` 開頭那一段變數，下面的規則只用變數；深色模式的顏色在緊接著的那一段。想讓改法在換新版之後留著，就在 iPLoT 資料夾（跟 `config.py` 同一層）建一個 `custom.css`，把要改的變數寫進去，例如 `:root { --accent: #e0703d; --icon: 64px; }`——它在 `style.css` 之後載入，同名的變數以它為準；換新版時 `ui/` 整個換掉，`custom.css` 不在裡面。改完重新開 iPLoT 才看得到。要改版面或行為，再往下是 `ui/index.html` 和 `ui/app.js`：沒有框架、不用 build、不連任何外部網址，文字編輯器就能改。

**想用 iPLoT 給的能力的人。** 寫 `def run(app)`，`app` 能做的事全部在 `docs/api.md` 一頁：寫訊息區、開檔案、開編輯器、在資料夾中顯示、開終端機、搬到垃圾桶、跑別的模組、問人（`app.ask` 問一個字串、`app.confirm` 問確定或取消）、選檔案、`app.memory` 跨次記東西。這一版多了三樣：`app.config`（`config.py` 讀出來的設定，唯讀）、`app.version`（核心的版本字串）、`app.page`（開一個視窗顯示模組自己的一頁 HTML；那一頁的 JS 可以呼叫模組交給它的 Python 物件的方法，視窗關掉模組才往下跑）。想做自己的一頁畫面的模組就用 `app.page`——「工作坊」的清單就是這樣做的，整頁是 `modules/工作坊/page.html` 一個檔。安全模式與後備的 tkinter 面板沒有頁面，`app.page` 在那裡只會在訊息區記一行。介面只加不減：0.4.0 破例拿掉過一樣（沒有 tkinter 主視窗了，所以 `app.window` 沒有了，`api_version` 升到 2，D66）；這一版只加，`api_version` 是 3（D72）。

**想改核心、或想換掉一塊零件的人。** `core/` 任一檔改完雙擊「重新啟動」。每個檔開頭的 docstring 說它做什麼；規格在 `docs/02_重構設計.md`，理由在 `docs/03_設計決定.md`；哪些地方可以整塊換掉（畫面、作業系統、動作、事件）、各自的規則與擋住規則的測試，在 `docs/07_接口與邊界.md`。改完跑 `python -m pytest`（現在 1485 個測試）。新用途一律做成模組，不進核心——505 行的上限就是為了逼這件事。

前例一句話：Emacs 的核心很小、所有功能都是可改的 Lisp；HyperCard 讓人用滑鼠長出卡片和按鈕；Smalltalk 裡一切都是可以當場改的物件。iPLoT 想做的是這三者用 Python、給不開終端機的人用的版本。

## 四、還沒做的

- 拖放檔案到圖示上、匯入原版 `X/X.txt` 模組、自動啟動——這三件都還沒做。拖放延到 M2 後段，要先看 pywebview 的拖放支援再定。
- 中途停掉模組、同時跑兩個模組。現在模組跑在一條工作執行緒上：跑很久時視窗不會凍住，可以捲、可以看訊息；但模組仍然在 iPLoT 自己的程序裡執行，一次只跑一個、跑到一半不能停，關掉視窗會結束整個程序——模組還在跑的時候關視窗，也不會先問一聲（這一項決定延後）。這跟「模組在哪裡執行」是同一題（D56，仍延後），見 `docs/07_接口與邊界.md` 第 8 節。
- Linux 的網頁面板。pywebview 在 Linux 要系統層的 GTK／WebKit2GTK，pip 裝不了；這一版 Linux 開的是後備的 tkinter 面板：沒有圖示格，也沒有工作坊的清單頁（按「工作坊」只會在訊息區看到「這個面板沒有頁面（安全模式與備用面板都是）；這個功能要在一般的網頁面板裡用」那一句）。
- 「更新」只做了最基本的：不會自己檢查有沒有新版、不比較新舊差在哪、沒有一鍵回到舊版（備份在 `.backup/`，用手搬回去，步驟在 `README.md`）。
- 「工作坊」只做了安裝、更新、覆蓋：沒有移除、降回舊版、評分、留言、自動更新，也只能看一份清單。
- 放檔案的地方是 GitHub Pages 上的兩個公開 repo（M7，D100、D101）：「更新」讀 `iplot-workshop`（`https://william10310406.github.io/iplot-workshop/`，只有研究助理能寫）；「工作坊」讀 `iplot-modules` 的清單（`https://william10310406.github.io/iplot-modules/`，誰都能上傳，沒有人審查）。隨附的 `config.py` 已經填好這兩個網址。從 GitHub Pages 上的 `iplot-workshop` 真的下載、更新、安裝，2026-10-06 在 macOS 上用 `tests/acceptance_workshop.py` 走過一次（全部通過；確認框的長相、用瀏覽器看那一頁、沒有網路時的那一句，要人眼看的部分還沒做；那一次的清單是 `iplot-workshop` 的舊清單，`iplot-modules` 的新清單還沒對真的網址走過）；在這之前的整個流程只在 macOS、用本機的 `file://` 網址驗過。
- 安裝時只釘版本，還沒有釘 hash（pip 的 `--require-hashes`）。
- 面板的 HTML／CSS／JS 沒有自動測試：`tests/test_boundaries.py` 只釘住它跟 Python 那一頭對得上，滑鼠實際按下去的行為靠人工驗收。工作坊清單頁（`modules/工作坊/page.html`）裡的 JS 也一樣。
- 人工驗收。0.4.0 與 0.5.0 的驗收項目（`docs/plans/2026-10-05-M2-網頁面板與更新.md` 第 11 節的 (a)–(m)、13.6 的 (a)–(g)）都還沒有人照著從頭到尾按過一遍。
- **Windows、Linux 的實機驗證。** Windows 的做法（包括第一次啟動的安裝、檢查有沒有 WebView2 Runtime）只用假的系統呼叫驗過參數，沒有在 Windows 上跑過，`requirements/web-win.txt` 的版本是用 pip 解出來的、沒有在 Windows 上裝過；Linux 沒有在真的桌面上按過；CI 設了三個平台，但沒有遠端，一次都沒跑過。怎麼驗見 `docs/07_接口與邊界.md` 第 9 節。
- 工作情境切換、檔案整理規則是更後面的事。

## 五、試用：七步看到新東西

1. 要有 Python 3.10 以上、含 pip。任何來源的 Python 都可以；python.org 的版本最省事，因為它內含安全模式與後備面板要用的 tkinter（開發和實測用的也是它，3.14）。把 iPLoT 資料夾放到 `~/iPLoT`（不要留在「下載項目」），雙擊 `iPLoT.command`；第一次 macOS 問要不要打開，選「打開」。**第一次啟動要網路**：跟著開的終端機視窗會顯示「第一次啟動：正在安裝介面（需要網路，約 40 MB）…」和 pip 一行行的進度，介面裝進 iPLoT 自己的 `lib/`；在開發用的 Mac 上，乾淨下載花了 1 分 46 秒，看網路速度。裝完印一句「安裝完成，重新啟動中…」，視窗自己出現，標題是「iPLoT v0.6.0」。之後每次雙擊都直接開視窗，不再安裝、不用網路。Windows 是雙擊 `iPLoT.bat`，未經實機驗證；Linux 這一版沒有網頁面板，開的是後備的 tkinter 面板（見這一節後面）。
2. 單擊「開工」：那一格被選起來，下面的狀態列顯示它的名稱和說明（`iplot.py` 開頭那段 docstring 的第一段）。單擊只是選取，雙擊才執行：雙擊「開工」，iPLoT 資料夾、`docs/`、設計文件、終端機各開一個，訊息區出現「開工 完成（… 秒）」。右鍵任一個模組是選單：執行、打開程式碼、在資料夾中顯示、在終端機打開、在這裡新增下一層模組…。
3. 按「這一層」最後那一格虛線的 ＋，面板裡跳出對話框問名字，打「猜數字」，確定。編輯器開了範本，面板上多了一格「猜數字」。把範本全部刪掉，貼上這段，存檔：

```python
import random
答案 = random.randint(1, 10)
while True:
    try:
        n = int(input("猜 1 到 10"))
    except ValueError:
        print("要輸入數字")
        continue
    if n == 答案:
        print("對了！")
        break
    print("太大" if n > 答案 else "太小")
exit()
```

4. 回 iPLoT 雙擊「猜數字」。`input()` 是面板裡的對話框（Enter 確定、Esc 取消），上一輪印的「太大」出現在下一個問題上面；猜對後訊息區出現全部輸出；結尾 `exit()` 不算錯。再雙擊一次，這次按「取消」：模組停，訊息區說「模組『猜數字』第 N 行出錯：EOFError，在提問時按了取消」，那一行右邊有「打開檔案」（用編輯器打開出錯的檔案；`config.py` 的 `EDITOR` 設成認得行號的編輯器時會直接跳到那一行，預設的系統文字編輯器只打開檔案）和「詳細」（展開 traceback，再按一次收起）。
5. 右鍵「猜數字」→「在這裡新增下一層模組…」，取個名字，確定。編輯器開了範本；回 iPLoT，「猜數字」的圖示右下角多了 ▸。按 ▸ 進去：裡面是剛取名的模組，這一組的顏色點是紫色，麵包屑多了一段（「iPLoT ▸ 猜數字」），點「iPLoT」回到頂層。任一模組都能這樣加下一層；還沒有下一層的模組沒有 ▸，第一個就從右鍵加。有了下一層，右鍵選單會多一項「進入下一層」。
6. 給「猜數字」一個圖示。現在它的圖示是一個「猜」字：沒有圖示的模組用名字第一個字，底色由資料夾名稱算出來，每次都一樣。右鍵 →「打開程式碼」，在最上面加一行 `ICON = "🎲"`，存檔，點回 iPLoT 視窗：圖示變成 🎲。或者右鍵 →「在資料夾中顯示」，丟一張叫 `icon.png` 的圖進那個資料夾（檔名要一字不差，1 MB 以內；`icon.svg` 也可以），點回視窗：圖示變成那張圖。兩種都有時用圖檔。
7. 雙擊「作業系統」：訊息區說現在用的是哪個檔（macOS 上是 `mac.py`）。右鍵它 →「打開程式碼」看到的是選擇器 `iplot.py`；打開檔案、開終端機、垃圾桶這些動作的五個函式，加上第一次啟動的安裝會問的兩個（`requirements` 回答裝哪一份、`webview_ready` 回答缺什麼），都在旁邊的 `mac.py`（右鍵 →「在資料夾中顯示」）。改了存檔，下一次動作就生效。

**更新與工作坊：不用網路也能試。** 隨附的 `config.py` 的 `UPDATE_URL` 指到 GitHub Pages 上的 `iplot-workshop`，`WORKSHOP_URL` 指到 `iplot-modules` 的清單，雙擊「工作坊」就是那一份清單。下面這一段不連網：用本機的 `file://` 網址代替，檔案用發佈工具 `tools/publish.py` 產生。這個工具用 `git archive` 打包核心，所以這一段要在有 git 紀錄的 iPLoT 資料夾裡做（`git clone` 下來的；從壓縮檔解開的資料夾沒有 git 紀錄，也沒有 `tools/`：核心的包不帶發佈工具）。`core/`、`ui/`、`main.py`、`requirements/` 裡有還沒 commit 的修改的話先 commit：後面按「更新」會把這四樣換成包裡的內容。這兩個模組只在 macOS 上驗過；下面這十步是照程式的行為寫的，還沒有人在真的視窗裡照著從頭到尾按過一遍（第四節的「人工驗收」）。接著上面七步做：

1. 先看沒設定的樣子。打開 `config.py`，把 `UPDATE_URL`、`WORKSHOP_URL` 兩行的網址都換成 `None`，存檔，雙擊「重新啟動」。雙擊「更新」，訊息區說「尚未設定更新來源：在 config.py 的 UPDATE_URL 填 update.json 的網址」；雙擊「工作坊」，說「尚未設定工作坊的來源：在 config.py 的 WORKSHOP_URL 填 index.json 的網址」。兩個都沒有連網；除了每個模組執行前照例存進自己 `.history/` 的那一份 `iplot.py` 快照，也沒有寫任何檔案。
2. 產生檔案。模組的包只收 git 追蹤的檔，「猜數字」還沒 commit 過，所以先 commit 它（七步裡第 5 步加的下一層模組在它的資料夾裡，會一起進去；`.history/` 在 `.gitignore` 裡，不會進去）。雙擊「開Terminal」，終端機開在 iPLoT 資料夾；執行：

   ```
   git add modules/猜數字
   git commit -m "猜數字"
   python3 tools/publish.py --version 0.6.0 --ref HEAD --base-url "file://$(pwd)/交付/發佈" --modules 猜數字 開工
   ```

   `交付/發佈/` 裡多了 `iPLoT-v0.6.0.zip`、`update.json`、`index.json`，和 `模組/` 裡的 `猜數字.zip`、`開工.zip`。最後印出 `UPDATE_URL = "file:///…/update.json"`、`WORKSHOP_URL = "file:///…/index.json"` 兩行（路徑裡的中文寫成 `%XX`，是同一個位置）；前面那句「注意：工作目錄有還沒 commit 的改動…」說的是第 1 步改的 `config.py`，不用管。`--ref HEAD` 是「照最後一次 commit 打包核心」，`--version` 要跟那一次 commit 裡 `core/__init__.py` 的版本一樣（這一版是 0.6.0），不一樣工具會停下來；「猜數字」是前面七步裡第 3 步做的那個模組；`modules/` 裡有 `iplot.py` 的資料夾都可以拿來放，沒 commit 過的一樣要先 commit，不然工具會說「沒有任何 git 追蹤的檔」。
3. 填設定。打開 `config.py`，把剛才改成 `None` 的 `UPDATE_URL`、`WORKSHOP_URL` 兩行換成剛才印出來的那兩行，存檔，回 iPLoT 雙擊「重新啟動」。印出來的那兩行前面沒有空白，整行從行首貼上就好。
4. 從工作坊安裝。「猜數字」已經在 `modules/` 裡了，先讓它變成這台電腦上沒有的模組：右鍵「猜數字」→「在資料夾中顯示」，把那個資料夾改名成「猜數字-原本」，點回 iPLoT，那一格跟著改名。雙擊「工作坊」，開出一個清單視窗，兩列：「猜數字」的狀態是「未安裝」，按鈕是「安裝」；「開工」的狀態是「版本未知」（資料夾在，但不是從工作坊裝的），按鈕是「覆蓋」，這次不用按。按「猜數字」那一列的「安裝」：狀態變成「已安裝」，按鈕不見了。關掉清單視窗，面板上多了一格「猜數字」。
5. 第一次執行前的確認。雙擊剛裝進來的「猜數字」，先跳出對話框：「『猜數字』是從外面裝進來的，第一次執行前確認：要執行嗎？」按取消：訊息區說「已取消執行『猜數字』」，沒有執行。再雙擊一次，還是會問；這次按確定，照常開始猜數字。之後再執行都不會問了。按 ▸ 進去，前面七步裡第 5 步加的那個下一層模組也跟著裝進來了，它第一次執行前也會先問。
6. 已修改與覆蓋。右鍵「猜數字」→「打開程式碼」，隨便改一個字（例如把「太大」改成「大了」），存檔。雙擊「工作坊」：「猜數字」的狀態變成「已修改」，按鈕是「覆蓋」。按「覆蓋」，按鈕變成「確定覆蓋」和「取消」，旁邊一句「這會覆蓋現有的模組，舊版會整個存進它的 .history/」；按「確定覆蓋」，狀態回到「已安裝」。關掉清單視窗，在終端機執行 `ls modules/猜數字/.history`：多了一個 `<日期時間>-folder.zip`，裡面是覆蓋之前的整個資料夾。覆蓋算重新裝了一次，下一次執行「猜數字」會再問一次。
7. 更新：先讓這台「變舊」。雙擊「更新」：包的版本跟現在一樣，訊息區說「已是最新（0.6.0）」。打開 `core/__init__.py`，把 `__version__ = "0.6.0"` 暫時改成 `"0.4.9"`，存檔（不要 commit——包是照最後一次 commit 打的，裡面還是 0.6.0），雙擊「重新啟動」，視窗標題變成「iPLoT v0.4.9」。
8. 壞掉的包（可以跳過）。打開 `交付/發佈/update.json`，把 `sha256` 那一串裡的一個數字換成另一個數字，存檔。雙擊「更新」，對話框問要不要更新，按確定：訊息區說「沒有更新：下載的檔案跟 update.json 寫的 sha256 對不上（update.json 或下載的檔案有問題）」，`core/` 沒有被動到。把那個數字改回來，存檔。
9. 更新。雙擊「更新」：對話框說「有新版 0.6.0（現在是 0.4.9）」，接著是 `CHANGELOG.md` 裡 0.6.0 那一節的第一段（摘要），問要不要更新。摘要叫已經在用的人先按「取消」、先到工作坊換「互通」、裝「回報與討論」（工作坊裡找不到的，從 `.backup/` 裡的包換三個模組、改 `WORKSHOP_URL`），這裡都不用做：這台的 `modules/` 本來就是 0.6.0 的（「互通」是 0.2.0，「回報與討論」也在），`config.py` 也要留著本機的網址，直接按確定。訊息區說「已更新到 0.6.0，執行「重新啟動」就會用新版。舊版備份在 .backup/0.4.9-<日期時間>/」。雙擊「重新啟動」，標題回到「iPLoT v0.6.0」。`config.py`、`custom.css`、`modules/` 裡的東西（包括剛才的「猜數字」和它的 `.history/`）都沒有被動到；`.backup/0.4.9-<日期時間>/` 裡是換掉之前的 `core/`、`ui/`、`main.py`、`requirements/`。
10. 收尾。把 `config.py` 的兩行改回隨附的網址（`UPDATE_URL = "https://william10310406.github.io/iplot-workshop/update.json"`、`WORKSHOP_URL = "https://william10310406.github.io/iplot-modules/index.json"`），或留著 `None` 不連網，雙擊「重新啟動」。「猜數字-原本」要留要丟都可以；`交付/發佈/` 和 `.backup/` 是這次試用產生的，不要了可以刪掉（這兩個都不在 `.gitignore` 裡，`git status` 會列出它們）。

放到網路上給別人用的做法（核心放 GitHub Pages 上的 `iplot-workshop`，D79；模組從 `iplot-modules` 的上傳表單傳，D100）、按下去之後每一步做了什麼、怎麼回到舊版，在 `README.md` 的「更新與工作坊」。

**安全模式與後備面板。** 在終端機裡、iPLoT 資料夾中執行 `python3 main.py --safe`，開的是 tkinter 面板：標題多了「（安全模式）」，只掃 `modules/`，所以只有「這一層」；一欄文字按鈕，沒有圖示和狀態列，**單擊就執行**；右鍵四項（打開程式碼、在資料夾中顯示、在終端機打開、在這裡新增下一層模組…），＋ 在每組標題的右邊。它需要 tkinter。什麼時候用：網頁面板開不起來的時候；上一層或 `config.py` 多掃的位置裡有東西讓面板出問題的時候。安全模式只有這一個入口，要自己加 `--safe` 才會進去。介面裝不起來時（沒有網路、pip 失敗、這個平台沒有網頁面板）不用自己下指令，iPLoT 會自己退到後備面板：終端機說明原因，同樣的說明也寫在訊息區最前面；有網路之後重新啟動 iPLoT，它會再裝一次。後備面板是同一個 tkinter 面板，但不是安全模式：標題沒有「（安全模式）」，照常掃上一層與 `config.py` 的 `ROOTS`（0.4.0 在這種時候是直接進安全模式，這一版改了，D75）。Linux 就是這樣：不加 `--safe` 啟動，終端機先說一句網頁面板還不支援 Linux，接著開的是掃完整範圍的後備面板；加了 `--safe` 才只掃 `modules/`。連 tkinter 都沒有的 Python 會印「這個 Python 沒有 tkinter，安全模式與備用面板都開不了；請用 python.org 的版本」然後結束。

已知會踩到的：

- 模組跑很久（長迴圈、`time.sleep`、等網路）時視窗不會凍住，可以捲、可以看訊息；但一次只跑一個，這段時間雙擊別的模組、右鍵的動作、重掃都排在後面，等它跑完才輪到。跑到一半不能停；關掉視窗會結束整個 iPLoT。tkinter 面板（安全模式與後備面板）還是會凍住。
- `print()` 的東西在模組結束時才一起進訊息區（碰到 `input()` 時會先出現在問題上面）；要邊跑邊看到，用 `app.log`。
- 第一次啟動要網路。沒有網路時終端機說明原因、退到後備的 tkinter 面板（不是安全模式，上一層與 `ROOTS` 的模組都在）；有網路後重新啟動 iPLoT 就會再裝。
- 驗證迴圈寫什麼都接的 `except:` 按取消出不去（請接 `except ValueError`）。
- 模組不能再拿 iPLoT 的 tkinter 主視窗來畫自己的介面：`app.window` 沒有了。模組裡用 `turtle` 或 tkinter 開視窗，在預設的面板上不會執行，訊息區說一句要用安全模式；這類模組用 `python3 main.py --safe` 開 iPLoT 就能跑。
- 圖示檔是空的、超過 1 MB、讀不到，或不是一張讀得出來的圖時，當作沒有這個檔，訊息區說一次。
- 「重新啟動」後終端機可能多一行 `Task policy set failed`（已經開過視窗的程式重啟自己時 macOS 印的），沒影響。
- 改壞「作業系統」模組時，右鍵「打開程式碼」和錯誤訊息的「打開檔案」自己也會壞（它們也是交給這個模組做的）；用檔案總管打開 `modules/作業系統/` 底下的檔案改回來。
- Linux 這一版沒有網頁面板，開的是後備的 tkinter 面板；而且沒有在真的 Linux 桌面上跑過。
- Windows 未經實機驗證；網頁面板在 Windows 另外需要 Microsoft Edge WebView2 Runtime（Windows 11 內建）。
- 「更新」換完要重新啟動：換的是磁碟上的檔案，開著的 iPLoT 還是舊版。執行「重新啟動」才會用新版，`app.memory` 記的東西會清空。還沒重新啟動又按一次「更新」，只會提醒去重新啟動。
- 「更新」把 `core/`、`ui/`、`main.py`、`requirements/` 整個換掉：自己改過核心或面板的話，改的地方不會留在新版裡，換掉之前的那一份在 `.backup/`。外觀的改法要留著，寫在 `custom.css`。
- 用「更新」換了版本、新版要的套件跟舊版不一樣時，下一次啟動要網路（重裝 `lib/`）；沒有網路就先用現有的開，之後每次啟動再試。
- 「工作坊」在安全模式與後備面板上沒有清單頁，所以 Linux 也沒有：按了只會在訊息區看到「這個面板沒有頁面（安全模式與備用面板都是）；這個功能要在一般的網頁面板裡用」。
- 工作坊的「已修改」只看當初裝進來的那些檔：改了或刪了其中一個才算；模組自己另外存的檔（設定、記錄）不算。模組要是把資料寫回包裡本來就有的檔，用過之後也會顯示「已修改」。照樣可以覆蓋：舊資料夾先整個存進 `.history/`，包裡沒有的檔案不會被刪。
- 工作坊裝進來的模組（包括包裡的下一層模組），每裝一次（安裝、更新、覆蓋）第一次執行前就問一次。
- 工作坊不覆蓋「作業系統」「更新」「工作坊」：清單上它們是「隨附模組」、沒有按鈕（覆蓋之後它們會帶著第一次執行前的確認，右鍵的動作每次先問，啟動時要安裝介面卻沒辦法回答，D74 修訂）。要換新版，自己把新的資料夾複製進 `modules/`。
- 「更新」換上去的時候出錯，已經換上去的會全部放回；但要是剛好在兩次改名之間被強制結束（毫秒級的空檔），磁碟上會暫時新舊混在一起，直到下一次用「更新」換版本時才收回。iPLoT 啟動時不檢查這件事。剛好少了 `core/`、`ui/` 或 `main.py` 的話 iPLoT 開不起來，要照 `README.md` 的「怎麼回到舊版」用手把備份搬回去。

## 六、怎麼回報

試用時碰到的事記進 `docs/05_使用紀錄.md`，一件事一行：哪天、按了什麼、卡在哪或哪裡多餘。自己做的模組都在 `modules/` 裡，更新核心不會動到。用過一陣子之後回頭看三個問題：有沒有真的用它啟動東西、想做但面板上沒有的事怎麼繞、有沒有哪次壞了但沒說哪裡壞。
