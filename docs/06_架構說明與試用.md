# iPLoT v0.4.0：架構說明與試用

想法來自原版 iPLoT；程式碼與架構是新的。每一個可以推翻的設計決定都在 `docs/03_設計決定.md`，附理由和沒選的做法；不同意哪一條，改那裡，不要只改程式。

## 一、保留了什麼

三個原則一個字沒動，是所有決定的檢查標準：

1. **機器本身不為任何功能。** 核心不內建任何用途，連 iPLoT 自己隨附的五個模組（開工、打開核心原始碼、開Terminal、重新啟動、作業系統）都是模組。刪掉它們核心照樣能開；刪掉「作業系統」會少掉打開檔案、開終端機這類動作，面板會說為什麼（介面還沒裝過的話，第一次啟動要裝哪一份也是問它，沒有它就只能開安全模式）。
2. **所有人都能改原始碼。** 所以核心要看得到、小到一個下午讀得完、改壞了救得回來。
3. **大多數事情只用滑鼠。** 連「長出新能力」都要滑鼠能做。

三層掃描（上一層／這一層／下一層）、資料夾就是按鈕、雙擊啟動——都保留。

「零安裝」這一項改了（D62）：第一次啟動時 iPLoT 自己把介面要用的套件裝進資料夾裡的 `lib/`，那一次要網路；之後每次啟動都不用網路。裝好的套件只在 iPLoT 自己的資料夾裡，不碰系統的 Python；整個資料夾丟進垃圾桶就移除乾淨（pip 自己的下載快取不在這個資料夾裡，那是 pip 的）。

## 二、改了什麼，為什麼

| 原版 | 現在 | 為什麼 |
|---|---|---|
| 兩個檔：`iPLoT.py` 載入 `iPLoT.txt`，用字串 `exec` | 一個資料夾 `core/`，11 個小檔（含只放版本號的 `__init__.py`），每個只做一件事；核心邏輯（`core/` 扣掉文字 `text.py`）合計不超過 500 有效行，現在 490。面板搬到 `ui/`，六個檔各有上限（現在的有效行／上限）：`web.py` 189/200、`tk.py` 118/180、`install.py` 49/80、`index.html` 30/120、`app.js` 226/400、`style.css` 125/300。七個數字都有測試擋（`tests/test_budget.py`） | 原則 2：讀得完、改得動。原版 traceback 檔名是 `<string>`，錯了找不到位置。面板換成網頁之後程式變多、多了兩種語言，所以每個檔另訂上限（D68） |
| 資料夾 `X` 裡放 `X.txt` 才是模組 | 資料夾裡有 `iplot.py` 就是模組，叫什麼都行 | 在檔案總管改資料夾名稱就是改模組名稱，不會壞；原版要改兩處。原版的 `X/X.txt` 之後用一個「匯入」工具模組轉過來，不進核心 |
| 所有模組 `exec` 進同一個命名空間，互相蓋變數；資料夾名稱必須是合法的 Python 識別字 | 每次按下都在乾淨的命名空間重跑 `iplot.py`，就像在模組資料夾裡打 `python3 iplot.py` | 模組之間不會互相干擾；中文、空白、數字開頭的名字都可以 |
| 課本程式要改寫才能當模組；`input()` 會把整個視窗凍住 | 課本怎麼寫就怎麼貼：`input()` 變對話框、`print()` 進訊息區、`open("x.txt")` 讀寫模組自己的資料夾、`import helper` 找旁邊的檔案、`exit()` 是正常結束 | 來自 2026-10-03 的使用紀錄：「要用 app.ask 才能問問題，感覺無法自由發揮」（D47、D49） |
| 錯誤靜默：少套件就無聲退出、50 分鐘後視窗自毀、模組出錯整個程式死 | 任何錯誤變成面板上一句白話＋檔案＋行號＋「打開檔案」按鈕；iPLoT 不會死 | 原則 2 的下半：改壞了要知道哪裡壞 |
| 空無一物時無法啟動（除以零） | 空的也能開；按 ＋ 用滑鼠長第一個模組 | 原則 3 |
| 改壞了沒有退路 | 每次執行前 `iplot.py` 存一份到模組自己的 `.history/`；核心或面板改壞了 `python3 main.py --safe`，再不行 `git checkout -- core/ ui/` | 原則 2 |
| 工具按鈕寫死在主程式 | 設定只有 `config.py` 三個值（掃哪裡、用哪個編輯器、留幾份快照）；改壞了用預設值啟動並說哪裡壞 | 核心不為任何功能 |
| 碰作業系統的事寫死在主程式 | 都在模組 `modules/作業系統`，macOS、Windows、Linux 各一個檔；核心零作業系統程式碼（測試會擋） | 原則 1；要換系統、要換終端機程式，改的是模組不是核心（D50） |
| 面板是 tkinter 視窗裡的一欄文字按鈕，按一下就執行（這次重寫到 0.3.0 為止也是） | 圖示格：面板是 `ui/` 裡的 HTML／CSS／JS，在 pywebview 開的原生視窗裡跑——不是瀏覽器分頁，沒有 server、沒有 port。單擊選取（狀態列顯示說明）、雙擊執行、右鍵選單；每組最後一格是 ＋。tkinter 面板留著當安全模式 | 照 macOS／Windows 的習慣；單擊就執行等於一按錯就跑程式。tkinter 做不出要的樣子（D61、D63、D64） |
| 按鈕只有文字，顏色只用來標來源 | 每個模組有自己的圖示：模組資料夾裡放 `icon.png`（或 `icon.svg`），或在 `iplot.py` 寫一行 `ICON = "🧩"`；都沒有就用名字第一個字，底色由資料夾名稱算出來，每次都一樣。來源的顏色變成每組標題前面的點 | 每個新模組一開始都沒有圖示；預設的要是一格灰方塊，面板就沒有個性（D65） |

## 三、怎麼在上面搭東西

分四種人，由淺到深，彼此不衝突：

**只想做用途的人。** 按 ＋、取名、貼程式、雙擊。不用知道 `core/` 存在。改完檔案再雙擊一次就是新版本，不用重啟。

**想改面板長相的人。** 顏色、圖示多大、一格多寬、訊息區多高，都是 `ui/style.css` 開頭那一段變數，下面的規則只用變數；深色模式的顏色在緊接著的那一段。想讓改法在換新版之後留著，就在 iPLoT 資料夾（跟 `config.py` 同一層）建一個 `custom.css`，把要改的變數寫進去，例如 `:root { --accent: #e0703d; --icon: 64px; }`——它在 `style.css` 之後載入，同名的變數以它為準；換新版時 `ui/` 整個換掉，`custom.css` 不在裡面。改完重新開 iPLoT 才看得到。要改版面或行為，再往下是 `ui/index.html` 和 `ui/app.js`：沒有框架、不用 build、不連任何外部網址，文字編輯器就能改。

**想用 iPLoT 給的能力的人。** 寫 `def run(app)`，`app` 能做的事全部在 `docs/api.md` 一頁：寫訊息區、開檔案、開編輯器、在資料夾中顯示、開終端機、搬到垃圾桶、跑別的模組、問人（`app.ask` 問一個字串、`app.confirm` 問確定或取消）、選檔案、`app.memory` 跨次記東西。介面只加不減；這一版破例拿掉了一樣：沒有 tkinter 主視窗了，所以 `app.window` 沒有了，`api_version` 升到 2（D66）。

**想改核心、或想換掉一塊零件的人。** `core/` 任一檔改完雙擊「重新啟動」。每個檔開頭的 docstring 說它做什麼；規格在 `docs/02_重構設計.md`，理由在 `docs/03_設計決定.md`；哪些地方可以整塊換掉（畫面、作業系統、動作、事件）、各自的規則與擋住規則的測試，在 `docs/07_接口與邊界.md`。改完跑 `python -m pytest`（現在 317 個測試）。新用途一律做成模組，不進核心——500 行的上限就是為了逼這件事。

前例一句話：Emacs 的核心很小、所有功能都是可改的 Lisp；HyperCard 讓人用滑鼠長出卡片和按鈕；Smalltalk 裡一切都是可以當場改的物件。iPLoT 想做的是這三者用 Python、給不開終端機的人用的版本。

## 四、還沒做的

- 拖放檔案到圖示上、匯入原版 `X/X.txt` 模組、自動啟動——這三件都還沒做。拖放延到 M2 後段，要先看 pywebview 的拖放支援再定。
- 中途停掉模組、同時跑兩個模組。現在模組跑在一條工作執行緒上：跑很久時視窗不會凍住，可以捲、可以看訊息；但模組仍然在 iPLoT 自己的程序裡執行，一次只跑一個、跑到一半不能停，關掉視窗會結束整個程序。這跟「模組在哪裡執行」是同一題（D56，仍延後），見 `docs/07_接口與邊界.md` 第 8 節。
- Linux 的網頁面板。pywebview 在 Linux 要系統層的 GTK／WebKit2GTK，pip 裝不了；這一版 Linux 只有安全模式。
- 更新與工作坊（M3，0.5.0）。「按一下更新核心、不碰自己做的東西」和「像外掛一樣下載模組」只定了原則（D69、D70），程式還沒寫；現在換新版是手動換資料夾，步驟在 `CHANGELOG.md`。
- 安裝時只釘版本，還沒有釘 hash（pip 的 `--require-hashes`）。
- 面板的 HTML／CSS／JS 沒有自動測試：`tests/test_boundaries.py` 只釘住它跟 Python 那一頭對得上，滑鼠實際按下去的行為靠人工驗收。
- **Windows、Linux 的實機驗證。** Windows 的做法（包括第一次啟動的安裝、檢查有沒有 WebView2 Runtime）只用假的系統呼叫驗過參數，沒有在 Windows 上跑過，`requirements/web-win.txt` 的版本是用 pip 解出來的、沒有在 Windows 上裝過；Linux 沒有在真的桌面上按過；CI 設了三個平台，但沒有遠端，一次都沒跑過。怎麼驗見 `docs/07_接口與邊界.md` 第 9 節。
- 工作情境切換、檔案整理規則是更後面的事。

## 五、試用：七步看到新東西

1. 要有 Python 3.10 以上、含 pip。任何來源的 Python 都可以；python.org 的版本最省事，因為它內含安全模式要用的 tkinter（開發和實測用的也是它，3.14）。把 iPLoT 資料夾放到 `~/iPLoT`（不要留在「下載項目」），雙擊 `iPLoT.command`；第一次 macOS 問要不要打開，選「打開」。**第一次啟動要網路**：跟著開的終端機視窗會顯示「第一次啟動：正在安裝介面（需要網路，約 40 MB）…」和 pip 一行行的進度，介面裝進 iPLoT 自己的 `lib/`；在開發用的 Mac 上，乾淨下載花了 1 分 46 秒，看網路速度。裝完印一句「安裝完成，重新啟動中…」，視窗自己出現，標題是「iPLoT v0.4.0」。之後每次雙擊都直接開視窗，不再安裝、不用網路。Windows 是雙擊 `iPLoT.bat`，未經實機驗證；Linux 這一版沒有網頁面板，只能用安全模式（見這一節後面）。
2. 單擊「開工」：那一格被選起來，下面的狀態列顯示它的名稱和說明（`iplot.py` 開頭那段 docstring 的第一段）。單擊只是選取，雙擊才執行：雙擊「開工」，iPLoT 資料夾、`docs/`、設計文件、終端機各開一個，訊息區出現「開工 完成（… 秒）」。右鍵任一個模組是選單：執行、打開程式碼、在資料夾中顯示、在終端機打開、在這裡新增下一層模組…。
3. 按「這一層」最後那一格虛線的 ＋，面板裡跳出對話框問名字，打「猜數字」，確定。編輯器開了範本，面板上多了一格「猜數字」。把範本全部刪掉，貼上這段，存檔：

```python
import random
答案 = random.randint(1, 10)
while True:
    try:
        n = int(input("猜 1 到 10"))
    except ValueError:
        print("要輸入數字")
        continue
    if n == 答案:
        print("對了！")
        break
    print("太大" if n > 答案 else "太小")
exit()
```

4. 回 iPLoT 雙擊「猜數字」。`input()` 是面板裡的對話框（Enter 確定、Esc 取消），上一輪印的「太大」出現在下一個問題上面；猜對後訊息區出現全部輸出；結尾 `exit()` 不算錯。再雙擊一次，這次按「取消」：模組停，訊息區說「模組『猜數字』第 N 行出錯：EOFError，在提問時按了取消」，那一行右邊有「打開檔案」（用編輯器打開出錯的檔案；`config.py` 的 `EDITOR` 設成認得行號的編輯器時會直接跳到那一行，預設的系統文字編輯器只打開檔案）和「詳細」（展開 traceback，再按一次收起）。
5. 右鍵「猜數字」→「在這裡新增下一層模組…」，取個名字，確定。編輯器開了範本；回 iPLoT，「猜數字」的圖示右下角多了 ▸。按 ▸ 進去：裡面是剛取名的模組，這一組的顏色點是紫色，麵包屑多了一段（「iPLoT ▸ 猜數字」），點「iPLoT」回到頂層。任一模組都能這樣加下一層；還沒有下一層的模組沒有 ▸，第一個就從右鍵加。有了下一層，右鍵選單會多一項「進入下一層」。
6. 給「猜數字」一個圖示。現在它的圖示是一個「猜」字：沒有圖示的模組用名字第一個字，底色由資料夾名稱算出來，每次都一樣。右鍵 →「打開程式碼」，在最上面加一行 `ICON = "🎲"`，存檔，點回 iPLoT 視窗：圖示變成 🎲。或者右鍵 →「在資料夾中顯示」，丟一張叫 `icon.png` 的圖進那個資料夾（檔名要一字不差，1 MB 以內；`icon.svg` 也可以），點回視窗：圖示變成那張圖。兩種都有時用圖檔。
7. 雙擊「作業系統」：訊息區說現在用的是哪個檔（macOS 上是 `mac.py`）。右鍵它 →「打開程式碼」看到的是選擇器 `iplot.py`；打開檔案、開終端機、垃圾桶這些動作的五個函式，加上第一次啟動的安裝會問的兩個（`requirements` 回答裝哪一份、`webview_ready` 回答缺什麼），都在旁邊的 `mac.py`（右鍵 →「在資料夾中顯示」）。改了存檔，下一次動作就生效。

**安全模式。** 在終端機裡、iPLoT 資料夾中執行 `python3 main.py --safe`，開的是 tkinter 面板：標題多了「（安全模式）」，只掃 `modules/`，所以只有「這一層」；一欄文字按鈕，沒有圖示和狀態列，**單擊就執行**；右鍵四項（打開程式碼、在資料夾中顯示、在終端機打開、在這裡新增下一層模組…），＋ 在每組標題的右邊。它需要 tkinter。什麼時候用：網頁面板開不起來的時候；上一層或 `config.py` 多掃的位置裡有東西讓面板出問題的時候。介面裝不起來時（沒有網路、pip 失敗、這個平台沒有網頁面板）不用自己下指令，iPLoT 會自己退到安全模式：終端機說明原因，同樣的說明也寫在訊息區最前面；有網路之後重新啟動 iPLoT，它會再裝一次。連 tkinter 都沒有的 Python 會印「這個 Python 沒有 tkinter，安全模式開不了；請用 python.org 的版本」然後結束。

已知會踩到的：

- 模組跑很久（長迴圈、`time.sleep`、等網路）時視窗不會凍住，可以捲、可以看訊息；但一次只跑一個，這段時間雙擊別的模組、右鍵的動作、重掃都排在後面，等它跑完才輪到。跑到一半不能停；關掉視窗會結束整個 iPLoT。安全模式的 tkinter 面板還是會凍住。
- `print()` 的東西在模組結束時才一起進訊息區（碰到 `input()` 時會先出現在問題上面）；要邊跑邊看到，用 `app.log`。
- 第一次啟動要網路。沒有網路時終端機說明原因、退到安全模式；有網路後重新啟動 iPLoT 就會再裝。
- 驗證迴圈寫什麼都接的 `except:` 按取消出不去（請接 `except ValueError`）。
- 模組不能再拿 iPLoT 的 tkinter 主視窗來畫自己的介面：`app.window` 沒有了。
- 圖示檔超過 1 MB 或讀不到時當作沒有這個檔，訊息區說一次。
- 「重新啟動」後終端機可能多一行 `Task policy set failed`（已經開過視窗的程式重啟自己時 macOS 印的），沒影響。
- 改壞「作業系統」模組時，右鍵「打開程式碼」和錯誤訊息的「打開檔案」自己也會壞（它們也是交給這個模組做的）；用檔案總管打開 `modules/作業系統/` 底下的檔案改回來。
- Linux 這一版只有安全模式，而且沒有在真的 Linux 桌面上跑過。
- Windows 未經實機驗證；網頁面板在 Windows 另外需要 Microsoft Edge WebView2 Runtime（Windows 11 內建）。

## 六、怎麼回報

試用時碰到的事記進 `docs/05_使用紀錄.md`，一件事一行：哪天、按了什麼、卡在哪或哪裡多餘。自己做的模組都在 `modules/` 裡，更新核心不會動到。用過一陣子之後回頭看三個問題：有沒有真的用它啟動東西、想做但面板上沒有的事怎麼繞、有沒有哪次壞了但沒說哪裡壞。
