description: 整理今天的 iPLoT 日誌（docs/日誌/）：從 git、對話紀錄、iPLoT 使用痕跡、GitHub 重建，不問任何問題
---

替 iPLoT 整理「今天」的每日日誌。操作這個指令的是使用者的助理，使用者本人不會記得自己今天做了什麼。所以：**執行時不准問任何問題**，一律從證據重建；證據裡找不到的就不寫，或寫進「留下的」標成「無法判斷：…」，讓助理之後去問。

格式、規矩與索引都寫在 `docs/日誌/README.md`，先讀它。這個指令只改 `docs/日誌/` 底下的檔，不改任何程式碼，不切分支，不合併，不 push。

名詞：「使用者」是下指令、對話紀錄裡說話的人，日誌裡的角色稱呼是「研究助理」；「老闆」是另一個人（課程與需求的來源），只有證據明講老闆做了什麼才寫。

## 0. 先弄清楚幾件事

```bash
TZ=Asia/Taipei date +%F          # <今天>，下面都用這個日期（Asia/Taipei）
git worktree list --porcelain    # 第一筆是主工作區；其餘是各個 worktree
```

- 要看的是整個 repo，**不只是你現在站的這個 worktree**。git 的歷史與分支是共用的；但「沒 commit 的變更」與「iPLoT 的 logs／.history」每個 worktree 各一份，要一個一個看。
- `<日誌目錄>`：寫日誌的地方。目前這個 worktree 有 `docs/日誌/README.md` 就用它；沒有（例如站在別的功能分支上），到 `git worktree list` 裡找有這個檔的 worktree（通常是分支 `docs/journal`，或已經合進去的 `main`），之後的 `git add`、`git commit` 都用 `git -C <路徑>` 在那邊做。**找不到就停下來**，最後回覆說「目前沒有任何 worktree 有 docs/日誌/；需要問他：要不要把 docs/journal 合進 main？」。

## 1. 重建「今天做了什麼」：四個來源都要看

### 1.1 iPLoT repo

```bash
# 今天的 commit（所有分支，含別的 worktree 的）
TZ=Asia/Taipei git log --all --since="<今天> 00:00 +0800" --until="<今天> 23:59:59 +0800" \
  --date=format-local:'%H:%M' --format='%h %ad %D %s'

# 今天 commit 動過的 docs/
TZ=Asia/Taipei git -c core.quotepath=false log --all --since="<今天> 00:00 +0800" --until="<今天> 23:59:59 +0800" \
  --name-only --format= -- docs/ | sort -u

# 還沒合進 main 的分支，各比 main 多幾個 commit
git for-each-ref refs/heads --format='%(refname:short)' | while read b; do
  n=$(git rev-list --count main.."$b"); [ "$n" != 0 ] && echo "$b 比 main 多 $n 個"; done

# 每個 worktree：分支、沒 commit 的變更（只列檔名，不讀內容、不貼 diff）、今天改過的 docs/ 檔
git worktree list --porcelain | awk '/^worktree /{print $2}' | while read w; do
  echo "== $w"; git -C "$w" branch --show-current; git -C "$w" status --short
  find "$w/docs" -type f -newermt "<今天> 00:00" ! -newermt "<今天> 23:59:59" 2>/dev/null | sort; done
```

任何一個 worktree 的指令超過 30 秒沒回應（例如外接硬碟或有權限提示的資料夾），就在指令前面加 `perl -e 'alarm 30; exec @ARGV'` 重跑一次；還是不行就略過那個 worktree，並在「留下的」寫「無法判斷：某個 worktree 讀不到」。

讀今天 commit 的訊息；必要時 `git show --stat <hash>`，或讀今天新增的設計／回報／驗收文件，弄清楚做了什麼。D 編號看 commit 訊息與 `docs/03_設計決定.md`。沒 commit 的變更只能寫成「工作樹裡有 N 個檔案還沒 commit（檔名…）」，不要猜內容。

### 1.2 使用者今天的 Claude Code 對話紀錄

對話紀錄在 `~/.claude/projects/` 底下名字含 `iplot` 的資料夾（主工作區、各 worktree 各有一個），每個 session 一個 `.jsonl`。下面的指令只取今天的、使用者說的話與每個 session 助理的最後幾段：

```bash
python3 -I - <今天> <<'EOF'
import json, re, sys, glob, os
from datetime import datetime, timezone, timedelta
TPE = timezone(timedelta(hours=8)); day = sys.argv[1]
def text_of(m):
    c = m.get('content')
    if isinstance(c, str): return c
    return '\n'.join(b.get('text', '') for b in c if isinstance(b, dict) and b.get('type') == 'text')
files = []
for d in glob.glob(os.path.expanduser('~/.claude/projects/*iplot*')):
    files += glob.glob(d + '/*.jsonl')
for f in sorted(files, key=os.path.getmtime):
    users, asst, branches, stamps = [], [], set(), []
    for l in open(f, encoding='utf-8'):
        try: o = json.loads(l)
        except ValueError: continue
        ts = o.get('timestamp')
        if not ts or o.get('type') not in ('user', 'assistant') or o.get('isSidechain') or o.get('isMeta'): continue
        t = datetime.fromisoformat(ts.replace('Z', '+00:00')).astimezone(TPE)
        if t.strftime('%Y-%m-%d') != day: continue
        txt = text_of(o.get('message') or {}).strip()
        if o['type'] == 'user':
            txt = re.sub(r'</?pasted_content[^>]*>', '', txt)
            txt = re.sub(r'<system-reminder>.*?</system-reminder>', '', txt, flags=re.S).strip()
        if not txt or txt.startswith(('<command-', '<local-command', '<task-notification', '[Request interrupted')): continue
        stamps.append(t); branches.add(o.get('gitBranch') or '')
        (users if o['type'] == 'user' else asst).append((t.strftime('%H:%M'), txt))
    if not stamps: continue
    print('## 對話', os.path.basename(f)[:8], '分支:', ','.join(sorted(b for b in branches if b)),
          stamps[0].strftime('%H:%M') + '–' + stamps[-1].strftime('%H:%M'), '使用者', len(users), '則 助理', len(asst), '則')
    for h, t in users[:25]: print('  [使用者]', h, t[:600].replace('\n', ' '))
    for h, t in asst[-3:]: print('  [助理結尾]', h, t[:700].replace('\n', ' '))
EOF
```

印出來的太簡略時（使用者的訊息很長、重點在後半），用同一個 session 檔自己讀需要的部分。從裡面整理：

- 使用者交代了什麼（目標、範圍、限制）。
- 做到哪（助理結尾說的、對應的 commit）、卡在哪。
- 使用者明講的決定與取捨。
- 使用者抱怨、嫌麻煩、放棄的地方（給「想要但做不到」）。

**對話紀錄只用來理解與摘要。** 日誌裡一律用自己的話寫，**不貼原文**、不貼長段指示、不寫 session 檔名或 id。這些對話裡常有本機路徑與人名，寫之前先去掉。

### 1.3 iPLoT 實際被使用的證據（用來寫「iPLoT 使用紀錄」）

**不要把開發當成使用。** 只有下面這些算使用的證據：

```bash
for w in $(git worktree list --porcelain | awk '/^worktree /{print $2}'); do
  echo "== $w"
  # logs/ 今天有寫入的檔
  find "$w/logs" -type f -newermt "<今天> 00:00" ! -newermt "<今天> 23:59:59" 2>/dev/null
  # 各模組 .history/ 的快照：檔名是 YYYY-MM-DD_HHMMSS.py（本機時間）
  find "$w/modules" \( -name .venv -o -name lib -o -name site-packages -o -name node_modules \) -prune -o \
    -path '*/.history/*' -name "<今天>_*" -print 2>/dev/null
done
```

- **快照 = 有人按了那個模組**（執行前與復原前各存一次）。從路徑取模組名、從檔名取時間，整理成「幾點按了哪些模組」。
- `logs/` 只看今天有沒有寫入、大約幾筆錯誤；**內容可能帶本機路徑與學生資料，不要貼進日誌**，用「出現 N 筆錯誤、種類是…」帶過。
- 今天有 commit 動到某個模組、同一個模組又有快照時，快照可能只是開發者自己試按；寫成「有按過（可能是開發時的試按）」，不要寫成有人在用。
- 沒有快照也沒有 logs：「iPLoT 使用紀錄」就寫「無」。不要拿 commit、測試、驗收腳本、探針來湊。
- 對話紀錄裡使用者明講自己拿 iPLoT 做了什麼（例如在面板上按驗收清單），可以寫，出處標「對話紀錄」。

### 1.4 GitHub（只讀）

```bash
gh api graphql -f query='{repository(owner:"william10310406",name:"iplot"){discussions(first:10,orderBy:{field:CREATED_AT,direction:DESC}){totalCount nodes{number title createdAt category{name}}}}}'
gh issue list -R william10310406/iplot-modules --state all --limit 15 --json number,title,createdAt,state,labels
gh issue list -R william10310406/iplot --state all --limit 10 --json number,title,createdAt,state
```

只挑 `createdAt` 換成 Asia/Taipei 之後是今天的。**不要抓、也不要寫作者的姓名或帳號**（gh 的輸出裡有真實姓名，`--json` 不要加 `author`）；要區分時只說「其他上傳者」。只讀：不留言、不關 issue、不改標籤。`gh` 沒登入或沒網路，就在「留下的」寫「無法判斷：GitHub 今天讀不到」，不要卡住。今天沒有新的就不寫。

## 2. 寫今天的日誌

寫到 `<日誌目錄>/docs/日誌/<今天>.md`，格式（`決定`、`想要但做不到`沒有內容就整節省略；其他節沒有內容就寫「無」）：

```
# YYYY-MM-DD
## 做了什麼
（條列，白話寫做了什麼，不是貼 commit 訊息）
## 決定
（當天定下的設計決定，附 D 編號）
## iPLoT 使用紀錄
（當天實際「使用」iPLoT 做了什麼、卡在哪）
## 想要但做不到
（每條註明：只要加模組／需要動核心）
## 留下的
（沒做完、延後、待驗收的事）
```

**每一條都要有出處**，寫在條目後面的括號裡：

- commit：短 hash，例如 `（a1b2c3d）`。
- 對話紀錄：`（對話紀錄）`。
- iPLoT 使用：`（快照）`、`（logs）`。
- GitHub：`（Discussions #3）`、`（iplot-modules #18）`。
- **找不到證據的事不要寫。** 推測也不寫；有線索又無法確認的，寫進「留下的」，開頭用「無法判斷：」。

各節怎麼寫：

- **做了什麼**：commit 與對話紀錄合起來看，同一件事合成一條。分支還沒合進 main 的，寫明「在分支 X、還沒合進 main」。
- **決定**：commit 或文件裡有 D 編號的寫 D 編號；只在對話裡定下、沒有 D 編號的也寫，出處標「對話紀錄」，不編造 D 編號。
- **想要但做不到**：只從對話紀錄裡使用者抱怨、嫌麻煩、放棄的地方找。每條註明「只要加模組」或「需要動核心」（判斷不了就查程式：那個行為在 `core/`、`ui/`、`main.py` 裡就是需要動核心；用模組就能做到的是只要加模組）。沒有就省略這一節。
- **留下的**：沒做完、延後、等使用者人工驗收的事（例如分支附了人工驗收清單、還沒有人按），以及「無法判斷」的事。
- 不確定是哪天發生的，寫在最接近的那天並標「（日期推定）」。
- **公開規矩**：不能出現本機路徑（家目錄、外接硬碟路徑）、帳號以外的人名、學生的任何資料、對話原文。人一律用角色稱呼：老闆、研究助理、上傳者、同事。

如果 `docs/日誌/<今天>.md` 已經存在：**合併，不覆蓋**。先讀它，把新的條目加進對應的節，已經有的不重複、不刪掉。今天完全沒有證據（沒有 commit、沒有文件活動、沒有對話、沒有快照）就不建檔，最後回覆說「今天沒有活動」，結束。

## 3. 更新索引

在 `docs/日誌/README.md` 的索引表加入（或更新）今天這一列：`| [YYYY-MM-DD](YYYY-MM-DD.md) | 一句話摘要 | 里程碑 |`。照日期順序排；今天已經有列就改那一列，不重複。

## 4. 公開規矩檢查

在 `<日誌目錄>` 底下跑：

```bash
grep -rnE '/Users/|/Volumes/|/home/[A-Za-z]|\.claude/projects|[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}' docs/日誌/ || echo '乾淨'
```

有輸出就改掉再往下（這個指令自己的檔不在 `docs/日誌/` 底下，不會被抓到）。再把今天寫的內容自己重讀一遍：沒有人名（含 GitHub 顯示的真實姓名）、沒有學生資料、沒有從對話貼過來的原文。

## 5. Commit

只 commit `docs/日誌/` 底下的檔，其他變更（包括已經 stage 的）都不碰：

```bash
git add docs/日誌/
git commit -m "日誌：<今天>" -- docs/日誌/
```

- 訊息第一行就是「日誌：YYYY-MM-DD」；環境要求的結尾行（例如 Co-Authored-By）照加。
- 在 `<日誌目錄>` 目前的分支上 commit，不 push。commit 之後 `git status --short` 看一眼，確認沒動到 `docs/日誌/` 以外的東西。

## 6. 第 7 天與第 14 天的提醒

讀 `docs/日誌/README.md` 頂端的起始日。

- 起始日是「未設定」：**不要問、不要自己設**。最後回覆加一句「需要問他：兩週使用期間從哪一天算第 1 天？」讓助理轉問。
- 起始日是日期：算今天是第幾天（起始日當天是第 1 天）。

**今天是第 7 天或第 14 天**時，最後回覆額外做：

1. 提醒：今天要做兩週使用期間的檢視（第 7 天期中、第 14 天總檢視）。
2. 讀起始日到今天所有日誌的「iPLoT 使用紀錄」，摘要哪幾天有用、用了什麼、卡在哪、哪幾天是「無」。
3. 彙整這段期間所有「想要但做不到」，**按兩組列出**，同一件事出現多次合併並標日期：只要加模組就能做到的；需要動核心的。
4. 第 14 天另外：哪些模組真的被按了、卡在哪裡、哪些服務沒人碰、除了維護者還有沒有人在用（從日誌的使用紀錄與 GitHub 回答）。

不是第 7、14 天就不用提這一步。

## 7. 最後回覆

給助理看的白話摘要，**三行以內**：今天日誌的檔名、新增或合併了幾條、commit 的短 hash 與分支；今天最重要的一件事；（如果有）「需要問他：…」與第 7／14 天的提醒。不要把日誌全文貼回來。
