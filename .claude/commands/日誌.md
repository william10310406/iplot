---

你要替 iPLoT 整理「今天」的每日日誌。格式、規矩與索引都寫在 `docs/日誌/README.md`，先讀它。這個指令只改 `docs/日誌/` 底下的檔，不改任何程式碼。

## 0. 先弄清楚「今天」

用 Asia/Taipei 時區：

```bash
TZ=Asia/Taipei date +%F
```

下面的 `<今天>` 都指這個日期（YYYY-MM-DD）。

## 1. 收集今天的活動（不要先問人）

```bash
# 今天的 commit（所有分支）
TZ=Asia/Taipei git log --all --since="<今天> 00:00 +0800" --until="<今天> 23:59:59 +0800" \
  --date=format-local:'%H:%M' --format='%h %ad %s'

# 今天 commit 動過的 docs/ 檔案
TZ=Asia/Taipei git -c core.quotepath=false log --all --since="<今天> 00:00 +0800" --until="<今天> 23:59:59 +0800" \
  --name-only --format= -- docs/ | sort -u

# 今天改過的 docs/ 檔案（包含還沒 commit 的）
find docs -type f -newermt "<今天> 00:00" ! -newermt "<今天> 23:59:59" | sort

# 工作樹裡沒 commit 的變更：只列檔名，不讀內容、不貼 diff
git status --short
```

讀今天 commit 的訊息，必要時看 `git show --stat <hash>` 或今天新增的設計／回報文件，弄清楚「今天做了什麼」。D 編號（設計決定）看 `docs/03_設計決定.md` 與 commit 訊息。

## 2. 問我三個問題（一次問完）

把前面收集到的活動用兩三行摘要給我看（讓我知道你看到了什麼），然後**在同一則訊息裡**問：

a. 今天有沒有實際「用」iPLoT 做事？做了什麼、卡在哪？
b. 有沒有想做但 iPLoT 做不到的事？
c. 還有什麼沒反映在 commit 裡的工作或決定？

可以回「無」。等我回答再往下，不要自己替我編答案。

如果 `docs/日誌/README.md` 頂端的起始日還是「未設定」，在同一則訊息多問一句：今天是不是兩週使用期間的第 1 天？我回「是」，才把頂端那一行改成 `**兩週使用期間起始日：<今天>**`。

## 3. 寫今天的日誌

寫到 `docs/日誌/<今天>.md`，格式如下（`決定`與`想要但做不到`沒有內容就整節省略；其他節沒有內容就寫「無」）：

```
# YYYY-MM-DD
## 做了什麼
（條列，白話寫做了什麼，不是貼 commit 訊息；每條後面附相關 commit 短 hash）
## 決定
（當天定下的設計決定，附 D 編號）
## iPLoT 使用紀錄
（當天實際「使用」iPLoT 做了什麼、卡在哪）
## 想要但做不到
（每條註明：只要加模組／需要動核心）
## 留下的
（沒做完、延後、待驗收的事）
```

- 「iPLoT 使用紀錄」只寫我在 a 回答的使用，以及當天有證據的驗收紀錄。**不要把開發當成使用**：為了驗證而跑的測試、探針、驗收腳本都不算。我回「無」就寫「無」。
- 「想要但做不到」來自我在 b 的回答；每條都要註明是「只要加模組」還是「需要動核心」。不確定就問我，不要猜。
- c 的內容放進「做了什麼」「決定」或「留下的」，看性質。
- 不確定是哪天發生的事，寫在最接近的那天並標「（日期推定）」。沒有證據的事不編。
- 如果 `docs/日誌/<今天>.md` 已經存在：**合併，不覆蓋**。先讀它，把新的條目加進對應的節，已經有的不重複、不刪掉。
- 今天沒有任何 commit、沒有文件活動、而我三題都答「無」：不建檔，告訴我「今天沒有活動，沒有建日誌」，結束。

## 4. 更新索引

在 `docs/日誌/README.md` 的索引表裡，加入（或更新）今天這一列：`| [YYYY-MM-DD](YYYY-MM-DD.md) | 一句話摘要 | 里程碑 |`。照日期順序排。今天已經有列就改那一列，不要重複加。

## 5. 公開規矩檢查

這個 repo 是公開的。寫完之後：

```bash
grep -rnE '/Users/|/Volumes/|/home/[A-Za-z]' docs/日誌/ && echo '有本機路徑，要改'
```

有輸出就改掉再往下。另外自己把今天寫的內容重讀一遍：

- 沒有本機路徑（家目錄、外接硬碟的路徑）。
- 沒有帳號以外的人名；人一律用角色稱呼：老闆、研究助理、上傳者、同事。
- 沒有學生的任何資料（姓名、學號、作業內容）。我在回答裡提到人名或學生資料時，也要改成角色稱呼或略過，不要照抄。

## 6. Commit

只 commit `docs/日誌/` 底下的檔，其他變更（包括已經 stage 的）都不碰：

```bash
git add docs/日誌/
git commit -m "日誌：<今天>" -- docs/日誌/
```

- 訊息第一行就是「日誌：YYYY-MM-DD」。環境要求的結尾行（例如 Co-Authored-By）照加。
- 在目前的分支上 commit，不切分支、不合併、不 push。
- commit 之後 `git status --short` 看一眼，確認沒有動到 `docs/日誌/` 以外的東西。

## 7. 第 7 天與第 14 天的提醒

讀 `docs/日誌/README.md` 頂端的起始日。起始日是日期的話，算今天是第幾天（起始日當天是第 1 天）。

**如果今天是第 7 天或第 14 天**，在最後的回覆額外做：

1. 提醒我：今天要做兩週使用期間的檢視（第 7 天是期中檢視，第 14 天是總檢視）。
2. 讀起始日到今天所有日誌的「iPLoT 使用紀錄」，摘要：哪幾天有用、用了什麼、卡在哪、哪幾天是「無」。
3. 彙整這段期間所有日誌「想要但做不到」的條目，**按兩組列出**，同一件事出現多次合併成一條並標出現的日期：
   - 只要加模組就能做到的
   - 需要動核心的
4. 第 14 天另外提醒：回頭看開發前定的問題——有哪些模組真的被按了、卡在哪裡、哪些服務沒人碰、除了維護者還有沒有人在用。

不是第 7 天或第 14 天就不用做這一步，也不用提它。

## 8. 最後回覆

簡短告訴我：今天日誌的檔名與路徑、新增或合併了幾條、commit 的短 hash 與分支、（如果有）第 7／14 天的提醒。不要把日誌全文貼回來。
