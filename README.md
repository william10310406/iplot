# iPLoT — 需要 Python ≥ 3.10（含 pip）；第一次啟動要網路

第一次接觸先看 [docs/06_架構說明與試用.md](docs/06_架構說明與試用.md)。

一個可以放在任何位置的資料夾。啟動後把周圍含有 `iplot.py` 的資料夾變成面板上一格格的圖示；雙擊就執行那個檔案，錯了在面板上說清楚；按「＋」用滑鼠長出新的一格。核心本身不內建任何用途，連 iPLoT 自己的工具都是模組。

## 安裝

1. 裝 Python 3.10 以上，要含 pip：
   - macOS：Python 3.10 以上、有 pip 就可以，不必是 python.org 的（Homebrew 的照理也行，但沒有實測過）。[python.org 的安裝檔](https://www.python.org/downloads/)最省事：它內含 tkinter，安全模式和後備面板要用。開發和實測用的是 python.org 的 3.14。
   - Windows：python.org 的安裝檔，安裝時勾選 tcl/tk（安全模式和後備面板要用）。網頁面板另外需要 Microsoft Edge WebView2 Runtime（Windows 11 內建）。**未經實機驗證。**
   - Linux：這一版沒有網頁面板，開的是 tkinter 面板。發行版的 Python 加上 `python3-tk` 套件（Debian／Ubuntu：`sudo apt install python3-tk`）。
2. 到 [https://william10310406.github.io/iplot-workshop/](https://william10310406.github.io/iplot-workshop/) 下載 `iPLoT-vX.Y.Z.zip`（那一頁也列了工作坊裡的模組），解壓縮，資料夾放哪裡都可以（例如 `~/iPLoT`）。
3. 啟動：
   - macOS：雙擊 `iPLoT.command`。第一次 macOS 可能問你要不要打開，選「打開」。
   - Windows：雙擊 `iPLoT.bat`。**未經實機驗證。**
   - Linux：執行 `./iPLoT.sh` 或 `python3 main.py`。終端機先說一句網頁面板還不支援 Linux，接著開後備的 tkinter 面板，照常掃上一層與 `ROOTS`；加 `--safe` 才是安全模式，只掃 `modules/`（見下一節）。**只由測試驗過參數，沒有在真的 Linux 桌面上跑過。**
4. 第一次啟動會自動安裝介面（Linux 沒有這一步），要網路：終端機顯示「第一次啟動：正在安裝介面（需要網路，約 40 MB）…」和 pip 的進度，套件裝進 iPLoT 資料夾裡的 `lib/`，裝完視窗自己出現。在開發用的 Mac 上，乾淨下載花了 1 分 46 秒（看網路速度），`lib/` 裝完 36 MB。之後每次啟動直接開視窗，不用網路（例外：按「更新」換了版本、新版要的套件跟舊版不一樣時，下一次啟動會重裝一次，見「更新與工作坊」）。沒有網路或裝不起來時，終端機會說原因，並自動改開後備的 tkinter 面板——不是安全模式，見下一節；有網路後重新啟動 iPLoT 就會再裝一次。

三個系統的差別都在 `modules/作業系統/` 這一個模組裡（打開檔案、開終端機、垃圾桶各系統的做法，以及第一次啟動要裝哪一份、缺什麼）；現況與怎麼驗見 [docs/07_接口與邊界.md](docs/07_接口與邊界.md) 第 9 節。

不用自己安裝任何套件：介面要用的套件由 iPLoT 第一次啟動時裝進它自己的 `lib/`（版本釘死在 `requirements/`），不碰系統的 Python。要移除就把整個資料夾丟進垃圾桶（pip 自己的下載快取不在這個資料夾裡，那是 pip 的）。開發端另外需要 `pip install -r requirements-dev.txt`（pytest、pytest-cov、ruff）。

## 安全模式

在終端機裡、iPLoT 資料夾中執行 `python3 main.py --safe`（Linux 也可以 `./iPLoT.sh --safe`），開的是 tkinter 面板，不用 `lib/`、不用網路。安全模式只有這一個入口：要自己加 `--safe` 才會進去。

- **什麼時候用**：網頁面板開不起來；模組要用 `turtle` 或 tkinter 開自己的視窗（在預設的面板上這類模組不會執行，訊息區會說要用安全模式）；上一層或 `config.py` 多掃的位置裡有東西讓面板出問題。
- **長什麼樣**：標題是「iPLoT v0.5.1（安全模式）」；只掃 `modules/`，所以只有「這一層」；一欄文字按鈕，沒有圖示和狀態列，單擊就執行；右鍵四項（打開程式碼、在資料夾中顯示、在終端機打開、在這裡新增下一層模組…）；＋ 在每組標題的右邊。
- **需要 tkinter**（python.org 的 Python 內含；Linux 裝 `python3-tk`）。沒有的話印一句「這個 Python 沒有 tkinter，安全模式與備用面板都開不了；請用 python.org 的版本」就結束。
- **裝不起來時退到的是後備面板，不是安全模式**：沒有網路、pip 失敗、這個平台沒有網頁面板（Linux）、Windows 缺 WebView2 Runtime（這一項未經實機驗證）——iPLoT 在終端機說明原因，改開後備的 tkinter 面板，同樣的說明也寫在訊息區最前面。後備面板跟安全模式是同一個 tkinter 面板（一欄文字按鈕、單擊就執行、右鍵四項），差別在範圍：它照常掃上一層與 `ROOTS`，標題沒有「（安全模式）」。它一樣需要 tkinter。0.4.0 在這種時候是直接進安全模式，0.5.0 改了。
- **這兩種 tkinter 面板都沒有頁面**：模組用 `app.page` 開自己的一頁畫面時，只會在訊息區看到一句「這個面板沒有頁面（安全模式與備用面板都是）；這個功能要在一般的網頁面板裡用」。隨附的「工作坊」就是這種模組（見「更新與工作坊」）。

連安全模式都開不起來（核心改壞了）：從 git（`git checkout -- core/ ui/`）或原本的壓縮檔把 `core/`、`ui/` 拿回來；用「更新」換過版本的話，換掉之前的那一份也在 `.backup/` 裡。

## 三層

**資料夾裡有 `iplot.py` 就是模組。** 三層都用這一條，資料夾叫什麼模組就叫什麼：

| 層 | 在哪裡 | 顏色 |
|---|---|---|
| 這一層 | `iPLoT/modules/` 底下的資料夾。隨附的九個模組和自己做的模組都在這 | 藍 |
| 上一層 | iPLoT 資料夾的上一層底下的資料夾。把 iPLoT 放在 `~/`，`Documents` 只要放進一個 `iplot.py` 就變成按鈕 | 紅 |
| 下一層 | 任何模組資料夾裡面再有模組，圖示右下角出現 ▸，點 ▸ 進去看，可以一直往下。還沒有下一層的模組沒有 ▸，第一個從右鍵「在這裡新增下一層模組…」加 | 紫 |

顏色是每一組標題前面的那個點。要多掃別的地方（例如桌面），打開 `config.py` 在 `ROOTS` 加一行，多加的位置是綠色；設定改壞了 iPLoT 會用預設值啟動並告訴你哪裡壞。

`config.py` 另外還有四個設定：用哪個編輯器（`EDITOR`）、每個模組留幾份上一版（`HISTORY_KEEP`），以及「更新」「工作坊」的來源網址（`UPDATE_URL`、`WORKSHOP_URL`，見「更新與工作坊」）。

## 三下做出第一個模組

1. 按那一組最後一格的 **＋**（虛線框那一格）。
2. 打名字（中文、空白都可以；不能含 `/ \ : * ? " < > |`，結尾不能是 `.` 或空白），按確定。名字不合規則時，對話框會說哪裡不行、不會關掉。
3. 編輯器開了範本，新的一格已經在面板上；雙擊它，訊息區出現「<名字> 執行了」。

範本只有一個函式，前面兩行註解是可以打開的選項（結尾還有一段 `on_files` 的註解，這裡省略）：

```python
"""一句話說明這個模組做什麼。"""
# TITLE = "顯示名稱"   # 要讓按鈕文字跟資料夾名稱不同時才打開這一行
# ICON = "🧩"   # 按鈕的圖示：一個 emoji；或在資料夾放 icon.png

# run 可省略：沒有 run 時，最外層程式碼就是按下的動作（input()、print() 照常用）
def run(app):
    """按下按鈕時執行。app 的用法見 docs/api.md"""
    app.log(f"{app.module.title} 執行了")
```

圖示有三個來源，前面的優先：模組資料夾裡的 `icon.png`（或 `icon.svg`；檔名要一字不差，1 MB 以內）→ `iplot.py` 裡的 `ICON = "🧩"`（把範本那一行開頭的 `# ` 拿掉，換成想要的 emoji）→ 都沒有就用名字第一個字，底色由資料夾名稱算出來，每次都一樣。改了存檔、點回 iPLoT 視窗，圖示就換了。

`run` 可省略：沒有 `run` 時最外層程式碼就是按下的動作。課本寫的腳本不改一行就能當模組——執行它就像在模組自己的資料夾裡打 `python3 iplot.py`，只是 `input()` 變成面板裡的對話框、`print()` 進訊息區：

```python
x = input("年齡")
print("你的年齡是" + x + "歲")
```

改完檔案再雙擊一次就是新版本，不用重啟。`app` 能做的事見 [docs/api.md](docs/api.md)。每次執行前 iPLoT 會把 `iplot.py` 存一份到模組自己的 `.history/`，改壞了找得回來。

## 面板長這樣

```
┌ iPLoT ─────────────────────────────────────────────┐   麵包屑；進到下一層變成「iPLoT ▸ 開工」，點任一段回去
│ ● 這一層  modules/                                 │   一組：顏色點、標題、路徑
│   [🧭]▸      [🧬]        [整]!       [＋]          │   一個模組一格：圖示和名稱
│   開工       打開核心    整理桌面    新模組        │   ▸ 底下還有模組，點它進去；! 語法錯誤
│              原始碼                                │   每組最後一格是 ＋
│ ● 上一層  ../                                      │
│   [D]▸       [＋]                                  │   沒有圖示的用名字第一個字
│   Documents  新模組                                │
├────────────────────────────────────────────────────┤
│ 開工  每日入口：一鍵打開 iPLoT 資料夾、docs/…      │   狀態列：單擊選到的模組和它的說明
├────────────────────────────────────────────────────┤
│ • 已掃描 modules/、../，找到 4 個模組              │   訊息區：錯誤、print() 和 app.log 都在這
│ • 模組『開工』第 7 行出錯：                        │
│   NameError，name 'x' is not defined               │
│                              [ 打開檔案 ] [ 詳細 ] │
└────────────────────────────────────────────────────┘
```

單擊選取，狀態列顯示它的說明；雙擊執行。右鍵有六項：「執行」「進入下一層」（有下一層才出現）「打開程式碼」「在資料夾中顯示」「在終端機打開」「在這裡新增下一層模組…」。視窗一取得焦點就重掃，在檔案總管建好資料夾點回來，新的一格就在。視窗可以拉大，格子自動重排；深色模式跟著系統。模組的 `input()` 和問名字都是面板裡的對話框（Enter 確定、Esc 取消）。

這是預設的網頁面板；安全模式與後備面板的樣子不同，見上面「安全模式」。

## 改外觀

面板是三個檔：`ui/index.html`（骨架）、`ui/style.css`（外觀）、`ui/app.js`（行為）。沒有框架、不用 build、不連任何外部網址，文字編輯器就能改；改完重新開 iPLoT 才看得到。

- **改顏色、大小**：改 `ui/style.css` 開頭那一段變數，下面的規則只用變數。例如 `--accent` 是選取與主要按鈕的顏色、`--icon` 是圖示的邊長、`--tile` 是一格最窄多寬、`--log-height` 是訊息區的高度；深色模式的顏色在緊接著的那一段。
- **讓改法在換新版之後留著**：在 iPLoT 資料夾（跟 `config.py` 同一層）建一個 `custom.css`，把要改的變數寫進去：

  ```css
  :root { --accent: #e0703d; --icon: 64px; }
  ```

  它在 `style.css` 之後載入，同名的變數以它為準；沒有這個檔也沒關係。換新版時（用手換，或按「更新」）`ui/` 整個換掉，`custom.css` 不在裡面。

## 更新與工作坊

兩個隨附模組，跟其他模組一樣在 `modules/` 裡：

- **更新**（⬆️）：把 iPLoT 的核心換成新版，不動到自己做的東西。
- **工作坊**（🧰）：從一份清單安裝、更新別人做的模組。

平常不連網。只有按下去的那一次才連，iPLoT 不會自己去看有沒有新版。隨附的 `config.py` 已經填好來源（GitHub Pages 上的 `iplot-workshop`，見「怎麼設定」），剛拿到的 iPLoT 按下去就有東西。把來源改成 `None` 就不連網：按了只會在訊息區說一句怎麼設定——不連網；除了每個模組執行前照例存進自己 `.history/` 的那一份 `iplot.py` 快照，不寫任何檔案；其他功能不受影響。

這兩個功能只在 macOS 上驗過：自動測試與在真的視窗裡走的大部分用本機的 `file://` 網址；從 GitHub Pages 上的 `iplot-workshop` 真的下載、更新、安裝，2026-10-06 在 macOS 上用 `tests/acceptance_workshop.py` 走過一次（全部通過；確認框的長相、用瀏覽器看那一頁、沒有網路時的那一句，要人眼看的部分還沒做）。python.org 的 macOS Python 預設沒有根憑證（要另外執行「Install Certificates.command」），這兩個模組遇到憑證庫是空的時候改用 macOS 自己的 `/etc/ssl/cert.pem`，所以不用另外執行；憑證照樣驗證。Windows 未經實機驗證。安全模式與後備面板（所以 Linux 也是）沒有工作坊的清單頁。

### 怎麼設定

`config.py` 裡的兩行，隨附的已經填好 iPLoT 自己放檔案的地方：

```python
# 「更新」從哪裡看有沒有新版、「工作坊」的模組清單。按了才連網；改成 None 就不連網
UPDATE_URL = "https://william10310406.github.io/iplot-workshop/update.json"
WORKSHOP_URL = "https://william10310406.github.io/iplot-workshop/index.json"
```

不想連網：把網址換成 `None`（不加引號），存檔，執行「重新啟動」；按下去只會說一句怎麼設定。要用別人放檔案的地方：換成那個人給的網址（字串，要加引號）。兩個可以只設一個。填的不是字串也不是 `None` 時，跟其他設定一樣：整份 `config.py` 用預設值啟動，並說哪一項不對。從 0.4.0 用手換上來、`config.py` 裡還沒有這兩行的話，照上面那三行自己加上去；不加等於沒設定（`None`）。

### 怎麼發佈

這是放檔案的人做的事；只是拿「更新」「工作坊」來用的人不用做，隨附的 `config.py` 就指到 iPLoT 自己放檔案的地方。`tools/publish.py` 把一個版本變成這兩個模組讀得懂的檔案。它用 `git archive` 打包核心，所以要在有 git 紀錄的 iPLoT 資料夾裡執行：

```
python3 tools/publish.py --version 0.5.0 --base-url <放檔案的地方> --modules 整理桌面 開工
```

`--modules` 後面是要放進工作坊的模組，寫 `modules/` 裡的資料夾名稱（「整理桌面」是舉例；`modules/` 裡沒有的名稱，工具會說是哪幾個，不產生任何檔）。沒給 `--modules` 時只發佈核心：不打模組的包，`交付/發佈/` 裡原本的 `index.json` 也不動。它在 `--out` 指的資料夾（沒給就是 `交付/發佈/`）產生下面這些檔，最後印出要填進 `config.py` 的那兩行：

| 產生的檔 | 誰用 | 內容 |
|---|---|---|
| `iPLoT-v0.5.0.zip` | 「更新」下載 | 核心的包，也就是交付用的那一整包（最上層是 `iPLoT-v0.5.0/`；「更新」只取裡面的四樣）：`git archive` 打出 `v0.5.0` 這個 tag 的內容。還沒打 tag 時加 `--ref HEAD`，照最後一次 commit 打。打包的那一版裡 `core/__init__.py` 寫的版本要等於 `--version`，不一樣工具就停下來說一句，不產生任何檔 |
| `update.json` | 「更新」讀 | 版本、zip 的網址、zip 的 sha256、這一版改了什麼（取自 `CHANGELOG.md` 那一版那一節的第一段，也就是摘要；它會整段顯示在「要更新嗎」的對話框裡） |
| `模組/<名稱>.zip` | 「工作坊」下載 | 每個模組一包，最上層是 `<名稱>/`。各台電腦自己的東西不帶（名字不分大小寫）：`.history/`、`.origin`、`.unconfirmed`、`__pycache__`、`.DS_Store` |
| `index.json` | 「工作坊」讀 | 每個模組的名稱、版本、zip 的網址、zip 的 sha256、說明、圖示（說明與圖示取自模組的 `iplot.py`）、這一版改了什麼（`notes`，取自模組的 `CHANGELOG.md`） |
| `index.html` | 用瀏覽器看的人 | 一頁：核心的版本、下載連結、sha256、怎麼開始用；每個模組的圖示、名稱、版本、說明、這一版改了什麼、zip 連結、sha256。資料跟上面兩個 JSON 是同一份；沒有 JS、沒有外部資源 |
| `.nojekyll` | GitHub Pages | 空檔：讓 Pages 照原樣放出每個檔 |

模組的版本寫在模組資料夾裡的 `CHANGELOG.md`，格式跟 iPLoT 自己的 `CHANGELOG.md` 一樣：一版一節，`## [1.2.0] - 2026-10-06`，最新的在最上面，標題底下第一段說這一版改了什麼。工具取最上面那一節的版本號當模組的版本（`[Unreleased]` 不算），取那一段當 `index.json` 的 `notes`。沒有 `CHANGELOG.md` 的模組，版本跟 `--version` 一樣、`notes` 是空的：每發一版，它的版本都跟著變，裝過的人會看到「可更新」。也可以在指令列寫「名稱=版本」，例如 `--modules 整理桌面=1.2.0`；跟 `CHANGELOG.md` 寫的不一樣時，工具說一句就停，不產生任何檔；`CHANGELOG.md` 讀不出最上面那一版（版本要寫成 `1.2.0` 這種只有數字與點的樣子，不能是 `1.2.0-beta`、`v1.2.0`）也一樣。隨附的「開工」「作業系統」「打開核心原始碼」各有一份 `CHANGELOG.md`。

模組的包直接從 `modules/` 裡的資料夾打，不經過 git：還沒 commit 的檔會放進去；指到檔案的符號連結，放進去的是它指到的內容（指到資料夾的連結不放）；zip 裡記著每個檔的修改時間，所以內容一樣、檔案時間不一樣時，重打出來的 sha256 也不一樣。git 追蹤的檔有還沒 commit 的改動時（還沒 `git add` 過的新檔不算），工具會多印一句提醒：核心的包是從那個 tag（或 `--ref`）打的，不含那些改動；模組的包含。

`--base-url` 是 `交付/發佈/` 這個資料夾放上去之後對應的網址。兩個 JSON 裡的下載網址都是照它寫的，所以要先決定放哪裡，再跑工具。產生的檔要一起放上去：JSON 裡記著 zip 的 sha256，只換其中一邊就對不上，「更新」「工作坊」會拒絕。

**放在 GitHub Pages：iPLoT 自己就是這樣發佈的（D79）。** 另一個公開 repo `iplot-workshop`，GitHub Pages 從它 `main` 分支的根目錄出，網址是 `https://<帳號>.github.io/iplot-workshop/`。它的本機 clone 放在 iPLoT 資料夾隔壁（`../iplot-workshop`），`--out` 直接寫進去，然後 commit、push。完整的指令，在 iPLoT 資料夾裡：

```
python3 tools/publish.py --version 0.5.0 --base-url https://<帳號>.github.io/iplot-workshop --out ../iplot-workshop --modules 開工 作業系統 打開核心原始碼
```

還沒打 `v0.5.0` 這個 tag 時加 `--ref HEAD`。再到 `../iplot-workshop`：

```
git add -A
git commit -m "0.5.0（<iPLoT 的短 sha>）"
git push
```

推上去之後 Pages 要一兩分鐘才換成新的（`https://<帳號>.github.io/iplot-workshop/update.json` 打開來是新的版本就好了）；那之前按「更新」，拿到的可能還是上一版。第一次推的 repo，要在 GitHub 上那個 repo 的 Settings → Pages 選「Deploy from a branch」、`main`、`/ (root)`。repo 要是公開的：iPLoT 取檔時不帶任何帳號密碼。

用的人在 `config.py` 填 `UPDATE_URL = "<base-url>/update.json"`、`WORKSHOP_URL = "<base-url>/index.json"`，也就是工具最後印出來的那兩行（網址裡的中文會寫成 `%XX`，是同一個網址）；那兩行前面沒有空白，整行從行首貼進 `config.py` 就好。隨附的 `config.py` 填的是 `https://william10310406.github.io/iplot-workshop/` 底下那兩個。`index.html` 是給還沒裝 iPLoT 的人看的那一頁，網址就是 `https://<帳號>.github.io/iplot-workshop/`。從 GitHub Pages 上的 `iplot-workshop` 真的下載、更新、安裝，2026-10-06 在 macOS 上用 `tests/acceptance_workshop.py` 走過一次（全部通過；確認框的長相、用瀏覽器看那一頁、沒有網路時的那一句，要人眼看的部分還沒做）。

**推上去之後：對真的網址驗一遍。** 在 iPLoT 資料夾裡執行：

```
python3 tests/acceptance_workshop.py
```

它跟 `tests/smoke.py` 一樣是自己跑的腳本（pytest 不收），要 macOS、裝好的 `lib/` 和網路，會開出 iPLoT 的視窗，約一分鐘。照 `config.py` 的兩個網址做兩件事：一、等網路上的 `update.json`、`index.json` 跟 `../iplot-workshop` 裡的一樣（Pages 還沒換好就每 10 秒再試一次，最多 10 分鐘），再下載 `index.html`、核心 zip、每個模組 zip，sha256 要跟 json 寫的一樣；二、把 iPLoT 資料夾複製到暫存處（真的工作樹不動），版本改成 0.4.9、刪掉複本的「打開核心原始碼」，開複本真的視窗，用程式代替滑鼠：按「更新」從網路換成新版、按「重新啟動」、打開「工作坊」看清單上的每一列與「這一版」、從網路裝「打開核心原始碼」。每一項印出證據（訊息區的句子、sha256、pid），全部通過結束碼是 0。`--keep <資料夾>` 把複本留在那裡，人工驗收可以接著用（要給一個還不存在、或空的資料夾：裡面已經有東西的話，它說一句就停，什麼都不刪）；`--published <資料夾>` 換掉拿來比的那個資料夾。確認框的長相、用瀏覽器看那一頁、關掉 Wi-Fi 之後按「工作坊」只有一句話，這些要人眼看，不在腳本裡。

**在本機試，用 `file://`。** 不用上傳、不用網路：`--base-url file:///<絕對路徑>/交付/發佈`。在 iPLoT 資料夾裡可以直接這樣寫：

```
python3 tools/publish.py --version 0.5.0 --ref HEAD --base-url "file://$(pwd)/交付/發佈" --modules 開工
```

### 按「更新」會發生什麼

1. 讀 `UPDATE_URL` 指的 `update.json`。`version`、`zip_url`、`sha256` 三項都要有、都要是文字，不然說一句、結束（這在比版本之前就檢查）。上面的版本不比這台的新 → 訊息區說「已是最新（0.5.0）」，結束。
2. 比較新 → 跳出對話框：新版本、現在的版本、這一版改了什麼，問要不要更新。按取消就什麼都不做。
3. 按確定 → 下載 zip 到 `.backup/download-<版本>.zip`，核對 sha256。對不上：刪掉下載的檔，說一句，什麼都不換。
4. 把現在的四樣複製到 `.backup/<舊版本>-<日期時間>/`，例如 `.backup/0.5.0-20261005-183519/`。
5. 換上新的四樣：先各自放成 `<名稱>.new`，再逐一改名換上去（舊的先改名成 `<名稱>.old`，全部換完才在原地改名成 `.update-old-<名稱>-<n>` 刪掉；刪不掉的——例如唯讀的子資料夾裡的檔——留著那個名字，下一次用「更新」換版本時會再刪一次，也可以自己刪），`core/` 最後換，所以磁碟上的版本是新的，就代表四樣都換好了。換的過程中出錯（例如磁碟滿了、沒有權限），已經換上去的全部放回、`.new` 丟掉：四樣要嘛都是新的、要嘛都是舊的。訊息區是一句話，照磁碟上的實況說：都放回了，是「沒有更新：<錯誤>。core/、ui/、main.py、requirements/ 都還是原來的」；放回時也出錯了，開頭是「沒有更新，而且放回原來的版本時出錯了：<錯誤>」，接著列出留下的 `<名稱>.old`、`<名稱>.new` 與不見了的那幾樣要用手整理，並說第 4 步的備份在哪個資料夾（備份本身就失敗時說這一次沒有做成備份），做法見下面「怎麼回到舊版」。還留著的缺口：剛好在換的過程中 iPLoT 被強制結束（兩次改名之間，毫秒級的空檔），磁碟上會暫時新舊混在一起，直到下一次用「更新」換版本時才收回：還有 `<名稱>.new` 就表示上一次沒換完，先照留下的 `.old` 把舊的全部放回去，最後才丟 `.new`（放回的途中又被強制結束，下一次還看得到 `.new`，會接著收）；沒有 `.new` 就表示上一次已經全部換好、只是舊的沒刪掉，留下的 `.old` 不放回去，改名成 `.update-old-<名稱>-<n>` 刪掉。iPLoT 啟動時不檢查這件事。要是剛好停在同一樣的兩次改名之間，`core/`、`ui/` 或 `main.py` 會暫時不在，iPLoT 開不起來、也按不到「更新」：照下面「怎麼回到舊版」把第 4 步存的備份搬回去，留下的 `<名稱>.old`、`<名稱>.new` 刪掉。
6. 訊息區說「已更新到 0.5.1，執行「重新啟動」就會用新版。舊版備份在 .backup/…/」。

**換的只有四樣：`core/`、`ui/`、`main.py`、`requirements/`。** 其他一律不碰：`config.py`、`custom.css`、`modules/`（自己做的模組、每個模組的 `.history/`、隨附模組都在這裡）、`logs/`、`lib/`；iPLoT 資料夾以外也不寫任何東西。所以：

- 隨附模組不會跟著核心一起換。「作業系統」「更新」「工作坊」要換新版，自己把新的資料夾複製進 `modules/`（工作坊不覆蓋這三個，見下面）；其他隨附模組的新版從工作坊來。
- 資料夾裡其餘的檔案——`README.md`、`docs/`、`CHANGELOG.md`、`iPLoT.command` 這些啟動檔——也不在四樣裡，更新之後還是舊的。
- 自己改過 `core/` 或 `ui/` 的話，改的地方會被新版換掉；換掉之前的那一份在 `.backup/` 裡。

**換完要重新啟動。** 換的是磁碟上的檔案，開著的 iPLoT 還是舊版；執行「重新啟動」（或關掉再開）才會用新版，`app.memory` 記的東西會清空，檔案都在。還沒重新啟動又按一次「更新」，只會說「已經換成 0.5.1 了，執行「重新啟動」就會用新版」，不會再下載、再換一次。

**新版要的套件不一樣時，下一次啟動會重裝介面的套件。** `requirements/` 是四樣之一。裡面的清單變了，下一次啟動時，開面板之前終端機會說「介面要用的套件換了版本，正在重新安裝（需要網路）…」，把套件重新裝進 `lib/`，裝好直接開面板。這時候沒有網路：終端機和訊息區都說「介面的套件這次沒有換成新的：…先用現有的開；有網路之後重新啟動 iPLoT 會再試一次。」，先用現有的套件開面板，之後每次啟動都會再試，直到裝成。`--safe` 不碰 `lib/`。

**出問題時是一句話，不是一串錯誤訊息**：連不上來源或下載到一半斷了、網址寫錯（那一句會說去看 `config.py` 的 `UPDATE_URL` 或 `update.json` 裡的 `zip_url`）、`update.json` 不是 JSON、少了項目或項目不是文字、下載的不是 zip、sha256 對不上、包不完整（四樣少一樣，或最上層不只一個資料夾）。這些情況一樣都不換。第 4、5 步寫檔時出的錯（例如磁碟滿了、沒有權限）也是一句話，照磁碟上的實況說四樣是不是都還是原來的（見上面第 5 步）。

**沒有做的**：自動檢查有沒有新版、比較新舊差在哪、一鍵回到舊版（用手搬，見下面）。

### 怎麼回到舊版

每次更新換掉的四樣都留在 `.backup/<舊版本>-<日期時間>/`。要回去，用手搬：

1. 關掉 iPLoT。
2. 找到要回去的那一份。`.backup/` 的名字以 `.` 開頭，macOS 的 Finder 預設不顯示；在終端機裡、iPLoT 資料夾中執行 `ls .backup` 看得到有哪幾份，macOS 上執行 `open .backup` 會用 Finder 打開它。
3. 把 iPLoT 資料夾裡現在的 `core/`、`ui/`、`main.py`、`requirements/` 移走（丟進垃圾桶，或先搬到別的地方），再把備份裡的四樣複製過來。要整個換，不要把新舊兩份資料夾合在一起。
4. 啟動 iPLoT。兩版要的套件不一樣的話，這一次啟動會像上面說的那樣把 `lib/` 重裝一次。

`config.py`、`modules/`、`custom.css` 本來就沒有被更新動過，不用搬。`.backup/` 不會自己清：每更新一次多一份，下載的 zip 也留在裡面，不要了可以自己刪。`.backup/`、刪不掉而留下來的 `.update-old-…`，和工作坊寫進模組資料夾的 `.origin`、`.unconfirmed` 都不在 `.gitignore` 裡：iPLoT 資料夾是 git repo 的話，`git status` 會列出它們。

### 按「工作坊」會發生什麼

讀 `WORKSHOP_URL` 指的 `index.json`，開一個視窗列出清單。每個模組一列：圖示、名稱、說明（作者寫了這一版改了什麼的，底下多一行「這一版：…」）、清單上的版本、在這台電腦上的狀態、一顆按鈕。狀態有六種：

| 狀態 | 意思 | 按鈕 |
|---|---|---|
| 未安裝 | `modules/` 裡沒有這個名稱的資料夾 | 安裝 |
| 已安裝 | 從工作坊裝的，裝完之後內容沒變，清單上的版本也不比它新 | 沒有 |
| 可更新 | 從工作坊裝的，內容沒變，清單上的版本比較新 | 更新 |
| 已修改 | 從工作坊裝的，但當初裝進來的檔有改過或被刪掉（或來源記錄 `.origin` 壞了） | 覆蓋 |
| 版本未知 | 資料夾在，但不是從工作坊裝的：自己做的同名模組，或「作業系統」「更新」「工作坊」以外的隨附模組 | 覆蓋 |
| 隨附模組 | 「作業系統」「更新」「工作坊」：iPLoT 自己要用的，工作坊不覆蓋（見下面） | 沒有 |

- **安裝、更新、覆蓋做的是同一件事**：下載那個模組的 zip、核對 sha256；資料夾已經在的話，先把整個舊資料夾（最上層的 `.history/` 自己除外）壓成 `modules/<名稱>/.history/<日期時間>-folder.zip`；再把包裡的檔案蓋上去（包裡沒有的舊檔案留著）；最後在資料夾裡寫下來源記錄 `.origin`（從哪個網址、哪一版、裝了哪些檔、什麼時候裝的）。只寫進 `modules/<名稱>/` 和一個做完就清掉的暫存資料夾（`modules/.workshop-tmp/`），別的模組、別的地方都不碰：資料夾裡指到外面的符號連結不會被順著寫出去（連結本身拿掉，換成包裡的檔案），`modules/<名稱>` 本身是符號連結就不裝。蓋到一半出錯（磁碟滿、沒有權限、鎖定的檔…），照剛才存的那份快照把資料夾放回裝之前的樣子；原本沒有這個資料夾就整個拿掉。放回時遇到刪不掉、寫不回去的檔也不停下來，能刪的刪、能放的放，最後逐檔跟快照比對，那一列照實說「沒有裝成，已從快照放回」或「沒有裝成，放回時出錯，快照在 <快照的路徑>」；快照本身讀不到的話一樣都不刪，說「沒有裝成，快照讀不到、沒有放回，資料夾現在是新舊混合：<資料夾的路徑>」；連快照都存不成（磁碟滿）的話，什麼都還沒動，說「沒有裝成，還沒動到資料夾（存快照時出錯）」（原本沒有這個資料夾的話，是「沒有裝成，裝了一半的資料夾已經拿掉」或「沒有裝成，裝了一半的資料夾拿不掉：<資料夾的路徑>」）。沒能放回的話，留下來的每個有 `iplot.py` 的資料夾都帶著第一次執行前的確認：裡面可能有新下載的程式。清單頁上連按兩列，會一列裝完再裝下一列。
- **「覆蓋」會先問**：按下去，按鈕變成「確定覆蓋」和「取消」，旁邊一句「這會覆蓋現有的模組，舊版會整個存進它的 .history/」；再按「確定覆蓋」才做，按「取消」回到只有一顆「覆蓋」的樣子。
- **「更新」有時也會先問**：從工作坊裝過的模組，包裡的檔放上去會蓋掉或拿掉模組自己存的檔（不在 `.origin` 記的那份清單裡的：同名的檔、同名的資料夾、擋在要建資料夾的地方的檔）時，下載、解開之後就停下來，資料夾不動，那一列一樣變成「確定覆蓋」「取消」和那一句。按「確定覆蓋」會再下載一次、照上面的做法裝；按「取消」回到「更新」，下次按一樣先問。只會蓋到當初裝進來的那些檔時不問。
- **裝進來的模組第一次執行前會問**：「『<名稱>』是從外面裝進來的，第一次執行前確認：要執行嗎？」按取消就不執行，下次還問；按確定才執行，之後不再問。包裡與磁碟上那個模組資料夾裡每一個有 `iplot.py` 的資料夾都一樣（新的包只帶了下一層模組旁邊的檔、沒帶它的 `iplot.py` 也算）：按 ▸ 進去執行下一層的模組，也會先問。更新或覆蓋之後算重新裝了一次，會再問一次。這一問是提醒，不是檢查：sha256 只保證下載到的跟清單寫的是同一個檔，模組做什麼沒有人把關——它跟自己寫的模組一樣，是用這個使用者的權限執行的 Python 程式（[docs/07_接口與邊界.md](docs/07_接口與邊界.md) 第 7 節）。
- **關掉清單的視窗**，面板重掃一次，新裝的那一格就出現。
- **什麼算「已修改」**：當初裝進來的那些檔（`.origin` 裡記著是哪些）有改過或被刪掉。執行過不算；模組自己另外存的設定、資料（不在那份清單裡的檔）也不算，所以會在自己的資料夾存東西的模組，用過之後不會因此變成「已修改」。模組要是把資料寫回包裡本來就有的檔，那就算改過。已修改的照樣可以覆蓋：舊資料夾先整個存進 `.history/`，包裡沒有的檔案也不會被刪。
- **不裝、資料夾不動、那一列改成「無法安裝：…」的情況**：連不上，或下載到一半斷了；sha256 對不上；zip 的最上層不是 `<名稱>/`；包裡沒有 `iplot.py`；包裡的路徑有 `..`；清單上的名稱不是單純的資料夾名（含 `/`、`\`，或以 `.` 開頭）；`modules/<名稱>` 本身是符號連結。蓋檔蓋到一半出錯也是「無法安裝：」開頭，接著是那個錯，再照實說放回去了沒有（見上面）。
- **「作業系統」「更新」「工作坊」不從工作坊換**：這三個是 iPLoT 自己要用的隨附模組。清單上有它們時，狀態是「隨附模組」、沒有按鈕，那一列多一句「這是 iPLoT 自己要用的隨附模組，工作坊不覆蓋它；要換新版，自己把新的資料夾複製進 modules/。」名稱寫法不同（大小寫、Unicode 的另一種寫法）也算同一個；這三個資料夾被刪掉了，也不從工作坊裝回來。要換新版，只能自己把新的資料夾複製進 `modules/`（「更新」不碰 `modules/`）；自己複製進來的資料夾不帶第一次執行前的確認。不讓工作坊覆蓋，是因為從工作坊裝進來的「作業系統」會帶著那一問：在面板上按過一次確定之前，右鍵的動作、「打開檔案」每次先問；啟動時剛好要安裝介面的話，終端機那一頭沒辦法回答這一問。其他隨附模組（「開工」這些）照舊是「版本未知」，可以覆蓋。
- **沒有清單頁的地方**：安全模式與後備的 tkinter 面板，所以 Linux 也是。在那裡按「工作坊」，訊息區只有一句「這個面板沒有頁面（安全模式與備用面板都是）；這個功能要在一般的網頁面板裡用」。
- **沒有做的**：移除模組（要移除，把那個資料夾丟進垃圾桶）、降回舊版、評分、留言、自動更新、一次看多份清單。

## 在面板外打開模組

裝了工作坊模組「互通」之後，任何模組都能不開面板就打開：從 Spotlight、Dock、一行指令，或在模組資料夾直接 `python3 iplot.py`。打開之後跟在面板裡一樣拿得到 `app`；對話框、訊息與錯誤出現在一個小小的彈出式視窗。再裝「主控面板」，任何模組寫一行 `app.run("主控面板")` 就能叫出面板（已經開著就叫到最前面）。

1. **裝**：0.5.1 起新下載的 iPLoT 已經帶著「互通」與「主控面板」（在 `modules/` 裡）。從 0.5.0 按「更新」升上來的（「更新」不碰 `modules/`），在面板按「工作坊」安裝這兩個。
2. **在面板按一次「互通」**：它會記下面板用的 Python、替每個模組做一個捷徑，然後顯示狀態頁：幾個模組能在面板外打開、幾個能直接執行、捷徑放在哪裡、指令怎麼寫。它不改任何模組檔案。
3. **Spotlight**：按 ⌘＋空白鍵，打模組的名稱，按 Enter。下一層的模組叫「父 › 子」。
4. **Dock**：狀態頁按「在 Finder 中顯示」，把 `捷徑` 這個資料夾拖到 Dock，點開就是一排按鈕。
5. **一行指令**（終端機、macOS 的「捷徑」App、快捷鍵）：狀態頁上有一行可以直接複製，長這樣：`<Python> <iPLoT>/modules/互通/run.py 開工`。最後一個字換成模組的名稱或資料夾；後面再接檔案路徑，就交給模組的 `on_files`。
6. **直接執行**：終端機進到模組的資料夾，`python3 iplot.py`。0.5.1 起用 ＋ 建的模組本來就能這樣跑。之前就有的舊模組，要在面板按「互通」，在狀態頁「可以加上那一小段的模組」那一區看清楚會改哪幾個檔（名稱與 `iplot.py` 的完整路徑），按「加上（N 個檔）」：每個檔的開頭加上「互通」的那一小段，改之前先在模組自己的 `.history/` 存一份。只改 iPLoT 的 `modules/` 裡的模組；上一層（iPLoT 旁邊）與 `config.py` 的 `ROOTS` 另外加的資料夾裡的模組一律不改。還沒裝「互通」（或模組不在 iPLoT 裡、也不在它旁邊）時，它說一句找不到，然後照一般的腳本跑，跟以前一樣。在編輯器裡直接 Run／Debug 一個模組、要中斷點停得到時，設環境變數 `IPLOT_DIRECT=1`：一律照一般的腳本跑，不交給彈出式視窗。

彈出式視窗平常藏著，模組有話要說（訊息、錯誤、問問題）或跑超過 1 秒才出來；跑完沒說話就什麼都不顯示，說過話就倒數 3 秒自己關，出錯就留著。按「停止」或關掉它，結束的是那一次執行，面板不受影響。每一次面板外的執行都是獨立的：不跟開著的面板共用 `app.memory`，訊息不進面板。

- **第一次可能會問權限**：iPLoT 放在「文件」「桌面」「下載項目」裡時，第一次從捷徑打開，macOS 會問要不要讓「Python」取用那個資料夾，按允許。允許的是 Python 本身：所有捷徑共用這一次，任何用這個 Python 跑的程式也都讀得到那個資料夾。（開發用的那台 Mac 在測之前就已經允許過 Python，所以「只問一次」還沒在別的機器上親眼看過。）iPLoT 放在家目錄底下（例如 `~/iPLoT`）也可能會問：`ROOTS` 預設會掃 iPLoT 的上一層，那就是家目錄，掃的時候會碰到「文件」「桌面」「下載項目」（推測，還沒在乾淨的 Mac 上看過）。
- **換了 Python**：在面板按一次「互通」重新記下；捷徑找不到記下的 Python 時會跳出來說這一句。
- **`config.py` 的 `ROOTS` 另外加的資料夾**（例如 `~/Desktop`）裡的模組，從捷徑與指令照樣打得開；直接 `python3 iplot.py` 時那一小段找不到 iPLoT，照一般的腳本跑（沒有 `app`、不用彈出式視窗）。
- **用舊 Python 直接執行**（例如系統內建的 `/usr/bin/python3`）：那一小段會換成記下的 Python 再跑；但檔案裡用了舊 Python 看不懂的語法（例如 `match`）時，在讀檔階段就出錯，輪不到它換。
- **加了不想要**：把檔頭兩行 `# ── 互通 ──` 之間那一段整段刪掉，或從模組的 `.history/` 拿回加之前的那一份。沒有任何東西會自動加回去（同步、捷徑、按「互通」都不改模組檔案），只有再按一次「加上」才會。工作坊裝來的模組、「作業系統」「更新」「工作坊」、用了 tkinter 或 turtle 的模組（加了之後直接執行反而開不了它的視窗）不在可以加的清單裡。
- **只在 macOS 驗過**：捷徑、權限的那一問、叫到最前面只在 macOS；Windows 的彈出式視窗未經實機驗證；這一版的 Linux 沒有網頁面板，在面板外打不開。
